## Reviewed behavior and evidence

- **Registration and shutdown:** `transaction-service.ts:202–222` checks service lifetime and pre-abort, reserves capacity and installs abort wiring before invoking the callback, and removes the registration on either settlement. `:430–449` closes admissions before cancelling streams and snapshots/drains both stream completion and finite work before owner close. No asynchronous gap exists between the synchronous registration steps for native AbortSignals. The service test independently passed pre-abort, capacity, shutdown cancellation, already-admitted scheduled sequence drain/reopen, and refusal after close. A stream callback awaiting the service close that waits on it remains outside the specified internal callback contract; runtime does not do that.
- **One frame at a time:** `transaction-sse.ts:37–64,77–95` keeps only the current page/frame, awaits drain before next pull or comment, and removes drain/error/close/abort listeners on every settlement. Additional independent probes verify successful drain causes exactly one pull from the published checkpoint, a second blocked frame cannot accumulate comments/read-ahead, error and close reject without another pull, pre-abort publishes nothing, and abort during an outstanding read prevents publishing its returned group. No duplicate/missing group was observed in real replay/live/reconnect tests. Synthetic probes isolate the pump's sequencing; their minimal page objects are not wire conformance fixtures.
- **Initial context, media and conditional ordering:** `transaction-http.ts:395–438` selects representation but performs the effective owner read before success negotiation/conditional outcomes, keeps URL intent mandatory, and uses the first page/context directly. JSON wins ties and ignores even repeated malformed reconnect headers; selected SSE uses the raw inventory preserved by `transaction-runtime.ts:143–149`. HEAD, 304 and 412 return finite outcomes before stream registration, with current context and no body. The real wire tests exercise them while the live slot is occupied. The shared Read helper retains its prior JSON/204 behavior; all focused Read HTTP tests passed.
- **Disconnect and failures:** the extracted `node-http-disconnect.ts` is the same incoming-abort/outgoing-unfinished-close bridge previously local to index.ts. Runtime attaches it before asynchronous handling. `transaction-runtime.ts:161–196` destroys after a streaming failure instead of entering finite delivery; blocked pump errors preserve the injected error identity. Actual post-header owner-fault testing observes one HTTP status and no invented error Event. This evidence proves pump rejection identity and wire closure, not a new persistent operational logging facility. No live disk/network fault campaign was performed.
- **Replay and partial publication:** the final raw proxy test in `transaction-sse.test.ts:600–669` forwards actual response bytes while withholding the final frame LF/chunk terminator, observes zero complete frames, closes, and reconnects from the applied genesis checkpoint. This is an actual partial-wire witness, distinct from the separate replica publication-failure and owned-Link/source consistency oracle. The recorder deliberately exposes complete HTTP chunks before recognizing blank-line SSE completion; it does not claim incremental application of a partial HTTP chunk. Reconnect, restart, no-op silence, literal numeric normalization, current epoch/view errors, overridden stale query and start-now/minimum-wait anchoring tests all passed.
- **Configuration and bounds:** stream defaults and the existing four transport settings enter runtime identity; closed own-data timing seams suppress metadata and cannot become installed launch settings.
