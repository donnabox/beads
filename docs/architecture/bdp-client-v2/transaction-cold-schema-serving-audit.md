## Authority and limits of the conclusion

Normative `docs/specs/bdp.md:1091–1098` describes Type inventory as enabling clients to preload schemas;1198 identifies propertiesSchema as an absolute JSON Schema URL;1234–1243 allows ordinary Web descriptor retrieval and assigns JSON Schema2020-12 reference semantics. Sections2533–2584 require a complete immutable pinned local closure, offline request validation and exact retained artifacts. Serving the advertised local content from that capture is consistent with these rules. Sections1935–2007 govern cumulative GET/HEAD, negotiation, authentication-before-conditional shortcuts, HEAD metadata and HTTP preconditions;5768–5774 gives the general Transactional Scope-response tuple.

Precision: the inspected spec does **not** contain an explicit blanket MUST that every authority host every installed properties-schema URL. Clients may skip schema reads (2592 onward), and schemas may be externally hosted. The mandatory status here comes from the already accepted cold-client deployment objective with **this deployment's own local URLs**, together with the URL's stated schema role. Do not invent a new universal hosting obligation, classify external schemas as invalid, or claim offline retention alone implies public hosting.

The protocol bundle and problem-family identifiers are a different case: spec46–56 explicitly permits their use without dereferenceability and requires conformance validators to load the bundle offline. This audit does not request serving the GitHub bundle URI or changing describedby identifiers.

## Proposed next serving slice

After the active sequence slice is frozen/integrated and root assigns a reviewed parent, add a source-private TX schema adapter for **exact captured schema retrieval URIs under the configured `${scope}schemas/` namespace**. This is a bounded initial deployment convention, not a new BDP URL law. Include every captured local schema resource in that namespace, including transitively referenced resources; do not serve only the descriptor's root schema. External artifacts remain usable for offline validation and are not proxied, fetched or rewritten. Non-schema artifacts, arbitrary paths, aliases, percent-encoded alternate identities, query variants and uninstalled URIs must not gain access through a prefix-only lookup. No new installation rejection is needed to make the known local fixture usable.

Construct the immutable lookup from `contracts.capture.artifacts` (kind, exact retrieval URI, byteLength, sha256 and bytesBase64), not mutable caller options. Preserve original UTF8 bytes, including whitespace and numeric literals; do not pass schema objects through the current runtime `deliver()` JSON serializer and call that exact-byte serving. Use the existing lossless decoding only where needed by HTTP semantics. Existing ingestion ceilings bound artifacts to1MiB each and16MiB total; account for any decoded in-memory copy rather than describing it as free. No new cache validator or public digest is required.

Keep existing raw-target/authority, method, trusted credential, Origin, close and disconnect gates. Use `application/json`, the existing supported representation and RU precedent, with private/no-store and the non-attesting marker; use current HTTP negotiation/precondition helpers. Successful local schema GET/HEAD and their selected304/412/406 responses should receive a current immutable Scope tuple from one owner observation under the service's finite-work lifetime.
