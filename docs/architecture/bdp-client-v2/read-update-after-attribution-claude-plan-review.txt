**Location** Plan §60 (R step 4), against the table at §51–53

**Problem** Step 2 creates the subject with `properties.value` set to the admitted replacement (9007199254740992 / 0.125 / 1e300). Step 4 then "correct[s] only the literal and key" on the refused patch — and the only admitted literal the plan supplies per case is that same replacement. **Impact** The row's strongest positive discriminator is weaker than stated; a real propertiesChange-dropping regression passes R.

**Fix** Have step 4 correct to a *different* admissible literal than step 2's postimage — integer 9007199254740994 (which also exercises §51's even/odd-past-2^53 point against the preceding row), precision 0.25, overflow 1e299. ## LOW — the Problem-response controls cannot use the seam §79 names

**Location** Plan §79 and controls 2, 5, 6, 7, 8; `read-update-matrix.test.ts:455–491` (client seam) vs `:397–435` (raw seam)

**Problem** `RetryControl` is applied inside `actionExecutor`, which positionally selects `actions.filter(a => a.family === "client")` — it cannot reach a raw exchange. Controls 2/5/6/7/8 corrupt the Problem returned to a **raw** mutation (§39 puts every numeric create/update on `family:http`), so they must go through the `numericControl` branch of `executeExact`, whose hit predicate is hardcoded to one scenario ID and two idempotency-key literals and whose mode is a three-literal union. Control 1 (pre-transmission token swap) likewise. Only 3, 4 and 9 are `RetryControl`-shaped. Separately, the one existing response-substituting branch rewrites `status`, `bodyText` **and** `bodyOctets` together; a control that edits a diagnostic field without recomputing `bodyOctets` will trip octet assertions too and violate §91's "exact intended assertion set".

**Impact** §79 reads as if one seam covers all nine; an implementer following it literally stalls on five of them, and the derived-field hazard is undocumented.

**Fix** In §79, split the nine explicitly by seam (1,2,5,6,7,8 → exact raw wrapper; 3,4,9 → client `RetryControl`), and require response-substituting controls to keep `bodyOctets` consistent with the substituted `bodyText`.

**Location** Plan §23 (nested-refusal limit column), against `packages/protocol/src/json-admission.ts:3–5` and `packages/server/src/development-authority.ts:51,54`

**Impact** None to feasibility — the hedge errs conservative — but the sentence misstates why depth 16 is a sampling choice, which matters if a later reviewer tries to justify the sample size from a bound.

**Fix** Cite the 64 KiB body/properties bounds and the 128-level artifact depth cap instead.
