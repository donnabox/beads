## Findings

### 1. MEDIUM — Stale command-minimum claims left in the progress record
**Location:** `docs/design/transaction-implementation-progress.md:600–601` (and, ambiguously, `580–582`)

**Issue:** Plan item 6 required superseding the current command-minimum descriptions. The draft updated two sites (`657–663`, `1725–1737`) and left a third, unambiguous one:

> 600: Unsupported minimum-context fields on commands also fail before any key binding
> 601: or effect; no command barrier semantics are inferred.

After the `transaction-http.ts:294–302` deletion this is exactly false: those fields now admit the key and execute effects. `580–582` ("Minimum context controls likewise cannot yield success or a conditional shortcut") sits inside a paragraph about command carriers (set/depth/alias-sequence requests) and reads the same way.

**Impact:** The published design record asserts the opposite of both the shipped code and the new normative paragraph at `docs/specs/bdp.md:5792–5800`. No test reads this document (`grep` for `transaction-implementation-progress` in `*.ts`/`*.mjs` → no hits), so the measured gate cannot catch it. The next slice reanchors on this file.

**Smallest correction:** Mirror the 660/1730 edits — replace 600–601's first sentence with a superseding one (e.g. "Copied read minimum fields on commands are ignored under the later command-minimum amendment; no command barrier semantics are inferred."), and scope 580–582's sentence to reads ("Read-side minimum context controls …").

### 3. LOW — The "empty copied field value" cell in source test A may not be observable on the wire
**Location:** `packages/server/src/transaction-http.test.ts:1143` (`["batch", ""]`)

**Issue:** Test A assigns the empty value to the `batch` column and sends it via `fetch`. Nothing in the test asserts the field reached the server. If undici elides an empty field value, those three cells silently degrade to "no copied field present" — and the test still passes, so the gap is invisible. No existing repo test establishes undici's behaviour here (`transaction-schema-http.test.ts:219–221` exercises empty values but through `node:http`, not `fetch`).

**Impact:** The report's claim "Distribute empty, invalid-token and comma-joined values across the three carrier columns" would be unproven for 3 of 9 A cells. Coverage is not actually lost: the installed TX scenario sends `{"bdp-scope-epoch": ""}` through the exact raw serializer (step 7), where `HTTP_FIELD_VALUE = /^[\t\x20-\x7e\x80-\xff]*$/` accepts empty and the byte is written literally.

**Smallest correction:** Either attribute the empty-value evidence to the installed raw-serializer cell in the report, or move A's batch column to a non-empty invalid token so the source cohort claims only what `fetch` demonstrably sends.
