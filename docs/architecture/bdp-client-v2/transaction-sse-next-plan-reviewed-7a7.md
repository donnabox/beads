Read-only proposal for native/Claude council; no implementation authorized by this document. Sole fork design remains plan authority. ## Recommendation and sequence

Implement **G2a: actual changefeed SSE replay/live delivery over the existing one-group reader**, after root serializes the service/HTTP/runtime overlap with Snapshot HTTP. This is the smallest useful live transport slice: it needs no second log, generic subscription framework or new durable cursor format. Then implement **G2b: Scope and Resource Event SSE** using the same bounded transport, with an owner-backed sparse-source progress seam if needed. Full erasure publication fencing and mutable-view/replay-retention support are mandatory later gaps; G2a is not full SSE or Transactional qualification.

Required HTTP set operations remain important, but are not a prerequisite for observing already supported writes over SSE. The private valid set core is implemented; its normal HTTP admission is closed. The sole design checkpoint still lists Selector complexity admission as unresolved, and batch admission text (spec 4493–4527) does not by itself classify every grammar/complexity failure. Do not use this SSE slice to decide that issue. A root-approved set error mapping could make sets a parallel or earlier slice in a separate owner lane, but SSE's settled replay/framing portion can advance independently. Physical service/runtime authoring is **not** independent of active Snapshot HTTP; only this plan and pure framing tests are independent until root assigns an integrated base and exclusive files.

## G2a design

### Admission and representation selection

1. Preserve raw-target/Host/method handling and authentication/nondisclosure. Parse canonical changefeed query/control syntax and compute the effective live cursor before owner admission. A positive Last-Event-ID overrides `after` for SSE only; finite JSON continues ignoring it. The effective header is checked against the exact existing token/cursor codec and current epoch/view; an obsolete overridden query cursor is not looked up as the effective cursor.
2. Reuse `service.changes` to capture first page, starting anchor and context. A `start=now` admission must retain `page.after` even when minimum waiting lets more commits happen; never recapture now on each poll. Do not obtain headers from a later inspect call. Existing unsupported minimum categories remain explicit development gaps.
3. Select supported representation with a small private helper using inherited media-range parsing. Default/tie preference JSON preserves existing default; positive SSE-only or higher-quality SSE selects stream. Wildcards and explicit q=0 exclusions obey specificity. Retain Vary: Accept. Reuse the existing conditional decision algorithm after owner/context checks. For acceptable SSE, set Content-Type:text/event-stream and Cache-Control:no-store,no-transform; omit finite Content-Length and validators. HEAD returns the same decision/context and closes, without subscribing or sending frames. 304/412 remain bodyless with required current context, no cursor advancement. No fictitious stream ETag.
4. Return a source-private discriminated transport result: ordinary finite response or stream admission with initial metadata/first page and controlled read capability. Do not widen the public server HttpResponse interface to accept arbitrary callbacks/streams. If extraction of read-http private helpers is disallowed due to ownership, pause that file and perform pure framing tests; do not duplicate policy machinery.

### One owner, one frame at a time

- First page is held from admission; each next pull is `service.changes({after:lastPublishedCheckpoint})`. This reads existing durable groups, not a second Event queue. Never keep SQLite open across an await, socket write, sleep or application callback.
- Emit exactly `id: <checkpoint>\nevent: change-group\ndata: <lossless complete group JSON>\n\n`. Use `stringifyJsonValue`, not JSON.stringify, so exact numeric literals survive. JSON escaping keeps embedded LF/CR inside data strings from becoming SSE fields. Check codec token safety rather than sanitizing IDs.
- At current head, wait using cancellable bounded polling outside the owner. Start with a private100ms poll interval and an optional comment heartbeat every5s to fit the current10s idle timeout, subject to council/actual idle test. No per-client retained history pin, notification bus, or promise that heartbeat is protocol-mandatory.
- A whole frame is passed to Node's transport as one write. `write(false)` means bytes were accepted into the transport buffer, not unapplied: record authority publication at the write boundary, then await drain/error/close **before pulling/materializing another group**. This does not imply client delivery or durable application. On half-frame disconnect the client's staging oracle discards the incomplete message and keeps its prior checkpoint.
- Bound simultaneous stream admissions initially to one in this private fixture; HEAD consumes no live slot. An exhausted live slot is actual temporary service unavailability (existing503), not a new named protocol limit. This conservative private cap is an implementation setting, not public specification. Tests may use a narrow lower timing seam with attestation suppressed; installed evidence uses actual defaults. Re-evaluate the cap only with materialization measurements.
- On disconnect/error/service close, cancel polling/drain waits and release stream registration. Service close cancels stream observations before awaiting active work; it continues to drain accepted mutation transactions. Preserve original and cleanup failures. Do not await service.close from a stream task that service.close is itself waiting on.
- An error before headers uses existing finite status/problem/bodylessness. An owner fault or gap after stream headers closes the stream; no invented BDP `error` SSE event, fake projection advance or silent cursor skip. Retain diagnostics privately.

### Bounds derived from current source

The proven stored Event-group bound is169,345,024 encoded bytes; finite served changefeed envelope bound is186,334,744. This is a conservative source-derived bound; realizable induced Events may be lower for this operation/match tuple. Do not label every Event ceiling as attainable.

A single SSE group JSON is a component of that finite page. Adding at most256 ID bytes plus fixed id/event/data/newline spelling is bounded by the existing served-page bound +512 =186,335,256 encoded bytes, below pinned Node24 `MAX_STRING_LENGTH` (check actual constant in implementation test rather than assume another Node build). No huge proof allocation is necessary. This is encoded framing/string safety, **not** a heap/RSS bound: parsed rows, serialization and transport buffers coexist. One live stream/one pending frame prevents per-client unbounded queues but is not a universal process memory claim. Do not retrospectively reject an already admitted valid group because a new streaming buffer is smaller. Keep materialization limits unchanged; root's active budget work remains separate.

## G2b Event Sources, explicitly separate

Event SSE frames repeat each already-rendered Event ID/type/data and preserve transaction/ordinal. Start without cursor at earliest retained; supplied `after` or effective Last-Event-ID is exclusive within that source. Reuse the same current projection for Scope, Bead and Link; self-Link two endpoint facts, deleted Resource source continuity, updates/reversals and no-op absence remain observable.

Blindly polling `readEvents(source,lastEventId)` is correct under the current no-pruning view but can repeatedly scan unrelated groups when a Resource source is sparse. The smallest efficient follow-up is a **lifetime-checked private scan state** bound to source/epoch/view with authority-group scan position and intra-group offset, advanced only for fully scanned groups/returned facts. It is not a public Event ID, checkpoint, durable subscription or new log. It must preserve stable Event IDs and validate source/cursor exactly once at admission, then use the same renderer/guarded reader for each pull. No persisted state or store format change should be needed. Inspect/review that seam before authoring; it is not needed by G2a and must not delay its real transport evidence.

Metadata-only incident Link projection remains explicitly unqualified until root's pending ruling. A Scope-source SSE implementation can progress without deciding that Resource-source case. Full erasure-withheld cursor semantics and mutable-view behavior are separate required gaps, not failures to be papered over with the all-visible contiguous-ordinal assumptions.

## Real ambiguities and existing conventions

1. **Last-Event-ID with original start=now, or with no query intent:** spec explicitly says it overrides original `after` and requires exactly one starting intent. It does not expressly say whether header alone replaces `start=now` on reconnect. Recommended clarification is that the live header supplies the effective exclusive starting checkpoint and overrides initial URL intent, which supports native EventSource reconnect; this plan does not install that interpretation as a ruling. Clear initial start=now and explicit after+header paths can be implemented/tested independently; unresolved combination remains an explicit private gap until root disposition. Do not claim full reconnect support while it is unresolved.
2. **Malformed/repeated/empty Last-Event-ID:** token profile prohibits empty/whitespace values as tokens, and current finite codecs map invalid tokens to local-reference400 invalid-parameter. Proposed reuse is a documented reference convention; no claim that every malformed HTTP header has a new normative BDP error. Duplicate field handling must happen from raw header inventory before Headers joins values. Keep query-key/duplicate syntax checks separate from effective cursor lookup.
3. The spec does not prescribe heartbeat/poll interval/live slot counts, SSE max lifetime, or choice among equally acceptable representations. Those are bounded implementation choices above, not product questions. Do not impose a fixed lifetime merely to turn a streaming test into a finite success.
4. **Mandatory erasure fence:** not ambiguous, simply unimplemented by this owner (stored `erasures:[]`, no erasure publication/rotation API). A future writer must atomically serialize publication eligibility with erasure floor advance; a loop that holds an old materialized frame and writes it later is not that mechanism. Restrict G2a's claim to the current configuration. Before erasure is enabled, integrate an owner publication gate and tests for caught-up/behind/backpressured streams and view-specific floors; do not claim finite polling automatically supplies it.

2. Starting after a real checkpoint is exclusive. genesis includes complete retained history; start=now captures admission head once and delivers only later groups. During a minimum wait, commits after admission are not silently skipped by recapturing head.
