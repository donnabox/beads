## Dynamic route and wire-evidence fidelity

The revised receipt adapter resolves the previous blocking contradiction without relaxing `http-executor.ts:544–563`'s frozen route law. It obtains authority to follow a receipt only from a validated original POST/receipt observation; captures include source action/response/pointer, canonical URL, method role and credential/view context. Same-Scope checks alone are insufficient, so exact captured-value equality, receipt path grammar and unobserved/cross-row/foreign/credential-substitution controls are required before credential resolution/dialing.

A single dynamic route receives a separately snapshotted exact executor configuration and digest, tied to the already validated child/listener/full configuration. The private report must preserve the originating exchange and link that distinct per-route digest; it must not claim membership in the base fixed-route digest. Fixed operation/resource observations retain their ordinary exact execution path. This is an appropriate bounded private exception for server-allocated receipt identities, not a wildcard route framework.

Parsing original received bytes for assertions is acceptable. Reconstructing a successful Response from parsed JSON would lose evidence fidelity; the plan now expressly preserves status, header lines, body bytes/text and request observation and prohibits such reconstruction. Counterfactuals are clearly separated test mutations. Request authorization evidence must use existing redaction/fingerprints, never export raw credentials. If the current runner result cannot preserve this linkage, H1b must propose the small private recorder change before implementation; H1a need not speculate or build it now. This review accepts the model, not an unimplemented wire recorder.
