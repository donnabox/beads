# Dolt lowering: primary-source checks

Checked 2026-10-20. This is source research for an **unexecuted lowering sketch**, not qualification of the installed Dolt build or Beads adapter. No Dolt query, product test, Go command, build, Git command, or publication action was run for these findings.

The official documentation lists CTEs, joins, subqueries, `UNION`, JSON extraction/type/presence functions, and `INSTR`/`LOCATE` as supported. That feature list alone does not establish the query language's strict semantics. [CTEs](https://www.dolthub.com/docs/sql-reference/sql-support/miscellaneous/), [SQL support table](https://www.dolthub.com/docs/sql-reference/sql-support/expressions-functions-operators/).

This is a source snapshot, not an assertion that Beads uses that version. ## Bounded graph traversal

- Recursive CTE construction accepts `UNION`, `UNION DISTINCT`, and `UNION ALL`; do not infer a blanket MySQL-style prohibition on recursive distinct. The builder passes a deduplication choice to the recursive plan. [Builder](https://github.com/dolthub/go-mysql-server/blob/239e0ad6b2f9f32ba9c5752a8b5930e4d682d2cf/sql/planbuilder/cte.go#L54-L61), [distinct selection](https://github.com/dolthub/go-mysql-server/blob/239e0ad6b2f9f32ba9c5752a8b5930e4d682d2cf/sql/planbuilder/cte.go#L172-L189).
- The iterator deduplicates **the whole recursive row**. For bounded reachability, deduplicating `(root edition, endpoint edition, depth)` retains different depths while collapsing parallel witnesses at the same depth. An explicit `depth < maximum` remains necessary: including depth prevents identity-only cycle termination. Final endpoint deduplication is a separate operation. This is an inference from the iterator, not an executed graph result. [Iterator](https://github.com/dolthub/go-mysql-server/blob/239e0ad6b2f9f32ba9c5752a8b5930e4d682d2cf/sql/rowexec/rel_iters.go#L628-L701).
- A reachability row must not include a Link ID unless distinct Link witnesses are intended: that changes the deduplication unit. Graph output needs separate edge selection preserving parallel Link identities; path output needs explicit path state and cycle rules. `UNION ALL` plus finite depth is another possible lowering, but can enumerate exponentially many repeated walks before final deduplication. These are lowering implications, not engine performance measurements.
- Keep the recursive member simple: one recursive table reference joined directly to preselected edges. The builder contains a TODO describing one-reference/no-subquery restrictions, but that comment is not sufficient proof that every such invalid shape is currently rejected. Avoid a recursive `NOT EXISTS` against the CTE; exact support for more complex recursive shapes remains a qualification task. [Recursive shape handling](https://github.com/dolthub/go-mysql-server/blob/239e0ad6b2f9f32ba9c5752a8b5930e4d682d2cf/sql/planbuilder/cte.go#L196-L249).
- Do **not** rely on `SET cte_max_recursion_depth` as the application budget. The variable is declared with default 1000, while this iterator uses a hard-coded `cteRecursionLimit = 10001`. The inspected enforcement does not read that variable. Neither a depth bound nor a final `LIMIT` substitutes for row/edge/byte/time accounting and cancellation in the adapter. [Variable declaration](https://github.com/dolthub/go-mysql-server/blob/239e0ad6b2f9f32ba9c5752a8b5930e4d682d2cf/sql/variables/system_variables.go#L693-L700), [actual limit](https://github.com/dolthub/go-mysql-server/blob/239e0ad6b2f9f32ba9c5752a8b5930e4d682d2cf/sql/rowexec/rel_iters.go#L704-L712).

## Strict values and literal text

- `JSON_CONTAINS_PATH(properties, 'one', '$."status"')` is the right candidate primitive for physical presence; `JSON_EXTRACT` returns a JSON wrapper for a found value and SQL null for a missing path. Preserve presence separately from the query read value, which deliberately collapses absence and explicit JSON null. Generate JSON paths from parsed property names rather than interpolating user expression text. [Presence implementation](https://github.com/dolthub/go-mysql-server/blob/239e0ad6b2f9f32ba9c5752a8b5930e4d682d2cf/sql/expression/function/json/json_contains_path.go#L47-L94), [extraction](https://github.com/dolthub/go-mysql-server/blob/239e0ad6b2f9f32ba9c5752a8b5930e4d682d2cf/sql/expression/function/json/json_extract.go#L75-L119).
- Guard string comparison with `JSON_TYPE(...) = 'STRING'` before `JSON_UNQUOTE`; unquoting alone must not become implicit cross-type conversion. The type implementation reports `'NULL'` for a nil document as well as JSON null, so do not use `JSON_TYPE(...) IS NULL` as the missing-property test. The numeric type labels include several SQL representations; strict numbers and precision need adapter normalization rather than dependence on one label. [Type handling](https://github.com/dolthub/go-mysql-server/blob/239e0ad6b2f9f32ba9c5752a8b5930e4d682d2cf/sql/expression/function/json/json_type.go#L78-L148), [unquoting](https://github.com/dolthub/go-mysql-server/blob/239e0ad6b2f9f32ba9c5752a8b5930e4d682d2cf/sql/expression/function/json/json_unquote.go#L79-L104).
- **`LOCATE(BINARY needle, BINARY haystack)` is not a supported case-sensitive lowering in this snapshot.** `LOCATE` converts to text and unconditionally lowercases both inputs. Binary casts cannot change that implementation. Its offset is also byte-based, with a reported multibyte-position issue; a boolean `> 0` use avoids interpreting the position but does not fix case or empty-string behavior. [Implementation](https://github.com/dolthub/go-mysql-server/blob/239e0ad6b2f9f32ba9c5752a8b5930e4d682d2cf/sql/expression/function/locate.go#L92-L182), [upstream report](https://github.com/dolthub/go-mysql-server/issues/3649).
- `INSTR(haystack, needle) > 0` is a better **candidate** for sensitive literal matching: the inspected implementation compares rune subsequences directly, giving `%`, `_`, and `*` no pattern meaning. It has a `StringWrapper` substring assignment defect in this snapshot, so require plain/binary operands and qualification of that exact input path or evaluate in the adapter. It must not be assumed to implement insensitive Unicode case folding. [Implementation](https://github.com/dolthub/go-mysql-server/blob/239e0ad6b2f9f32ba9c5752a8b5930e4d682d2cf/sql/expression/function/substring.go#L612-L687), [upstream report](https://github.com/dolthub/go-mysql-server/issues/3650).
- `BINARY identity = BINARY ?` and `ORDER BY BINARY identity, BINARY revision` have direct implementation support: the unary operator produces a binary-collated blob, comparison promotes binary operands to that type, and string comparison uses the type's collation. Its documented source contract includes byte comparison and significant trailing spaces. Prefer explicit binary edition keys in prepared relations as well, so recursive distinct/grouping cannot use a case-insensitive text key. This remains an unexecuted sketch; qualify parameter types, empty/trailing-space values, ordering and distinct/grouping on the actual version. `BINARY` is not a universal repair for function-specific semantics such as `LOCATE`. [Binary operator](https://github.com/dolthub/go-mysql-server/blob/239e0ad6b2f9f32ba9c5752a8b5930e4d682d2cf/sql/expression/binary.go#L24-L60), [comparison promotion](https://github.com/dolthub/go-mysql-server/blob/239e0ad6b2f9f32ba9c5752a8b5930e4d682d2cf/sql/expression/comparison.go#L370-L379), [string comparison](https://github.com/dolthub/go-mysql-server/blob/239e0ad6b2f9f32ba9c5752a8b5930e4d682d2cf/sql/types/strings.go#L267-L335).

## Dolt history is a different revision axis

`AS OF '<immutable Dolt commit hash>'` selects a committed database snapshot. Branch names and `HEAD` are moving references; `AS OF` excludes uncommitted working changes. Different tables can be given different snapshots, so the adapter must deliberately keep its selected relations coherent. A Dolt commit is **not automatically a Bead revision token**. Resource revision/pinned-target resolution still belongs in edition selection and the adapter's mapping; SQL `AS OF` cannot stand in for that mapping. [Dolt history semantics](https://www.dolthub.com/docs/sql-reference/version-control/querying-history/).

## Minimum qualification still needed

On the actual selected Dolt version: diamond/parallel-edge/cycle fixtures; min/max-hop boundaries and positive-cycle return to the root; exact target edition versus current head; binary edition identity/grouping; absent/null/string/number separation; plain and wrapped literal text including empty needle and Unicode; controlled budget exhaustion without a success-shaped partial answer. These are proposed checks, not checks executed here.
