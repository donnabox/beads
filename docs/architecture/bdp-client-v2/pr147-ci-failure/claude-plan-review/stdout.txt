**1. [Medium] Failure 1 replacement is weaker than it needs to be — `transaction-set.test.ts:1109–1111`.**

Defect in the proposal: its primary option, positive-preparation/`.not.toThrow()`, would still pass if the deep mixed path skipped Selector grammar analysis entirely — exactly the property focus (1) wants preserved.
Smallest correction: take the plan's parenthesised option, not the `not.toThrow` option. Bind `const preparedDeep = batch.prepareTransaction(scope, JSON.stringify({ operations: [deep, update()] }))`; assert `preparedDeep.carrier.operations.length === 2`; assert `operations[1].input.selector` is the original literal; narrow with the discriminant (`if (op.operation === "updateWhere")`, not a cast — `PreparedTransactionSet.operation` is disjoint from the six RU kinds and carries `name?: never`, so `tsc` narrows cleanly) and assert `transactionSelectorCapacity(op)` is `undefined`. **2. [Medium-High] Oracle rewrite form: guard the existing matchers rather than replace them — `transaction-submission.test.ts:1754–1756`.**
Defect: replacing the two matchers with bare throws makes new custom predicates the sole pass/fail authority and deletes the only failure localization across a ≳300k-node traversal; current messages like `"deep submission primitive mismatch"` (1753) already carry no context, and the plan correctly forbids accumulating path strings.
Smallest correction: compute the booleans and invoke the *original* matcher only on mismatch, with a trailing throw so failure is guaranteed even if the matcher disagrees with the predicate:
`if (Array.isArray(a) !== Array.isArray(b)) { expect(Array.isArray(a)).toBe(Array.isArray(b)); throw new Error("deep submission array-kind mismatch"); }` and the same shape for the sorted key vectors. Steady-state matcher cost is zero, failure output and assertion semantics are byte-identical to today, and the diff is smaller than a new throw-site rewrite.

**6. [Medium] Pass criterion and near-timeout mode are not stated — plan §"Validation" step 3.**
Required saving is ≥9,305.4ms of 29,305.4ms (31.8%), not "some".
