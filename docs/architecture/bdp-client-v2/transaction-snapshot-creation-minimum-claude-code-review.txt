## A. Actual defects

Plan §"One terminal preflight branch" requires "Direct HTTP spy/count tests show one service call and no capture after preflight for **each branch**", and done-when requires "both fresh paths using one finite wait".
Impact: a regression that inserted an authoritative preflight before the plain-GET capture — two owner entries, two `waitForTransactionMinimum` deadlines, double the behind budget — passes every current test. **2. Low — `packages/server/src/transaction-service.ts:257` — `signal` is silently discarded on the no-minimum path, and the comment that justified it was deleted.**

Impact: no behavior change versus parent `82a0a02` — this is a correctness-of-reading defect. The next maintainer reading lines 252–271 will reasonably conclude a disconnected client stops no-minimum Snapshot work; it does not, and no test would tell them otherwise.
Fix: restore the rationale as a comment on the `supplied === undefined` branch. Do **not** silently add `signal?.throwIfAborted()` there — that changes pre-abort behavior for no-minimum retained reads, which is outside this slice's owned change set and needs plan authority.

## C. Already-resolved plan choices — stated, not re-litigated

These are consequences of the accepted design, each explicitly closed in the dispositions/native closure; I verified the code implements them as decided and I am not reopening them.

- **Minimum before capacity.** `checkTransactionMinimum` precedes `snapshots.expire`/`preflight`/`capture`, so a behind minimum on an exhausted scope (8 live handles, `transaction-snapshot.ts:25`) yields `503 catch-up-timeout` rather than `503 temporarily-unavailable`. Closed as External4; discriminated by exact code in the new tests versus the existing capacity cohort (`:645`). A satisfied minimum correctly lets the owner capacity problem win, because `TransactionSnapshotFailure` returns `{kind:"problem"}` rather than throwing, so the wait never retries it.
- **Minimum before negotiation/conditionals.** `Accept: text/plain` plus a future minimum returns a `503 application/problem+json` body. Closed as External1 — implementation ordering inside the existing owner-before-406 path, explicitly not a universal precedence law.
- **A capture committed after disconnect still consumes a live handle for `lifetimeMs` (5 min).** The abort check is per-attempt, so a client that drops during the winning attempt leaves an undelivered handle. Plan explicitly disclaims instantaneous interruption of synchronous copying and forbids compensating a committed identity; "failed minimum attempts allocate zero" is the property under test, and it holds.
- **Behind attempts skip `snapshots.expire`.** Intended, and newly pinned by `transaction-snapshot.test.ts` "does not expire retained Snapshot details on an ineligible fresh attempt" — it is also why ~200 retries/second open zero write transactions.
- **Retained-anchor position interpretation and malformed-control protocol redesign** remain excluded, per your instruction and the plan.
