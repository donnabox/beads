## Intended contract and cutline

Publish the common selector/projection/output contract first. Generic Bead and Link commands use it without translating all Resources into Issues. Query grammar and richer graph operators follow through the same structured selection model and output descriptors. The output work need not wait for the complete query language.

The first implementation covers the generic BDP Resource read paths of `bd show`, `bd link show`, `bd list` and `bd link list`. Add generic collection count with list where an exact count can be implemented under the same read contract. Retained Resource version reads follow as a separate result family. Pure mutation output and query-language execution are separately bounded follow-on work.

Leave `bd dep` and Issue/Dependency-specific operations on their compatibility contracts: ready/blocked, children/epic, scheduling/state, compound workflow commands and their specialized flags are not migration targets. The eventual wrapper inventory still tests their requirements as design inputs; it does not require rewriting those commands in this rollout. A future `bd issue` domain namespace, with `bd dep` as the Dependency facade, is a separate product proposal. Do not make command renaming or moving every legacy caller a prerequisite.

“Generic” describes the selected operation and Resource contract, not a guarantee that the current native Issue route already implements it. Existing root command spellings contain both generic graph routes and Issue-specific behavior. Before changing a default or shared flag, record exactly which route adopts the new contract and how existing scripts retain their current behavior. Do not introduce silent fallback between pure and legacy predicate meanings.

## Per-command dependency handoff for Cleo

**2026-10-19 bounded coordination review.** This matrix feeds Cleo's consolidated rollout rather than superseding it. Availability below means registered in the inspected source at product base `5779b6b846d358c40bdc7bad4a2fcffc779aadb6`, not qualified in the current installed binary. Janet must recheck her selected candidate before assignment. Existing spelling does not establish generic semantics or readiness for the new output contract.

Use these dependencies:

- **O:** Cleo's output options/result descriptors/masks/framing, plus exact Resource/reference resolution. No predicate parser required.
- **S:** one normalized simple selection request for population, exact/family Type, endpoint tests, order, read context and paging. List/count/provider adapters share it. CLI flags may construct it directly; the textual query parser is not a prerequisite.
- **P:** selected typed predicate semantics and parser/checker lowering into that same request: field resolution, null/presence/defaults, explicit conversions, literal text and array predicates, with explicit evaluation errors.
- **G:** normalized correlated existence/expansion/bounded-walk and graph-result contracts, including seed/prune/post-filter separation, parallel Links, exact revisions and completeness. Typed graph flags may construct these operations without going through a textual parser.
- **D:** the relevant domain/History/Types/write/assessment result contract and qualified provider capability. This is not permission to implement missing protocol semantics in the output layer.
