## Numbered findings

**1. Medium — pair transport rejections are counted twice and misattributed to cleanup.** `apps/bdptest/src/transactional-guarded-batch-installed.test.ts:755-756` wraps the pair reasons in a *new* `AggregateError` and throws it; the catch stores that wrapper (`primaryFailureCount` = 1). The drain at `:929-930` then re-collects the *member* reasons from `pending`, and `addFailure` (`:281-283`) dedupes by object identity only, so the members are not recognized as already-reported. Impact: a single contender transport fault yields `failureCount: 2` (or 3) with `cleanupFailureCount >= 1`, i.e. the evidence artifact reports a non-existent cleanup defect alongside the real transport fault, and the thrown `AggregateError` nests the same cause twice. Note the single-send paths (`:726`, `:822`, `:826`, `:832`, `:842`) are *not* affected, because the identical error object is both thrown and drained, so dedupe works there — which makes the pair path an inconsistency rather than a uniform convention. Minimal correction: `for (const reason of pairErrors) addFailure(reason);` before throwing, or throw `pairErrors[0]` when `length === 1` and otherwise record members individually so `includes` suppresses the drain copy.

**2. Medium (oracle discrimination) — `frozen-loser-replay-input` is three-quarters tautological.** `:809-821`: `replayBody` is assigned `losingInput.body` at `:818`… the subsequent `expect(replayBody).toBe(loserIndex === 0 ? aBody : bBody)`, `expect(sha(replayBody!)).toBe(losingInput.hash)` and `expect(Buffer.from(replayBody!)).toStrictEqual(Buffer.from(losingInput.body))` all compare the same in-memory string (and a hash derived from it) against itself; only `expect(replayKey).toBe(loser.key)` can fail. Impact: the named check appears in `performed` as replay-input freeze evidence while proving nothing about the bytes that were actually dispatched for the losing key; a divergence between the in-memory `originals` entry and what request 2/3 actually wrote on the wire would not be detected. The test already retains the wire fact needed (`responses[].requestBodySha256`, captured at `:562-573` before any decode). Minimal correction: replace the three self-comparisons with `expect(sha(replayBody!)).toBe(responses.find((r) => r.index === (loserIndex === 0 ? 2 : 3))!.requestBodySha256)`, and (optionally, after `send(4)`) assert request 4's recorded `requestBodySha256` equals that same value.

**3. Low — the `--outputFile` containment scan is bypassable and checks the wrong parent.** `:341-351` matches only `--outputFile` (separated) and `--outputFile=…`. Vitest also accepts the per-reporter form `--outputFile.json=<path>` / `--outputFile.junit=<path>`, which `argument.startsWith("--outputFile=")` does not match and which is skipped by the `else continue`. Additionally the resolved path is only checked `outside(…, directory)`, never `outside(…, root)`, although the stated invariant is exclusive output outside both the store and the worktree (the test's own evidence path *is* checked against `root` at `:122`). Impact: a reporter artifact can be directed inside the worktree, or — via the dotted form — inside the store directory that `rmSync` later deletes at `:970`, defeating the containment guard. Minimal correction: extend the predicate to `argument.startsWith("--outputFile.")` (taking the substring after the first `=`), and apply both `outside(resolved, directory)` and `outside(resolved, root)`.

**4. Low/Medium — the report serializations in `finally` are unguarded, so a serialization fault discards every aggregated failure.** `:1063` and `:1075` call `JSON.stringify(observation())` outside any `try`. `observation()` embeds `binding` verbatim (`:992`), whose `served` sub-object is produced by an external helper; any non-serializable member (cycle, `BigInt`) makes the `finally` block throw. A throw from `finally` replaces the pending completion, so `:1092-1094` never runs and the real primary failure (plus `childPid`, `directoryAbsent`, cleanup flags) is lost; stdout gets nothing, not even the minimal record that `:1080-1089` exists to provide. `writeFileSync` is already protected at `:1068-1073`; the serializations are not. Minimal correction: wrap each `JSON.stringify(observation())` in `try/catch`, and on failure set a flag, `addFailure`, and fall through to the minimal `console.log` payload already defined at `:1081-1088`.

**5. Low — `namedAssertion` can present a transport/setup label as a named oracle.** `:1026-1027` emits `failedAssertion` under both keys, but `currentAssertion` is also set to `guarded-batch:setup` (`:230`), `guarded-batch:launch` (`:375`), `guarded-batch:transport-N` (`:396`) and `guarded-batch:receipt-N` (`:617`). Impact: a supervisor filtering on `namedAssertion` to confirm the control's sole failure is the named `guarded-batch:one-retained-revision-failure` can be satisfied by a dial/transport abort instead; `failedPhase` disambiguates, but the two fields assert different things under identical values. Minimal correction: `namedAssertion: failedPhase === "oracle" ? failedAssertion : null`.

**6. Low (oracle discrimination) — the pair-socket observation is only an upper bound.** `:772` and `:912` assert `maximumLiveSockets <= 2`, which also holds if the two contenders were never concurrently socketed (e.g. 1 at a time). Because both `ClientRequest`s are constructed synchronously at `:749-750` and each `socket` event (`:499-515`) fires before either response, `maximumLiveSockets` must be exactly 2 by the time `dispatch-discipline` runs. Impact: the recorded "two live pair sockets" claim is weaker than the facts the harness already has. Minimal correction: in `check("dispatch-discipline")` assert `expect(maximumLiveSockets).toBe(2)` and keep `<= 2` as the ceiling in `complete-fixed-schedule`.

**7. Low (oracle discrimination) — intra-group Event `time` is wholly self-referential.** `:874`, `:886`, `:896` pin each event's `time` to `record(events[i]).time`, so the field is unconstrained beyond the schema's `date-time` format. Per `packages/server/src/transaction-batch.ts:705`, every event in one group is stamped from the single captured `now`, so `events[1].time === events[2].time` is a necessary consequence of the winner's two effects belonging to one transaction, and `events[0].time <= events[1].time` follows from group ordering. Impact: a projection that re-stamped per-event times, or mixed times across groups, would pass. Minimal correction: add `expect(record(events[1]).time).toBe(record(events[2]).time)` and an `events[0].time <= events[1].time` comparison inside `complete-rollback-event-linkage`.
