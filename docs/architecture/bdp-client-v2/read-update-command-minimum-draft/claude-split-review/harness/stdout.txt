## Optional improvements

5. **Low–Medium — per-exchange assertion identity is unpinned.** `finish()`, `expect(outcomes).toHaveLength(controlled ? 8 : 47)` plus the single-failure filter. Only the aggregate count and the one failing `singleton-replay.outcome` pair are fixed; the mapping of the 47 outcomes to exchanges is not. A runner misattribution, a renamed assertion id, or a duplicated-plus-dropped pair with a compensating count would pass. The static callback already computes the exact binding list (`a.assertions.map(q => `${a.id}.${q.id}`)`). Smallest improvement: assert `outcomes.map(o => `${o.exchange}.${o.id}`)` equals that binding list (sliced for the controlled case), which also makes the bare literal `8` self-documenting.

6. **Low — the control leaves a contradictory sibling field.** `complete()`, controlled branch `return { ...actual, bodyText, bodyOctets: Buffer.byteLength(bodyText) }`. The spread retains `wireResponseBytes` (and `effectiveRequest`) from the genuine response, so the projected object asserts `outcome: "updated"` in `bodyText` while its exact wire bytes still say `"created"`. This is consistent with the documented `wireBodyUnchanged: true` claim and is currently detected if it ever matters (a wire-reading assertion that rescued `outcome` would break `finish`'s exact one-failure expectation), but the inconsistency is undocumented at the call site. Smallest improvement: one comment stating that `wireResponseBytes` is intentionally left genuine and that `finish`'s single-failure expectation is what proves the projection was consumed.

7. **Low — 30 s callback budget is below the worst case of the code it guards.** New callbacks `it("observes ignored command minimum fields…", …, 30000)` and `it("rejects a changed retained outcome…", …, 30000)`. With `requestTimeoutMs: 5000` and eleven exchanges plus a 10 s launch bound, a degraded-but-not-hung run exceeds 30 s, yielding a bare vitest timeout; the post-cleanup `persistMinimum(cleanupComplete)` never runs and the retained evidence is lost — the same failure mode as the original 895 s review timeout. Smallest improvement: raise the budget above the derivable bound (≈70 s) or thread an `AbortSignal` into `run` so the abort path reaches the retention writes.

8. **Low — `cleanupComplete: false` is written as a placeholder, not a state.** `persistMinimum(false)` at both pre-cleanup call sites. A consumer reading a file left behind by a killed process cannot distinguish "not yet determined" from "cleanup failed". The direction is fail-closed, so this is cosmetic. Smallest improvement: accept `boolean | "pending"` and pass `"pending"` for the two in-run writes.

9. **Low — interference check can dump observation payloads.** The added loop `for (const collected of [observations, setupObservations, nativeReadObservations]) expect(collected.filter(r => coldObject(r).scenario === commandMinimumId)).toEqual([])`. On the failure it is designed to catch, the diff prints whole client/native observation records; `assertColdDirectory`'s `client(id).request.body` shows those records carry request payloads, and their header content is omitted context. Smallest improvement: assert on a projection (`.map(r => coldObject(r).scenario)` or `.length`) and surface detail through a label rather than the matcher's received value.

10. **Low — positional argument hack in the negative callback.** `const args: Parameters<typeof run> = [undefined, [commandMinimumId]]; args[16] = "replay-outcome";`. The tuple element type is checked, but the *position* is not self-describing; a future optional parameter of a compatible type inserted before `commandMinimumControl` would re-bind index 16 silently, and the symptom would be the opaque `expect(report.commandMinimum.completions).toHaveLength(2)` failure. Smallest improvement: write the placeholders explicitly with a trailing comment naming the slot, or add `expect(report.commandMinimum.control).toEqual({ name: "replay-outcome", kind: "assertion-input-only" })` so a mis-bound slot fails with a named cause.

Both are unconditional literals reachable only because the preceding expectations did not throw; in the persisted document they read as independently recorded results. Smallest improvement: drop them, or rename to something that states the real meaning (e.g. `oracleChecksReached: true`).
