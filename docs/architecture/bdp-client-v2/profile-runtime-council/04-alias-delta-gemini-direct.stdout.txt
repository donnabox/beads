### 1. Findings (Proven Defects vs. Questions Needing Omitted Context)

#### Proven Defects

* **Severity**: Low
* **File & Line**: `apps/bdptest/src/development-matrix.test.ts`, line 105
* **Concrete Issue**: Fragile URL canonicality check in `observeIdentity`: `new URL(identity).href === identity` throws an unhandled `TypeError` (terminating the test process with an uncaught exception rather than failing an assertion) if `identity` returned in `response.body.resource.id` is not an absolute URL (for example, if the receiver returned a relative path like `beads/alloc-1` or an unparseable URI string).
* **Reachable Trigger**: A receiver regression where an authority-allocated Bead ID fails to format as an absolute URL or returns a non-URI token while `input.observeIdentity === true`.
* **Impact**: The test runner crashes abruptly during test action execution with an unhandled exception rather than recording a clean diagnostic assertion failure at `/identity/canonical`.
* **Fix/Next Step**: Safely validate the URL format (e.g., using `URL.canParse(identity)` or wrapping `new URL(identity)` in a `try/catch` block that evaluates `canonical: false` upon throwing).

### 3. Supplement Focus Area Analysis

* **Alias Canonicalization & Validation (`alias-invalid-targets`)**:
  Correctly tests rejection (422 `validation-failed`, single descriptive diagnostic) of alias targets pointing to local aliases, absolute aliases, Link paths, external URIs, and opaque URNs. Read-back (`GET alias/{path}`) confirms that rejected alias creations leave no state (`resource-not-found`). Re-running with a fresh key succeeds. Re-running the original key with the invalid target retains the 422 failure, and re-running that key with a corrected target fails with 409 `idempotency-conflict`.
* **Unknown and Wrong-Root Subjects (`alias-unknown-subjects`)**:
  Correctly observes that non-existent canonical Bead targets and deletes of unknown aliases return 404 `resource-not-found` without acting as an oracle. Wrong-root subjects (`beads/wrong` in alias put, `links/wrong` in alias delete) fail with 404. When the missing Bead is subsequently created, retrying under the original key returns the retained 404, while retrying under a fresh key succeeds.
* **Retained Targets vs. Fresh-Locator Retry (`alias-recorded-targets`)**:
  Validates that an alias locator recorded with an original link creation (`alias/old` -> `beads/a`) retains its target (`beads/a`) on idempotency retry across alias repointing, deletion, reassignment, and cross-slot reuse (`target: "alias/old"`). Conversely, tests that a previously unrecorded fresh locator (`alias/fresh`) is resolved anew on retry: succeeding when it points to `beads/a`, conflicting (409) when repointed to `beads/b` or deleted, and succeeding again once restored to `beads/a`. State read-back (`GET links/kept`) confirms original links remained intact throughout retries.
* **Retained Misses & Live State Proofs (`alias-recorded-misses`)**:
  Validates that an originally recorded missing alias retains its miss status across subsequent assignment, deletion, and reassignment. Distinct missing alias locators and direct canonical references compare unequally (409 `idempotency-conflict`). Read-back verifies that neither target Bead was affected or deleted.
* **Opaque Pin Equality & Sequence-Local Renaming (`pinned-references`)**:
  Verifies that pins are treated strictly as provenance: opaque revision strings are preserved byte-for-byte and compared for exact equality. Demonstrates that NFC vs. NFD Unicode encodings (`past:\u00e9/%2F` vs. `past:e\u0301/%2F`) correctly trigger 409 `idempotency-conflict` due to byte inequality. Demonstrates that sequence-local `@name` references resolve to creator durable identity and that renaming a local label (`@made` to `@renamed`) preserves semantic identity on retry.
* **Test Harness Extensions (`development-matrix.test.ts`)**:
  The addition of `targetBinding`, `referenceBindings`, `absoluteReferences`, and `observeIdentity` cleanly enables dynamic URL binding, relative-to-absolute expansion, and structural inspection of authority-minted IDs without altering production runtime pathways.
