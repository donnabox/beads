## Minor findings (not gate-blocking)

**3. D does not assert the 503 media type, only that HEAD matches GET.**
Severity: Minor missing oracle. `packages/server/src/transaction-events.test.ts:1489-1494` captures `getType` from the GET and only compares HEAD against it; there is no positive assertion that the selected 503 GET carries `application/problem+json` (E does assert this, at `apps/bdptest/src/transactional-event-missing-context-installed.test.ts:555-556`). Schema validity plus the exact body equality make a stream or page impossible in practice, so the plan's "never a stream" intent is covered indirectly.
Impact: a regression that served the correct Problem JSON under a wrong media type would pass D (and would still be caught by E).
Smallest fix: in the GET branch add one assertion that `response.headers.get("content-type")` splits to `application/problem+json` when `status === 503`.

**4. No HTTP-layer oracle distinguishes "timed out after real waiting" from "timed out on the first attempt".**
Severity: Minor missing oracle (plan-consistent). D's log (`:1540-1548`) records only `calls`, `productChildren`, `directoryAbsent`, `failureCount`; nothing records attempts, waits or elapsed time for the six 80 ms exchanges, and no elapsed-time assertion exists. Structurally, `waitForTransactionMinimum` cannot reach `catch-up-timeout` without at least one `wait` unless 80 ms elapsed inside the first attempt, so 503 does imply waiting — but the *budget* is not witnessed at this layer.
Impact: D cannot by itself detect a future change that collapsed the budget to ~0; B/C carry the precise 2/3-wait and 4/5-attempt oracles, and the existing `transaction-events.test.ts:399` callback carries the recognized-minimum catch-up proof.
Smallest fix: optional — record `Date.now()` deltas for the three 503 pairs into the existing log object (diagnostic only, no assertion), or leave as-is since the plan fixed D's workload.

**5. Three diagnostic log fields are asserted-by-construction constants rather than measured counters.**
Severity: Minor. `transaction-events.test.ts:1388` logs `seedMutations: 1`; `transaction-service.test.ts:2685` logs `postCloseDirectRefusals: 1`; `:2758` logs `serviceCalls: 1`. Each is true for the authored body (one `f.run`, one preceding `expect(() => …).toThrow`, one `service.events`), and the plan's "never hard-code" rule was scoped to `directoryAbsent` — which *is* measured in both D (`:1545`) and E (`:624`).
Impact: if these callbacks are later edited, the logs could silently misreport; no current inaccuracy.
Smallest fix: increment real counters (as A already does for `reads`) instead of literals.

**6. E omits the ordered route/method inventory assertion its historical sibling carries.**
Severity: Minor. E asserts `attempted === 3` (`:565`) and pushes one fingerprint per completed exchange, which together pin the count; the historical callback additionally asserts `responses.map(…)` equals an exact ordered list (`:339-352`). E has no equivalent, and no `expect(responses).toHaveLength(3)`.
Impact: a future edit that reordered or substituted the GET/HEAD pair would still satisfy the count bound.
Smallest fix: add `expect(responses.map(({method,status}) => [method,status])).toStrictEqual([["GET",200],["GET",503],["HEAD",503]]);` next to line 565.

**7. `?? "unsupported"` on the new HTTP branch is unreachable for the selected predicate, and two predicate conjuncts are implied by their companions.**
Severity: Minor (defensive, plan-mandated). At `packages/server/src/transaction-http.ts:513-517`, `currentReadMinimumHeaders` cannot return `undefined` once `malformedTransactionMinimumHeaders` (`:404-405`) has passed with `hasMinimumControls` true: both use the same `token` regex and the malformed gate already requires all three fields present and token-valid. Likewise `eventRequest.source.url === new URL("events/", scope).href` is implied by `source.kind === "scope"` (`transaction-events.ts:161`), and `!url.searchParams.has("after")` is implied by `eventRequest.after === undefined` (`transaction-events.ts:155-177`).
Impact: untested dead branches; the plan explicitly asked for exactly these redundancies, so this is a note, not a defect.
Smallest fix: none recommended — changing it would deviate from the accepted plan.
