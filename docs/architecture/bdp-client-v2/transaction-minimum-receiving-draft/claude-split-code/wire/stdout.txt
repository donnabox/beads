## Findings

1. **Low — normative table completeness.** `docs/specs/bdp.md`, the operation/target status table at the `4627` hunk. The delta adds `400 malformed-request` to exactly four rows (`operations/`, receipt URL, receipt page URL, `receipts` root), while the new prose at the `5816` hunk states the rule for *any* read (`MUST`), and `route()` in fact returns it on every authenticated read route — Scope root, `bdp.json`, `snapshot`, `changes/`, `?view=events`, `events/`, alias and Resource reads. Impact: per-target enumerations for those other read targets under-state the reachable status set, which is the kind of asymmetry that later gets "fixed" in the wrong direction. Fix: either add the status to the sibling read-target rows or add a one-line pointer from those tables to the new receiving paragraph. *Verification gap:* the supplied delta does not include those sibling tables, so I cannot assert they lack the row — name it as the exact thing to check, not as an established omission.

2. **Low — undocumented dependency in the repeat check.** `transaction-consistency.ts`, `malformedTransactionMinimumHeaders`. Repeat detection is *derivative*: `headers.get()` returns undici's `", "`-joined value, and `,`/space are outside `/^[A-Za-z0-9_-]{1,256}$/`, so repeats fail lexically rather than by count. That is correct for every current caller — `transaction-runtime.ts:145-147` builds the `Headers` with `append` over `rawHeaders`, preserving duplicates, and the raw wire checks (`transaction-http.test.ts:4699-4731`, indices 0–2 duplicate each field name in mixed case, index 3 uses `genesis,genesis`) pin it end-to-end through the real listener. Impact: a future caller that builds the request from a last-value-wins map, or a transport that pre-dedupes fields, would silently accept a repeated field while the spec says "exactly one nonempty value for each field." Fix: state the dependency in the existing comment above the predicate (it currently only disclaims unknown token identities), so the lexical alphabet is visibly load-bearing for the cardinality rule.

3. **Low — coverage, mutation-ignore guard.** The supplied test excerpts pin the no-owner witness (33 calls, zero owner entries before the ordinary root `readReceipt`) and the raw duplicate/comma/HEAD/SSE checks, but no supplied case sends a malformed or partial tuple to a *command* target (`operations/batch`, a singleton, `sequence`) and asserts it is ignored. The POST case in `transaction-http.test.ts:4553-4563` targets `receipts/`, which is a `405` method refusal, not a command branch. Impact: `bdp.md:3581-3588` is currently satisfied only structurally — the `operation !== undefined` block returns on every sub-path, so the guard is unreachable for commands — and a refactor hoisting the guard above that block would break the mutation rule with no failing test. 4. **Low — coverage, SSE-selected routes.** The only `Accept: text/event-stream` malformed case (raw check index 5) targets `beads/`, which is not an SSE route; the direct witness covers `changes/`, `?view=events`, and `events/` without SSE negotiation. By construction the guard precedes both stream branches (so `media === "sse" && fields.length > 1` → `TransactionChangefeedParameterError` is preempted, and no `streamResponse` is reachable), but nothing pins it. Fix: one `changes/` + SSE + malformed-tuple wire case asserting `400`, `application/problem+json`, no `bdp-scope-*`, no stream.

## Verified order/non-disclosure properties

- **Guard position.** `route()`: POST target-byte check → `methodResponse` (target shape → `404`/`405`) → `operation !== undefined` command block (returns on every path) → `unauthenticated` → `malformedTransactionMinimumHeaders` → snapshot / changefeed / alias / events / receipts / Read. Matches the delta's "after transport, target/method, authentication, before any owner read or target-existence lookup" and keeps `transaction-runtime.ts:161-166` Origin `403` earlier.
- **Uniformity and non-disclosure.** `transactionHttpProblem("malformed-request")` is called with no observation, so `context()` never runs: no `bdp-scope-epoch` / `-authorization-view` / `-scope-position`, no `x-bdp-development-limit`, identical for existing, foreign, expired, and absent receipts and pages — the refusal precedes `service.receipt*` / `owner.readReceipt*` entirely.
- **Schema fast path cannot bypass.** `transaction-schema-http.ts:39-47` returns `undefined` whenever `hasMinimumControls(request)` is true, which is presence-based; a malformed tuple always has ≥1 of the three fields present, so no `observe()` owner read occurs.
- **No negotiation/conditional/HEAD drift.** `applyReadHttpSemantics` (`read-http.ts:10-25`) only rewrites `200`+`application/json` or `204`; the `400` carries `application/problem+json`, so it cannot become `304`/`412`/`406`. HEAD takes the `selected.body !== undefined` branch, setting `content-length` from `stringifyJsonValue` and dropping the body; `deliver` (`transaction-runtime.ts:87-95`) computes GET's length with the same function and leaves HEAD's header intact — GET/HEAD metadata agree on the wire.
- **Valid/absent tuples unchanged.** Not-malformed plus any field present implies all three present and token-valid, so `transactionMinimumHeaders` can only return `undefined` for an alphabet-valid non-`genesis`/`pos-N` position, preserving the retained `developmentGap("minimum-position")` / `"unsupported"` branches and the owner's principal/epoch nondisclosure before `checkTransactionMinimum` (`transaction-store.ts:881-886`, `2069-2072`).
- **Validator hygiene.** `token` is non-global (no `lastIndex` reuse), anchored, bounded — no ReDoS; `snapshotTransactionMinimum` rejects proxies, accessor descriptors, extra string *and* symbol keys, and inherited fields, returning a frozen copy; `waitForTransactionMinimum` rejects non-finite/non-monotonic clocks and never renews the deadline.
