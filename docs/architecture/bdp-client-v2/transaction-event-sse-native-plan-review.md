## Source-grounded assessment

**Owner and lifetime.** Existing `transaction-store.ts:1370–1470` already performs retained identity, minimum/context, cursor projection membership and materialization within one synchronous owner entry. `retainedGroupReader` (`560–582`) prepares bounded length/body lookups and leaves no iterator open. A per-owner WeakMap capability holding only detached descriptor/context/position/ordinal/head fits this boundary. Rejecting fabricated and other/reopened-owner tokens, retaining `enter` fencing, and rechecking current source/context prevent the optimization from becoming a caller-chosen numeric cursor. Tokens need not be durable or public. The plan correctly avoids claiming rescans of already inspected immutable history detect arbitrary out-of-owner corruption.

**Sparse work and ordering.** Repeated finite `readEvents(source,lastID)` currently starts at the last Event's group and traverses unrelated later groups again. Advancing a private inspected prefix solves that concrete cost. One group per stream entry, exact expected-position lookup and zero group reads when caught up are sufficient without another table or index. A partial packet must retain the same group and exclusive last **included** ordinal; reaching an item cap is not proof that the rest of the group has been traversed. The existing projection validates original index/ordinal (`transaction-events.ts:225+`) and emits two endpoint facts for a self-Link without renumbering filtered results. Initial cursor membership and its remainder can share that same parsed group. Reparse of a large relevant group across packets is explicitly bounded by admitted group/Event counts and is not hidden in the sparse-prefix claim.

**Finite equivalence.** Keep finite calls' actual lookahead and exact envelope/continuation byte reservation (`transaction-store.ts:1418–1465`). A full finite page may still have `next:null` if no later matching Event exists. Stream `caughtUp` cannot replace that decision or leak onto the wire. Shared extraction should keep the finite tests' independent expected facts, page bytes, source-local IDs and end-of-source tests; comparing two new paths using the same changed helper alone would not be an independent oracle. The proposed existing regression suite plus explicit same-group boundary tests provides that independence.

**Packet adoption and transport.** Current `transaction-sse.ts:38–78` treats write(false) as accepted into Node, then waits for drain/error/close/abort and removes listeners. The new packet continuation must not be adopted or used for another owner read until all frames have traversed that path. This is server-side progress, not acknowledgment by an application or replica. On disconnect, discard the packet and reconnect through a fresh validated public Event ID. `transaction-runtime.ts:163–186` registers the stream before headers and destroys transport in finally; preserve this ordering and its post-header failure behavior. No fake terminal-success record or new error Event is needed.

**Service lifecycle.** `transaction-service.ts:202–224` provides one registry and capacity check; `431–451` stops admission, aborts registered streams, drains accepted finite work, then closes the owner. Begin/advance observations belong to finite `run` tracking, while the pump belongs to `stream`. Use that single registry for both changefeed and Event streams. Initial minimum retries remain one bounded `waitForTransactionMinimum` call; a subsequent successful fixed-context scan must not restart the original wait deadline. Infinite stream lifetime must not enter the finite active-work set.

**Disclosure/HTTP ordering.** The finite Event path (`transaction-http.ts:440–453`) resolves retained unknown identity before minimum/cursor checks in the owner. The proposed malformed/repeated reconnect flag, handled after source/minimum inside begin, preserves that ordering; copying the changefeed route's early repeated-header rejection would not. Existing URL/query grammar validation still occurs before source lookup, while an otherwise syntactically valid overridden query cursor is not separately looked up. Selected JSON ignores every Last-Event-ID value. Selected SSE validates effective public membership, current context and initial projection before refusal/conditionals; HEAD/304/412 do not register a stream or publish progress. Current raw header collection (`transaction-runtime.ts:143–145`) retains repetition information; do not collapse it via Headers.get alone.

**Bounds and provenance.** The Event packet uses the existing4MiB page bound, not the169,345,024-byte retained group envelope as an assumed frame limit. Event type maximum8 and token maximum256 make the additional512 framing reservation conservative. The plan correctly distinguishes encoded byte bounds from group parse cost, heap and latency. Named actual stream constants belong in captured settings and the runtime identity, alongside existing timers. Installed proof must bind the new payload/settings/source afresh; old G2a configuration evidence cannot be relabeled.

## Concrete implementation acceptance conditions

1. **Cursor/packet discriminators:** seed a group with multiple relevant Events, force both item and byte boundaries, disconnect between self-Link endpoint facts, and reconnect after the first accepted complete Event. Assert exact original ordinals, IDs and second fact, with no skipped or duplicated delivered Event. Separately insert a commit after a packet's head capture and prove the next advance observes it. No public synthetic head cursor.
2. **Sparse/body-count oracle:** count actual group-body reads, not SQL prepares or elapsed time. After traversing N unrelated groups, repeated idle advances read zero historical bodies; one new irrelevant group costs one inspection, followed by actual relevant delivery. Source identity/context metadata reads are legitimate and should not be mistaken for rescans. Test fresh empty Scope and retained Resource history separately.
3. **Backlog fairness and heartbeat detail:** keep the monotonic heartbeat check active for empty historical packets as well as caught-up polls. A long yielding sparse backlog should not suppress every write until the end and hit the unchanged10s idle transport timeout. Yield one cancellable Node turn between backlog packets rather than sleeping100ms per group. Once write(false) occurs, no heartbeat, scan or second frame may proceed until drain/abort. A scaled deterministic test is sufficient; no timing-only performance claim or timer widening.
4. **Finite regressions:** retain original finite tests and add exact-cap/no-later-match, same-group partial page and later-match-in-another-group cases. Compare complete paged finite Event sequences to complete SSE frames under a controlled common source head, and keep independently authored membership/type/ordinal expectations. Concurrent append tests are separate from exact snapshot-of-history equality.
5. **Disclosure matrix:** unknown Resource with malformed/repeated reconnect remains404; known Resource runs the existing minimum/context decision before invalid reconnect refusal. Valid header overrides a syntactically valid query, JSON ignores headers, and malformed query grammar remains rejected. Test HEAD/304/412/406 without a slot or frame, plus current required context/cache/marker headers. The never-issued400 convention and fixed-context stale/foreign controls remain private implementation evidence, not a new universal ruling.
6. **Cleanup and one-slot law:** mix one changefeed stream with an attempted Event stream, then reverse the roles; use actual drain/disconnect and idle service-close cases. Verify finite mutation progress while a stream is blocked, accepted write survival after close/reopen, slot release, listener removal and no second HTTP response after headers. Preserve original error/cleanup causes.
7. **Installed acceptance:** use the actual packed payload, canonical Host/physical listener, CSPRNG credentials and fresh configuration metadata. Retain raw bytes and complete-frame boundaries, observe the unchanged-timer15s sparse idle interval and later real mutation, then drain/close. No emitted-module addition without its separate packaging boundary review. Public flags and catalog coverage remain unchanged.

These conditions are bounded realizations of the submitted plan, not demands to solve optional or deferred features. In particular, no metadata-only incident-Link membership is invented: preserve the existing initial projection gap and post-header close behavior, while Scope/Link projection continues as supported. No erasure, variable-grant, history-expiry or pruning semantics are assigned by this review. Their future invalidation/publication contract must precede any claim that the private inspected-prefix optimization supports those transitions.
