Prefer one frozen tuple consumed and hashed, not a separately copied list that can drift. Runtime metadata must include the real effective defaults, not caller omissions. Scope/contracts/persisted compatibility identity and live listener/auth identity remain distinct; do not silently add new persisted-file compatibility rules.
- `profile:"transactional"`, `history:false`, and `claimEligible:false` are private candidate metadata, not an HTTP Service Description assertion or evidence admission. This request touches `transaction-runtime.ts`, which belongs to G1. H1 does not edit TX store/service/http/runtime concurrently. ## First observation cohort

Prefer four normative bindings, each initially partial, with independent literal state oracles and schema validation using unchanged normative `$defs`. Exact final row IDs/citations are audited before authoring; these IDs already exist:

1. `transactional.batch.atomic-commit`: one batch creates a named Bead with stage-1 properties, updates it to stage-2, creates a second Bead and a Link using the staged identities. Assert completed receipt, exact indices/order/operation names, correct per-operation postimages/revisions, canonical references and final graph by HTTP GET. Capture dynamic IDs/revisions only where necessary; compare properties and topology to literal independently authored expected values. Earlier receipt postimage must remain stage-1 while final GET is stage-2. The separate local-reference variants (pins/forward references) remain missing.
2. `transactional.batch.rollback`: seed one Bead over HTTP, capture its original Resource, submit a batch that would update it and create a second Resource before a real later guard refusal. Assert failed receipt with the correct failing index/problem and no committed results, unchanged original Resource/revision, absent new Resource and unchanged finite Event sequence. A fresh independent mutation afterward must succeed, proving the child is usable. Final graph does not by itself prove absence of transient visibility, so isolation/race variants stay unqualified.
3. `transactional.receipt.readable`: GET the actual completed and failed receipt URLs, require 200 and normative receipt shape; compare identity/disposition/results exactly to the corresponding observed mutation receipt. Use enough small entries to traverse a real continuation under the production receipt bound (do not lower it through a test seam). If the ordinary bound prevents a tiny paginated fixture, keep pagination missing for this first slice; never permit the page assertions to skip silently. Close/reopen the child with the same store/Scope and compare the available receipt/final graph again. Distinguish mutable receipt detail/current authorization caveats from this immediate same-policy witness.
4. `transactional.idempotency.failed-retained`: first batch fails because a subject is missing; create that subject with a separate fresh key; retry the identical original carrier/key and assert exact retained failed receipt plus unchanged new subject. A fresh-key copy then succeeds, distinguishing replay from re-evaluation. Also exercise a changed carrier under the retained original key: require conflict and unchanged afterstate. This does not qualify expiry, concurrent pending join, unresolved comparison, principal transfer or cross-carrier equality.

A completed retry witness accompanies (1)/(3): after a separate fresh mutation changes live state, exact-key retry must return the old completed receipt while GET still shows the new state. It is not treated as complete semantic-idempotency coverage.

Use existing finite Event HTTP pages for an additional available final-effect witness: record the Scope sequence before/after, assert independently expected types/order and actual ordinal/source/effect-position relationships. Do not infer execution ordering from receipt array order. No direct store inspection or synthetic positions. The current head has no served changefeed final `changes` plane; final graph is observed via GET and cannot be called replica/change-group qualification. Metadata-only incident cases are outside this initial graph fixture.

Prefer declarative exact HTTP actions already supported by the runner. Predeclare canonical operation/point routes; captured receipt/page/allocated identity URLs must be validated, confined and admitted as exact routes. A tiny TX-specific adapter is warranted only for this dynamic routing; it should reuse the raw executor and preserve original status/body/headers/exact request observations. Do not broaden the RU client's known GET/path rules or use a wildcard target allowlist. The successful execution path never fabricates responses. Counterfactual mutation of captured observations belongs only in explicitly labeled test-negative controls and cannot emit accepted evidence.

## Budgets, cleanup and discriminating controls

Pin Node 24.16.0/pnpm 11.20.0; frozen install, clean/typecheck/build before emitted tests. Fresh pack/install in disposable directories; prove root/deep-import boundaries and exact installed path. Initial fixtures use at most eight operations per request, small properties (less than 1 KiB each), no stress allocation. Existing server 65,536-byte request limit, compiler capture ceilings, exact-wire observation cap (2 MiB), ordinary artifact 1 MiB and cumulative manifest 4 MiB bounds stay intact. Bound IPC ready/output to a small closed response and existing 64 KiB output ceiling; never echo configuration credentials.

Use 10-second startup/close, 5-second requests, 120-second whole cohort budget, maxWorkers2; these are harness deadlines, not protocol timing assertions. Abort cleanup always closes the child, awaits actual exit, escalates only after deadline, reports forced termination as failure, and removes disposable stores after exit. Test startup refusal, parent disconnect, caller abort and assertion failure cleanup; prove owner lock release by normal reopen. Existing half-open transport limitations must not be disguised by accepting SIGKILL as a passing close.

Negative controls must fail for their intended assertions: alter a receipt index/postimage; keep a would-be rolled-back Resource visible; mutate retained failure to success after the subject becomes live; return the fresh final state as an old replay; return 404 for either receipt/page GET; mismatch payload/contracts/policy/authentication/Scope/profile/fixture binding; use a noncanonical/foreign captured target; remove a selected catalog row; pass TX through the public runner or RU factory; expose clock/outcome IPC fields. Record exact failing assertion, not merely nonzero exit. Missing observations remain missing, not N/A due to absent harness capabilities.
