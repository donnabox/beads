## Exact origins and the unavoidable startup boundary

Name O the actual first ordinary-root invocation sample, before any newly claimed D03 root preparation; name R the first clock sample of a dedicated ancestor once its minimal independent timer primitive is ready; name A the point its independent absolute alarm is armed; name N the unchanged H6 native BEGIN origin. The current source proves N is later than root preflight and its alarm stops at native exit. The proposed ancestry moves all D03 collector imports, role preflight, source/tool/authority hashing, attempt acquisition and file work below an independent ancestor, so none of that target work may occur before A. No D03-specific preflight belongs in an unprotected launcher.

A fixed timer origin R can precede fork/exec of the collector and all collector imports. Minimal interpreter/dynamic-loader/clock/timer initialization before R is still outside that timer. Calling R the earliest *ordinary-tool* sample O when O actually came first would be false. A later timer armed with remaining O+120-now expires at the correct absolute time once armed, but cannot retroactively enforce the interval O..A or terminate an initialization that never reaches A. Checking after startup and refusing a late launch is observation/refusal, not independent coverage of a startup hang. An unbounded pre-arm phase is not cured by a timestamp argument, a future fast sample or a larger grace interval.

No already accepted upstream timer covers O..A, as established by existing-clock audit c590/001e. Therefore the unchanged interpretation requiring independent coverage beginning at the earlier ordinary-tool O remains UNPREPARED. Before implementation root must explicitly choose the required boundary: (1) retain O and identify/review an already-active upstream fixed primitive covering initialization through root terminal, which is currently absent; or (2) explicitly adopt the narrower first-ready-ancestor boundary R while retaining actual O-based normal strict115 observation as a separate conjunct. Option2 is a scope decision, not a consequence of this plan or a silent closure of the original requirement. No such decision is adopted here. If no excluded minimal timer initialization is permissible, the proposed fixed ancestor alone cannot satisfy the unchanged condition.

## Minimal fixed mechanism after the boundary is armed

The only source precedent is H6 hard_limit.pl:10,30–56,61–67: an independent timer process, direct fork-child ownership, a responsive waitpid(WNOHANG) loop, independent SIGALRM, safe direct fallback, and bounded nonblocking final emission. Existing code cannot simply be invoked around another program:13–14 and42 hardcode the H6 entry. A future *separately authorized* source packet would need exactly one fixed ancestor body and one fixed D03 collector body. They are roles only here; no executable file, command cell or implementation is authored.

After required primitive initialization and the first adopted origin, the ancestor must arm its original absolute120 deadline before forking the collector. Its loop performs no path/authority/source hashing, JSON parsing, raw stream drain, file publication or blocking wait. All such target work lives in the subordinate collector. The timer remains alive after the native child exits and through collector imports, preflight, post-native parsing, raw-file hashes/closes and final receipt publication. It is not cancelled to let finalization finish. Its own final terminal emission must use the existing nonblocking single-write precedent, with missing/short/EAGAIN/write failure becoming nonzero/UNKNOWN rather than a successful tail repair. No new native-output allowance or native three-event grammar is introduced. Exact outer tool metadata bytes and bounds remain future source-review obligations.

The fixed ancestor creates and immediately retains one unreaped direct collector child. The child's fresh session/group creation is required before normal work; until that completes, direct-child signaling remains the fallback. Only this still-unreaped direct creation handle authorizes signals to its PID and its own creation group under the existing precedent. Once reaped, no numeric historical PID/PGID authorizes a later signal. The ancestor never reads a journal and treats a historical native PID or PGID as signal authority. Existing ownership/bootstrap/identity allowlists, zombie rules, ACK-before-unmask semantics and sticky UNKNOWN policy do not change.

At root-origin+115 the ancestor requests TERM of its owned direct collector; at+119 it requests KILL if still unreaped; at+120 its independent alarm enforces failed termination of that child and itself using the same ownership basis. Normal success requires no force and actual child/ancestor terminals strictly before115. SIGTERM may be delayed by the collector's Python/C I/O state; the independent ancestor KILL is the point that avoids reliance on that cooperative handler. Neither signal dispatch nor OS scheduling is a hard-real-time or machine-failure guarantee. Detailed source/error handling and actual fit remain unprepared and require independent review.

## Separate native lifetime and failure honesty

The collector launches exactly the unchanged H6 hard_limit.pl D03 unit original catalog argv with its separately adopted external release. H6 creates its own session and records N; its115/119/120 remain relative to N, not R or O. No root-origin argument is inserted into H6, no native alarm is reset or cancelled, and no early native KILL is introduced. On collector failure its existing direct-handle safe TERM may request native cleanup without cancelling the limiter's independent alarm. A blocked/killed collector may never deliver that request.

The native session is outside the collector's creation process group. If the ancestor kills its own collector, the native limiter can outlive both and remain armed until N+120. When N>R, that native bound is later than R+120; moving it earlier would change the preserved native contract. The ancestor must not signal an orphaned native group merely from copied IDs. Thus the proposed root boundary bounds the intact timer/collector domain, not universal descendant termination by the root deadline. If whole-tree absence by O+120 is also required on failure, this design cannot meet it while preserving those native boundaries and signal rules. That is a separate exact constraint conflict, not authority to weaken ownership or report absence.

The future source must prove descriptor containment: collector tool stdout/stderr are not inherited as unintended extra writers by its separate native session; native streams remain dedicated collector-owned PIPEs with normal close-fds behavior and explicit retained handle/stream ownership. Actual outer tool EOF remains required, never inferred from leader exit. An unexpected inherited writer, missing native tail, failed close, unknown orphan or absent ownership receipt makes failure/UNKNOWN, even if root timer fired. No source-only assertion of global containment follows. Unexpected loss of the independent ancestor itself breaks the timer fault assumption; existing native safety covers only its own already-created domain, not root work. Host loss or an unkillable OS task cannot be guaranteed away by additional software polling.
