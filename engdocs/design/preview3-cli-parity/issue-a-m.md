## Release blockers and notable behavior

**P1 silent identity divergence, both storage engines.** Shipping embedded:
- create Parent --id audit-parent --json -> id audit-parent, properties of the Issue identify audit-parent.
- create Child --parent audit-parent --json -> id audit-parent.1.
- children audit-parent --json -> child id audit-parent.1, dependency depends_on_id audit-parent.

Preview embedded:
- create Parent --id audit-parent --json -> canonical id https://example.test/cleo-audit/beads/audit-parent, but properties.id audit-y9x, exit 0.
- create Child --parent audit-parent --json -> canonical child .../beads/audit-y9x.1, exit 0.
- children audit-parent --json -> child id beads/audit-y9x.1 and parent beads/audit-parent, while the dependency depends_on_id is audit-y9x.
- Human mode repeats it: create Human Explicit --id audit-human prints “Created beads/audit-human”; create Human Child --parent audit-human prints “Created beads/audit-7so.1”; children audit-human shows the latter under beads/audit-human.
- On real shared-server Dolt: explicit canonical graphaudit-parent has properties.id graphaudit-8io; its child is beads/graphaudit-8io.1; linking by shipping-style graphaudit-parent.1 fails not_found.
Source: Preview cmd/bd/graph_preview_issue.go:22-24 expressly permits distinct canonical/backing IDs, :66-69 sets an explicit path, :153-158 builds the Issue without setting its ID, and :169-187 passes the path and Issue to graph storage or creates a child from the parent record. This may be an intentional internal distinction, but the child naming and legacy dependency projection silently break the shipping command’s visible ID relationship. Keep release staging blocked until identity semantics and the projection are fixed or explicitly decided. The integration owner was notified immediately.

**P1/P2 workflow difference, explicitly advertised.** Shipping embedded close audit-batch audit-absent --json exits 1 at resolution and leaves audit-batch open. Preview embedded executes the first close, emits its success record on stdout, reports not_found for the second on stderr, exits 1, and a subsequent show confirms audit-batch closed. Preview cmd/bd/graph_preview_workflow.go:323-341 implements per-ID continuation; its close help advertises partial batches. This is a contract change that release notes must state for scripts; whether Preview should follow shipping direct-Dolt atomic resolution or the ordinary proxied partial-success policy is open.

## Verification and limits

- Embedded Dolt: both exact-commit CGO binaries initialized clean disposable workspaces; ran default/type create, explicit parent-child creation, assign, children, comment/comments, close and mixed close, create-form refusal, delete preview/force, edit no-op, gate/label refusals, positional and canonical Link operations, and list filters/outputs. Follow-up embedded probes covered inline create fields, Markdown create, comment file/stdin, close reason-file/session/force, all editor-field no-ops, revision-guarded assign/close/delete, close --claim-next, Link create/update/delete, and selected canonical output/page refusals. Real shared-server Dolt: both binaries initialized separate databases on the same isolated Dolt server and repeated parent-child identity, assign, comment/comments, edit no-op, create-form, label/gate, list parent, and positional Link checks. Shared-server confirmed the P1 identity mismatch.
- Build detail: initial CGO build failed because ICU headers were not on include paths; rerun with CGO_CFLAGS and CGO_CXXFLAGS including /opt/homebrew/opt/icu4c/include and CGO_LDFLAGS including its lib succeeded. CGO-disabled builds worked for help but cannot run embedded Dolt. The real-server probes used the successful CGO binaries.
- No staged candidate PR was built or treated as integrated. Source inspection of the graph admission allowlist supplies refusal coverage, but not a claim that every accepted flag combination works. I did not exhaustively vary dates, time zones, output templates, editor mutations, large result caps, several revision guards, partial-ID ambiguity, or every canonical collection pagination flag. Those are explicitly untested, not parity claims.
- Shipping v1.3.1 direct embedded semantics were the baseline for mixed-close comparison. Proxied-server shipping behavior was not run; the graph help and existing audit indicate it can differ, so the batch policy needs a decision.

### Inherited flags and remaining high-impact probes

--json is inherited rather than local. It was executed for assign, children, close, comment, comments, create, delete, link positional/canonical forms, and list. edit/create-form/gate/label reject or are interactive before any useful graph JSON result. Shipping Issue read/write JSON shapes are preserved for assign, children, comments and filtered list; graph create/close/delete/positional link use a preview envelope, and Markdown create uses a legacy array. The inherited graph selector --graph-mode link is required only as an assertion once the workspace marker is present. Other inherited switches such as --actor, --directory and --readonly are admitted by graphPreviewFlags at cmd/bd/graph_preview.go:401-415 but were not systematically cross-checked here; backend override switches and routing are a separate workspace-authority question.

High-impact untested combinations: true live-claim takeover with assign --force; a newly unblocked blocker case; actual editor content replacement and concurrent edit; connected survivor cleanup; partial-ID ambiguity on positional link; Link endpoint pin and re-pin behavior; canonical collection pagination/output-format variants; large list caps and repeated filters; every date-filter/time-zone boundary; and full gate/label workflows because graph admission rejects them. Candidate PR behavior remains untested at this integration commit.
