# Independent Review — principal-namespace cumulative evidence draft (app scope)

## Findings

**1. [High] Positional consumption of the first `maximum` exchanges, with no content gate — `principalNamespaceWire.onDispatch` / `afterExchange` / `joined` (diff: new wire factory, and `joined()` body).**
Both callbacks consume run-global events by index: `onDispatch` compares the *first* dispatch of the whole cohort against `principalRequests[0]`, `afterExchange` compares the *first* response against `principalRequests[0]`, and `joined()` pairs report exchange `i` of the principal row with `dispatches[i]`. In the composed sixteen-row test these hooks are installed on `observe()` globally (`control?.onDispatch?.(...)` fires for all 220 dispatches; `withPrincipalWire` calls `principal.afterExchange` for every response). Correctness therefore requires that the principal row's 7 exchanges are the *first seven exchanges of the entire run*, including before any runner preflight and before every other implemented row. Nothing in the supplied scope establishes that: the reordered `uniqueRoutes`/preimage prove only *manifest* order, not execution order, and the draft claims no runs. By contrast the pre-existing composition gates on content (`memberHandoff` matching url+digest+key+writeState). Failure mode is also badly attributed: `onDispatch` throws *inside* `exactExecution.execute`, so a mismatch surfaces as a harness error on whatever unrelated row dispatched first.
*Smallest correction:* gate consumption on identity rather than position — in `onDispatch`, only consume when `input.credentialRef` is one of the three principal refs (otherwise run the existing post-maximum guard), set a `pending` flag, and in `afterExchange` consume only when `pending` is set (clearing it); keep `expect(dispatches.length).toBe(responses.length)` as the pairing invariant.

**2. [Medium] Expected Event IDs for B's event are derived from A's authorization view — `afterExchange`, `index === 6` branch (`const expected = resources.map(...)`, `hash("view", view)`).**
`view` is the `bdp-authorization-view` of the index-6 response, fetched with `credentialRef: "principal-a"`. Both expected event IDs embed that single value, so the assertion silently requires either A/B view equality or reader-keyed event identity. The run already observes B's view at index 1 and stores it (`responses[1].view`), and the governing instruction is explicitly not to assume A/B view equality or inequality.
*Smallest correction:* build each expected ID from the recorded writer's view: `hash("view", responses[i]!.view)` (equivalently `responses[i === 0 ? 0 : 1]!.view`), leaving the rest unchanged. This is correct under equality *and* inequality.

**3. [Medium] The complete-collection and Events assertions assert cross-principal read visibility inside a row named `principal-isolation` — `afterExchange`, `index === 5` (`expect(body).toStrictEqual({ items: resources, next: null })`) and `index === 6` (`expect(events).toHaveLength(2)`).**
`resources` holds both A's and B's beads, so the row asserts that a `principal-a`-credentialed complete collection and Events page contain B's namespace. Combined with the shared `scopeEpoch` assertion (`expect(epoch).toBe(a.scopeEpoch)`) and the global `pos-1`/`pos-2` progression, the demonstrated isolation is *idempotency-key/receipt* isolation only; read view and scope position are shared. Nothing in the assigned diff states this, and the row name plus `performed: "namespace-distinct"` read as a stronger claim than the evidence supports.
*Smallest correction:* add a one-line comment at the `index === 5` branch recording the observed fact ("one shared scope position/epoch and a shared read view; isolation here is per-principal idempotency retention only"), and ensure no wording in the pinned plan/row literal claims read-view isolation. If the actual observation is that A does *not* see B's bead, items/events expectations are wrong and must be rebuilt from A's resource alone.

**4. [Medium] Both new tests write their observation artifact to the same path — `principalOutputPath()` plus both `onObserved` writers.**
`BDP_TRANSACTIONAL_PRINCIPAL_CUMULATIVE_OUTPUT` is read by both the positive and the collapse test and passed directly to `writeFileSync`, so when the variable is set the second test silently overwrites the first test's retained evidence (the cross-carrier control writer avoids this with a `-${control}` suffix).
*Smallest correction:* `function principalOutputPath(mode: "positive" | "collapse")` returning `${output}-${mode}.json` after the existing absolute/length validation, and pass the mode at each call site.

**5. [Medium] The safe supplement persists raw redacted-class header values — `summary()` → `responses[].epoch` / `responses[].view` (pushed at the end of `afterExchange`).**
`bdp-scope-epoch` and `bdp-authorization-view` are report-redacted header values; the supplement captures them from the live response and writes them verbatim into the observation files in all three writers. The supplement contract in force is hashes/positions plus input-ref/response/report boundaries; `position` qualifies, `bodyDigest`/`requestBodyDigest` qualify, raw epoch/view do not. The wire already has a digest helper for exactly these two values.
*Smallest correction:* store `epochDigest`/`viewDigest` (e.g. `createHash("sha256").update(JSON.stringify(["epoch", epoch])).digest("base64url")`, matching the existing `hash()` helper) instead of the raw strings; keep raw values local to the assertions.

**6. [Medium] Run-wide aggregates in the composed test are not shown to be updated for the seven new leading exchanges — `apps/bdptest/src/transactional-matrix.test.ts` around line 404 (`const dynamic = observed.result.scenarios.flatMap((s) => s.exchanges)...`) and the unshown block between the supplied hunks (~lines 420–580), plus the `implemented` set used at line ~402.**
The diff updates scalar counts (pass 15→16, sessions 22→23, children 23→24, totals 213→220, and every control bound by exactly +7 — all internally consistent), but every assertion that enumerates or counts *all* exchanges now also sees the principal row's 7. In particular, if `implemented` is a literal id list rather than a manifest-derived set, it still has 15 entries, so `for (const row of ...filter((s) => implemented.has(s.id))) expect(row).toMatchObject({ state: "pass" })` silently skips the new row while `filter(state === "pass").toHaveLength(16)` still passes.
*Smallest correction:* confirm `implemented` is derived from `bundle.manifest.scenarios` (or add `principalId` to it), and re-check each aggregate in the unshown region against +7 exchanges / +139 assertions / the three new credential refs, updating the affected pins.

**7. [Medium-low] `assertPrincipalPositive` validates the principal row against the unmutated bundle while the cross-carrier controls run a mutated manifest — `assertPrincipalPositive` (`const declared = bundle.manifest.scenarios.find(...)`), called from `it.each(crossCarrierControls)`.**
`observe()` builds `runBundle` from the control-mutated manifest, but the declared-assertion comparison reads the frozen `bundle`. If any cross-carrier mutation touches the principal row (the `batch-semantic-conflict` control is adjacent in subject matter, and the principal row is the manifest's first batch user), the comparison is against the wrong declaration while still expecting `state === "pass"`.
*Smallest correction:* inside the cross-carrier test's `manifest(value)` callback — which already receives the mutated object — assert the principal row is untouched, e.g. `expect(value.scenarios.find((s) => s.id === principalId)).toEqual(bundle.manifest.scenarios.find((s) => s.id === principalId))` before/after `applyCrossCarrierControl`.

**8. [Low] `principalRequests[i].status` is never compared with any observed status — `afterExchange` uses `expect(response.status).toBe(refused ? 409 : 200)`.**
The literal `status` field is dead data (it cannot be used directly, since collapse mode legitimately turns literal `200` into an actual `409`), so a wrong literal status would never be caught, and the `status: 409` on `pk-a-conflict` carries no verification weight.
*Smallest correction:* in `assertPrincipalStatic`, add `expect(principalRequests.map((r) => r.status)).toEqual([200, 200, 200, 200, 409, 200, 200])`, which binds the literals to the `refused` logic without affecting collapse mode.

**9. [Low] The static manifest-partition cross-check is one-sided, and the row's total assertion count is unpinned — `assertPrincipalStatic` (`b.assertions.map((a) => a.id).filter((id) => !principalPassingIds.some(...))`) and `assertPrincipalPositive`.**
Filtering out the passing ids detects extra/renamed failing ids but not a *missing* or duplicated passing id, so the declared action-2 inventory is not fully pinned on the app side (the runtime partition in the collapse test is what actually pins it). The row's claimed 139-assertion total is never asserted here, although the app scope is meant to represent the new row literal independently.
*Smallest correction:* add `expect(b.assertions).toHaveLength(25)` and `expect(b.assertions.map((a) => a.id).filter((id) => principalPassingIds.some((p) => p === id))).toEqual(principalPassingIds)` in `assertPrincipalStatic`, and `expect(row.exchanges.reduce((n, e) => n + e.assertions.length, 0)).toBe(139)` in `assertPrincipalPositive`.

**10. [Low] The new throw inside credential resolution loses its diagnostic, and literal credential refs are not statically checked — `principalHeaders` (`throw new Error("unknown principal credential reference")`), reached via `exactMode.resolveCredentials`.**
Previously any ref other than `operator`/`anonymous` fell through to the reader token; now an unknown ref throws from inside request construction, where `packages/conformance/src/http-executor.ts:782-790` replaces non-`HttpTransportError` errors with the generic `"exact HTTP request configuration is invalid"`. The specific message is therefore unreachable in the installed path, and nothing statically confirms that the three new literal refs (and every existing manifest action ref) are members of the role set.
*Smallest correction:* in `assertPrincipalStatic`, add `for (const literal of principalRequests) expect(roles.map((r) => r.ref)).toContain(literal.credentialRef);` and, in `observe()` next to the `uniqueRoutes` expectation, assert every manifest action `credentialRef` is in `[...roles.map((r) => r.ref), "anonymous", undefined]` so a bad ref fails with a readable message before dialing.

**11. [Low] No evidence that an `authorization` header line was emitted on the principal exchanges — `afterExchange` header checks.**
The draft checks the authored prefix header lines and that no further `bdp-` headers appear, but never that the trailing lines include `authorization`. Asserting presence (not value) is compatible with the no-wire-credential-attestation rule and closes the gap between the authored handle and the serialized request.
*Smallest correction:* add `expect(exact!.headerLines.map((h) => h.name.toLowerCase())).toContain("authorization");` in `afterExchange` (header-line block).

**12. [Low] The raised derivative fence records no measured basis — lines ~1755 and ~2166 (`toBeLessThanOrEqual(847979)` / `toBeLessThanOrEqual(22128)`).**
Both sites preserve the historical basis comments (701716/18263 and 756707/19731, each "plus 4096B/64nodes") but no comment records the new generation's measured maximum, breaking the file's own convention that each fence is traceable to a measurement. The arithmetic itself checks out: 843883 + 4096 = 847979 and 22064 + 64 = 22128.
*Smallest correction:* add `// Principal measured maximum 843883B/22064nodes plus4096B/64nodes.` above each updated pair.

**13. [Low] Predecessor-log comment went stale with the summary rename — line ~604, `// Predecessor logs retain installed-tx-twelve/thirteen/fourteen-partial-summary.` with `kind` changed to `installed-tx-sixteen-partial-summary`.**
`installed-tx-fifteen-partial-summary` is now also a predecessor and is unlisted.
*Smallest correction:* `twelve/thirteen/fourteen/fifteen`.

**14. [Low] `principalRequests` hardcodes the absolute scope prefix** (`"https://reference.invalid/acme/operations/batch"`, etc.) while the surrounding file and the same literals' `reportedUrl` check use `${scope}`. Divergence would fail loudly at runtime rather than silently, but the literals are no longer scope-parameterized.
*Smallest correction:* template the `url`/`dispatchUrl`/`reportedUrl` literals from `${scope}` as the existing route inventories do.

**Verified as internally consistent (no finding):** +7 exchanges applied uniformly to all seven updated bounds plus session/child counts; the five POST bodies are each exactly 150 B with correct per-body digest reuse (A ≡ rotated-A, B ≡ B-replay, C distinct) and one create per batch; the reordered route inventory and the digest preimage match each other, preserve the 15-route authority set and relative order of the untouched routes, and correctly keep `Buffer.byteLength(preimage) === 1228` under a pure reorder; the 18/7 assertion split is coherent with a `transactionalProblem` body (`no-next` fails on `exists: true`, `no-owned-links`/`no-provenance` pass vacuously, request-side and header-presence ids pass); schema-ref selection is exhaustive and unreachable-branch-free for both modes; collapse mode changes only `principal-b`'s principal before its own bootstrap; retained evidence is captured in `onObserved` before cleanup; receipts/tokens never reach the supplement.

## Necessary missing context

1. `apps/bdptest/src/transactional-matrix.test.ts` lines ~363–580 (the composed test's aggregate assertions) and the definition of `implemented` — required for finding 6.
2. The scenario execution order contract of `runCumulativeTransactionalMatrix` (catalog order vs. manifest order, any preflight exchange, reopen replay of a row) — required to settle finding 1.
3. Bodies of `crossCarrierWire`, `commandMinimumWire`, `assertCommandMinimumPositive` and `applyCrossCarrierControl` — to confirm the old observers tolerate seven new *leading* exchanges and that no control mutates the principal row.
4. The `ExactHttpModeOptions` declaration (`resolveCredentials` parameter types, `credentialHandles` contract) — to confirm `principalHeaders(roles, credentialRef, ...)` type-checks and that `anonymous` is the only non-role ref.
5. The runner code that initializes `ObservedExchange.request.url`/`id` in exact mode (the supplied `runner.ts:1358-1373` shows `effectiveRequest` is `undefined` when `exact`) — required to validate the `reportedUrl` literals, specifically `beads/?<redacted>` for `pk-current`.
6. The new manifest row literal (7 actions, credential refs, assertion ids/order, 139 total) and the canonical/coverage fence updates (829145/841861/21972/125561) — separately reviewed scope; findings 7 and 9 depend on them.
7. Server semantics for `bdp-scope-position`/`bdp-scope-epoch`/`bdp-authorization-view`, event-ID composition, and whether positions are global or per-principal — the draft's `pos-1`/`pos-2` and event-ID expectations rest on these.
8. `schemas/bdp-v0.schema.json` `$defs` names used here (`transactionalProblem`, `mutationReceipt`, `currentBeadCollection`, `eventPage`, `beadRecord`).

## Review limits

No tools, filesystem, build or test execution were available: every hash in the draft (`9a9404e7…`, the three body digests, event-ID digests), the 1228-byte preimage length, the measured byte/node maxima, and all claimed response bodies/headers are unverifiable here and reviewed only for internal consistency and arithmetic. The draft itself claims no runs, so no finding is corroborated or refuted by observed behaviour — positional and semantic assumptions (findings 1–3) are unvalidated by construction. Cross-scope dependencies on the composition/static/JSON diff are noted but not reviewed. I did not review the frozen working regions beyond the supplied excerpts, and this is not an exhaustive whole-repository review. One residual risk I cannot size: the composed test's `63000` ms wall-clock bound is unchanged while gaining a 23rd session and 7 exchanges — worth confirming headroom from CI elapsed logs, since raising the deadline is outside the authorized fence.
