## What is implemented

`captureSnapshot`, `readSnapshot`, and `readSnapshotPage` are private synchronous owner entries. They return immutable manifest/page values plus the same-entry current serving context. A capture observes complete Bead/Link streams at one owner prefix, persists independent record bodies and fixed ranges, then commits before returning its usable identity. It creates no graph mutation, key, receipt, revision, Event or change group. Existing exclusive SQLite ownership remains the authority. Expiry reclamation commits separately inside that same owner entry before the capture transaction: a subsequent failed capture does not undo legitimate disposal of previously expired detail.

Captured bodies use the existing admitted-record codec: those stored numbers have already passed numeric admission; no raw unadmitted request is parsed or normalized here. Complete records include properties, common metadata, revision provenance and owned Links. Validation rejects incidental `links`, wrong-kind/unknown Types, endpoint-index inconsistencies, missing local endpoints, and missing/contradictory owned versus first-class Link inventories. The identity-only inventory is bounded and sorted with `compareCanonicalIds`, not SQLite collation; resource bodies are processed one at a time.

The persistent format is `bdp-private-transaction-snapshot-9`; numeric identity policy remains `transaction-revision-provenance-4`. Configuration includes Snapshot capacities and `snapshotTokenPolicy: hmac-sha256-ordinal-1`, so different configuration or prior format refuses before BDP maintenance. No migration, reseeding or resealing is provided.

Every capture has a fixed five-minute expiry. Both immediate owner expiry and maintenance use the existing injected clock/instant seam. The expired disposition remains permanently issued for the epoch; only bodies and ranges are discarded. Disposal is irreversible even if the wall clock moves backward. Temporary pressure uses the existing temporarily-unavailable/503/unavailable/after-delay tuple, with body retryAfter derived from earliest live expiry (guidance, not a capacity guarantee). Permanent size/issuance refusal uses limit-exceeded/413/size/never. Unknown identities use resource-not-found/404/not-found/after-state-change; expired issued identities use cursor-expired/410/gone/after-state-change. No retryAfter is emitted on 404/410. These bodies are checked against the actual transactionalProblem schema. HTTP status/header rendering remains S1b.

The encoded compact disposition, including identity, stays <=1 KiB. It includes the epoch/view/anchor, expiry, counts/bytes, page-plan commitment, secret 256-bit token seed, two page counts, and a corruption-detecting commitment. Tokens directly authenticate Snapshot/kind/ordinal with HMAC-SHA256; no unbounded ordinal scan or permanent page-detail ledger is needed. Context and committed disposition validation precede token recognition; recognition precedes expiry. Known next tokens get 410 after disposal/reopen, while arbitrary, wrong-kind or other-Snapshot tokens stay 404. This fixes the existing spec 5916 distinction, not a new policy.

## Bounds and tested observations

- 4,096 resources and 32 MiB encoded captured records per Snapshot. Count/total bytes precede body reads; each complete record obeys existing R=262,144.
- Eight live handles and 64 MiB live captured record bytes, independently enforced. Expired detail is reclaimed in the entry before capacity measurement, independent of the timer.
- 65,536 permanent issued identities, each <=1 KiB encoded metadata+identity. This is not a promise about total SQLite file/index overhead or total owner history.
- Private snapshotPageItems=32 and 4 MiB encoded page bound. Actual near-R records produce 15-item pages under the byte cap. The manifest embeds both first pages with a checked 10 MiB bound. Page fit includes an actual absolute continuation URL; no truncation fallback.
- Per-page body commitments and a committed whole range plan detect missing/changed bodies, wrong kinds, missing ranges, wrong contexts/anchors/expiry and oversized retained material. Bounds are checked before loading retained bodies or oversized metadata. Semantically corrupted context/anchor/expiry controls are independently resealed to reach those validation branches; a separate stale commitment control proves fail-closed integrity.
- Real admitted graph: 37 Beads/35 Links over multiple transactions and both streams, owned/first-class agreement, stable refetch and restart after subsequent mutations, checkpoint catch-up with an actual committed group, and independent `owner.inspect()` authority comparison. Replica staging rejects an owned contradiction without changing its prior generation. Independent expected IDs reject coherent omissions/premature termination even when individual records/manifests still satisfy wire schema.
- Actual 4,096/4,097 row distinction; complete 128*262,144=32 MiB capture; two captures fill 64 MiB before the eight-handle ceiling; 129 records refuse; eight small handles refuse the ninth; 65,536 issuance refuses despite expired detail. Capacity fixtures are explicitly offline complete-record fixtures, not evidence of mutation admission for those populations.
- Injected pre-copy/committed-delivery failures, before/after uncertain COMMIT and rollback failure exercise atomicity and sticky owner fencing. A real abruptly exited emitted child leaves an in-flight capture to rollback-journal recovery. Reopen never invents/replays a capture.
