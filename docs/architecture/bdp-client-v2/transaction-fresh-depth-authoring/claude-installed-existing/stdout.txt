### Findings

**1. Low (robustness) — the new metadata expectations are pinned only by a label-string match, with no count assertion.**
`apps/bdptest/src/transactional-depth-key-order-installed.test.ts:351` and `transactional-sequence-depth-installed.test.ts:268`
Reason: the patch made the depth loop load-bearing. `freshInput.metadata` (`:567-575`) and `records(...)[0]!.metadata` (file 2 `:484`) take the *expected* response metadata straight from the request literal, so the only thing preventing a vacuous "server echoes what we sent" assertion is the `row.label.includes("deep") || row.label.endsWith("fresh-depth")` loop that pins 41 levels + `"leaf"`. If a label is ever renamed, the loop silently matches nothing, the structural floor disappears, and both tests still pass.
Fix: count matches and assert the expected number, e.g. `let deepChecked = 0; … deepChecked++;` then `expect(deepChecked).toBe(4)` in each file (4 deep rows in each: 2/8 + 4/10 in file 1; 2/5/7/8 in file 2). No HTTP change.
