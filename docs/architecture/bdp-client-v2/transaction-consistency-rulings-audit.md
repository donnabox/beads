## Next safe serving implementation

Recommend **fresh Snapshot creation minimums**, not another coverage-only row. This has a direct normative answer and useful replica-bootstrap behavior without deciding retained-handle semantics. Proposed narrow production ownership: `transaction-store.ts` (optional captured minimum only for create/preflight; check in same owner entry before capture), `transaction-service.ts` (bounded existing wait and disconnect propagation for this scoped path), `transaction-http.ts` (allow complete tuple only on no-query creation; conditional/HEAD paths use eligible preflight and actual GET rechecks). Existing `transaction-consistency.ts` need not change. Tests belong in existing Snapshot/service/HTTP tests and actual `apps/bdptest/src/transactional-snapshot-installed.test.ts`. No schema, token format, public config, profile advertisement, retention lifetime, capture shape or new error code.

Acceptance plan should explicitly cover:

- Current/behind/foreign/expired contexts and GET/HEAD, independent literal manifest Resource state and anchor/response context.
- Deterministic real commit between behind attempts, no allocation on failed attempts; installed fixed-head timeout with current unmodified budget. Do not infer waiting from a successful concurrent read.
- Same-request conditional decision cannot skip the minimum; GET capture rechecks current eligibility rather than reusing a stale HEAD-style probe.
- Abort during wait prevents later attempts and service close drains; no installed clock/scheduler seam.
- Existing manifest/page no-minimum behavior and reopen unchanged; supplied retained minimum still explicitly out of this slice, not accidentally enabled.
- Three or fewer live Beads/one Link, two installed sessions (create/reopen), at most40 wire exchanges, inherited5s exchange/90s aggregate/120s outer and existing lifecycle deadlines; measure rather than expand.

This is a planning recommendation for council, not authorization to edit. C1 and alias integration must release shared HTTP/store files first. No new Event question is raised; the two existing Event questions remain with their current owners.

## What should leave the human-dependent blocker list

Fresh Snapshot creation and ordinary already-supported complete-minimum current reads are implementable now. Compatible/satisfied-minimum missing-target404 is likewise not a fundamental semantic puzzle. A speculative mutation precondition/barrier is not required by the existing text and should not block completion as if it were accepted scope. Keep only field applicability/error grammar, retained-anchor versus current-observation interpretation, simultaneous nondisclosure/minimum refusal ordering and the existing embedded Selector phase as genuinely unsettled precise contracts. Some may have existing root rulings; consult them before sending human questions.
