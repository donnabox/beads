# Findings

Line numbers are the frozen copies, which are byte-identical to the working tree.

### G1 — MEDIUM · `internal/storage/graphstore/legacy_import_test.go:323-410` · the grown case matrix now shares one 90-second store context with ~3,300 statements

**Trigger.** `TestLegacyImportFreshDataPlanes` on a loaded machine, or on the `server` backend where every statement is a TCP round trip.

`issueExperimentOptions` (`issues_test.go:27`) creates **one** `context.WithTimeout(…, 90*time.Second)` and that ctx covers `Init` (the full main + ignored migration pass — the single most expensive operation in the file) *and* every subsequent call. The repair's cost per backend subtest:

- `legacyImportState` is now 33 statements per call — `workflowState`'s 15 `SELECT *` (`workflow_test.go:242`) + `reopenState`'s 2 (`issue_reopen_test.go:57`) + the 14 added at `legacy_import_test.go:249` + 2 scalar reads.
- It is called 59 times: 19 cases × (1 `before` + 2 post-refusal) + 2 in the ordinary-config block → **1,947 statements**.
- 40 `ImportLegacy` calls (19 × dry/apply + 2 successes), each ≈ 33 statements inside `withTx` (4 `SET`, `active_branch()`, `BEGIN`, `checkBinding`, 24 `COUNT(*)`, `bd_events_seq`, `config`, `ROLLBACK`) → **~1,320**.

That is ~3,270 statements, against ~1,200 for the heaviest pre-existing user of the same helper and the same budget (`TestLegacyImportAtomicityAndPersistence`), and ~2.5× the pre-repair version of this test.

**Impact.** Not a correctness defect — a diagnosability and CI-reliability one. If the budget is exceeded, the deadline lands in whichever subtest happens to hold the ctx: `ImportLegacy` returns `context.DeadlineExceeded`, `errors.Is(err, storage.ErrValidation)` is false, and line 375 reports `occupied plane admitted or result leaked` — i.e. a timeout is reported as a *guard failure* on an arbitrary plane. Every later case and the ordinary-config block then fail too, because `test.remove` (line 382) never ran. Because the test is authored-but-unrun, this margin has never been measured.

**Fix.** Cheapest: take one post-refusal snapshot after both modes instead of one per mode (59 → 40 calls), accepting that a mutation is then attributed to the pair rather than to `dry`/`apply` — the guard is shared, so the pair is the real unit. Better: give this test its own per-case table set (each fixture can only touch its own table plus `config`/`graph_preview_scope`/`issue_prefix`), keeping `legacyImportState`'s full 33-table dump for the single-import tests that need it.

### G2 — LOW · `internal/storage/graphstore/legacy_import.go:213-219` · 8 of the 26 guarded planes are pinned by no assertion anywhere

**Trigger.** Any future edit that shortens either source of the list — the fixed literal at line 213, or `issueops.DeleteCascadeTables`.

Guarded planes: 24 tables (9 fixed + 15 from the two `DeleteCascadeTables` calls, deduped) + `bd_events_seq` + the `config` memory rule = 26. The 19 cases pin 18 of them. **Unpinned: `issues`, `dependencies`, `comments`, `wisps`, `issue_versions`, `graph_preview_versions`, `graph_preview_issue_versions`, `graph_preview_catalog`.**

The repeat-import assertion in `TestLegacyImportAtomicityAndPersistence:521-528` does not cover them: a successful import leaves *many* of those tables non-empty, so dropping any single one from the list still leaves the repeat import refusing, and the assertion only checks `err != nil`.

**Impact.** The drift direction is realistic, not hypothetical. `DeleteCascadeTables`'s contract is "every table a DELETE of one issue row removes rows from" — maintained for Dolt staging (#3807), not for import freshness. It currently lists `child_counters`, whose `fk_counter_parent` main migration `0039_drop_child_counters_fk.up.sql` **drops** (and `ignored/0002_create_wisp_child_counters.up.sql:28-40` silently re-adds). Someone reconciling that list with cascade reality would take a plane out of the import guard with no signal. `wisps` is the worst case: live wisp rows are a genuinely non-fresh destination and nothing in the tree pins that refusal.

**Fix.** Add cases for the cheap ones — `issue_versions`, `graph_preview_versions`, `graph_preview_issue_versions`, `graph_preview_catalog` are single-row inserts with no FK (`orphan: false`), and `comments`/`dependencies` mirror the existing `event` fixture (`orphan: true`). `wisps` needs its full `NOT NULL` set from `0020_create_wisps.up.sql`, which is presumably why it was skipped; it is the one most worth the cost.

### G3 — LOW · `internal/storage/graphstore/legacy_import.go:247` · the bound `LEFT()` length is a byte count compared against a character count

```go
tx.QueryRowContext(ctx, "SELECT COUNT(*) FROM config WHERE LEFT(`key`,?)=?",
    len(kvkeys.MemoryConfigKeyPrefix), kvkeys.MemoryConfigKeyPrefix)
```

**Trigger.** `kvkeys.MemoryConfigKeyPrefix` (`kvkeys.go:29`, currently `"kv." + "memory."`) changed to any value containing a non-ASCII byte.

**Impact.** `len()` is Go's byte length; SQL `LEFT()` counts characters. They agree only because the prefix is ASCII. A multi-byte prefix makes the length operand larger than the prefix's character count, `LEFT()` returns a longer string than the bound literal, the comparison never matches, and **config-backed KV Memories silently pass as a fresh destination again** — exactly the defect this repair closes, re-opened with no compile error. The new `kv-memory` / `empty-kv-memory` cases would catch a change to the prefix *value*'s ASCII spelling (they hardcode `kv.memory.retained`), so this is narrowly the non-ASCII case; `kvkeys_test.go` pins the constant, not this coupling.

**Fix.** Drop the length operand entirely by using the canonical prefix-scoped config seam, which also carries the `%`/`_` escaping `memoryops.ListInTx` warns about:

```go
rows, err := tx.QueryContext(ctx, issueops.ConfigPrefixLikeQuery,
    issueops.ConfigPrefixPattern(kvkeys.MemoryConfigKeyPrefix))
```

then refuse on row presence (not value), preserving the empty-value requirement. `graphstore` already imports `issueops`, and the BUILD dep is already there. If the `COUNT(*)` shape is kept for the count in the message, `utf8.RuneCountInString` is the minimum correction.

### G4 — LOW · `internal/storage/graphstore/legacy_import.go:228`, `:238`, `:247` · the guard's engine errors return unclassified, and the repair newly makes "table absent" reachable

**Trigger.** A workspace missing one of the clone-local tables the repair added: `leases`, `bd_events_journal`, `bd_events_seq`, `wisp_child_counters`. That is not a theoretical population — `ignored/0012_create_leases`, `ignored/0019_create_events`, `ignored/0022_create_events_journal` and `ignored/0023_repair_events_journal_shape` exist precisely because a clone arrives with the cursor at-latest and those dolt-ignored tables absent.

**Impact.** The three `return err` sites hand a raw driver error up. `graphStorageError` (`cmd/bd/graph_preview.go:787-788`) has no case for it, so the default branch reports code **`graph_not_initialized`, exit 5**, with the bare engine text and no hint — describing an initialized workspace with an unmaterialized ignored plane as an uninitialized graph. `engdocs/ERROR_HANDLING.md:371` lists "Error messages provide actionable hints when possible" as a review gate, and the right pattern is already modelled 150 lines up in this same function family (`legacy_import.go:78` wraps the `issue_prefix` read in `ErrInvalidStore` with an explanatory message). The guard's own comment at line 215 ("Missing tables fail closed; import never repairs the schema") states the intent the error text does not carry.

**Fix.** Wrap the per-table query error: `fmt.Errorf("%w: workspace schema is incomplete; %s is missing, so freshness cannot be established (import never repairs the schema): %w", ErrInvalidStore, table, err)`. That routes to `invalid_store`/exit 5 and names the table. Same for the `bd_events_seq` and `config` reads.

# Validation of the repair

**No false-refusal path on the enlarged list.** Every newly guarded table is empty after `graphstore.Init`, which is only `schema.MigrateUp` + `installPreview` (`backend.go:115-148`): `0016_default_config` seeds nine compaction keys and nothing under `kv.`; `installPreview` writes only `graph_preview_scope` and `graph_preview_types`, neither guarded; `ignored/0002`'s backfill `INSERT IGNORE INTO wisp_child_counters … JOIN wisps` selects from empty tables; `0064`/`ignored/0022` leave `bd_events_seq` at exactly `(0,0)`; `0062`'s events re-insert reads an empty flip table; nothing seeds `issue_counter`. The guard sits inside the single `withTx` before `touchCoordination` and before the `issue_prefix` UPDATE, and `withTx` rolls back identically for `write=false`, so apply and dry-run refuse identically with nothing reserved and no writer-token churn — which is what makes the test's `writer_token` assertion load-bearing.

**Every new fixture satisfies the real schema.** I checked each insert against the current DDL: `events` (3 `NOT NULL` + `CHAR(36)` PK, FK to `issues`), `provenance_events` (`id`/`issue_id`/`kind`/`source` `NOT NULL`, FK), `child_counters` (FK present via `ignored/0002`), `issue_snapshots` (all 7 `NOT NULL` supplied), `compaction_snapshots`, `wisp_events`/`wisp_comments` (`id` default dropped by `ignored/0010`, so the explicit id is required), `wisp_dependencies` (explicit id, and `depends_on_external` alone satisfies `ck_wisp_dep_one_target`), `wisp_child_counters`, `bd_events_journal` (`actor` has a `NOT NULL DEFAULT ''` from `ignored/0025`), `leases` (all 5 `NOT NULL` supplied, no FK), `issue_counter`, and both preview tables. `FOREIGN_KEY_CHECKS=0` is established practice against this engine (migrations `0043`/`0047`/`0050`, `cmd/bd/doctor` tests), and the `orphan` flag is correct on all 19 — `false` exactly where no FK exists. Every `remove` statement matches its insert, so the matrix leaves the store clean for the ordinary-config block.

**`BUILD.bazel` is consistent**: `//internal/storage/kvkeys` is in the `go_library` deps, and the test's new import (`database/sql/driver`) is stdlib, so no `go_test` dep is needed. `make ci-pr-lint`'s record in the manifest is clean across all three golangci passes.

**Not run, and not qualified.** Both backend modes of `TestLegacyImportFreshDataPlanes` and the other engine-backed tests in this file remain authored and unexecuted — the frozen `pure.log` covers only the five non-database tests (`PrefixAdmission`, `LabelSetAndInternalState`, `CommentBudgetAndOriginalUTF8`, `MemoryPaths`, `CommentVerification`). I make no readiness claim; everything above is static reasoning against the frozen copies, the real migration and preview DDL, and the existing `graphstore`/`dolt` test seams. G1 in particular is a margin I could not measure without running the suite.
