## Findings (all Low; no correctness or regression defect found in `export_current.go`)

**1. Low — `export_current_test.go:81` (also 107-108, 130-131): the fresh/reopened snapshot fingerprint carries no Type identity.**
`graph.TypeDescriptor` (graphops/types.go:797) has only unexported fields and no `MarshalJSON`, so `canonicalJSON(Snapshot)` emits `"Types":[{},{},{},{},{},{}]` — the fingerprint preserves the Type *count* and nothing else.
*Impact:* the only Type assertions that bite are `len(empty.Snapshot.Types) != 6` (line 26) and `reflect.DeepEqual(ordinary, current.Snapshot)` (line 78), both on the first same-store acquisition. A regression that substituted or reordered descriptors on reacquisition or after reopen — e.g. dropping the `sort.Slice` at `collection_read.go:61`, or `installedPreviewTypes` returning a different six — still yields byte-identical `wantSnapshot`/`freshSnapshot`/`reopenedSnapshot` and the test passes.
*Fix:* add `reflect.DeepEqual(fresh.Snapshot.Types, ordinary.Types)` and the same for `reopened` (`DeepEqual` does compare the unexported `id`/`canonical`/`fingerprint`), or fold each `descriptor.Fingerprint()` into the compared string.

**2. Low — `export_current_test.go:296-305`: the "baseline must fit deleted-head test budget" guard measures a different state than the assertion it anchors, with thin headroom.**
The baseline charges the live `beads/filler` twice (12 KiB `graph_preview_payloads` row + its 12 KiB retained `graph_preview_versions` snapshot) plus all six installed descriptors against a 40 KiB ceiling; the failing check at 317-334 first deletes the filler payload and relabels it `deleted`.
*Impact:* a modest unrelated growth — one longer Type `Description` in `schema.go`, added common metadata, a wider retained snapshot — pushes the baseline past 40 KiB, and the test fails with `baseline must fit deleted-head test budget` rather than the deleted-final-head behaviour it exists to prove. Engine tests are unrun, so this would first surface in Janet's slot.
*Fix:* move the two isolation statements (delete `graph_preview_payloads WHERE path='beads/filler'`, mark it `deleted`) into the baseline block so both sides measure the same configuration, or raise `deletedHeadByteLimit` and state the intended headroom in the comment.

**3. Low — `export_current.go:192` with `export_current_test.go:208-215`: the `wisp_dependencies` plane refusal is both untested and unreachable in a referentially intact store.**
`wisp_dependencies.issue_id` carries `FOREIGN KEY ... REFERENCES wisps(id)` (migration 0021), and the `wisps` probe is first in the loop, so any store that can hold a `wisp_dependencies` row is refused by `wisps` before reaching this entry. The four other planes (`wisps`, `wisp_comments`, `wisp_labels`, legacy KV) all have cases.
*Impact:* a regression in this probe — a renamed table, a typo'd query, a dropped entry — produces no test failure; the branch only matters for an FK-bypassing out-of-band write.
*Fix:* either exercise it (insert an orphan row under `SET FOREIGN_KEY_CHECKS=0` and assert the message names `wisp_dependencies`) or record in the comment at 187-189 that the entry is deliberately defense-in-depth for FK-bypassed corruption and is not independently reachable.

**4. Low — `export_current_test.go:492-527`: `exportSourceState` is a near-verbatim copy of `workflowState` (`workflow_test.go:239`).**
The two differ only in the table list and in joining `rows.Close()` into the fatal error.
*Impact:* the fingerprints drift — a table added to one state helper and not the other means the export tests silently stop fingerprinting rows the rest of the package does, weakening every "read changed source rows" assertion (lines 85, 111, 134, 229, 293) without any failure.
*Fix:* extract one helper that takes the table list (`tableState(t, ctx, s, tables ...string)`); have `workflowState` and `exportSourceState` each pass their own list and compose.

**5. Low — `export_current.go:234-236` and `242-244`: feed/count drift is reported as `ErrInvalidStore`.**
Both refusals ("comment feed differs from its bounded inventory", "incomplete comment feed") compare the feed against the `COUNT(*)` taken earlier in the same transaction. Given the documented repeatable-read snapshot (`engdocs/design/dolt-concurrency.md:149`) they are unreachable from corrupt persisted state — they can only fire if that snapshot guarantee degrades.
*Impact:* a store whose engine or driver ran at a weaker isolation would turn a benign concurrent `AddIssueComment` into `graph preview store identity or schema is invalid`, pointing the user at recovery rather than retry; the message gives no hint that the feed changed under the reader.
*Fix:* keep the refusal but classify the mismatch distinctly from store corruption (per `engdocs/ERROR_HANDLING.md`) — e.g. an `ErrOutcomeUnknown`-joined or explicitly "feed changed during acquisition" refusal — leaving `ErrInvalidStore` for the owner/UTF-8 checks that really do indicate corrupt rows.
