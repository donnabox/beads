# Fixed intrinsic publication

This pure package checks and retains the exact BDP intrinsic publication from
`gastownhall/bdp@ba8d18c6355cbd6dd3499befe03641874bb01c73`,
`specs/profiles/types/intrinsic-1.json`, SHA-256
`73b16c93b6963f9657be3569ba9d16f722edbf6f49090803e748c907c39aab7e`.
The embedded file is an unchanged byte copy. `SelectedSource` records its source,
not a runtime pin or a claim of publication service availability.

`LoadSelected` has no arbitrary-publication or caller-digest constructor. It
checks the embedded bytes, four assigned exact definition records, two retained
Refines declarations and their captured owner copies. It preserves complete
original records, affiliations, properties, ownership captures and schema maps.
It checks abstract/category facts, exact closure, and the recorded Refines DAG
separately from metatype self-affiliation. Retained schema fingerprints bind all
four roots and eight standard resources. Properties are checked under their
exact metatype using the pinned offline JSON Schema compiler. Application schemas
are added explicitly. Only the eight exact retained standard identities use the
JSON-value-matched built-ins in pinned jsonschema/v6.0.2, after retained presence,
identity, dialect and source fingerprints are checked. Every resource is still
compiled without a network loader. Reserved built-in availability does not
authenticate supplied content; altered or missing retained standards refuse. All outputs and separate loads are independent copies.

This is a fixed trusted source loader, not general Type admission or a Types1
provider. It does not call the generic `typecatalog.New` constructor or change
its public intrinsic-name refusal. It does not register/install Types, allocate
ordinary Resources, infer an origin Scope, choose defaults, advertise a
capability, expose CLI commands, or implement packs. Shared published identities
and revisions are retained literally and are never rebound to local ownership.
Ordinary local definition Beads are the selected direction; their ownership
mapping while preserving the shared global intrinsic identities remains separate.

The private semantic validator and schema helper support finite refusal tests;
they are not an alternate public trust boundary. Pure tests do not prove
installed CLI behavior, storage, registration or provider conformance.

## Successor with an optional local schema

The candidate additionally retains byte-exact `intrinsic-2.json` from committed
BDP source `38534cf653a4dab7ed5a0a3f25337c90318a9b2e`, SHA-256
`d5541ba6edcd9f02524e78726a77e4f4b37d2a35af0b9f9694bc075d9b7e983b`.
This is source selection pending normal qualification, not a claim that BDP main
or a running provider has adopted it. `SelectedSource`/`LoadSelected` retain
publication1 exactly; `CurrentSource`/`LoadCurrent` select publication2 for new
fresh contexts. `LoadSource` accepts only either complete built-in tuple and
never authenticates arbitrary caller bytes using a supplied digest.

Both editions retain four explicit bootstrap schema environments. Edition2's
metatype permits an ordinary definition to omit `propertiesSchema`; null still
refuses and present schemas retain their validation rules. Recorded contexts
select their own exact definitions, declaration captures and schema fingerprints.
Publication1 bytes, pins and semantics remain unchanged; unknown or mixed tuples
refuse. There is no installation, migration, registration or default API.
