### 1 — MEDIUM — no assertion in any of the three rows observes an owned Link's *own* revision transitioning, yet `update-link` is pinned `wholeContract:true` and the spec's obligation for that row includes exactly that

**Location** `packages/conformance/matrices/read-update-v1.json:13310` (`owned-properties`, update-link row) and its twins `:18378`, `:22836`; the only owned-Link revision consumers are `owned-properties`←`link-created-revision`, `owned-metadata`←`link-properties-revision`, `owned-delete`/`owned-noop`←`link-metadata-revision`. Claim sites: `packages/conformance/catalog/read-update-v1.json:253` (title) and its requirement 2 ("An owned Link remains a first-class Link with its own URL **and its own revision**"); `packages/conformance/test-support/read-update-coverage-v1.json:1395-1398`; pinned list `packages/conformance/src/cumulative-artifact.test.ts:166`. Normative: `docs/specs/bdp.md:6730` — "`update-link` returns the Link postimage; **an unowned Link's update moves only the Link's own revision** and versions no endpoint"; `:2143` ("Every successful create — and every update that changes `properties`, common `metadata` … produces a fresh opaque Resource revision"); `:2190` ("creating or updating an owned Link versions **both the Link and its source**").

**Impact** Each Link revision is captured once and consumed exactly once, as the then-current guard; no revision is ever re-sent after it is superseded, no assertion compares two Link revisions for inequality, and the runner has no not-equals assertion kind. Consequently **an authority that returned one frozen revision string for every version of a Link — or the same string for the Link and its source — passes all 346/399/300 assertions of the three new rows.** The owner side has the full fresh-then-stale discipline (`matching-owner-*` 200 + `stale-owner-*` 409 after each of the four transitions, all four 409s present in the recorded run); the Link side has only the accepted-guard direction. Two consequences: (a) the spec matrix clause "moves only the Link's own revision" is the half of `update-link`'s obligation that the catalog `title` silently drops (`:253` omits it) and that no `requirements[]` entry cites, so the `wholeContract` flag covers an unobserved normative sentence; (b) the no-op row's central claim "retains the existing revision" has no demonstrated contrast class inside the slice — retention is indistinguishable from never-transitioning. The unowned leg is mitigated: the inherited `read-update.singleton.delete-link` row does carry `stale-link-delete` (`expectedRevision: initial-link-revision` → 409) after an update, so the *unowned* Link transition is observed cross-row. For the **owned** Link it is observed nowhere. This is also the one place the slice departs from its own stated standard — the plan's "proving the version changed rather than only echoing a token" was applied to the source and not to the Link.

**Fix** Mirror the `matching-*`/`stale-*` pair onto the Link. In `owned-link-source-revision`, after `link-after-properties`, add `stale-link-properties`: `POST update-link`, `bodyBindings {link: "w1b.link", expectedRevision: "link-created-revision"}`, a no-op `propertiesChange`, asserting `status 409`, `harnessInstalled_readUpdateProblem`, `/body/code == "revision-mismatch"`, followed by a `link-after-stale-properties` GET asserting `/body equalsBinding link-properties`; repeat after `link-after-metadata` with `link-properties-revision`. In `owned-link-no-op`, add `stale-link-noop` guarded by `link-properties-revision` → 409 (proving the retained revision is the only live one) and `matching-link-noop` guarded by `link-metadata-revision` → 200 with `retained-link-envelope`. In `update-link`, add the same stale control for `unowned-create-revision` after `unowned-update` so the row no longer takes silent cross-row credit. Then add one `it.each` entry to `apps/bdptest/src/read-update-matrix.test.ts:675` keyed on the new idempotency key (e.g. `["stale-link", …, "stale-link-properties", ["revision-mismatch"]]`) injecting `body.code = "not-revision-mismatch"`. Separately, align `catalog/read-update-v1.json:253` with `docs/specs/bdp.md:6730` and add a requirement citing `#mutation-revisions-and-guards`'s fresh-revision sentence, so the dropped half is represented in the clause list the flag is audited against.
