## Actual defects

**1. Severity: medium — counterfactual returns a self‑contradictory response envelope.**
`apps/bdptest/src/read-update-matrix.test.ts:1025‑1067` (control branch: `return { ...actual, bodyText, bodyOctets: Buffer.byteLength(bodyText) }`).
Issue: only `bodyText` and `bodyOctets` are rewritten. `actual.headers` (hence any `content-length`) and `actual.wireResponseBytes` are spread through unchanged, and per `packages/conformance/src/http-executor.ts:23‑110` the socket‑level executor is exactly the one that supplies `wireResponseBytes`. The returned object therefore describes a body that is one member shorter than its own framing evidence.
Impact: the pending controlled test pins a very specific shape — sole failure `directory:schema`, and `exchanges[2].assertions` exactly `[status:true, schema:false]`. If the runner derives `wireBodyOctets`/`decodedBodyBytes` from the wire bytes, or cross‑checks framing in exact mode, the observed failure becomes a `harnessError`/`exact-observation` rather than the named assertion failure. Fail‑closed (the oracle would fail), but it would fail for the wrong reason.
Smallest correction: destructure `wireResponseBytes` out of the returned object and rewrite `content-length` when present: `const { wireResponseBytes: _w, ...rest } = actual; return { ...rest, headers: { ...actual.headers, ...(actual.headers["content-length"] === undefined ? {} : { "content-length": String(Buffer.byteLength(bodyText)) }) }, bodyText, bodyOctets: Buffer.byteLength(bodyText) };`

**2. Severity: low‑medium — oracle logic embedded in the transport path degrades failure shape.**
`apps/bdptest/src/read-update-matrix.test.ts:1025‑1067` (`validateCold`, `expect(body).toEqual(coldDirectory)`, the alias‑404 `retry` expects, and the unguarded `JSON.parse(actual.bodyText)`).
Issue: these are oracle assertions executed inside the executor wrapper. A genuine server deviation (bad directory member, missing `retry`, non‑JSON error page) rejects the executor, so the runner records a synthesized transport/execution error on that action instead of the scenario's own named assertion. The `expect(body).toEqual(coldDirectory)` is additionally redundant: `readUpdateOperationDirectory` already pins all nine values with `const` + `required` + `additionalProperties:false`, so the `directory.schema` assertion covers it.
Impact: diagnostic quality only; no claim is weakened, but a real defect reports as a transport category rather than `directory:schema` or `read-deleted-alias:*`.
Smallest correction: keep the pre‑mutation `validateCold` call inline (it is load‑bearing for the counterfactual's "genuine 200 first" honesty), and move the alias `retry`/`code` checks and the equality to `assertColdDirectory` by recording the observed values into `coldRaw[i].body` (already retained) instead of asserting in the wrapper.

**3. Severity: low — `report.coldDirectory` is emitted on every run, including runs where the scenario never executed.**
`apps/bdptest/src/read-update-matrix.test.ts:1591‑1602`.
Issue: the block is unconditional with `checksPassed: false`, empty ledgers, `aliasRetryPassed: false`. Every unrelated report (all other installed tests, both shards) now carries a cold‑directory block that reads as an unverified/failed check.
Impact: report honesty and shape; also any existing whole‑report shape pin elsewhere in the suite now needs updating.
Smallest correction: conditional spread — `...(coldAttempts.length ? { coldDirectory: { … } } : {})` — and keep the existing `if (coldAttempts.length)` guard around the `checksPassed = true` mutation.

**4. Severity: low — the saved report counts control applications but never names the applied control.**
`apps/bdptest/src/read-update-matrix.test.ts:1681‑1710` (`controlApplications` in the written object).
Issue: the file records `controlApplications: 1` but not *which* assertion input was mutated; the mutated directory body also reaches the file through `result` as an apparently observed response. The contract document names the mutation, the artifact does not.
Impact: a reader of a retained failure report cannot tell from the artifact alone that `updateLink` was deleted from assertion input.
Smallest correction: add `...(directoryControl === undefined ? {} : { control: directoryControl })` to `report.coldDirectory`.

**5. Severity: low — `mode: 0o600` does not constrain an existing path, and the "distinct path per invocation" contract is unenforced.**
`apps/bdptest/src/read-update-matrix.test.ts:1681‑1710` (`writeFileSync(filename, safe, { mode: 0o600 })`).
Issue: `mode` applies at creation only; an existing file keeps its prior permissions and is silently overwritten. The writer is intentionally called 2–3 times per run, so a blanket `wx` flag is not available.
Impact: a caller‑supplied path that already exists (reuse, or a pre‑created world‑readable file) receives the report at the pre‑existing mode.
Smallest correction: track a local `let coldReportWritten = false;` in `run`, pass `{ mode: 0o600, flag: coldReportWritten ? "w" : "wx" }`, and set the flag after a successful write.

**6. Severity: low — `claimEligible` is written as a literal rather than projected.**
`apps/bdptest/src/read-update-matrix.test.ts:1681‑1710` (`claimEligible: false`).
Issue: the file always claims ineligibility regardless of `report.claimEligible`. Both new tests assert the report value separately, but the aggregate path also writes this file without that pairing inside the writer.
Impact: a future divergence between runner state and the retained artifact would not be detected at the write site. (Direction is safe — it can never over‑claim.)
Smallest correction: `claimEligible: report.claimEligible,` plus `if (report.claimEligible !== false) throw Error("cold directory report must not claim eligibility");` before the size/secret gate.

## Supplied‑context gaps (cannot be resolved from what was provided)

**7. Severity: high (blocking verification) — the two `exactConfigurationDigest` replacements are unexplained and unexercised.**
`apps/bdptest/src/read-update-matrix.test.ts:2053` and `:2486` (`3224c31c… → 26da5a28…`).

The omitted‑context boundary states exactMode is built "from fixed artifactRoutes with explicit operator/anonymous/unknown handles, requestTimeout5000" — if that list is a fixed literal and unchanged, this digest should not have moved. **8. Severity: high (blocking execution) — client GET to the operation directory requires an installed exact route.**
`apps/bdptest/test-support/read-update-exact-client.ts:70‑100` against scenario action `directory-captures`.
Issue: for `method === "GET"`, the helper admits the request only if `mode.routes` contains it, or if the resolved path matches `^beads/[^/]+$`. `operations/` cannot take the fallback (and the follow‑on canonical‑bead check also throws), so `GET https://reference.invalid/acme/operations/` must already be in `artifactRoutes` — as must POST `operations/sequence` and the GETs for `types/task`, `types/relates`, `alias/w1-locator`, `links/w1-l`, `beads/w1-a`, `beads/w1-b`. `artifactRoutes` is neither in the diff nor in the supplied excerpts.
Impact: if any is absent, the scenario cannot run at all (helper throw for the client GET, exact‑mode rejection for raw GETs). Resolves together with finding 7. Smallest correction: none if present; otherwise this becomes a route‑table change, which the stated scope forbids — so it must be confirmed, not assumed.

**9. Severity: medium — fixture bindings and URL literals are assumed, not pinned.**
Scenario actions `put-alias-get`/`deleted-link`/`deleted-bead`/`final-b` (bindings `w1.alias`, `w1.l`, `w1.a`, `w1.b`), the `types` + `path` joins, and every URL literal in `coldDirectoryRequests` (`:152‑719`).
Issue: nothing CPU‑verifiable ties `w1.alias → ${scope}alias/w1-locator` or the discovery `operations`/`types` links to the trailing‑slash forms the URL table and the two in‑wrapper hooks (`sent.url === \`${scope}operations/\``, `\`${scope}alias/w1-locator\``) assume. Fixtures are out of scope and were not supplied.
Impact: a trailing‑slash or binding‑name mismatch makes the hooks silently not fire. This is fail‑closed — `expect(coldControlApplications).toBe(directoryControl ? 1 : 0)` and `expect(coldAliasRetryPassed).toBe(!directoryControl)` convert silence into failure — so the risk is a failing pending run, not a false pass. Smallest correction: none required; if cheap pinning is wanted, assert the four fixture binding values in the CPU pin test from the loaded fixture.

**10. Severity: medium — request‑level idempotency keys are unverified, and `sequence` declares none.**
Scenario action `sequence` (`input` has no `idempotencyKey`; the member body carries `"directory-sequence-b"`), versus every other mutation action which declares one; oracle `:152‑719`; pin test `:1791‑1893`.
Issue: the client helper only emits the `idempotency-key` header when `input.idempotencyKey` is present, the helper's observation output omits the key entirely, and neither the pin test nor `assertColdDirectory` checks it. Whether the installed reference requires a request‑level key for a sequence POST is not determinable from the supplied excerpts.
Impact: if a header is required, the pending positive run fails at the last mutation; either way the change adds ten mutations whose idempotency‑key provenance no local check covers.
Smallest correction: add `expect(action.input.idempotencyKey).toBe(<expected>)` per client action to the CPU pin test (cheap, offline), and resolve the `sequence` question explicitly — do not add a key on speculation.

**11. Severity: low — strict full‑Resource and postimage equalities depend on unseen response projections.**
Oracle `resource()` and `expect(raw.at(-1)?.body).toEqual(final)` (`:152‑719`); scenario `final-b.postimage`.

Impact: plausible failure mode for the unrun positive test; no correctness claim is overstated. Smallest correction: none if precedent exists; otherwise `final-b` would need the explicit view the client helper already models (`query.view`), which raw http actions cannot express — so confirm precedent first.

**12. Severity: low — secret scanning and report shape rest on omitted structures.**

If exact‑mode `request.headers` or `configuration` ever carried the operator token, the writer would throw on every invocation rather than leak — correct direction, but it would make the feature unusable and surface as a cleanup error.
Impact: no leak path identified; usability/robustness unknown. Smallest correction: none; optionally scan for the configured credential header values generically instead of two literals.

**13. Severity: low — the control path returns before the remainder of the executor wrapper.**
`:1025‑1067` (early `return` inside the `cold` block, ahead of `if (admissionHit)` and everything after it).

**14. Severity: low — `currentScenario` is never cleared, so the attempt caps stay armed after the scenario body returns.**

## Optional suggestions

**20.** `:1791‑1893` — the pin test asserts the nine capture *bindings* equal `Object.values(coldDirectory)` but never their *pointers*. A cross‑wired capture (binding `create-bead` from `/body/deleteBead`) passes all seven CPU callbacks and fails only in the pending live run. The nine pairings in the supplied scenario are correct, so this is a guard gap, not a defect. Add `expect(row.actions[3].captures.map(c => [c.binding, c.from.pointer])).toEqual(Object.entries(coldDirectory).map(([k, v]) => [v, \`/body/${k}\`]))`.

**21.** `packages/conformance/src/read-update-artifact-set.test.ts:155‑185` — `coldDirectorySpan` starts at `text.indexOf(JSON.stringify(key))`, which is unanchored; a future `"scenarios"`/`"rows"` substring in an earlier string value shifts the scan start, and the failure mode is a wrong hash rather than a clear error. Anchor on `'"scenarios": ['` / `'"rows": ['`, or derive the offset from the parsed index.

**22.** All four coverage byte fences now sit exactly at 718307 B with zero slack, and three of them are different views of the same file length. This is deliberate per the existing comments, but the next coverage row must edit four numbers in two files. If that is unwanted, consolidate to one exact pin plus three untouched historical bases.

**23.** `:1767‑1790` — the controlled test calls `run` with sixteen positional arguments and eleven `undefined` placeholders, and `assertColdDirectory` shadows its outer `expected` request table with a per‑request `expected` inside the loop. Both are readability hazards only; a trailing options object for *new* controls would not touch the shared helper API that the non‑goals protect.
