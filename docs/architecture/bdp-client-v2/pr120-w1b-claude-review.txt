## Findings

**No actionable findings.** I could not substantiate a correctness, secrecy, scope, or failure-hiding defect in this diff.

What I checked, and why each cleared:

1. **Cannot throw and pre-empt the real assertion.** This was the main hiding risk, since the diagnostic is computed eagerly before expectation 1. `run()` has a single return shape (932–970) in which `result`, `observations`, and `cleanupComplete` are always present, so the helper's top-level accesses are safe. The two unguarded `.assertions.filter(...)` walks inside the helper (2231, 2238) are safe because `ObservedExchange.assertions` and `ObservedAction.assertions` are required in `packages/conformance/src/runner.ts:186,198` and are initialized to `[]` before `push` (1028, 1179). `row.exchanges`/`row.actions` are optional-chained; the nullish observation shapes are covered by the secrecy unit (2376–2395). `JSON.stringify` operates on a flat primitive projection — no cycles, no BigInt.

2. **Does not suppress the failure.** chai 6.2.2 composes the message as `flagMsg + ": " + msg` (`chai/index.js:961`) — the custom string is a *prefix*; the standard message and `err.actual`/`err.expected` (hence Vitest's diff) survive. Vitest 4.1.10 has no `outputTruncateLength` option at all (absent from the whole package), and the two `truncateString` call sites are terminal-column/code-frame formatting, not error messages. So the diagnostic reaches CI logs intact and `expected 0 to be 1` is still printed.

3. **Diagnostic projection is secrecy-safe.** The helper emits only ids, statuses, failed-assertion ids, error *categories* and `writeState` — never bodies, headers, error messages, or child output. `token` and `wrongToken` (lines 65–66) are the only credential values in the fixture (sole injection point is line 231), and both are `replaceAll`-redacted. Runner-side exchange URLs are already `redactUrl`'d upstream; the only unredacted-source field is `lastObservedRoute.url` from the raw exact client, which is exactly what the redaction targets, and the secrecy unit asserts it adversarially with `${scope}${token}/${wrongToken}` plus a blanket `not.toContain` over all three secrets.

4. **Types and gates.** `Pick<RetryControl,"scenario"|"action">` is `{scenario: string; action: string}`; the `as const` tuple literals for `id`/`actionId` are assignable. The function declaration at 2213 is hoisted, so the 1642 call site is fine. Max changed-line width is 91 (unchanged line 1648 is 99) against biome `lineWidth: 100`, trailing comma matches the committed style — no `format:check` risk. The identical 2-arg `expect` form is already committed at 2415/2417/2423, so lint and typecheck precedent exists in the tree CI already runs.

5. **Actionability against counter-0.** The W1b gate (871–876) keys on `w1bInput.method`, `idempotencyKey`, and `targetBinding`. On a repeat `counterfactualApplications === 0`, the diagnostic now discriminates the main branches: `category` (`deadline`/`aborted`/`not-run`/`observation-limit`) separates a CI-only timing truncation from a logic mismatch; `actions[].id` + `executionCategory` show whether the target action ran at all or errored first; `exchanges[]` gives the HTTP sequence with statuses and transport/harness fault categories; `observedScenarios` catches selection drift; `observedClientExchanges` + `lastObservedRoute`/`Status` confirm the exact client was engaged. That is a real improvement over the previous bare `expected 0 to be 1`.
