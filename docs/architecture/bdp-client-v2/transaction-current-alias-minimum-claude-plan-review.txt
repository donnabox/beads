# Actual issues

### 1. [Medium] The file-3 gate edit is under-specified: the alias permit must short-circuit *before* `requestFromUrl`, not merely drop one disjunct
**Plan:** §35 item 3, §13. **Source:** `packages/server/src/transaction-http.ts:521-536`; `packages/server/src/read-request.ts:142-255`.

`requestFromUrl` has no `alias` arm — every `alias/…` path falls through to the terminal `return notFound()`, a 404 `ReadProblem`. So the gate rejects aliases through **two** disjuncts: `alias !== undefined` *and* `isReadProblem(parsed)`. "Permit a classified well-formed alias through the minimum route gate" read as an edit to the condition at `:529-534` still yields `500 minimum-position-route`, and the plan's declared "three narrow forwarding/gate edits" would be complete while rows 3–17 all fail.

**Impact:** an implementation faithful to the plan's literal text produces a non-functional slice; also leaves `problem(parsed)` at `:527` nominally on the alias path.

**Repair:** state explicitly that the alias case must be taken before the `requestFromUrl` call — e.g. `if (alias === undefined) { …existing parse + Resource predicate… }` wrapping lines 526-535 — so that no alias URL is parsed as a canonical ReadRequest and `:527` is unreachable for aliases.

### 2. [Medium] Structural collision with the Type/incident plan on the same gate expression; landing order must be pinned
**Plan:** §7, §35 ("including any independently accepted Type/incident extension"). **Source:** `transaction-http.ts:531-534`; `transaction-current-type-incident-minimum-plan.md` §23, §29, items 1–2.

That plan *replaces* the duplicated admission expression with a single shared `isCurrentTransactionMinimumRead(request)` predicate used by both `minimumFor.perform` and the HTTP gate. If the alias permit is woven into the existing disjunct and the Type/incident edit lands second, a wholesale predicate substitution silently deletes it.

**Impact:** regression risk invisible at review time of the second plan.

**Repair:** add one sentence requiring the alias branch to be structurally outside the Resource predicate (per finding 1), so either landing order is safe; and name the preferred order (Type/incident first) in §7.

### 3. [Medium] The plan records the missing+incompatible behavior but not its observable consequence — rows 10 and 14 make alias existence distinguishable at an unsatisfiable bound
**Plan:** §27, §55, rows 10 and 14. **Source:** `transaction-read.ts:63-80`; `transaction-http.ts:561-574`, `585-586`; `bdp.md:254-269`, `1422-1440`.

Both rows are well-formed alias reads with a recognized future bound (pos-2). Live alias → wait → `503 catch-up-timeout` **with** current context and `Retry-After: 1`. Unknown alias → `TransactionMinimumVisibilityGap` → immediate bodyless `500 minimum-position-visibility` with **no** context and **no** wait. The two rows therefore differ only in whether the alias exists, in a surface whose cited spec text says unknown aliases return the same 404 "under the same authorization projection: aliases are not an enumeration oracle." This is pre-existing in kind for Resources at 7791 and is harmless *only* because this owner is fixed all-visible (`canRead:()=>true`, `transaction-read.ts:88`) — but the plan newly commits it to installed evidence on the alias surface.

**Impact:** the 18-row ledger could later be read as conformance evidence about alias absence disclosure.

**Repair:** one recording sentence in §27/§55: the 503-vs-500 distinguishability and its context/no-context difference are acknowledged artifacts of the still-unqualified missing+incompatible collision, sound only under the current all-visible policy, and not conformance evidence. No ruling requested or implied — the boundary stays unqualified.

### 4. [Medium] Row 9 collides with the host file's `context()` helper, which asserts no ETag

### 5. [Medium] Rows 11–12 claim an "exact context/body projection" for a HEAD refusal, which cannot carry a body

### 6. [Low-Medium] §27 pairs "existence/visibility" but only the existence half is observable in this slice
