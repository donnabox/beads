## Ordering and smallest scope

The three proposed production seams are sufficient. Existing lexical capture/current eligibility checking and finite waiter already support unproved matched-context observations; no consistency-module redesign is needed. HTTP must retain its pure candidate and single terminal preflight for HEAD/304/412/406. Its current `instant()` call occurs before semantic comparison; the recommendation should not be implemented as an unrelated clock reorder.

Snapshot service currently captures the supplied tuple synchronously, then reads/checks kind, then enters `run()` and waiter policy/clock/abort processing. The recommendation explicitly preserves this instead of copying Event first-attempt capture. Deterministic mutation/capture, pre-abort, pending-wait cancellation and close/drain tests are the appropriate discriminators; an opaque identity must remain unproved after an unrelated successful write.

At most seven existing files is a credible cap: three production files and four existing test files with their own fixtures. Reuse offline Snapshot table checks for allocation/expiry preservation and the existing current/known/foreign/retained regressions. No extra storage, launcher, protocol or broad test-suite dependency is required by the demonstrated gap.

Preserve the intended excluded-path behavior and synchronous order with bounded controls; do not accidentally admit retained minima or silently claim every old error remains identical.
