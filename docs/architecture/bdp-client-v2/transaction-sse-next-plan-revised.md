## Recommendation and sequence

Implement **G2a: actual changefeed SSE replay/live delivery over the existing one-group reader**, after root serializes the service/HTTP/runtime overlap with Snapshot HTTP. This is the smallest useful live transport slice: it needs no second log, generic subscription framework or new durable cursor format. Then implement **G2b: Scope and Resource Event SSE** using the same bounded transport, with an owner-backed sparse-source progress seam if needed. Full erasure publication fencing and mutable-view/replay-retention support are mandatory later gaps; G2a is not full SSE or Transactional qualification.

Required HTTP set operations remain important, but are not a prerequisite for observing already supported writes over SSE. The private valid set core is implemented; its normal HTTP admission is closed. The sole design checkpoint still lists Selector complexity admission as unresolved, and batch admission text (spec 4493–4527) does not by itself classify every grammar/complexity failure. Do not use this SSE slice to decide that issue. A root-approved set error mapping could make sets a parallel or earlier slice in a separate owner lane, but SSE's settled replay/framing portion can advance independently. Physical service/runtime authoring is **not** independent of active Snapshot HTTP; only this plan and pure framing tests are independent until root assigns an integrated base and exclusive files.

## G2a design

### Admission and representation selection

1. Preserve raw-target/Host/method handling, canonical query structure and authentication/nondisclosure. Pure media selection may run early, but cannot prematurely disclose406 or bypass route/auth/context decisions. Missing Accept, wildcard tie or equal quality prefers existing JSON; higher-quality acceptable SSE selects SSE. Merely mentioning `text/event-stream` is not selection. If JSON wins, ignore Last-Event-ID entirely, including malformed/repeated/stale values, exactly as the finite route does now.
2. Exactly one URL starting intent remains required. Header without `after`/`start` stays local-reference400 `invalid-parameter`; never relax the existing parser into a silent fallback. For selected SSE with explicit `after`, choose a supplied Last-Event-ID as effective exclusive cursor, retaining raw duplicate/header syntax information before Fetch Headers joins fields. Preserve query duplicate/key/syntax checks separately; an overridden old query token is not looked up against current epoch/view. Effective token parsing and epoch/view binding use the existing first `service.changes`/owner entry; no preliminary owner-context lookup or new exported checkpoint parser. A syntactically valid `genesis` header with an explicit `after` is a supported initial checkpoint, not automatically invalid because it is never assigned to a later group. `start=now` plus Last-Event-ID remains explicitly deferred; clear initial start=now without header remains supported.
3. Reuse `service.changes` to capture first page, starting anchor and current context in that owner observation. A `start=now` admission retains `page.after` even when minimum waiting lets more commits happen; do not recapture now on every poll. Existing minimum/control failures retain their ordering/context and explicit private gaps. No inspect call supplies later headers. Pure selected-representation calculation is distinct from issuing negotiation/conditional outcomes: checks happen first, then bodyless406 if neither media type is acceptable, then existing conditional algorithm for an acceptable representation.
4. For acceptable SSE set `Content-Type: text/event-stream`, exactly `Cache-Control: no-store, no-transform`, `Vary: Accept`, `x-bdp-development: non-attesting`, and `BDP-Scope-Epoch`, `BDP-Authorization-View`, `BDP-Scope-Position` from the first observation. No finite Content-Length, ETag or Last-Modified. HEAD gets the corresponding decision/context and ends without frames, polling or live-slot reservation. Conditional304/412 are bodyless, carry required current context, and never advance a checkpoint. No fictitious stream validator. Existing JSON200/204 semantics stay unchanged.
5. Return a source-private discriminated transport result: finite response or stream admission holding first immutable page/current context and controlled read capability. Do not widen public HttpResponse to arbitrary callbacks. Both admission headers and streaming delivery preserve the non-attesting marker. Do not reserve a slot for HEAD/304/412. A pre-aborted request or disconnect between first observation and registration must release any transient registration synchronously/through guaranteed cleanup; no timer/promise/slot leak. If additive private helper extraction cannot be coordinated, stop the overlapping edit and continue pure framing tests rather than clone policy.

### One owner, one frame at a time

- First page is held from admission; each next pull is `service.changes({after:lastPublishedCheckpoint})`. This reads existing durable groups, not a second Event queue. Never keep SQLite open across an await, socket write, sleep or application callback.
- Emit exactly `id: <checkpoint>\nevent: change-group\ndata: <complete admitted group JSON>\n\n`. Reuse finite `stringifyJsonValue` so group encoding matches the finite page component and existing delivery serializer, with a checked immutable snapshot and Unicode/accessor safety. It is not canonical identity serialization and does not preserve original number spelling: scalars use JSON.stringify formatting, after admission has established supported numeric-value fidelity. An admitted `1.0e2` need not survive lexically; test value100 and finite/SSE encoding equality instead. JSON escaping keeps embedded LF/CR inside data strings from becoming SSE fields. Check codec token safety rather than sanitizing IDs.
- At current head, wait using cancellable bounded polling outside the owner. Propose private100ms polling and optional comment heartbeat every5s, with actual continuous-idle behavior gated by the pinned-Node deadline observation below. One cancellable pump owns every write, including comments: while awaiting drain, do not poll/materialize another group or enqueue heartbeat writes; coalesce/suppress elapsed ticks. A comment has no ID and cannot move the checkpoint. No accumulating intervals or duplicate drain listeners. No per-client retained history pin, notification bus, or promise that heartbeat is protocol-mandatory.
- A whole frame is passed to Node's transport as one write. `write(false)` means bytes were accepted into the transport buffer, not unapplied: record authority publication at the write boundary, then await drain/error/close **before pulling/materializing another group**. This does not imply client delivery or durable application. On half-frame disconnect the client's staging oracle discards the incomplete message and keeps its prior checkpoint.
- Bound simultaneous stream admissions initially to one in this private fixture; HEAD consumes no live slot. An exhausted live slot is actual temporary service unavailability (existing503), not a new named protocol limit. This conservative private cap is an implementation setting, not public specification. Tests may use a narrow lower timing seam with attestation suppressed; installed evidence uses actual defaults. Re-evaluate the cap only with materialization measurements.
- On disconnect/error/service close, cancel polling/drain waits and release the separate stream registration. Observe outgoing response `close` (including destroy), not FIN alone. Handle pre-aborted admission and close-before-registration as normal cancellation. Close rejects new stream registration before cancelling the bounded registry, then drains current finite work and cancelled pumps; do not snapshot active work before closing admissions. Service close cancels stream observations before awaiting active work; it continues to drain accepted mutation transactions. Preserve original and cleanup failures. Do not await service.close from a stream task that service.close is itself waiting on.
- An error before headers uses existing finite status/problem/bodylessness. An owner fault or gap after stream headers destroys/closes the stream, with an explicit `headersSent` guard preventing the runtime finite500 fallback or second headers; no invented BDP `error` SSE event, fake projection advance or silent cursor skip. Retain diagnostics privately; normal client/service shutdown cancellation is not an owner fault. Test fault after a complete group and while backpressured. Neither branch manufactures a BDP error frame.

## Real ambiguities and existing conventions

1. **Last-Event-ID with original start=now:** the changefeed contract explicitly overrides original `after`; it does not expressly resolve overriding the alternative initial `start=now` intent. Keep this combination deferred in the private lane and do not claim full reconnect support. Initial start=now without header and explicit after+header need no new ruling. Header without query intent is not deferred: it remains400 because omitting both query intents is an error. The rationale is the existing spec wording, not an unobserved native-browser EventSource behavior.
2. **Malformed/repeated/empty Last-Event-ID:** token profile prohibits empty/whitespace values as tokens, and current finite codecs map invalid tokens to local-reference400 invalid-parameter. Proposed reuse is a documented reference convention; no claim that every malformed HTTP header has a new normative BDP error. Duplicate field handling must happen from raw header inventory before Headers joins values, only for selected SSE. `genesis` is reserved as the distinguished initial checkpoint and remains permitted with explicit after+header; apply future replay-floor restrictions to effective position0 as well as positive positions. Reject the review's proposed blanket genesis-header ban; do not add an erasure claim. Keep query-key/duplicate syntax checks separate from effective cursor lookup.
3. The spec does not prescribe heartbeat/poll interval/live slot counts, SSE max lifetime, or choice among equally acceptable representations. Those are bounded implementation choices above, not product questions. Do not impose a fixed lifetime merely to turn a streaming test into a finite success.
4. **Mandatory erasure fence:** not ambiguous, simply unimplemented by this owner (stored `erasures:[]`, no erasure publication/rotation API). A future writer must atomically serialize publication eligibility with erasure floor advance; a loop that holds an old materialized frame and writes it later is not that mechanism. Restrict G2a's claim to the current configuration. Preserve each poll's internal observed head/context for future eligibility checks, but do not add an SSE observedHeadPosition field/event or new wire ambiguity: caught-up eligibility is an authority-side fence, while finite-read catch-up metadata serves the client. Reject reviewF12's proposed new wire requirement/question. Before erasure is enabled, integrate an owner publication gate and tests for caught-up/behind/backpressured streams and view-specific floors; do not claim finite polling automatically supplies it.
