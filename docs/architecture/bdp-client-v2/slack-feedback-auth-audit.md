## Important durable-log and live-stream constraints

A view setter alone is unsafe. `transaction-events.ts:190–205` requires retained group.authorizationView === current context.authorizationView; `transaction-changefeed.ts:119–160` passes through that validation and returns the stored view/changes. A changed token would otherwise turn a fresh current-view historical scan into an integrity failure, or a careless equality deletion would disclose old all-visible facts. Keep persisted authority facts and their integrity validation distinct from the current serving projection. Never rewrite old groups/receipts or weaken stored epoch/position/ordinal checks merely to make a new token pass.

For the proposed empty projection only, validate retained authority facts under their original retained context, then emit **no Resource Events** and only the normative identifier-free projection-advance group when a current-view Changes request crosses an existing transaction. A fresh Snapshot/current collection is empty and Resource lookup is uniform404. Old tokens fail before scanning/rendering. This avoids general dynamic historical reprojection: old-view cursors reset; the new empty view has an unambiguous empty historical projection. A later partial-view implementation still needs original pre/post visibility facts and owned closure; this proposal does not claim those exist sufficiently today.

`transaction-store.ts:1680–1696` already compares each Event scan's captured epoch/view to current context. Changes polling re-enters readChanges and parses its checkpoint against current context. `transaction-runtime.ts:198–246` obtains subsequent packets through the service and destroys a failed stream. However `transaction-sse.ts:105–137` can hold an already-materialized packet and deliver its frames before the next owner pull. Therefore a safe transition must invalidate/abort registered old-view delivery leases at the serialized transition boundary, not merely wait for a later poll. Add a delivery fence before each next frame/owner pull. Bytes already written to Node/socket or delivered to the client cannot be recalled. The acceptance oracle is no *newly admitted* old-view frame after the transition boundary; do not claim instantaneous network erasure or use elapsed silence alone as proof.

Snapshot validation currently treats persisted d.view != context.view as integrity failure (`transaction-snapshot.ts:205–208`). An expected authorized view transition must be classified as a view fence before that corruption path; real corrupted records retain corruption handling. Ordinary collection continuation authorization must be captured freshly per request, not from transaction-read's currently immutable initial configuration. Receipt current disclosure must withhold record-bearing entries while preserving the original receipt identity/disposition/positions; hiding all data cannot leave its all-visible postimages available through replay.

## One concrete proposed implementation slice

Add a private trusted owner administration operation for the two supported policy states all-visible and empty. No raw request field, bearer value, callback supplied by a client, arbitrary policy language, remote endpoint or new public export is proposed. It executes under the existing guarded owner entry, atomically commits the new policy generation and stable opaque view identity, and publishes cancellation of old-view delivery leases. Same-state replacement is a no-op. Reopen must preserve the same new view; changing policy must not rewrite Scope epoch, Resource revisions, transactions, receipt disposition or invent a Scope transaction position. Rollback/failure must not publish the replacement view. A monotonic all→empty first slice avoids silently promising regrant or partial ACL support.

Owner reads capture one immutable current policy/context pair. Empty projection is closed over every Bead/Link automatically. Apply it consistently to current reads, new Snapshot materialization, finite Events/Changes and receipt delivery; mutation evaluation cannot continue to use unconditional canRead/canWrite when all subjects are hidden. Old issued collection/Snapshot/Event/Changes handles are rejected through their existing view-fence semantics, preserving actual expiry/nondisclosure distinctions. Scope-level authentication remains real and unchanged: the authorized caller can receive an empty projection, while unauthenticated requests remain401.

Likely production ownership: transaction-store (durable policy/context, receipt and snapshot entry points), transaction-read (fresh authorization capture), transaction-events/changefeed (retained fact validation versus empty projection), transaction-snapshot (expected view mismatch), service/runtime/SSE (lease capture and transition cancellation). Runtime-configuration metadata must describe actual policy rather than insist all-visible; do not add a credential/config grammar solely for this first in-process transition. Shared authority-read already has captured authorization/policy seams; reuse rather than rewrite it. Exact ownership must be frozen after a short caller/type fanout inventory. This is larger than a token-only patch because leaving any old-data exit open is unsafe. Existing installed launcher need not gain an administrative IPC command in the first slice.
