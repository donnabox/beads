## Assessment

- Scope and normative basis are sound. Spec 5794–5800 and 5841–5843 permit explicit bounded failure for ordinary reads whose requested eligibility cannot be established. The narrower Resource mandate at 5844–5849 is not asserted as a universal collection requirement. The proposed local choice for initial Bead/Link collections is compatible with those rules. Exclusions correctly preserve unresolved retained/Snapshot and foreign-context policy, successful incident lists, Types and public discovery. No S1/G2 decision is implied.
- A distinct descriptor-only initial-collection classification is the correct narrow seam. transaction-read.ts:86–99 and transaction-http.ts:578–590 currently classify/block these otherwise supported current routes. Both consumers must use the same kind, with canonical route validation retained. The plan explicitly catches the resource-not-found trap at transaction-read.ts:207–208: replacing strict with another kind must not turn collection refusals into the missing-Resource shortcut. Restricting that shortcut to resource/missing preserves original behavior.
- Receiving and control precedence are accounted for. HTTP authentication and malformed minimum tuple handling remain before the owner path (transaction-http.ts:405 onward; spec 5819–5839). authority-read.ts:746–767 materializes selector/limit refusals before the minimum condition. transaction-read.ts:201–226 preserves those invalid-parameter/limit-exceeded refusals. The plan correctly does not promise a new precedence for parser-invalid URLs or other later failures. Condition evaluation precedes successful HTTP semantics, so a timeout must not become 304/412; the specified conditional controls test this directly.
- Reusing the existing wait is sufficient at plan level. transaction-service.ts:382–417 captures request/delivery inputs and forwards the request signal. transaction-consistency.ts:138–180 creates one finite deadline outside its retry loop, accepts only unproved/behind retries, and checks cancellation between attempts. Each authority observation completes its owner entry before awaiting. service close drains admitted active reads before closing the authority and database (transaction-service.ts:680–698); no promise of immediate abort on service close should be added.
- The nonallocation claim has a concrete implementation basis: authority-read.ts:982–1017 applies the source condition before finish, and first-page continuation allocation is in finish at 852–900. Failed unknown-minimum attempts therefore exit before retention. The planned small-capacity/token-generation checks and an owner operation between attempts are appropriate evidence, alongside pre-abort, in-flight cancellation and close/drain cases.
- Verification scope is appropriate for this change. Both collections and both methods, literal 503/retry/context/bodylessness, conditional barriers, materialized control precedence, no-minimum/recognized-position preservation, named exclusions and the split historical negative table cover the changed behavior. Source-controlled clock evidence is correctly separated from a fresh installed stable-store run using real credentials, actual context and the existing default one-second bound. Exact callbacks, request/child budgets and final author-base binding are intentionally pending author preparation, and must remain prerequisites to execution release as the plan states.
