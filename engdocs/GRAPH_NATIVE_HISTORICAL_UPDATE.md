# Proposed native Issue historical Update crosswalk

Implementation subject: the existing graph `UpdateIssueRequest` and `issueops.ExecuteUpdate` setter path, based on published Type and endpoint work plus the Memory historical-update stack. This is a bounded native adapter engineering proposal for review. It does not change shipping `bd restore`, native lifecycle semantics, public BDP profiles, or fields admitted by ordinary graph Update.

The historical source must be an exact retained live native Issue of the same graph subject. The actual current graph revision is checked independently before source acquisition. Native recovery obtains a distinct current D and separately validates the retained last-current baseline. Memory recovery is implemented separately; authored and qualified states remain distinct from integration.

| Source native member | Historical composition | Explicit edit / ordinary authority |
|---|---|---|
| `title`, `description`, `design`, `acceptance_criteria` | Copy the historical editable value, including ordinary empty values | Existing string setters and native validators |
| `priority` | Copy the historical value, including P0 | Existing native priority validator |
| `estimated_minutes` | Copy the exact nullable value | Existing set/clear representation and native/storage bounds |
| `assignee` | Copy historical value, including unassignment | Existing active-assignment transfer fence; a graph revision guard grants no override |
| `notes` | Historical value supplies the notes base | Existing overwrite fence remains; append applies after that source base through native composition, preserving ordinary append intent when the source base equals current notes |
| `external_ref`, `spec_id`, `due_at` | Copy the exact supported nullable/scalar values | Existing column, null/empty and whole-second representation rules |
| top-level common `metadata` | Start with source metadata, then apply explicit common-metadata edits | Existing canonical I-JSON admission and metadata writer |
| `status`, `issue_type`, `owner`, scheduling/gate/molecule/message/event members outside the graph Update setter list | No automatic copying. A changed non-admitted editable member refuses historical mode with an explicit native-domain-mapping diagnostic | Separate ordinary native domain operations keep authority; no generic snapshot overwrite |
| Labels, parent, Dependencies, ID, graph Type, definition/endpoints and owned Links | Retain actual current identity/structure | Historical mode does not retype or recreate Links |
| native creation facts (`created_at`, `created_by`, `source_system`, `source_formula`, `source_location`, `storage_class`) | Retain current initialization facts | No reinitialization from the older content source |
| native operation/derived facts (`updated_at`, started/closed context, node-local lease liveness, readiness and compaction observations) | Remain under the ordinary current native writer/provider | Never copied blindly from retained content; native write actor/time describe the new operation |
| future/unclassified serialized native member | Refuse when source and current differ | Extend the reviewed adapter table before claiming faithful support |

Ordered native property changes evaluate the existing closed add/replace/remove operations against the selected historical editable setter projection inside the same transaction. Replacement retains the ordinary required title/priority rule and clears omitted optional setter fields. No lifecycle or structural member is added to that projection.

Effectful live updates mint one ordinary native retained revision and one graph mapping. Live equality returns the entire existing record without a revision, event or provenance-only write. Source admission, guards, ordinary domain validation and acquisition bounds still run for a no-op.

Proposed persistence: nullable `revision_context` on `graph_preview_issue_versions`, storing only optional Inception and historical source/predecessor context. Actor/status/time remain authoritative in the native `issue_versions` row; they are not duplicated in the context column or the native Issue payload. Ordinary minting preserves current Inception presence/value and drops the previous operation's historical context; no-op preserves the existing context. Exact/current readers merge the validated optional context with native actor/time. This stacks on endpoint PR133's fresh-only schema8 without a second bump, migration, or change to Type generation.

Required qualification before native integration: exact-source current/historical equality, nullable fields, metadata/ordered edits, append and overwrite/assignment fences, non-admitted-member refusal, stale/foreign/unknown source, context retention and ordinary mint reset, cumulative acquisition budget, rollback, races/replay/unknown responses, installed embedded/server journeys, independent source review and actual hosted CI. The authored live native slice now wires persistent context and the CLI source-only/`--properties`/ordered-property-change/metadata route; deleted native recovery is implemented in its terminal/lifecycle successor. Qualification and review receipts belong to its PR; publication does not itself mean integration or release qualification.


## Native deletion and recovery implementation

The graph terminal uses the existing closed Bead descriptor shape (`id`, `revision`, `version`, `state`, `previousVersion`, `attribution`). It omits Type, properties, metadata and owned structure. `BeadTerminalState` is the shared Go name; `MemoryTerminalState` remains a source-compatible alias. No new public BDP encoding/profile activation is asserted.

`DeleteIssue` still delegates native journal, lease and domain cleanup to `issueops.DeleteIssueInTx`. It now retains graph D in `graph_preview_versions` and moves the existing allocation head to D atomically. The underlying native `issue_versions` table receives no fabricated deletion payload or native deletion ordinal. A nullable private `native_participation_generation` cell on the terminal row captures the actual pre-deletion native admission fact. It is not copied from the selected historical content or exposed in the descriptor.

A nullable `history_ordinal` on native graph mappings permits one graph-local history order shared with D. Existing NULL mappings retain their native ordinal interpretation; ordinary new mappings choose at least their actual native ordinal and after the greatest graph history ordinal. This preserves native gaps, orders recovered versions after D, and leaves underlying native ordinals unchanged. This disposable implementation retains the agreed fresh-only schema8, checks both new column capabilities on open, and introduces no migration or release/default change.

Recovery validates D and its current optional guard before acquiring the historical source. It separately loads the exact last-current native snapshot and current participation evidence; missing/removed/malformed state refuses without fallback. The selected source supplies only the reviewed editable setter projection and common metadata, with explicit edits afterward. Source attribution (including an unknown historical actor) remains separate from the new operation actor/time. Source and protected baseline are charged cumulatively with current inputs before hydration; baseline-as-source is acquired once.

`issueops.RecoverRetainedIssueInTx` is the explicit native materialization seam. It requires absence in both native planes, uses the existing strict insert, validates against current native domain configuration, preserves retained creation facts, mints a fresh opaque native row-lock token, and retains the separately supplied participation generation. It uses `RecordVersionInTx`'s existing update-shaped admission fence; it never uses create-shaped admission to enroll a legacy NULL generation. It verifies the stored durable state round-trips (using ordinary native empty-metadata equivalence) and that the new actor is represented faithfully. It emits the existing native create journal/audit vocabulary for materializing the missing current row, then one native retained version. Graph context separately records Inception `revert`, selected source and actual D predecessor; it allocates no new graph/native ID and changes no shipping restore path.

Native template, notes overwrite and active-assignment protections are checked against the authorized last-current baseline. The new row preserves current native workflow/lifecycle facts; unsupported changed status/classification members still refuse under the published setter crosswalk. Native labels, parent/Dependency/owned membership and node-local lease liveness were removed by deletion and are not reconstructed from either payload. The current Type engine validates the final staged graph; this adds no second Type evaluator or generic native payload validator standing in for nominal native Issue authority.

Ordinary deleted reads and the History current-state descriptor validate D without hydrating the private recovery baseline. Exact old native snapshots do not require unrelated last-current payload hydration. Historical listing preserves metadata/content refusal boundaries; selecting a malformed terminal refuses, and a token naming both terminal and native snapshot states is invalid. Source-only live equality remains an ordinary full-envelope no-op; deleted-to-live equality always creates a fresh revision. Lost commit responses remain outcome unknown and are not replayed automatically.
