### Finding 1 — Derived-state oracle is over-constrained, and may be failing as written

**Severity:** Medium (correctness of the new test itself)
**Location:** `test.go.txt:208` (diff `+73`)

```go
if prepared.Issues[0].ContentHash != "" || prepared.Issues[0].RowVersion != 0 || ...
```

**Impact.** The assertion pins *two* properties at once: (a) the JSON clone discards the caller's `ContentHash`/`RowVersion`, and (b) nothing in `prepareLegacyImport` repopulates them. Only (a) is the stated goal. `prepareLegacyImportWithPrefix` calls `issue.SetDefaults()`, `validateIssueCreateFields(issue)` and `issueops.PrepareIssueForInsert(issue, nil, nil)` (`admission.go.txt:394,407,410`) on the cloned issue before returning. If `PrepareIssueForInsert` computes the content hash (there is a `ComputeContentHash` on `Issue`, `sdk-types.go.txt:243`) or stamps a row token (`sdk-types.go.txt:98`: "create stamps `freshRowLock()`"), this test fails outright on the first run. I cannot resolve which way it goes: `issueops` is not in the packet. The defensive zeroing of both fields in `verifyLegacyIssue` (`admission.go.txt:627-628`) is consistent with either reading.

Separately, even if it passes today, it is brittle in the wrong direction: recomputing a *derived* hash during preparation is a legitimate, behavior-preserving change that would redden an inventory test whose purpose is classification, not hash timing.

**Fix.** Assert non-survival of the sentinels rather than emptiness:

```go
if prepared.Issues[0].ContentHash == "source-cache" || prepared.Issues[0].RowVersion == 23 || ...
```

This is exactly as sensitive to the real hazard (a future change that preserves caller-supplied source-local state through the clone) and is indifferent to whether preparation later recomputes the derived values. If pinning "not repopulated here" is also wanted, keep it as a separate, separately-named assertion so the two failures are distinguishable.

### Finding 2 — Kind switch has no `default` arm; the inventory silently skips shapes it does not understand

**Severity:** Low
**Location:** `test.go.txt:167-190` (diff `+32..+55`)

**Impact.** `Interface`, `Chan`, `Func`, `Uintptr`, `Complex*` fall through to no case and return without a diagnostic. A future `map[string]any` or `any` field would be walked to its static type and then abandoned, so `json:"-"` fields on the dynamic value are never inventoried. The sibling `TestLegacyImportUTF8ShapeCoverage` does have the catch-all (`test.go.txt:137-139`) and would currently fail on such a field, so coverage exists today — but only by coupling this test's completeness to a different test that the task notes is deliberately "separate." Note also that map *keys* are not walked (`:173` only recurses `Elem()`); that one is benign, since a struct key cannot marshal at all.

**Fix.** Add `default: t.Errorf("new input shape needs clone-omission coverage: %s (%s)", path, shape)` so the inventory is self-contained.

### Finding 3 — A prose policy entry can silence the inventory with no refusal behind it

**Severity:** Low–Medium (durability of the oracle, which is this test's whole purpose)
**Location:** `test.go.txt:148-156`, `:198-200` (diff `+13..+21`, `+63..+65`)

**Impact.** The five `"refused ..."` entries assert nothing; the enforcement lives in `admission.go.txt:318-331` and is oracled by `TestLegacyImportLabelSetAndInternalState`, whose own five-name literal map (`existing-refusal-tests.go.txt:86-87`) is independent. So the next author who adds a `json:"-"` field can clear this test by typing `"refused <something>"` into `policies` without touching the admission refusal loop or adding a behavioral oracle — the field is then silently discarded while the inventory claims it is refused. The two field lists can also drift in the other direction: deleting an entry from the admission loop leaves this test green with a stale prose claim (the existing test would catch that specific case, but nothing links them).

**Fix.** Make the "refused" disposition checkable rather than declarative. Cheapest version: derive the refusal list once (a package-level table that `prepareLegacyImportWithPrefix`'s loop iterates and that both tests read), then here assert that every policy value with the `"refused"` disposition names a field present in that table, and that every table entry has a policy. That keeps this test a pure inventory while making the classification non-forgeable.

### Finding 4 — Unexported fields are skipped without classification

**Severity:** Low
**Location:** `test.go.txt:177-179` (diff `+42..+44`)

**Impact.** `field.PkgPath != "" → continue` means a new *unexported* field on `types.Issue` (or a nested input record) is discarded by the clone with no diagnostic. Reachability is limited — an SDK caller outside package `types` cannot set one — but the import path does invoke `types` methods (`SetDefaults`, `commonMetadata`, `PrepareIssueForInsert`), so a package-internal cached field is a plausible future shape. The sibling UTF-8 guard has the same skip (`test.go.txt:127`), so this is a shared blind spot rather than a regression.

**Fix.** Optional, and only if you want it closed here: record unexported fields under a distinct disposition (e.g. `"unexported; discarded by clone"`) rather than `continue`, so they too require a deliberate entry.

### Checked and *not* raising

- **Caller-isolation clause (`:208`, third/fourth operands) is not vacuous.** It is largely dominated by the first two operands, but it does cover a distinct bug class: preparation mutating the caller's record in place (the hazard the `issue.Labels[:0]` reuse at `admission.go.txt:386` creates for `Labels`, oracled at `existing-refusal-tests.go.txt:82`). Keep it.
- **`strings.Split(tag, ",")[0] == "-"`** misreads the legal-but-pathological `json:"-,"` (field genuinely serialized under the key `-`) as omitted. That fails loudly and demands review, which is the right side to err on. No change needed.
- **Path-keyed policies mean a second `[]*types.Issue` field on `Batch` would demand seven fresh entries.** That is correct, not noise: `admission.go.txt`'s refusal loop iterates `input.Issues` only, so a new issue-bearing field really is an unguarded admission surface.
- **Round-trip value drift** (`time.Time` monotonic/location, `omitempty` collapsing non-nil empty slices to nil, `json.RawMessage` whitespace) is outside the stated "json-ignored fields" scope and I did not treat it as a gap. One in-scope-adjacent mechanism this test cannot see is a duplicate `json` tag name, which makes `encoding/json` drop *both* conflicting fields silently; I mention it only because it is the one other way the clone can discard an exported field, and Finding 3's shared-table approach would not catch it either.
