- Impact: if a handle ever returns without a PID, the run fails (good) but the emitted report can simultaneously carry `pid: null`, `closure: "observed-clean-exit-and-close"`, `ownershipUnknown: false` and `directory.disposition: "removed"` — a fail‑open in the evidence model exactly where F5 requires UNKNOWN‑and‑retained. Practically unreachable on the frozen launcher (a failed spawn cannot produce the `qualification.ready` IPC handshake), so this is an evidence‑model defect rather than a live‑path bug.
- Smallest contract‑preserving correction: add one conjunct `owned.pid !== null &&` inside `clean()` (line ~166). It propagates to the reopen gate, stage loop, `ownershipUnknown`, `closure` label and the removal guard with no new field, no new check and no success‑path change.

**F‑B (Low) — workspace `diffSha256` digests a UTF‑8‑decoded string, not the actual diff bytes.**
- Source: `git` helper lines 229‑235 (`encoding: "utf8"`, `timeout: 2000`, `maxBuffer: 1048576`) reused at 258‑260 for `createHash("sha256").update(git(["diff","--binary","HEAD"]))`.
- Contract: `report-contract.json` successRequired "workspace bounded Git with **actual diff SHA**"; F4a constrains only the bounds (2 s / ≤1048576, no 8 MiB), not the encoding.
- Impact: any tracked modified content that is not valid UTF‑8 is transcoded to U+FFFD before hashing, so `diffSha256` is not the digest of the patch bytes and will not correspond to root's byte‑level patch identity (`bdd5eeaa…`). For the current ASCII‑only one‑file delta the two coincide, so this is latent, not currently wrong.
- Smallest correction: hash the diff from a Buffer while keeping the same single command and the same bounds, e.g. `createHash("sha256").update(execFileSync("git", ["diff","--binary","HEAD"], { cwd: root, timeout: 2000, maxBuffer: 1048576 }))`. Same Git command count, no widening, `status --porcelain` and `rev-parse` unchanged.
