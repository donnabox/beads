# Findings on the delta

## 1. MEDIUM — new docs paragraph is false for the first inspection every import performs
`docs/reference/graph-legacy-import.md:94-100` (new) · root cause `internal/storage/graphstore/schema.go:266,280,293` and `internal/storage/graphstore/informational_types.go:100`

The delta repairs cause/classification handling only inside `requireEmptyLegacyTarget` and the `issue_prefix` read. But `checkBinding` runs *before* both — once in `OpenExisting` (`legacy_import.go` → `withGraphStoreBudget` → `OpenExisting`) and again as the first statement inside the import transaction (`legacy_import.go:63`) — and it flattens every cause with `%v`, not `%w`:

```go
return fmt.Errorf("%w: read binding: %v", ErrInvalidStore, err)        // schema.go:266
return fmt.Errorf("%w: Issue configuration: %v", ErrInvalidStore, err) // schema.go:280
return fmt.Errorf("%w: incomplete schema: %v", ErrInvalidStore, err)   // schema.go:293
return nil, fmt.Errorf("%w: read %s descriptor: %v", ...)              // informational_types.go:100
```

**Failure scenario:** `bd import old.jsonl` in a graph workspace; the operator presses Ctrl-C (or the 5-minute `withGraphStoreBudget` deadline fires) while one of `checkBinding`'s ~10 reads is in flight. The driver returns `context.Canceled`, it is rendered to text, and the returned error wraps `ErrInvalidStore` with no context sentinel. `graphStorageError` tests `ErrOutcomeUnknown` → `context.*` → `ErrInvalidStore` in that order, so the context arm is skipped and the operator gets `{"code":"invalid_store"}` exit 5 with `graph preview store identity or schema is invalid: read binding: context canceled` — precisely the "damaged workspace" misdiagnosis follow-up 1 exists to remove, and the direct contradiction of the two sentences the delta just added ("Cancellation and the import's five-minute storage deadline currently use `capability_unavailable`" / "A missing or unreadable required schema/configuration record **without cancellation** instead uses `invalid_store`").

**Fix:** either route those four wraps through `legacyTargetInspectionError` (or an equivalent that uses `%w` for the cause), or qualify the docs paragraph to say the neutral-cancellation disposition applies to the freshness and prefix inspections and that an interruption during binding/schema admission still reports `invalid_store`. The code fix is preferable — `%v` there also loses the cause for every non-cancellation consumer.

## 2. LOW — "with the interrupted operation in the message" overclaims
`docs/reference/graph-legacy-import.md:95`

Only `legacyTargetInspectionError` emits `inspect legacy import target <plane>`. An interruption during `touchCoordination`, `CreateIssuesInTxWithResult`, the catalog/version `INSERT`s, or `checkCurrentReadBytes` returns the bare driver error with no operation name. **Fix:** narrow the sentence to the freshness/prefix inspection, or drop the clause.

## 3. LOW — interrupted-inspection message embeds a newline on the real Ctrl-C path
`internal/storage/graphstore/legacy_import.go:273`

```go
return fmt.Errorf("inspect legacy import target %s: %w", plane, errors.Join(cause, ctx.Err()))
```

`errors.Join(...).Error()` joins with `\n` whenever it holds two elements. When the cause is a driver error *and* `ctx.Err() != nil` — the ordinary Ctrl-C case, and exactly the case `TestLegacyImportInterruptedInspection:80-86` constructs — the user-facing `message` becomes two lines. The new test only uses `errors.Is` and `strings.Contains`, so it cannot catch this. (Mitigating: `withTxPolicy` and `withGraphStoreBudget` already produce joined multi-line errors, but only on secondary cleanup failure, not on every cancellation.) **Fix:** keep `errors.Join` for the `errors.Is` chain but render single-line, e.g. branch on `ctx.Err() != nil` and use `"...: %w (%w)"` with both causes.

## 4. LOW — `config.issue_prefix` non-interrupted text now mislabels a prefix read as a freshness gate
`internal/storage/graphstore/legacy_import.go:78` → message at `:275`

A missing/unreadable `issue_prefix` row (including `sql.ErrNoRows`) previously read *"fresh workspace Issue prefix configuration is missing or unreadable"*. It now reads *"cannot establish workspace freshness from config.issue_prefix; use a fully initialized fresh graph workspace (import does not repair schema)"*. Classification is unchanged (`invalid_store`) and the cause is preserved, so this is text quality only — but that read is the prefix-adoption step at line 74-86, not a freshness gate, and no test pins either wording. **Fix:** give the helper an optional condition clause, or keep a dedicated message for this call site.

No other defects found in the delta. Items 2/3, 4, 6 and 7 are correctly implemented (details below).
