# Findings — `read-update-required-next-plan.md` vs `4a8607a`

## 1. HIGH — "consumes all request bytes before admission" is false, and it inverts the plan's own evidence model

**Location:** plan line 20 → `packages/server/src/development-runtime.ts:443–466`

**Concrete:** `const text = await body(request)` is line **454**, *after* the content-type refusal (448), the content-encoding refusal (450), and the missing/stray-key refusal (453). For every probe in section B (all media refusals) and for A.2 (missing key × 8 targets) and A.4 (repeated / mixed-case), the authority **never reads or parses the body**.

A second consequence inside A.3: `header()` returns `""` for an empty field value, and `"" !== undefined`, so the **empty** key passes the HTTP gate, the body *is* read, and the rejection comes from `prepareReadUpdateSingleton`'s grammar. Verified over the real raw transport: `400`, `observedKey: ""`, `occurrences: 1`. The plan presents the whole A.3 corpus as one family on one path.

**Impact:** A.2's stated strengthening — "Prepared updates/deletes/alias changes must be real effects if executed; creates use distinct absent IDs" — is evidentially **inert** for exactly those probes. The authority never sees the operation record, so "no accidental mutation" is unfalsifiable by body content; the state proof degenerates to "a request that was never parsed changed nothing." The plan markets A.2 as the substantive no-accidental-mutation proof.

**Fix:** restate line 20 as "refuses media, multiplicity and presence before reading any body bytes; only a *present-but-malformed* key reaches `body()` and then `prepareReadUpdateSingleton`." Rebase A.2's discipline onto what actually discriminates (A.4's recovery witnesses, the line-45 controls), and call out empty-key as the single A.3 member that traverses the carrier path.

## 3. MEDIUM — there is no alias collection; line 23 asserts one

**Location:** plan line 23, A.1, A.2 → `packages/server/src/read-request.ts:941–951`, `development-runtime.ts:430–436`

**Concrete:** the alias root is redirect-only. `classifyAliasPath` returns `notFound()` for the empty path, so `GET ${scope}alias/` is a **404**; individual alias paths resolve as **307**. There is no `aliases` entry in the harness's `knownReadBindings` (`read-update-matrix.test.ts:173–185`).

**Impact:** A.1's "complete collections" and A.2's "equals its prior full value" have **no alias oracle** for the `put-alias` / `delete-alias` targets. An implementer following line 23 hits a 404 and will either widen scope or silently drop alias afterstate from two of the eight targets.

**Fix:** drop "alias" from the collections sentence and name the real oracle — proposed-alias absence as an exact 404 Problem, retained alias as 307 with `{kind:"header", name:"location", equalsBinding:<target>}`. Both are expressible: the `header` assertion permits any lowercase field name (the `STABLE_RESPONSE_METADATA_HEADERS` restriction applies only to `response-metadata-equals`).

## 5. MEDIUM — every `malformed-request` body is byte-identical, so most of A.3 has no control attributing the refusal to the key

**Location:** plan A.3, A.6, line 45 → `development-runtime.ts:96–110`, `packages/protocol/src/index.ts:534–547`

**Concrete:** `refused()` calls `readProblem(code)` with **no `detail`**, emitting exactly `{type, code, retry, status}`. A bad body, a bad route, a bad key and a repeated field all produce an identical 400. The declared controls cover only two corpus members (duplicate-key→single-key, 257→256). Nothing discriminates quoted token, internal space, internal tab, comma-combined, Latin-1, or empty.

**Impact:** A.6's "full deterministic fixture Problem equality" reads as a strong oracle but is the weakest available one here — it is satisfied by any unrelated 400. An implementation refusing at the wrong layer passes most of A.3, which directly undercuts the whole-contract claim.

**Fix:** generalize A.5's positive-boundary idea from the length boundary to **every** corpus member: pair each refusal with a same-row retry that changes *only* the key to a valid spelling and requires 200 plus the exact postimage.
