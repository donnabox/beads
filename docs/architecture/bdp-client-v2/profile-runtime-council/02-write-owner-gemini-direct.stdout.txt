### 3. Proven Defects

#### Finding 1: Medium Severity
- **File & Lines:** [`packages/server/src/transaction-batch.ts#L443-L450`](file:///Users/dbox/repos/wt/vickie/bdp-integration-logs/profile-runtime-council/packages/server/src/transaction-batch.ts#L443-L450) and [`packages/server/src/transaction-batch.ts#L483-L510`](file:///Users/dbox/repos/wt/vickie/bdp-integration-logs/profile-runtime-council/packages/server/src/transaction-batch.ts#L483-L510)
- **Concrete Issue:** Unhandled crash (`Error: update lacks previous state` or `Error: successful transition lacks Resource state`) when `bead` or `link` in an `updateBead`, `updateLink`, `deleteBead`, or `deleteLink` operation carries a Pinned Reference object (e.g. `{ uri: string, revision: string }`).
- **Reachable Trigger:** A caller submits a batch or singleton update/delete where the target Resource locator is supplied as a Pinned Reference object `{ uri, revision }`. In [`normalizeTransaction`](file:///Users/dbox/repos/wt/vickie/bdp-integration-logs/profile-runtime-council/packages/server/src/transaction-batch.ts#L298-L300) and [`evaluateTransaction`](file:///Users/dbox/repos/wt/vickie/bdp-integration-logs/profile-runtime-council/packages/server/src/transaction-batch.ts#L430-L442), `ref` is handled as `string | { uri: string, revision: string }`. However, lines 443–445 test `typeof locator === "string"`:
  ```ts
  const locator = input.bead ?? input.link;
  const beforeRow =
    typeof locator === "string"
      ? tx.resource(
          locator.startsWith(options.scope) ? locator.slice(options.scope.length) : locator,
        )
      : undefined;
  ```
  When `locator` is a Pinned Reference object, `typeof locator === "string"` evaluates to `false`, leaving `beforeRow` and `before` undefined. If the resource evaluator succeeds, line 508 (`if (!before) throw new Error("update lacks previous state")`) or line 484 (`if (!subject) throw new Error("successful transition lacks Resource state")`) throws an unhandled server error instead of processing the transition.
- **Impact:** Admitted updates/deletions specifying pinned references fail with unexpected internal 500 exceptions, aborting the transaction without producing a valid problem or receipt.
- **Fix / Next Step:** Normalize `locator` via `referenceUri(locator)` (which is already imported at [`packages/server/src/transaction-batch.ts#L8`](file:///Users/dbox/repos/wt/vickie/bdp-integration-logs/profile-runtime-council/packages/server/src/transaction-batch.ts#L8) and used at line 432):
  ```ts
  const rawLocator = input.bead ?? input.link;
  const uri = rawLocator ? referenceUri(rawLocator) : undefined;
  const beforeRow =
    typeof uri === "string"
      ? tx.resource(
          uri.startsWith(options.scope) ? uri.slice(options.scope.length) : uri,
        )
      : undefined;
  ```

### 5. Architectural Assessment of Boundaries

1. **Read -> Read+Update -> Transactional Boundaries:**
   - Durable write ownership, admission linearizability, and recovery are cleanly maintained across SQLite `BEGIN IMMEDIATE` transactions.
   - Idempotency key namespaces (Scope URL + Authenticated Principal, plus Scope Epoch for Transactional) and outcome retention rules (24h minimum floor, tombstones for committed outcomes, discarding of failed dispositions) match normative specifications.
   - Replay disclosure re-authorization against the present Authorization View correctly returns non-retained `forbidden` problems without erasing the original mutation outcome.

2. **Durable Retention and Recovery:**
   - In [`recovery-store.ts`](file:///Users/dbox/repos/wt/vickie/bdp-integration-logs/profile-runtime-council/packages/server/src/recovery-store.ts#L610) and [`transaction-store.ts`](file:///Users/dbox/repos/wt/vickie/bdp-integration-logs/profile-runtime-council/packages/server/src/transaction-store.ts#L298-L300), startup sweeps clear abandoned `claimed`/`pending` records to ensure restart recovery clears abandoned claims rather than locking them indefinitely.
   - Resource identity and revision allocations are safely isolated within savepoints and strict constraints.
