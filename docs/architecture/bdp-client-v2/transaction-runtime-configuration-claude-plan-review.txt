# Plan precision and test executability (M1)

## A3 · Blanket seam suppression discards the one fixture that already has the qualifying shape
**Severity:** Medium. **Location:** plan line 35 ("…or count/cadence overrides"), line 44; code `transaction-runtime.test.ts:55,61` — the `{pages:true, compiled:true}` row has explicit `stableScope` **and** compiled `artifacts`, disqualified only by `receiptMaximumItems: 2`; `transaction-http.test.ts:88` (passes `clock` always), `:637,:657` (no seams, stable Scope, but schema-free `types`).
**Impact:** No existing fixture qualifies — every `startTransactionRuntime` call in the repo either supplies a seam or lacks compiled artifacts. The qualifying combination is therefore **never currently exercised**, and item 4's claim that "the existing HTTP suite provide behavioral regression witnesses" witnesses the *seamed* path only. Meanwhile `receiptMaximumItems`/`maximumOperations`/`maintenanceIntervalMs` are plain integers the tuple already hashes: overriding them yields a *different truthful* digest, not an indistinguishable one.
**Fix:** Suppress on **function-valued** seams only (`clock`, `scheduler`, and `comparison`/`minimumReads` when they carry `now`/`wait` — `transaction-consistency.ts:79-83`, `transaction-comparison.ts:29,54`), and hash numeric seam values as effective configuration. That promotes `transaction-runtime.test.ts`'s `{pages:true,compiled:true}` row to a real qualifying witness instead of requiring a new child-process fixture. If the blanket rule is deliberate, item 4 must say the default path has *no* pre-existing behavioral witness and M1 must author one.

## A4 · `rawMethod` structurally cannot express item 5's canonical control
**Severity:** Medium. **Location:** plan item 5 (line 91); code `transaction-http.test.ts:737-770` — `rawMethod` derives the dial endpoint (`:744` `connect({host: url.hostname, port: Number(url.port)})`) and the `Host` header (`:767`) from the *same* URL.
**Impact:** Canonical mode is exactly the case where those diverge (dial `127.0.0.1:<ephemeral>`, send `Host: canonical.test`), and `fetch` cannot set `Host`. Item 5 has no vehicle. The existing workarounds (`transaction-runtime.test.ts:105-106` `wire()`, `transaction-http.test.ts:639-647` `send()`) rebase onto `listenUrl` — the very behavior canonical mode replaces.
**Fix:** Specify the helper change — an explicit `{dial, host, target}` triple — and enumerate the four Host cases: captured canonical host (accept), physical loopback host while in canonical mode (refuse), foreign host (refuse), canonical host while in listener mode (refuse). Worth adding that `transaction-http.test.ts:626-661` already proves canonical *Scope* works today (HTTPS scope, canonical receipt IDs, reopen across ports), so the canonical delta is only the `:172` comparison — that bounds the change usefully.

## A5 · "Default-port variation" is unconfigurable by construction; the control is mis-specified
**Severity:** Medium. **Location:** plan line 66 ("default URL port normalization follows the existing canonical URL parser. Test both cases") and item 5 ("default-port variation as applicable"); code `read-values.ts` `parseCanonicalHttpUrl` — `parsed.href !== value` → throw, which `parseCanonicalScope` builds on.
**Impact:** `https://acme.test:443/` or `http://acme.test:80/` can never be *captured*: `new URL(v).href` drops the default port, so it differs from `value` and the parser refuses. An implementer following "test both cases" will write a configure-with-`:443` test, see it refused by URL canonicalization, and may book that as a Host-gate control it is not.
**Fix:** Replace with the two reachable cases — (a) a nondefault port must appear in both Scope and Host; (b) a request sending `Host: acme.test:443` against a portless captured Scope is refused at `:172`. State that default-port Scope *configuration* is unreachable at `parseCanonicalHttpUrl`, not a Host-gate behavior.
