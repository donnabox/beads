All nine frozen files hash-match the manifest and the working tree is byte-identical to them, so the findings below are against the frozen content. I inspected source only — no tests, builds, CLI or DB engines were run.

## Numbered findings

**1. Medium — `internal/storage/graphstore/legacy_import.go:229` (also `:78`, `:239`, `:248`, `:257`): caller cancellation is reported as a workspace-freshness / invalid-store verdict.**
Defect: these five sites dress a query failure with `fmt.Errorf("%w: … %w", ErrInvalidStore, …, err)`. Because `fmt.Errorf` with two `%w` verbs builds a multi-unwrap chain, a `context.Canceled`/`DeadlineExceeded` cause survives in the chain. The repair's new `graphStorageError` case at `cmd/bd/graph_preview.go:838` ranks cancellation *above* `ErrInvalidStore`, so a Ctrl-C (or an exhausted 5-minute `withGraphStoreBudget`, `cmd/bd/graph_preview_import.go:45`) during the ~30 `COUNT(*)` probes emits `code: "capability_unavailable"` carrying the message *"cannot establish workspace freshness from issues; use a fully initialized fresh graph workspace (import does not repair schema)"*. The newly added `store_epoch` probe at `:248` was written with the same flaw.
Impact: a timeout/interrupt is reported as a false diagnosis of workspace state plus a code that tells an agent the capability does not exist, so the correct next action (retry with a larger budget) is suppressed. Reachable on any interrupt during the gate, and more likely on a non-fresh target where the counts scan real tables.
Fix: the repair already established the pattern one line above — `:199-201` was deliberately reworded to *"validate imported current-read representation"* precisely so cancellation stops reading as a size overflow. Apply it to the other five: when `ctx.Err() != nil`, return the cause without `ErrInvalidStore` and without the "not a fresh workspace / does not repair schema" wording (a neutral plane-naming prefix is fine).
Missing test: `legacy_import_freshness_error_test.go:21` already injects a per-query cause through `legacyFreshnessCountDriver`, so add rows with `cause: context.Canceled` / `context.DeadlineExceeded` asserting `!errors.Is(err, ErrInvalidStore)` and that the message does **not** contain `"use a fully initialized fresh graph workspace"` — the mirror of the existing `"exceeds the current-read budget"` assertion at `legacy_import_test.go:621-623`. The existing late-context cases inject at stage `import-retained`, which is long past the gate, so nothing currently reaches this.

**2. Medium — `cmd/bd/graph_preview_import.go:22-24`: the `--source-prefix=''` refusal is the sole distinguisher from an omitted flag, and no test reaches it.**
Defect: `resolveLegacyImportPrefix` treats `supplied == ""` as "not supplied" and falls through to inference (`legacy_import.go:490-498`), so the storage API cannot tell an explicit empty flag from an absent one. Only this CLI guard does. The repaired CLI test's `explicit-empty` case (`graph_preview_assignee_error_test.go:58`) runs `admitGraphPreview` against a non-link workspace, so it exits at `graph_preview.go:292` and never enters `runGraphPreviewImport`.
Impact: if the guard regresses, `bd import --source-prefix=''` silently becomes prefix *inference* instead of `invalid_properties` — i.e. a workspace adopts an inferred prefix the operator explicitly declined to assert, with no test failure.
Fix: no code change needed; pin it. Add `call(string(fixture), "invalid_properties", "import", "-", "--source-prefix", "")` to `TestGraphPreviewLegacyImportInstalledWorkflow` (`cmd/bd/graph_preview_import_workflow_test.go:45-68`), or assert at the storage layer that an explicitly-empty supplied prefix is distinguishable.

**3. Medium — `cmd/bd/graph_preview_assignee_error_test.go:68`: the admission test is tautological on command identity.**
Defect: the test does `importCmd = cmd` where `cmd` is a synthetic `&cobra.Command{Use: "import"}`, then calls `admitGraphPreview(cmd)`. The predicate under test is `cmd == importCmd` (`graph_preview.go:259`, `:292`), which holds by construction. It exercises the branch body, never that the real `bd import` reaches it, and never runs root pre-run — the thing the test name claims ("BeforeLegacyOpen").
Impact: the MEM-POL-001 property actually asserted is weaker than advertised; a divergence between the registered `importCmd` and the admission check would pass.
Fix: the repo already owns the right harness — `TestGraphPreviewGenericFlagsRefuseLegacyOpening` (`cmd/bd/graph_preview_policy_test.go:352-388`) runs the installed binary in a `.beads`-less temp dir, requires `capability_unavailable`, and diffs the workspace tree before/after. Add `{"import", "--source-prefix", "web-app"}` to that table (it passes under current code: `dir == ""` → `GetGraphMode()` returns `dependency` → `graph_preview.go:292`). Keep the unit test for the corrupt-metadata branch, which that harness does not cover. Separately, `--source-prefix` has **no** installed accept-path coverage: the workflow fixture's `legacy-a`/`legacy-b` IDs are unambiguous, and the only test that would cover it is the parked `engdocs/evidence/legacy-import-preview3/completeness-workflow.patch`, which is correctly blocked on the absent `testdata/legacy-import-complete/` producer corpus.

**4. Medium — `internal/storage/graphstore/legacy_import_test.go:930-961`: the one engine test the bounded-context repair missed is also the only one that writes 9 MB.**
Defect: `TestLegacyImportCurrentReadLimitRollsBack` uses `issueExperimentOptions`' single 90 s context (`issues_test.go:27`, which already covers `Init`) for `OpenExisting`, two `legacyImportState` full-table dumps, a 9 MB-description import and a 1001-memory batch. The repair added an `operationContext(t)` helper to four sibling tests (`:512-517`, `:696-701`, `:765-770`, `:861-866`) for exactly this reason and left this one out. `TestLegacyImportFreshDataPlanes` also still probes through `ctx` at `:354` and `:365-371`.
Impact: under `shard_count = 8` CI contention the budget expires and the assertion `errors.Is(err, ErrLimitExceeded)` fails with `context deadline exceeded` — a flake that reads as an error-classification regression rather than a timeout.
Fix: add the same `operationContext(t)` helper and use it for every call in the test.

**5. Low — `internal/storage/graphstore/legacy_import.go:213`: plane coverage is inconsistent; `metadata` is still unchecked while a writer-less table was added.**
Defect: the repair added `interactions`, which has **zero** SQL writers anywhere in the tree (`interactions.jsonl` at `internal/storage/domain/fs/beads.go:190` is the file-based audit log, not this table), so the probe can never fire in practice. Meanwhile `metadata` — the versioned KV identity plane holding `repo_id`, `clone_id`, `_project_id` and `last_import_time` (`cmd/bd/init.go:2103,3877,3947`, `cmd/bd/migrate.go:230,251,423`, `cmd/bd/doctor/fix/metadata.go:77,91,179`) — is covered by neither the table list nor any of the three predicates. `runGraphPreviewInit` (`cmd/bd/graph_preview.go:424-547`) writes `ProjectID` to the config *file* only and never touches the `metadata` table, so a non-empty `metadata` is positive evidence of prior use — exactly the signal `epoch_minted_addresses` was added for.
Impact: narrow (a link-mode workspace has no ordinary-init path), but the stated principle "deleting everything or bypassing graph writers never makes a workspace fresh again" is applied unevenly, and `last_import_time` is a durable prior-import marker.
Fix: add `"metadata"` to the list, or state the exclusion in the comment. Same class, needing a predicate rather than emptiness because migration 0024 seeds them: `custom_statuses`/`custom_types`, which `issueops.ResolveInfraTypesStrictInTx` reads at `:87` — an inherited custom type/status silently participates in import validation. `routes` and `federation_peers` are likewise unexamined.
Missing test: a plane-census guard asserting every non-seeded table in the installed schema is in the gate, covered by one of the three predicates, or on an explicit allowlist with a reason. Without it the next migration adds an unguarded plane silently.

The `store_epoch` predicate itself is correct, and the absent-or-pristine allowance is load-bearing rather than a hole: `issueops.ensureStoreEpochRow` (`epoch_cas.go:111-130`) lazily inserts `(1, 1)` with `bumped_at`/`bumped_reason` NULL, and the import's own `ScopeVersionedHistoryTransaction(tx, true)` at `:96` makes `RecordVersionInTx` a `store_epoch` writer (`version_history.go:190`), so requiring emptiness would make the importer disqualify itself. `EpochBumpInTx` (`epoch_cas.go:233`) sets both markers, which the predicate catches, and the empty-string `bumped_reason` case is pinned at `legacy_import_test.go:409`.

**6. Low — docs not updated for the widened refusal surface.** `docs/reference/graph-legacy-import.md` enumerates the disqualifying planes ("journals, leases, snapshots, previous identity/sequence allocations, counters and wisp auxiliary rows… classic KV Memories") with no mention of the epoch generation / minted-address planes, `interactions`, or the absent-vs-pristine-vs-bumped `store_epoch` rule — the only non-emptiness predicate an operator can hit (e.g. after a `bd doctor` epoch bump). The deadline disposition from `graph_preview.go:838` is also undocumented; the page currently documents only `capability_unavailable` for byte/resource ceilings and `outcome_unknown` for uncertain cleanup. `CLAUDE.md` requires user docs in the same change as a behavior change.

**7. Low — `internal/storage/graphstore/backend_transaction_policy_test.go:139-142`: the matrix omits the pre-`BEGIN` failure paths.** The mock always succeeds the four `SET` statements and always answers `active_branch()` with `main`, so the branch-mismatch refusal (`backend.go:223-225`) and a failing `SET` (`backend.go:215-217`) are untested. Both return before `BeginTx` with no transaction to finalize and rely solely on the deferred `conn.Close()` — precisely the shape the test's own `s.db.Stats().InUse != 0` assertion exists to police, and the only two `withTxPolicy` exits with no rollback/commit expectation at all. Fix: two cases (branch `"feature"` → `ErrInvalidStore`; `SET` → error), each asserting `InUse == 0`, no `ErrOutcomeUnknown`, and `attempts == 0`.

Everything the matrix does cover checks out: `withTx(ctx, false, …)` and `withTx(ctx, true, …)` map to `{mayWrite: write, commit: write}` so both legacy callers keep byte-identical semantics (the `reader-callback-and-rollback-failure` case pins that a reader's rollback failure still does *not* acquire `ErrOutcomeUnknown`); the dry-run `{mayWrite: true, commit: false}` path correctly classifies rollback failure as uncertain while a clean rollback returns nil; `ErrTxDone` precedence, single-invocation (`attempts == 1`), connection release, and `classifyCommitError`'s 1213/40001-only conflict narrowing are all asserted.

**8. Low — `internal/storage/graphstore/legacy_import.go:520-543`: `legacyImportStringsValid` fails open on unhandled reflect kinds.** The walker handles String/Pointer/Struct/Slice and returns `true` for everything else, so a future `map[string]string` or `any` field on `types.Issue`/`Dependency`/`Comment` would bypass the original-UTF-8 check and be silently replaced with U+FFFD by the `json.Marshal` clone at `:321`. The set is safe today — I checked `internal/types/types.go`: `Metadata json.RawMessage` (`:112`) is the only byte-typed field and is now explicitly validated at `:295`; there are no map or interface fields; the `json:"-"` fields are exactly `ContentHash`, `RowVersion` (normalized away in `verifyLegacyIssue`) plus the five refused at `:302-306`. Missing test: a guard that recursively walks `reflect.TypeOf(types.Issue{})` and fails on any exported field whose kind the walker does not handle, turning a silent data-loss regression into a caught one.
