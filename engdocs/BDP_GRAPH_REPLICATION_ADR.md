# Graph replication and merge ADR

**Status:** Implementation contract; engine qualification incomplete. P1 and the graph-migration gate remain open.
**Last reviewed:** 2026-09-14.
**Source baseline:** Beads `8af1e139770e3adbd81013558ce989a869ab99af`.

This ADR defines replication admission, conflict handling, recovery, and the explicit later-mint adoption operation under [plan ruling 14](BDP_BEAD_GRAPH_PLAN.md). The [architecture](BDP_GRAPH_ARCHITECTURE.md) and [CLI/storage specification](BDP_GRAPH_CLI_AND_STORAGE_SPEC.md) retain their authority. The selected ordering and acceptance conditions below are requirements for implementation. Gates E1–E8 identify the missing mechanisms and evidence; no storage, migration, authority, or public BDP capability is delivered by this document.

The council reviewed the source-pinned proposal; its corrected disposition rejects a precommitted lease write as sufficient merge exclusion and rejects a loss notice as sufficient preservation of permanent nonreuse records. Original review and correction evidence is tracked in [BDP implementation #1](https://github.com/gastownhall/bdp/issues/1).

## 1. Scope and binding laws

P1.0 records a mechanism and acceptance program under plan ruling 14, architecture A1/A5/A7/A9/A10, and the graph CLI/storage specification. It gates graph migrations; it does not complete their runtime prerequisites. This ADR retires A9's explicitly interim “loser rotates” remedy in favor of the explicit later-mint adoption below. Retiring that interim follows ruling 14 and does not rewrite the historical interview record or reopen the settled laws.

The fixed ordered replicated state is `graph_scope`, `graph_scope_history`, `graph_type_descriptors`, `graph_beads`, `graph_links`, `graph_ledger_seq`, `graph_ledger_events`, `graph_allocations` (storage spec table rows 906–913 at the pin). `graph_authority_lease` is ignored and excluded. A separate exact 24-trigger census includes definition identity and is independent of content version.

Ruling 14 requires SQL fetch→inspection→refusal before any foreign/unexplained merge; graph data is never selected cell by cell, and no graph conflict is resolved by strategy. A no-witness workspace takes a selected remote graph wholesale and remains a replica. A competing valid local mint is not a replica: its foreign graph delta is refused whole until explicit administrative adoption. Already-landed CLI/out-of-process/restore changes receive the state validator's table-scoped recovery, preserving later issue commits; they are not retroactively called premerge refusals. Hazard-R publication, fresh-remote-read and publication-recovery machinery remains deferred under A9. This ADR does not reactivate it.

## 2. Classification precedence and evidence

The classifier is private provider-owned code shared across routes. The specified SQL-free witness manager will own durable local identity/transitions; storage supplies engine evidence. Neither HTTP callers nor public graph requests supply witness, selected-state or permit assertions.

Use these ordered classifications:

1. A pending transition requires its existing evidence-based recovery before a permitted administrative operation; ordinary protected calls retain their ruled pending refusal. An unverified or invalid/mismatched witness always refuses graph-bearing replication. It is never absence and never a replica fallback.
2. Conclusive absence of an active witness and of every graph table on both sides permits `LegacyUnchanged`; ordinary legacy output and behavior remain unchanged. No StateVersioner requirement is imposed on a conclusively graph-free backend. A failed presence query is not absence.
3. A witness, any graph table, or unresolved presence requires the applicable graph evidence capabilities. Missing capabilities or unreadable/incomplete evidence refuses, naming the missing evidence. Partial schema is a refusal even without rows.
4. A valid minted-here witness uses authority-lineage classification, subject separately to current operation/topology restrictions. Matching Scope/authority/epoch without ledger/provenance explanation is insufficient. A foreign delta, fork or ledger rewind refuses whole.
5. A conclusively absent witness plus complete graph state uses `ReplicaWholesaleIncoming`. It may accept only one complete selected incoming graph state and remains unable to mint until the ruled rotate/steal path. It never merges independent local rows into that state.

A10 has two independent axes. Current topology decides whether embedded/local authority-dependent operations are permitted: solo means no server and no remote; a client host remains subject to the existing refusal contract and never gains HTTP serving. Durable valid minted-here provenance decides how replication treats local graph history. Adding a remote does not erase that provenance, invent absence, or authorize wholesale replacement as a replica. This reads the two A10 obligations together; lease possession alone proves neither provenance nor topology.

The closed internal outcome is `LegacyUnchanged | GraphUnchanged | AdmitIncomingGraph | ReplicaWholesaleIncoming | Refuse`. Refusal carries a finite reason and table/evidence source names: `unverified`, `pending_transition`, `invalid_witness`, `missing_capability`, `partial_schema`, `unreadable_evidence`, `unsupported_form`, `wrong_branch`, `changed_evidence`, `foreign_authority`, `forked_lineage`, `ledger_rewind`, `unexplained_same_authority`, `graph_conflict`, `fence_census`, `anti_reuse_loss`, `exclusion_unqualified`, or `recovery_required`. These are proposed internal diagnostics, not new protocol Problems or authority grants.

### Commit evidence versus working-set hashes

Pin local inspection HEAD and incoming commit IDs, default branch, actual current branch/session, witness generation, and the exact eight-table presence/schema state. Use `dolt_diff`/`DOLT_DIFF_STAT` for commit-relative comparison and validated `AS OF` reads for Scope/ledger facts at those immutable commits. `DOLT_HASHOF_TABLE` is only a working-set hash primitive; never pass a commit and claim an immutable incoming root.

Complete equality at a selected commit means an empty content **and schema** diff for all eight tables with successful iteration and known presence, plus valid Scope/ledger state. An empty data diff is not schema equality. Schema/AS OF evidence that the provider cannot produce reliably is gate E2. Local working hashes bind the mutable working set to the recorded inspection state; comparison against the selected commit uses the separately qualified diff/AS OF adapter, not invented commit hashes.

Inspect provenance over the complete changed-row set, verifying all required ledger links from the last trusted prefix and every explaining event, including removed rows. Do not reread all unchanged provenance on every pull merely to populate a giant evidence object. The adapter must declare finite local row/byte/time budgets and reject incomplete evidence on exhaustion; no truncated diff or ledger chain may receive a permit. Whole incoming graph structural validity is a separate required selected-state validation. Streaming/batching is an engineering choice; no fixed-memory or arbitrary-size success is claimed here.

## 3. SQL mutation ordering and the unresolved exclusion gate

All graph-bearing SQL mutations require one pinned provider session. Read back its current branch and assert it equals both the inspected branch and the graph default branch. Evidence, lease/exclusion checks and the mutating primitive must refer to that same session/database/branch. The current fresh-connection target defect be-5ybd is a prerequisite, not a passing assumption. Graph-bearing non-default or unpinnable routes refuse; legacy no-graph branch behavior stays unchanged.

Order each route as follows:

1. Under the existing workspace/provider ownership, validate local witness/state before any `CommitPending`, `commitBeforePull`, staging, or merge conclusion. Dirty unexplained graph data must not be laundered into a trusted commit. Retain each route's existing issue auto-commit behavior only after this validation.
2. Record `entryHead` before any allowed auto-commit for reporting. Run that existing preparatory auto-commit when the route has one; record `inspectionHead` after it. Fetch using the actual selected transport and pin its incoming tracking ref to a commit. A foreign-input premerge refusal leaves HEAD unchanged from `inspectionHead`, not necessarily from command entry. Report any preparatory commit honestly. Routes without a precommit have the same two heads.
3. Acquire qualified exclusion that spans the final authoritative evidence snapshot through the nonreplayable merge and its required result classification. Then obtain/revalidate complete evidence on the pinned session. No participating mutation admitted before exclusion may commit unseen after the final snapshot; no new participating writer may enter the gap.
4. Classify, preserve the immutable incoming operand, and invoke at most one mutating primitive for this attempt. A changed HEAD, working hash, witness generation, target branch, selected commit or exclusion identity invalidates the permit. A caller may retry a refused **pre-dispatch** attempt from new evidence; it may not replay an uncertain/committed merge closure.
5. Permit a whole-commit fast-forward when it selects the validated graph. For divergent issue history, ordinary merge is allowed only when graph comparison proves one side unchanged from the merge base and the exact selected graph survives whole. Both-sided graph changes require the separately qualified whole-table selection realization; until then that shape refuses as an implementation coverage gap, not permanent satisfaction of the wholesale contract.
6. Prescreen all conflict classes before any resolver, repair, staging or concluding commit. Then run existing issue-only settlement only if the complete graph prescreen permits it. Validate the resulting whole selected state, provenance, ledger and fences before reporting graph success or advancing the witness.

**E1 — shared-database nonreplayable exclusion is not qualified by this ADR.** A same-cell fence in a retryable transaction does not establish atomicity with a self-committing DOLT merge/pull. A separately committed fence write does not exclude a graph transaction already in flight or a subsequent lease writer. A post-merge check does not repair the missing premerge ordering. A process mutex, provider-local singleflight, or one workspace's file gate does not exclude other shared-database participants. Never wrap the merge in `withRetryTx`/`RunTxResult`, and do not relabel a rolled-back fence as a rolled-back merge.

The shared-DB realization must supply an actual database-wide participating-writer exclusion/admission mechanism with drain, continuity and uncertain-outcome evidence, qualified against an in-flight publisher, CLI writer, second process and renewer. Its exact mechanism is a named engineering gate; no new advisory-lock SQL or presumed row-lock behavior is invented here. Until E1 is proved, affected graph-bearing SQL mutations refuse before dispatch. On a genuinely solo embedded leg, its exclusive workspace gate supplies exclusion only while topology and single-process ownership remain valid; it is not evidence for the shared leg. Raw SQL deliberately outside the contract remains the ruled detection residual, never an excuse to leave ordinary participating writers unordered.

## 4. Conflict refusal, abort and post-change validation

Admission/settlement evidence is the complete error-checked union of `dolt_conflicts`, `dolt_schema_conflicts`, and `dolt_constraint_violations`, restricted to graph tables and their protected schema/fence definitions. Query, scan, iteration or required-system-table failure refuses; the existing diagnostic missing-table-as-empty behavior cannot be reused as proof. A graph schema conflict plus issue data conflict resolves zero tables. Graph constraint violations also precede FK repair. Both default allowlist and explicit ours/theirs paths, federation loops and low-level conflict APIs enforce this ordering.

Capture table names and conflict source before cleanup. Diagnostics label graph conflicts unresolvable by strategy and point to the applicable link-mode recovery route. No generic “try ours/theirs” hint is emitted for graph data. `CommitMergeResolution` validates current graph/witness evidence before staging or concluding even when an earlier process initiated/resolved the merge; generic Commit/Add are guarded as described below.

A graph-aware abort returns evidence rather than hiding cleanup errors. Never reach the current whole-database `DOLT_RESET('--hard')` fallback when graph state or its ignored lease is involved. While the same merge is active, a qualified `DOLT_MERGE('--abort')` may restore its recorded premerge working state; verify merge status and preserved unrelated dirty work afterward. When abort fails, HEAD moved, state already committed, or evidence is incomplete, do **not** blindly soft-reset to a guessed pre-head or run a generic table checkout. Keep protected graph operations blocked, durably mark uncertainty, and enter explicit recovery E3. A wedged merge is reported as recovery-required; the plan does not promise a safe unlock before its mechanism is proved.

Ruling 14 post-change recovery remains a new table-scoped corrective commit restoring only the eight graph tables to the recorded trusted ancestor state, preserving later issue commits and unrelated dirty issue tables. The deferred hazard-R “own operation is still HEAD” undo recipe is not an unconditional abort algorithm for these routes. Any ignored-lease compensation follows the existing same-holder/Scope/epoch/current-fence guard and writes a fresh fence; never overwrite a legitimate new holder. Do not use whole-database revert/reset as graph repair. E3 must prove the exact provider repair/abort sequence, including an already committed violation, open merge state, concurrent issue changes and lease preservation.

The specified state validator must implement one provider-local singleflight and one protected-call retry after `ErrStateChanged`; singleflight is not the shared-writer exclusion. IdentityReader remains diagnostic. No ancestry, ambiguous selected state or failed recovery durably marks an existing witness unverified and refuses. An unverified witness never becomes replica by that marking.

A read-only database cannot make a corrective commit or repair triggers. Mark the local witness unverified if writable, refuse protected use and identify writable recovery; if that file cannot be persisted, also report the persistence failure and continue refusing. Do not claim a read-only validation repaired the database.

Trigger census runs even if the eight content hashes are unchanged. Repair only missing definitions from the reviewed frozen migration source, never guess over a conflicting definition. Any `dolt_schemas` repair is a separate, explicitly scoped default-branch repair commit, staged without unrelated tables, recorded as fence repair and visible to peers; it remains outside the eight-table content version and never excuses incomplete schema evidence. Proving safe scope/commit behavior for that versioned table is part of E3/E4, not an assumed successful DOLT_ADD/COMMIT recipe.

Before known `BackupRestore` targets this workspace's resolved database identity, write and durably fsync `MarkUnverified` under the specified local manager lock **before invoking restore**, including matching-head restores. Failure to persist prevents that restore. Restore of an unrelated database must not invalidate this workspace merely because the same server executes it; destination ambiguity refuses the graph-aware route. Non-CLI provider/UOW entry points share the hook. External raw restore remains caught at next load/validation; it never gets an invented pre-action hook.

Force-push is an explicit operator action, not automatic authority transfer. A Dolt remote is not a bd receiver with a hidden validator hook. The next bd graph-bearing pull or protected validation observes the changed state; truncated same-authority history is `ledger_rewind`, not an explainable match of IDs.

## 5. Replica wholesale selection and explicit later-mint adoption

`ReplicaWholesaleIncoming` is the automatic no-witness case. Successful graph contents equal all eight selected incoming tables, with no cell-wise combination. If local divergent replica rows are discarded, emit a table/count loss notice, excluding raw values and credentials. That notice is diagnostic, not a substitute for anti-reuse or graph validity. Missing/partial incoming graph does not erase a local minted graph. Positive valid replica adoption remains a required runtime gate; temporary refusal is not completion.

The administrative form selected for implementation is:

`bd --graph-mode link adopt <remote> --branch <branch> --expect-local <commit> --expect-source <commit>`

It selects the already established lineage identified by the operator; no cross-machine wall-clock election is performed. Both expectations are mandatory, fetched source is pinned, canonical Scope URL is equal and competing mint identity differs. Require no uncommitted graph changes, full source validation and anti-reuse compatibility. Take the exclusive workspace gate, require the serving process stopped (name it on refusal), and establish the qualified underlying-database exclusion; a stopped local server alone is not exclusion of all shared-DB clients. Different URLs use the existing rotation workflow.

**Anti-reuse is a hard precondition.** Before replacing `graph_scope_history` or allocations, prove the selected source preserves every applicable local permanently refused URL and local allocation/nonreuse obligation. Comparing only live resources or printing a list of dropped `refuse_url` rows is insufficient. If the selected source lacks an obligation, refuse `anti_reuse_loss`; do not forgive it, silently union foreign ledger cells, fabricate an event kind, or tell the operator to reapply it after the loss. A broader adoption that preserves such obligations requires a separate law-preserving realization (E5). This named limitation blocks that adoption shape until resolved and is not claimed to satisfy all final P1 positive cases.

Implement and reuse the single SQL-free witness manager specified in [CLI/storage B3](BDP_GRAPH_CLI_AND_STORAGE_SPEC.md#b3-bodies-the-witness-manager-and-legs), including its `Transition`, bounded `.beads/graph-authority.lock`, Begin/SetPhase/Finalize/Abandon lifecycle, atomic persistence and directory durability. The manager, provider validator and transition lifecycle are not implemented at the pinned P0 baseline; the separate installation-ID helper does not supply them. Hold the lock continuously through completion/recovery. Add an explicit adopt transition kind and typed expected local/source commit evidence; do not create a parallel recovery file/state machine. Existing phase names suffice: begun → local_committed → published (local completion under A9) → config_written → finalized. Mark the active witness unavailable while pending. The implementation must specify the final active-witness removal through the manager's durable Finalize path; removal is not a client-authored file edit.

Adopt is a named recovery exception to finding a newly written op_id in the ledger: its source ledger is copied unchanged and receives no local adoption event. Record expected local/source immutable commits, complete eight-table comparisons, original working hashes and pre-lease in the transition. On recovery, compare actual selected state with those two complete recorded commit states using E2. Exact pre-state permits safe abandonment only if no partial administrative effects remain; exact source state finishes old-authority invalidation; mixed/unknown state remains pending/unverified and refuses. Phase alone never proves replacement. No second mint occurs on retry.

After successful adopt: all eight tables equal the selected source; source ledger bytes/op_ids remain unchanged; issue/wisp/config data outside the explicit graph configuration intent is preserved; the active local authority witness is absent following durable manager finalization; the old local ignored lease is removed only under its recorded identity/current-fence ownership checks and never replaced by a fetched lease. An unexpected new holder blocks completion rather than being deleted. Installation identity is unchanged. The durable transition/recovery rules prevent an interrupted old witness from rearming. The resulting no-witness workspace is a replica and receives no implicit steal; later authority uses the separately ruled promote/rotate path. E5 must prove finalization and crash ordering before this command is implemented.
