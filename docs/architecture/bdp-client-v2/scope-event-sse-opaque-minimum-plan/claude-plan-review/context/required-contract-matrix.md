# Required-contract matrix: actual bdptest profile completion

Source **caf5ca75a4e9b9c7865e61e97f849ab736c21e64**. Companion to [native plan review](profile-completion-native-plan-review.md). Source inspection only; no tests executed. Current U1/T1 work is intentionally not counted as completed at this frozen main pin.

**M** = mandatory for the selected profile. **C** = a conditional branch whose trigger/configuration must be recorded; it is not automatically an optional feature or a passing observation. All Read rows are inherited by Read+Update and Transactional. At Transactional, twelve explicitly retired Update expectations are replaced by their Transactional counterparts. This family-level matrix directs work; exact normative identifiers remain in the current JSON catalogs, not a duplicated new authority.

Current deduplicated catalog inventory (excluding optional History): Read: 49; Read+Update: 135 (49 + 81 + five additional numeric/owned Update rows); Transactional: 256 (135 + 133 − 12 retirements). Do not treat these counts as coverage or a target number of test cases. Conditional cases need evidence of applicability, and meaningful requirements may need multiple observations.

## Mandatory selection safeguards

1. Bundle all inherited identifiers before selecting a cumulative profile. `transactional-v1` alone is deliberately rejected. Apply the twelve current retirement mappings; do not edit the normative retirement list to accommodate implementation gaps.
2. Preserve numeric/owned companion obligations, accounting for Read identifiers already copied into the main Read catalog. Optional History remains separately capability-gated.
3. Use observations against the same installed target, store owner, auth/policy, Type contracts and advertised profile. A different static Read fixture does not satisfy inherited Read for a mutable listener.
4. Unknown applicability is a gap. A schema-free/all-visible installation can document genuine non-applicability, but cannot stand in for product qualification of supported schema/owned/hidden configurations. Unimplemented unconditional operations such as set mutation cannot be marked inapplicable.
5. Tests may arrange isolated initial state or controlled actual faults, but may not fabricate replies, authorization decisions, elapsed retention, positions or evidence to make the service appear compliant. Record process-crash/restart evidence at its actual failure boundary; do not claim power-loss or HA guarantees from it.
6. Keep experimental serves explicitly non-attesting until their complete applicable cumulative gates pass. The final gate is an actually installed discoverable service usable by a cold credentialed client, with fresh target-bound evidence and honest admission.
