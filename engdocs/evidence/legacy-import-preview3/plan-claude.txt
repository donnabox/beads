### 2. HIGH — prefix inference refuses ordinary multi-hyphen-prefix exports
**`internal/storage/graphstore/legacy_import.go:355-361` (`legacyImportPrefix`), used at `:248`**

`utils.ExtractIssuePrefix` falls back to the **first** hyphen when the suffix is 4+ base36 chars with no digit (`internal/utils/issue_id.go:83-99`). Beads hash IDs are base36 at adaptive length 3–8 (`internal/idgen/hash.go:55+`), so a 6-char hash is all-letters with probability ≈ (26/36)⁶ ≈ **13.6%**. Since prepare requires every ID to produce the identical prefix:

- `web-app-123` + `web-app-abcdef` → `web-app` vs `web` → *"legacy import requires one Issue ID prefix"*. An ordinary export of a `web-app` workspace is unimportable, with no workaround. With four issues, ~45% likely.
- A uniformly word-like batch (`web-app-abcdef` alone) is **accepted** and silently adopts `issue_prefix = "web"`, after which `validatePrefixWithAllowed` (`internal/validation/bead.go:97`) reports a prefix mismatch for later commands naming `web-app-*`.

Neither case is covered: the producer hard-codes 3-char suffixes (`-a1b`, `-b2c`, `-c3d`, `-d4e`), and `TestLegacyImportPrefixAdmission` tests `web-app-abc` (3-char free pass) but never `web-app-abcd`. The docs diff documents the *mechanism* but not the refusal.

**Fix:** two-pass consensus instead of per-ID equality. Collect `utils.ExtractIssuePrefix` candidates for all IDs, take the longest (lexicographic tie-break for determinism), then require for every ID `utils.ExtractIssuePrefixKnown(id, []string{P}) == P` — i.e. `strings.HasPrefix(id, P+"-")` with a nonempty remainder. `web-app-123`/`web-api-456` still refuses (neither candidate prefixes the other); `web-app-1`/`web-app-abcdef` is admitted as `web-app`. `ExtractIssuePrefixKnown` exists for exactly this. Add `{"web-app-abcdef"}` → `web-app` and `{"web-app-1","web-app-abcdef"}` → accepted to the admission test; both fail today.

**MEDIUM — `legacy_import.go:170`: Memory title/body are never verified against storage.** `if _, err := s.showMemoryInTx(...)` discards the record, so only a hard read error refuses; a silent coercion of `Properties.Title`/`Body` commits while `MemoryIDs` claims exact preservation. **MEDIUM — `legacy_import.go:212-218`: invalid UTF-8 in Issue fields is laundered, not refused.** The new pre-clone check covers `input.Memories` only. `json.Marshal(input)` at `:220` replaces invalid bytes in Issue title/description/notes/labels with U+FFFD; because both the comparison source and the stored row derive from the laundered clone, `verifyLegacyIssue` compares equal and the import reports preserving text it changed. ## What I verified as sound

The memory allocator (`legacyImportMemoryPaths`, `:364-394`) holds up on the properties you asked about:

- **Collision safety.** `graph.CanonicalSegment` is injective (`%` always escapes to `%25`, so the encoding is decodable), so two remapped keys never share a canonical path. Reserving all Issue paths *and* all valid direct Memory paths before any remap is what makes the alias pair safe — `記憶` yields `%E8%A8%98%E6%86%B6`, which the literal key already holds, so `記憶` correctly falls to the digest. Direct paths can't contend with each other (distinct keys ⇒ distinct paths); the only direct-path occupant is an Issue, which correctly forces a remap. `graph_preview_catalog`'s unique path is the backstop.
- **Deterministic identity.** `sort.Strings` over remaps only, plus an `occupied`-checked numeric suffix, makes the map a pure function of the key/ID sets — so dry-run and apply report identical addresses, and the reversed-input assertions (`legacy_import_test.go:83-88`, `graph_preview_import_workflow_test.go:214,221`) are the right pins.
- **Bounds.** Digest paths are 86–88 bytes, always inside `validatePath`'s 1024-byte limit; the canonical candidate is re-validated rather than assumed (which is what sends `control\x00` and `.`/`..` to the digest).
- **Comment verification** is behavior-preserving: the De Morgan rewrite of the zero-timestamp wildcard is equivalent, the `delete` strengthens it against repeated IDs, and no previously-refused input is admitted.
- No depguard/layering objection to the new `internal/utils` import from `graphstore` (`.golangci.yml` has no rule for either); the `BUILD.bazel` dep was added correctly.
