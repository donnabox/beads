### Findings

#### Proven Defects

* **Severity**: Low
* **File & Exact Line/Section**: [`packages/server/src/development-runtime.ts#L209-L213`](file:///Users/dbox/repos/wt/vickie/bdp-integration-logs/profile-runtime-council/packages/server/src/development-runtime.ts#L209-L213)
* **Concrete Issue**: Shadowed dead code causing incorrect HTTP status code routing. Line 213 (`if (!operation && name !== "sequence") throw new ReceivingError("resource-not-found");`) can never be reached under any circumstances. Line 209 checks `if (request.method !== "POST" || !mutationTarget)`. Because `mutationTarget` is defined on line 166 as `operation !== undefined || name === "sequence"`, whenever `mutationTarget` is `false`, line 209 unconditionally executes `empty(response, 405, "GET, HEAD"); return;`. Conversely, whenever line 213 is reached, `mutationTarget` is guaranteed to be `true`, rendering `!operation && name !== "sequence"` permanently false.
* **Reachable Trigger**: A client sends a `POST` request to an unknown or invalid operation target under `/development/` (for example, `POST /development/nonexistent-op` or `POST /development/unknown`).
* **Impact**: RFC 9110 status code violation. The server returns `405 Method Not Allowed` with `Allow: GET, HEAD` instead of the intended `404 Not Found` (`resource-not-found` Problem response), falsely communicating to the client that `GET` and `HEAD` methods are valid for the target resource when `GET /development/nonexistent-op` actually returns 404.
* **Fix / Next Step**: In `packages/server/src/development-runtime.ts`, discriminate unknown `/development/` operation paths before returning 405. If `rawUrl.startsWith("/development/")` and `!mutationTarget`, throw `ReceivingError("resource-not-found")` so unknown mutation endpoints correctly return 404 rather than 405.
