## T2-1 — LOW · assertion cannot fail · `apps/bdptest/src/read-update-matrix.test.ts:44-51`

**The new "actual child exit" assertion is unfalsifiable: it is tautological wherever it runs, and unreachable wherever it would matter.**

`closeInstalledChild` awaits `child.close()` then asserts `exitCode !== null || signalCode !== null`. The helper's close is `scripts/installed-reference-observation.mjs:76-78`:

```js
close: async () => {
  if (child.exitCode === null && child.signalCode === null) child.kill("SIGTERM");
  return bounded(exited);          // exited resolves on child.once("exit", …)
}
```

- Resolve path: `bounded(exited)` resolves only after the `'exit'` event, at which point Node has already set `exitCode` or `signalCode`. The assertion is implied by the `await` that precedes it.
- Timeout path: `bounded` SIGKILLs and **rejects** at 10 s (`:42-45`), so `await child.close()` throws and the assertion is never evaluated.
- Scenario-session path: `session.close` is invoked through `createRawHttpScenarioTarget`, where `settleCleanup` races it against `AbortSignal.timeout(cleanupTimeoutMs)` with `cleanupTimeoutMs = requestTimeoutMs = 5000` (`raw-http-scenario-target.ts:61`, test `:329`). If the child needs >5 s the race rejects first and the assertion is skipped.

There is no input for which this `expect` reports false. The report presents it as proof of "no live bootstrap leak" and "cancellation cleanup observable"; it establishes neither beyond what `await close()` already establishes.

**Failure scenario it misses:** the helper SIGKILLs on >64 KiB of stdout/stderr without rejecting (`:27, 31`), so a child killed for runaway output resolves `close()` with `signalCode === "SIGKILL"` and passes the assertion unchanged.

**Fix:** assert a distinguishing property — `expect(child.child.signalCode).not.toBe("SIGKILL")`, or pin graceful termination as `exitCode === 0 || signalCode === "SIGTERM"`. For leak coverage, the observable case is a child whose `close()` is never called (`runner.ts:738-745` skips `harness.cleanup` when preparation or an action did not settle); today that is swept by `target.close()` in `run`'s `finally` (`:629`), which is the property worth asserting.

## T2-2 — LOW · weak assertion on the cancellation negative · `apps/bdptest/src/read-update-matrix.test.ts:1199`

## T2-3 — LOW · the cooperative abort degrades less legibly than the timeout it replaces · `apps/bdptest/src/read-update-matrix.test.ts:637-638, 727`

**If the 90 s budget fires, the abort reason is discarded and the test fails on a scenario-state mismatch with no mention of the budget — and whether 90 s/120 s is sufficient is not established by the available CI datum.**

`controller.abort(Error("cumulative run budget exceeded"))` sets `signal.reason`. `relayAbort` (`runner.ts:2986-2992`) does forward it into the per-scenario controller, but every consumer discards it: the matrix loop emits `stoppedScenarioResult`'s fixed reason, and `runScenario`'s catch writes the fixed `"scenario run was aborted"` (`runner.ts:620-629`). `runConformanceMatrix` does not reject on abort, so `run()` returns a complete report and the first failure is the per-row `toMatchObject({state: "pass"})` at `:656-659`. The string "cumulative run budget exceeded" is dead code.

Separately, CI 38374131399 killed the test at 30 000 ms, so its true Linux duration is unknown; the report's ~40 s figure is inferred from "about 1 second each" × 40 scenarios. Locally the test is 9 995 ms (`read-update-budget-tests.json`) / 9 782 ms (`read-update-budget-final-tests.json`).

**Failure scenario:** the real Linux duration lands in (90 s, 120 s]. The cooperative abort fires, the run completes, and CI reports a per-row state mismatch on a truncated matrix — strictly harder to diagnose than the original clean `Test timed out in 30000ms`.

**Fix:** after `await run(...)`, check the controller and fail explicitly — `if (controller.signal.aborted) throw controller.signal.reason` — so the budget failure names itself before the row assertions run.
