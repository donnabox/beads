## Verified sound

- **Empty-destination refusal before IO** — `publish.go:58` precedes `create`; `publish_test.go:366` proves the factory is never called, so no stray temp lands in CWD from `filepath.Dir("") == "."`.
- **Umask-safe previous-mode assertion** — `publish_test.go:156` captures `beforeInfo` and compares it against the post-failure stat (`:228`), instead of asserting a literal `0o644`. The `||` short-circuit at `:228` also means the `info.Mode()` deref can't run on a nil `info`. The absolute `0o640` assertion at `:71` is independently umask-safe because `atomicfile.go:76` sets the mode via fchmod on the temp fd rather than relying on create-time bits.
- **Caller byte immutability** — clone-and-compare at `publish_test.go:58/63` and `:354/361` guards both entry points.
- **Abort/error-join plumbing** — the `defer` at `publish.go:65` is registered *after* the create-failure return, so the typed-nil `*atomicfile.Writer` from `atomicfile.Create` is never touched; `w, err := create(...)` correctly redeclares the named result (same block as the parameter list), so every shadowed `return err` in the inner `if` scopes does reach the abort closure. Abort-after-failed-`Close` is a no-op because `atomicfile.Close` sets `done` first — which is exactly what the new "cannot retry cleanup after a failed Close" sentence claims.
- **Short-write detection** — `errors.Join(err, io.ErrShortWrite)` at `publish.go:104` is non-nil even when the writer short-writes with a nil error, and `start = end` is only reached when `n == end-start`. Non-retry is correct against the `io.Writer` contract (and `os.File.Write` loops internally, so pipe/stdout output isn't falsely failed).
- **Doc claims that are factually accurate** — symlink destinations *are* replaced not followed (`filepath.Dir` of the link, `os.Rename` over the link inode); ownership/ACLs are not retained; no parent-directory fsync; the three cancellation checkpoints match `publish.go:55`, `:98`, `:75`; `TestPublishFileSuccessBoundary` genuinely pins "cancel during/after rename still succeeds".
- **BUILD.bazel** — `deps` on `//internal/atomicfile` is required by both the library and the in-package test; nothing else imported is non-stdlib.

## Findings

**1. Low — `publish.go:36` — permission doc names an API the code does not use, contradicting the symlink sentence below it**
The comment says "Permissions use os.Chmod". `atomicfile.go:76` uses `(*os.File).Chmod` on the *temporary file's descriptor, before rename*. `os.Chmod` takes a path and follows symlinks, so as written the comment tells a reader that the destination path is chmod'd — which directly contradicts `publish.go:38` ("Symlink destinations are replaced rather than followed"), and implies a chmod failure could leave an already-published file with the wrong mode when in fact it aborts before anything is published. The wording also loses the one fact that makes `publish_test.go:71`'s absolute `0o640` assertion sound: fchmod on the temp fd sets exact bits, unaffected by umask.
*Fix:* "Permissions are applied with `(*os.File).Chmod` to the temporary file before rename, so the published mode is exact and unaffected by umask; on Windows only the read-only attribute is honored and the file inherits the parent directory's ACL."

**2. Low — `publish.go:19` — the newly added `ErrEmptyPath` precondition is invisible in godoc**
`ErrNilContext`/`ErrNilWriter`/`ErrEmptyPath` have no per-var doc comments, and neither `PublishFile` (`:34`) nor `WriteStream` (`:84`) names them. The empty-path refusal is new behavior in this delta; a caller reading the exported API has no way to learn which sentinel to match with `errors.Is`, or that it is returned before any file is created. The precondition is only discoverable from the private test at `publish_test.go:366`.
*Fix:* add one sentence to `PublishFile`'s comment — an empty `path` returns `ErrEmptyPath` and a nil `ctx` returns `ErrNilContext`, both before the temporary file is created — and a line to `WriteStream` for `ErrNilWriter`.

**3. Low — `publish_test.go:50` — the newly documented symlink-replacement guarantee has no test**
`publish.go:38` makes a specific, platform-independent, cheaply testable claim (symlink destinations replaced rather than followed, link target left untouched). Nothing in the suite creates a symlink. This is the one new non-Unix/ownership boundary claim that *is* assertable on the dev platform, and a future change to `atomicfile`'s path handling — e.g. resolving the destination with `filepath.EvalSymlinks` before choosing the temp directory — would silently invert the documented behavior and overwrite the link target with no test failing.
*Fix:* add a subtest that writes `target`, symlinks `dest -> target`, calls `PublishFile(ctx, dest, …)`, then asserts `os.Lstat(dest).Mode()&os.ModeSymlink == 0` and that `target` still holds its original bytes. Note `requireNoTemps` (`:39`) asserts a single directory entry, so point the symlink at a target in a separate directory or give that subtest its own residue check.
