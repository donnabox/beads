## Settled law and sound implementation seams

- **Fresh creation is unambiguous in scope.** `docs/specs/bdp.md:5758–5787` requires strict current reads and a representation meeting the supplied same-view minimum or explicit consistency failure. Fresh Snapshot creation at `:5829–5843` obtains a new transaction-consistent anchor, and the creation response table at `:5915` expressly includes consistency failures. There is no old immutable anchor to reinterpret. HEAD has decision/context parity without a usable handle. This does not establish retained-anchor versus current-serving comparison law.
- **Same-entry owner check is the right boundary.** `transaction-store.ts:1425–1464` already captures context in one synchronous `enter`, performs expiry maintenance, then preflight/capture or retained lookup, and pairs expected Snapshot failures with that same context. Checking the captured minimum before expiry/copy/allocation preserves the proposed no-allocation rule and lets `TransactionMinimumFailure` escape the Snapshot-only catch. Keep retained requests explicitly rejected if misused through this new private argument. This is not an assertion that all maintenance is universally prohibited or that every simultaneous error has new normative precedence.
- **Reuse actual deadline/cancellation/lifecycle.** `waitForTransactionMinimum` snapshots one finite deadline, retries only reason=behind, checks signal before attempts, and returns the last attempted context on timeout. `service.run` tracks the awaited promise through close/drain. Capture controls before asynchronous retries and invoke the actual owner inside each attempt. A controlled wait may commit a mutation only after the prior owner entry unwinds. Pre-abort and disconnect controls are feasible using the existing C1 synchronization pattern; no instantaneous interruption of synchronous copying or pending sleep should be claimed.
- **Keep both authoritative HTTP branches.** `transaction-http.ts:417–430` uses a pure media/conditional candidate only to select capture versus nonallocating preflight. Both branches must receive the minimum and signal. `applyReadHttpSemantics` transforms only successful representations, so an authoritative consistency failure survives the outer conditional/negotiation pass. For a successful preflight, the JSON/no-validator decision is identical to the candidate; a non200 candidate therefore returns rather than reaching capture. Record that reasoning or assert the single-terminal-branch invariant so no second service call can renew a deadline. Capacity/integrity checks must remain on eligible preflight paths. Explicitly retain a406-with-minimum case as well as304/412/HEAD checks, without inventing a broad406/error precedence law.
- **Independent state evidence is feasible.** A deterministic behind→real commit→capture test can require literal newly committed Resource values plus matching manifest anchor/checkpoint/current context; bypassing the owner check returns old state and fails independently of a wait counter. Direct table counts after closing the owner can prove no handle/page/record allocation on unsuccessful attempts without whole-store inspection. Installed fixed-head waits supply real timeout evidence; they do not prove behind→catch-up scheduling. Preserve that distinction.
