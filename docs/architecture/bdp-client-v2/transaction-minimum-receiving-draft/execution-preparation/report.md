# Closed source validation preparation

Root release is absent. No supervisor, command, test or import has been executed.
The thirteen proposed stages run seven existing setup/static/build checks, then
six bounded exact-selection commands: three consistency callbacks, eight HTTP
callbacks, one Snapshot, one schema, one changefeed, and four citation/boundary
callbacks. The latter are CPU-only. This is18 selected callbacks total, with14
source callbacks accounting for131 scheduled HTTP dispatches/13 owner lifetimes.

The reviewed receipt supervisor is reused with only workspace/base/branch,
eleven-path inventory, command pins/order and direct Vitest launcher selection
substitutions. supervisor.patch retains the complete delta. Every command invokes
the session guard, pins Node24.16.0 in PATH, rechecks all source bytes/full diff
before and after, uses exclusive attempt files, and stops the prefix at any
failure. There is no retry, source edit, broader test selection or automatic
control/installed invocation. Output is raw log, verbose plus JSON results,
exact passed names/count, process sampling, elapsed/exit/timeout and temp evidence.
TERM115/KILL120 applies only to the owned process group. Unknown temp entries
are retained for classification; fixture prefixes must be absent. Known sampled
PIDs must be absent. A finite expected workload is not live network accounting.

Setup is the existing offline frozen install (ignore scripts). Later direct
Vitest.mjs exists only after that setup; no current installed dependency graph
is invented. Node and pnpm paths reuse pinned repository toolchain. Tests load
normal Vitest config/setup and declared source imports, while HTTP/Snapshot
fixtures dynamically import the newly built dist runtime. The future emitted
control requires a separately copied complete source/dist/config/setup/tool
closure, and fresh installed runs require a separate clean candidate/archive/
consumer gate. Neither is released by this preparation.
