**Issue.** The `wisp-comment` and `wisp-label` fixtures are declared `orphan: false`, i.e. inserted *without* `FOREIGN_KEY_CHECKS=0`. Both tables carry an FK to `wisps(id)`:

**Impact.** `INSERT INTO wisp_comments(... issue_id='absent' ...)` and the `wisp_labels` equivalent violate the FK, `legacyImportContaminate` returns the error, and `t.Fatal` fires in the parent subtest — so the `dry=true`/`dry=false` subtests never run. **Fix.** Set `orphan: true` on both fixtures. The `remove` statements need no bypass — `DELETE` of a child row never trips a parent FK.

### F3 — MEDIUM · `internal/storage/graphstore/legacy_import.go:212` · guard covers 4 of the 11 native planes its own contract names

**Issue.** `issueops.DeleteCascadeTables` (`internal/storage/issueops/wisp_routing.go:200-252`) is the in-tree authority on "every table a DELETE of one issue (or wisp) row removes rows from." Its union is `issues, dependencies, labels, comments, events, provenance_events, child_counters, issue_snapshots, compaction_snapshots, wisps, wisp_labels, wisp_events, wisp_comments, wisp_child_counters, wisp_dependencies`. The repaired literal list adds `labels`, `wisp_dependencies`, `wisp_comments`, `wisp_labels` and still omits `events`, `provenance_events`, `child_counters`, `issue_snapshots`, `compaction_snapshots`, `wisp_events`, `wisp_child_counters`. The omission is not hypothetical: the `wisp_events`/`wisp_child_counters` orphan class is the same incident that produced "3.03M orphan rows" on the production store per `wisp_delete_cascade_integration_test.go:74-81`, where the aux FKs are absent and no bypass is needed to create them.

**Impact.** A destination that is "fresh" by this guard can still carry `events`/`issue_snapshots`/`compaction_snapshots` rows keyed to an ID the import is about to allocate (e.g. leftover rows for `old-b`). `verifyLegacyIssue` (`legacy_import.go:551`) inspects only the Issue payload, comments and dependencies, so nothing catches it: the import commits, reports `History: "current data only; new initial graph versions"`, and the imported Bead silently inherits a stale event feed and stale compaction snapshots. The hand-maintained literal is also the drift vector — the next schema addition will not be covered and nothing will fail.

Docs are overstated against the same gap: `docs/reference/graph-legacy-import.md:38` claims "wisp auxiliary rows", but two of the four wisp auxiliary tables created by `0021_create_wisp_auxiliary.up.sql` / `ignored/0002` are admitted.

**Fix.** Derive the native half of the list from the existing seam rather than restating it — dedupe `issueops.DeleteCascadeTables(false)` with `issueops.DeleteCascadeTables(true)` and append the graph-preview tables and `issue_versions` explicitly. One caveat worth an inline note: every added table except `wisp_child_counters` is main-lane; `wisp_child_counters` comes only from `ignored/0002`, so either probe its existence or state why the ignored lane is assumed present (today's guard queries no ignored-lane-only table). If the list is intentionally held at the current four, narrow `docs/reference/graph-legacy-import.md:38` from "wisp auxiliary rows" to the three tables actually guarded, and extend `legacyImportState`'s dump (`legacy_import_test.go:249`) in step with whichever set wins.

### F4 — MEDIUM · `internal/storage/graphstore/legacy_import.go:225` · fourth spelling of the memory-key prefix, plus a magic length

**Issue.** `"SELECT COUNT(*) FROM config WHERE LEFT(\`key\`,10)='kv.memory.'"` hardcodes both the prefix literal and its byte length. `internal/storage/kvkeys/kvkeys.go` exists specifically to end that duplication — its package doc names the three structurally-forced copies it replaced and `memoryops` restates it: "A second copy of `kvkeys.Prefix + kvkeys.MemoryPrefix + key` is the drift kvkeys was created to end." There is also already a canonical prefix-scoped config read: `issueops.ConfigPrefixLikeQuery` + `issueops.ConfigPrefixPattern` (`internal/storage/issueops/config_metadata.go:56-68`), which escapes `%`/`_` with an explicit `ESCAPE '!'` — the exact `_`-wildcard hazard `memoryops.ListInTx` warns about and that the `LEFT()` form sidesteps by hand.

**Impact.** Renaming `kvkeys.MemoryConfigKeyPrefix` leaves this guard matching nothing, with no compile error and no test failure (`kvkeys_test.go` pins only the constant, not tree-wide literals): legacy KV Memories would silently pass as a fresh destination again, re-opening the dual-memory-plane defect this repair closes. The literal `10` is the worse half — it must be kept in lockstep with a string it does not reference, and an off-by-one in either direction either admits every `kv.memory.*` row or counts unrelated `kv.*` keys as memories.

**Fix.** Use both seams:

```go
rows, err := tx.QueryContext(ctx, issueops.ConfigPrefixLikeQuery,
    issueops.ConfigPrefixPattern(kvkeys.MemoryConfigKeyPrefix))
```

then refuse if any row comes back (row presence, not value, which preserves the empty-value requirement). `graphstore` already imports `issueops`, and no `.golangci.yml` depguard rule restricts `kvkeys` or `issueops`. A minimal alternative that keeps the current query shape is to bind both operands: `LEFT(\`key\`,?)=?` with `len(kvkeys.MemoryConfigKeyPrefix)` and `kvkeys.MemoryConfigKeyPrefix`.

### F5 — LOW · `legacy_import_test.go:307-317` (frozen copy) · failed FK restore returns a permissive session to the pool

**Issue.** In the frozen copy the deferred `SET FOREIGN_KEY_CHECKS=1` joins its error into the return value but still lets `conn.Close()` hand the connection back to the pool. **Already fixed in the working tree** (F2) by discarding the connection via `conn.Raw(… driver.ErrBadConn)`.

**Impact.** On a reset failure, a pooled connection with FK enforcement off serves every later statement in the same store — including the `ImportLegacy` under test and the `legacyImportState` dumps. Later subtests would then pass for the wrong reason, and the `t.Fatal` from the joined error could land in a different subtest than the one that broke the session.

**Fix.** Keep the working tree's `driver.ErrBadConn` discard. Defer ordering in both copies is correct — the restore is registered after `conn.Close()` and therefore runs before it, matching the comment.

## Validation of defect and repair

**Original defect is real, on both halves.** Pre-repair, `requireEmptyLegacyTarget` checked `graph_preview_catalog` but neither payload table, so a workspace whose catalog had been emptied — or whose payload rows were written bypassing the graph writers, which is the threat model the function's own comment states — passed as fresh. Orphan rows there are invisible to readers (`currentLinkInTx` gates on the catalog, `graphstore/dependencies.go:188`) but still occupy their primary-key paths, so a later create at the same path fails after its catalog insert succeeds. The config half is the sharper defect: classic `kv.memory.*` Memories survived an import that advertised a fresh destination, leaving `bd recall` serving the old plane while graph Memories existed separately.

**Repair is correct where it acts.** The guard runs inside the single `withTx` before any write and before the prefix `UPDATE`, so apply and dry-run refuse identically and nothing is reserved (`legacy_import.go:61-67`). Every newly listed table exists on the main migration lane and is empty in a freshly `Init`-ed workspace — `0016_default_config.up.sql` seeds only compaction keys, and `0035_migrate_infra_to_wisps` is a no-op with no `issues` rows — so there is no false-refusal path. Counting rows rather than non-empty values is the right call and is load-bearing, for the `ForgetInTx` reason in F6. `LEFT(…)=` over `LIKE` correctly avoids the `_`-wildcard trap inside `kv.memory.`; the control fixture `kv.memoryx.retained` is the right boundary case and would catch a `LIKE 'kv.memory%'` regression. On collation: a case-insensitive `config.key` collation could only over-refuse, never miss a real memory, so the comparison is safe in the direction that matters.

**Test shape is sound.** `legacyImportState` sorts every table dump, so the `reflect.DeepEqual` state comparisons are order-stable, and `workflowState` (`workflow_test.go:242`) already covers `graph_preview_payloads`/`graph_preview_links`, which is what makes the preservation assertion real for the orphan fixtures. Adding `config` to the dump is safe — `touchCoordination` writes only `graph_preview_scope` (`records.go:111`), so no existing before/after comparison in this file starts failing. The zero-result assertion holds (`legacy_import.go:204` returns `LegacyImportResult{}`; nil maps compare equal). F1 is the one thing standing between the authored test and a meaningful run.
