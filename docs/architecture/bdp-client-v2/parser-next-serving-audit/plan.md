In transaction-http.ts's existing Event branch, compute the media selector once. The new capture path requires ALL of:

- the ordinary receiver has accepted GET or HEAD and passed authentication and malformed-minimum receiving;
- transactionEventRequest returned source.kind === scope, source.url exactly new URL("events/", scope).href;
- its after is undefined AND URLSearchParams.has("after") is false (malformed/repeated query controls remain handled by the existing parser before this branch);

- request.headers.has("last-event-id") is false AND (lastEventIds?.length ?? 0) === 0. Header presence excludes even an empty value; raw field metadata is checked as well;

For that predicate only, currentReadMinimumHeaders preserves the whole lexical tuple. For all other Event requests retain transactionMinimumHeaders(...) ?? unsupported exactly as today. Do not move authentication, lexical validation, alias/receipt routing, Event parsing, or finite/SSE dispatch. SSE beginEvents and Last-Event-ID precedence are untouched. The response still goes through the existing catch/Problem/context/HTTP-semantic path; 503 must not turn into304/412/406 or a stream.

No new public option/feature flag is needed. The only newly admitted unknown tuple at HTTP is the exact initial finite Scope predicate above. Last-Event-ID is a wire receiving restriction; the internal finite owner API has no such header and does not need a synthetic header field.
