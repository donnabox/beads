## Outcome and authority

Make exact captured local schema documents retrievable by authenticated GET/HEAD at their actual configured `${scope}schemas/` retrieval URIs. Include captured transitive schema documents in that exact supported retrieval-identity subset. This is not complete hosting of every Scope-local installed closure. The existing Type inventory and descriptors already expose local propertiesSchema URLs; the current TX listener does not serve them. The accepted cold-client deployment objective requires this deployment's local links to work. This is not a blanket normative obligation to host or proxy every installed external schema.

Spec `docs/specs/bdp.md:1091–1098,1198,1234–1243` establishes Type/schema navigation and JSON Schema2020-12 reference semantics;2533–2584 requires the exact immutable pinned validation closure. General HTTP rules at1935–2007 supply GET/HEAD, negotiation, conditional and cache behavior. At5768 the actual general rule says “Transactional Scope-bounded responses carry” before the three-field block at5770–5774; it is not merely field syntax. There is no universal schema-route classification in that sentence. This implementation deliberately observes the selected authenticated exact local schema responses under this Scope owner and emits the actually observed current tuple as a conservative local serving contract consistent with that general rule. It neither classifies every static/external schema response as normatively Scope-bounded nor declares those responses exempt. This choice retains schemaObserved and its lifetime/current-context tests; it does not create minimum support or require a new operator ruling. Clients may skip schema reads (2592 onward), and external schemas remain valid offline contracts. Protocol bundle/problem identifiers explicitly need not dereference (46–56); do not attempt to host the GitHub bundle URI.

Complete cold discovery, public Transactional selection, arbitrary external hosting, schema minimum support, Event rulings and cumulative qualification remain separate. No normative schema/catalog change is proposed.

## Exact dispatch contract

At the existing runtime dispatch point immediately after the checks above and immediately before `handler.handle`, ask the private schema adapter for a handled result. It may handle a request only when **all** conditions hold:

1. Method is GET or HEAD.
2. Trusted authorization kind is authenticated. Read permission does not require canMutate; the configured owner remains all-visible.
3. None of these three request fields is present: `bdp-minimum-scope-position`, `bdp-scope-epoch`, `bdp-authorization-view`. Call the existing `hasMinimumControls(request)` from `transaction-http.ts:144–148`, exported solely for this source-internal reuse, and require it to return false. Its unchanged implementation uses `Headers.has` for every field. Do not copy the field list into the adapter. Empty values, malformed values, duplicate/combined values and partial tuples still count as present. Do not parse minimum values to decide eligibility.
4. The canonical request URL exactly matches one captured local schema retrieval URI in the private manifest. A prefix alone never grants a response.

Otherwise return an explicit not-handled result without observing the owner, then run the existing handler unchanged. Unknown/uninstalled/alternate targets, unauthenticated requests and every minimum-bearing schema request follow its actual existing behavior. **Never invoke the handler first and override its404 with a schema response.** Never invoke the schema adapter after a handler refusal to replace authentication/minimum/conditional behavior. Method-before-auth and Origin precedence remain those of the existing runtime; do not reinterpret a405/403 as a schema-specific decision.

For an eligible exact hit only, obtain schemaObserved once, attach its three current fields to the candidate200, apply shared HTTP selection exactly once, and deliver the result using the private raw-byte path. The sole transaction-http.ts change is exporting that existing guard; its implementation and all handler behavior stay unchanged. No package/index export, new list, consistency parser refactor or general framework is allowed. Normal runtime closing503 and unexpected-fault bodyless500 remain unchanged; no stale context fallback or claim of universal fault unreachability is introduced.

## Manifest and exact representation

Build a closed immutable lookup once from `contracts.capture.artifacts`, filtered to kind=schema and exact canonical, query/fragment-free retrieval URIs under the configured Scope's schemas namespace. Preserve external artifacts and artifacts outside this hosting namespace for offline validation; do not reject previously accepted installations or rewrite descriptor/reference URLs. A captured embedded `$id` is not automatically a retrieval alias. Existing offline graph compilation registers canonical and retrieval identities (`installed-schema-graph.ts:326–336`), resolves references against canonical IDs (498–500), and resolves descriptor propertiesSchema through that identity graph (513–517). Therefore differing `$id` reference bases and canonical/embedded-ID aliases can remain unreachable over HTTP even when the installed closure validates. Preserve that compatibility: no adapter-construction, configuration or runtime-start refusal for differing `$id`, outside-namespace artifacts or accepted query-bearing artifacts. Calling a refusal a serving assertion does not make it acceptable. Those cases remain explicit cold-traversal deployment gaps, not normative exemptions; the eventual complete profile milestone must account for them. Do not broaden the manifest to every Scope-local path or shadow real Resource routes. Do not serve descriptors, arbitrary files, normalized alternate encodings or a broader prefix route.

Use copied captured bytes, their byteLength and sha256, never mutable original administrative options or a new network fetch. An immutable UTF8 string reconstructed from captured base64 is suitable for exact raw delivery; keep any buffer private and avoid exposing mutable storage. Lossless decoding may supply the body object used by existing HTTP selection, but it is not the emitted representation. In particular, preserve whitespace, non-ASCII UTF8 and numeric spelling rather than serializing the object back to JSON.

Current `transaction-runtime.ts:86–93` serializes HttpResponse.body and therefore cannot carry these exact raw bytes. Keep the private adapter's result as selected HTTP metadata plus separate raw representation bytes/string; do not widen public HttpResponse. Extend the existing private deliver() with an optional exact representation bytes/string argument, used instead of JSON serialization when supplied. Supply it only for selected200; ordinary callers retain their current serializer. Keep the destroyed-response guard, x-bdp-development:non-attesting marker and defensive HEAD strip in that one sender. Do not add a parallel writer. Selected304/406/412 have no raw argument or body, so their selector metadata is preserved. HEAD200 may supply the exact representation to calculate the byte length but the existing final HEAD strip must suppress transmission.

Use the existing supported `application/json` representation, private/no-store and the shared `applyReadHttpSemantics`. No ETag, public digest or Last-Modified invention is needed. That helper handles negotiation/preconditions and strips HEAD body; after it returns, set Content-Length to the captured **byte** length only for selected200 GET/HEAD. Emit raw bytes only for200 GET. For304/412/406 emit no body and retain selected metadata: do not reattach Content-Type or invent Content-Length:0 for304. All selected responses keep the current Scope tuple, applicable cache fields and Vary. This follows the RU byte-hosting precedent without editing or refactoring RU.

Existing ingestion ceilings are1MiB per artifact and16MiB aggregate, with independent URI bounds. Decoded strings/parsed objects add real memory retention; measure and report those copies. This slice does not redesign capture storage or claim zero overhead.
