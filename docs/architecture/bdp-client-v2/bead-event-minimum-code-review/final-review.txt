### F2 — Owner comment is now narrower than the code it describes

### F3 — Service classification catch has an unreachable rethrow branch and no oracle
- **Severity:** low (informational; no change recommended).
- **Where:** `packages/server/src/transaction-service.ts:491-498`.
- **Analysis:** `transactionEventRequest` can only escape as `TypeError` (from `new URL(source)`) or `TransactionEventParameterError`; its internal `resolveCanonicalLocalResourceId`/`new URL(subject)` failures are already converted at `transaction-events.ts:167-173`, and `parseCanonicalScope` cannot fail for `owner.scope`. So `throw error` is defensive-only and untestable without mocking the parser (which the plan forbids). The adjacent `typeof source === "string"` test is likewise dead at type level; at runtime a non-string would throw `TypeError` from `new URL`, be swallowed as classification, and still reach the owner's `TypeError("Event source and cursor must be strings")` — i.e. the ordering requirement holds either way.
- **Impact:** none observable. Record it so the missing oracle is not later read as a coverage hole.
