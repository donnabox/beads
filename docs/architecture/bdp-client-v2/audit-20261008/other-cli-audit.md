# Non-Issue CLI portability audit

2026-10-08; immutable baselines in `baselines.json`. This is source-and-test-contract research, not a runtime qualification result. No source or database was changed, and no existing runtime test was run. “Portable” below means implementable by client/pack using generic BDP operations, with no Issue-specific server code. It does not mean the current Go implementation already takes that route. Main and Preview 2 are separate evidence sets.

## Verdict

Most non-administrative behavior can be implemented in a Rust client and packs using **Transactional BDP plus the optional History capability**. CRUD is not the obstacle. The substantial remaining questions are efficient selective reads, coherent graph views, portable restore semantics, and identifying the old commands that intentionally administer the underlying engine. A Read or Read+Update provider alone cannot satisfy every current operation: `sequence` is explicitly non-atomic, while `batch`, set mutations, snapshots and replication belong to Transactional. History is separately optional. A supported Issues-pack capability contract is therefore necessary; “any conforming BDP provider” must mean any provider meeting that contract, not an arbitrary Read-only implementation. [B docs/specs/bdp.md:97–190](https://github.com/gastownhall/bdp/blob/182f1fcf8a01d896976bff3c9e3fb87c596c6ca6/docs/specs/bdp.md#L97-L190)

Do not extend BDP with Issue endpoints to solve these issues. The read improvements should remain generic; admin commands should stay provider tooling; local integrations should stay client tooling.

## Existing primitives that must be credited

- Atomic ordered `batch` is one Scope, sees earlier staged operations, rolls back all operations on failure, and supplies durable idempotent receipts. Creation labels support later Bead/Link identity references but not result/property expressions. It has no interactive transaction. [B docs/specs/bdp.md:1246–1329](https://github.com/gastownhall/bdp/blob/182f1fcf8a01d896976bff3c9e3fb87c596c6ca6/docs/specs/bdp.md#L1246-L1329) [B docs/specs/bdp.md:4419–4493](https://github.com/gastownhall/bdp/blob/182f1fcf8a01d896976bff3c9e3fb87c596c6ca6/docs/specs/bdp.md#L4419-L4493)
- `updateWhere` and `deleteWhere` select and mutate at one serialization point, with cardinality guards. There is no expected-member-set guard. Limits fail the operation rather than silently truncating. Chunking is valid but loses whole-job atomicity. [B docs/specs/bdp.md:1586–1653](https://github.com/gastownhall/bdp/blob/182f1fcf8a01d896976bff3c9e3fb87c596c6ca6/docs/specs/bdp.md#L1586-L1653)
- Collection pages have stable snapshot semantics, exact type/endpoint filters, and bounded Boolean JSONPath. Selector explicitly excludes traversal, joins, projection, aggregation, functions and regex. Collection records are complete, have no per-request order and cannot include incident Links; complex ID unions can be encoded as OR selectors within target/selector limits. [B docs/specs/bdp.md:781–843](https://github.com/gastownhall/bdp/blob/182f1fcf8a01d896976bff3c9e3fb87c596c6ca6/docs/specs/bdp.md#L781-L843) [B docs/specs/bdp.md:5367–5455](https://github.com/gastownhall/bdp/blob/182f1fcf8a01d896976bff3c9e3fb87c596c6ca6/docs/specs/bdp.md#L5367-L5455)
- Transactional snapshots bootstrap a coherent complete authorized Scope containing Beads and Links. Continuations and a changefeed checkpoint preserve one anchor and support incremental local projections. This is stronger than two independently fetched collections. Strict current reads and minimum positions are freshness guarantees, not an arbitrary historical snapshot handle for every query. [B docs/specs/bdp.md:2035–2065](https://github.com/gastownhall/bdp/blob/182f1fcf8a01d896976bff3c9e3fb87c596c6ca6/docs/specs/bdp.md#L2035-L2065) [B docs/specs/bdp.md:5593–5725](https://github.com/gastownhall/bdp/blob/182f1fcf8a01d896976bff3c9e3fb87c596c6ca6/docs/specs/bdp.md#L5593-L5725)
- History lists retained versions with truthful completeness/participation metadata, exact reads, replaced lineage and historical diagnoses. Listing versions does not return their bodies; availability can differ between listing and subsequent fetch. [B docs/specs/bdp.md:3127–3293](https://github.com/gastownhall/bdp/blob/182f1fcf8a01d896976bff3c9e3fb87c596c6ca6/docs/specs/bdp.md#L3127-L3293)

## Highest-priority findings

### P1: Memory search is expressible only by fetching and searching the corpus

Preview `memories SEARCH` is literal Unicode case-folded substring search over title and body, produces excerpts, optionally owned-Link counts, and orders canonical IDs. It consumes one checked current snapshot and limits successful output to 50 unless `--all`, with a 1 MiB output bound. Tests pin Unicode behavior, excerpts, order and refusal at limits. [P cmd/bd/graph_preview_memories.go:16–50](https://github.com/donnabox/beads/blob/6c33ea17af3bffbdea46a5ac04715c6dccd7c9bf/cmd/bd/graph_preview_memories.go#L16-L50) [P cmd/bd/graph_preview_memories_projection.go:54–119](https://github.com/donnabox/beads/blob/6c33ea17af3bffbdea46a5ac04715c6dccd7c9bf/cmd/bd/graph_preview_memories_projection.go#L54-L119) [P cmd/bd/graph_preview_memories_projection_test.go:75–184](https://github.com/donnabox/beads/blob/6c33ea17af3bffbdea46a5ac04715c6dccd7c9bf/cmd/bd/graph_preview_memories_projection_test.go#L75-L184)

BDP type filtering can restrict to Memory Beads, but cannot express this substring/case-folded search. To return one matching summary, a cold client may fetch every full Memory body and owned payload. If there are N memories and page size P, this is at least ceil(N/P) page requests and O(total body bytes), even when output is a handful of characters. Client-local search over a synchronized projection is correct but introduces bootstrap, retention/erasure/view handling, disk and freshness obligations. Generic text-search semantics/projection are a protocol option; a Memory-specific endpoint is unnecessary. Do not quietly change substring semantics to equality or platform-specific full-text ranking.

Main `remember` has an optional corpus byte budget. Its source explicitly labels List + Remember **advisory, not atomic**: concurrent writers can exceed it. Preserving that behavior is straightforward using a filtered read and write; a new hard corpus budget would be a new requirement, not a defect in BDP parity. Main's `Remembered` versus `Updated` result is observed atomically by the memory role; generic create-if-absent and revision-guarded update with conflict/re-read can reproduce it, at extra round trips because no generic upsert member exists. [M cmd/bd/memory.go:442–529](https://github.com/gastownhall/beads/blob/5126de8c1a02d01db2481e4fd5e78dd41010e25f/cmd/bd/memory.go#L442-L529) [M cmd/bd/memory_embedded_test.go:516–560](https://github.com/gastownhall/beads/blob/5126de8c1a02d01db2481e4fd5e78dd41010e25f/cmd/bd/memory_embedded_test.go#L516-L560)

### P1: Coherent small graph traversal currently has a whole-Scope transfer fallback

Preview generic graph deliberately projects one checked snapshot, traverses in/out/both, preserves distinct Link identities at diamonds/self edges, reports frontier completeness, and bounds nodes/Links to 1000. It does not fetch missing endpoint bodies during traversal. Tests pin directions/depth, frontier, limits, invalid snapshots and summary allowlists. [P cmd/bd/graph_preview_generic_projection.go:45–187](https://github.com/donnabox/beads/blob/6c33ea17af3bffbdea46a5ac04715c6dccd7c9bf/cmd/bd/graph_preview_generic_projection.go#L45-L187) [P cmd/bd/graph_preview_generic_projection_test.go:55–150](https://github.com/donnabox/beads/blob/6c33ea17af3bffbdea46a5ac04715c6dccd7c9bf/cmd/bd/graph_preview_generic_projection_test.go#L55-L150)

Generic BDP incident-Link reads and endpoint collection filters make a client BFS possible. Without parallelism, a naive implementation performs one or more Link pages plus endpoint fetches per expanded node; parallel frontier requests reduce latency but do not establish one shared read snapshot. OR selectors can batch frontier IDs, subject to selector/URL limits, and still need another selection to hydrate Beads. Minimum-position headers cannot force all these reads to the same past point. A full Scope snapshot followed by local projection is the existing correct single-anchor route, costing O(all visible Beads + Links) on a cold invocation, not O(returned neighborhood). A persistent snapshot/changefeed projection is another correct route. A generic snapshot-bound multi-read/traversal facility is a candidate design improvement; this is an efficiency gap, not an impossibility of graph computation. [B docs/specs/bdp.md:2035–2065](https://github.com/gastownhall/bdp/blob/182f1fcf8a01d896976bff3c9e3fb87c596c6ca6/docs/specs/bdp.md#L2035-L2065) [B docs/specs/bdp.md:5326–5455](https://github.com/gastownhall/bdp/blob/182f1fcf8a01d896976bff3c9e3fb87c596c6ca6/docs/specs/bdp.md#L5326-L5455) [B docs/specs/bdp.md:5692–5725](https://github.com/gastownhall/bdp/blob/182f1fcf8a01d896976bff3c9e3fb87c596c6ca6/docs/specs/bdp.md#L5692-L5725)

### P1: “Export/import” and “backup/restore” need separate promises

Current Issue JSONL export collects all matching Issues and bulk relations (labels/dependencies/comments); memories are opt-in, and internal wisp-plane markers distinguish storage semantics. Import skips schema headers/tombstones and applies current records; it is not a full retained-history replica format. Tests explicitly require chunking, keeping blocking dependencies in each row's transaction, and a committed prefix after a middle chunk fails. Therefore whole-file atomic import is not required by today's CLI. [M cmd/bd/export.go:166–320](https://github.com/gastownhall/beads/blob/5126de8c1a02d01db2481e4fd5e78dd41010e25f/cmd/bd/export.go#L166-L320) [M cmd/bd/import.go:265–328](https://github.com/gastownhall/beads/blob/5126de8c1a02d01db2481e4fd5e78dd41010e25f/cmd/bd/import.go#L265-L328) [M cmd/bd/import_chunking_test.go:131–292](https://github.com/gastownhall/beads/blob/5126de8c1a02d01db2481e4fd5e78dd41010e25f/cmd/bd/import_chunking_test.go#L131-L292)

A portable current-state export can use a BDP snapshot and client projection. A portable content import can create/update generic Beads/Links in ordered batches, preserving dependency ordering and reporting partial job completion when limits require chunks. It must specify overwrite/merge/dedup/ID-map semantics, concurrency guards, historical attribution, and whether foreign absolute IDs are rehomed. It cannot silently promise identical source revisions, complete history, engine commits, timestamps, authority identities or erasure status simply by replaying create/update requests. `batch` is a mutation API, not a history-ingestion API.

BDP's History import/recovery contract explicitly requires origin/version and erasure evidence before retained copies become visible, and explicitly adds **no HTTP import endpoint**. Thus lossless historical clone/restore through an arbitrary provider's standard mutation endpoint is not currently provided. A client can acquire a complete current Scope snapshot and subsequent changefeed for a controlled replica, but instantiating that replica into another independent authority requires an implementation/admin route and identity decision. [B docs/specs/bdp.md:3327–3356](https://github.com/gastownhall/bdp/blob/182f1fcf8a01d896976bff3c9e3fb87c596c6ca6/docs/specs/bdp.md#L3327-L3356) [B docs/specs/bdp.md:5593–5725](https://github.com/gastownhall/bdp/blob/182f1fcf8a01d896976bff3c9e3fb87c596c6ca6/docs/specs/bdp.md#L5593-L5725)

Physical `backup init/sync/status/remove/restore` administers Dolt remotes and files. Existing tests intentionally allow it only where bd owns the local server and refuse shared/external topology. A generic BDP client should offer a clearly named logical export/checkpoint backup and leave engine backup/restore to Brian's Postgres/provider tooling. The old command's physical semantics cannot honestly be preserved by renaming a logical export. [M cmd/bd/backup_restore.go:18–109](https://github.com/gastownhall/beads/blob/5126de8c1a02d01db2481e4fd5e78dd41010e25f/cmd/bd/backup_restore.go#L18-L109) [M cmd/bd/capability_registry.go:198–228](https://github.com/gastownhall/beads/blob/5126de8c1a02d01db2481e4fd5e78dd41010e25f/cmd/bd/capability_registry.go#L198-L228) [M cmd/bd/backup_proxied_policy_test.go:90–180](https://github.com/gastownhall/beads/blob/5126de8c1a02d01db2481e4fd5e78dd41010e25f/cmd/bd/backup_proxied_policy_test.go#L90-L180)

### P1: History is portable; Dolt commits, revision ordinals and branch diff are not

Preview `versions` and `compare` can map to BDP retained-version pages and two exact historical reads, then a client diff. But Preview prints a **store-local ordinal** (`local_revision`) and demands at least one citable version for an allocated resource; generic BDP intentionally exposes no store ordinal and allows `not-tracked`, `undetermined`, incomplete/partial windows and absent metadata. A V2 output contract must represent those states honestly and cannot invent portable ordinals or missing timestamps. [P cmd/bd/graph_preview_versions.go:28–78](https://github.com/donnabox/beads/blob/6c33ea17af3bffbdea46a5ac04715c6dccd7c9bf/cmd/bd/graph_preview_versions.go#L28-L78) [P cmd/bd/graph_preview_compare.go:33–56](https://github.com/donnabox/beads/blob/6c33ea17af3bffbdea46a5ac04715c6dccd7c9bf/cmd/bd/graph_preview_compare.go#L33-L56) [B docs/specs/bdp.md:3242–3293](https://github.com/gastownhall/bdp/blob/182f1fcf8a01d896976bff3c9e3fb87c596c6ca6/docs/specs/bdp.md#L3242-L3293)

Main `history` returns Dolt commit hash/date/committer and optional Issue snapshots, while `diff <from-ref> <to-ref>` invokes store.Diff on engine references. BDP can provide resource-version history, but the exact existing Dolt result is not provider-neutral. Hydrating H full historical states costs versions pages plus H exact GETs; there is no standard bulk history body retrieval, though independent GETs can run concurrently. Tests pin full-hash history and explicit remote refusals, and Preview tests pin deleted-Link version behavior; these are useful parity or intentional-change contracts, not proof of HTTP BDP support. [M cmd/bd/history.go:66–126](https://github.com/gastownhall/beads/blob/5126de8c1a02d01db2481e4fd5e78dd41010e25f/cmd/bd/history.go#L66-L126) [M cmd/bd/diff.go:13–55](https://github.com/gastownhall/beads/blob/5126de8c1a02d01db2481e4fd5e78dd41010e25f/cmd/bd/diff.go#L13-L55) [M cmd/bd/history_remote_frontdoor_matrix_test.go:29–78](https://github.com/gastownhall/beads/blob/5126de8c1a02d01db2481e4fd5e78dd41010e25f/cmd/bd/history_remote_frontdoor_matrix_test.go#L29-L78) [P cmd/bd/graph_preview_versions_test.go:49–104](https://github.com/donnabox/beads/blob/6c33ea17af3bffbdea46a5ac04715c6dccd7c9bf/cmd/bd/graph_preview_versions_test.go#L49-L104)

### P1: Administrative compatibility must be explicit

`branch`, `vc merge/commit/status`, `conflicts`, `flatten`, Dolt lifecycle/remotes, native SQL, migration/schema repair and physical backup operate on engine-specific state. They have no equivalent in the BDP resource mutation vocabulary. Many already deliberately refuse remote/shared mode; the capability registry carefully separates design refusal from implementation gaps. “Permitted” only means a pre-run gate allowed a command, not that a route exists. Do not treat these entries as proof of BDP portability. [M cmd/bd/capability_registry.go:20–51](https://github.com/gastownhall/beads/blob/5126de8c1a02d01db2481e4fd5e78dd41010e25f/cmd/bd/capability_registry.go#L20-L51) [M cmd/bd/capability_registry.go:289–324](https://github.com/gastownhall/beads/blob/5126de8c1a02d01db2481e4fd5e78dd41010e25f/cmd/bd/capability_registry.go#L289-L324) [M cmd/bd/branch.go:12–75](https://github.com/gastownhall/beads/blob/5126de8c1a02d01db2481e4fd5e78dd41010e25f/cmd/bd/branch.go#L12-L75) [M cmd/bd/vc.go:170–285](https://github.com/gastownhall/beads/blob/5126de8c1a02d01db2481e4fd5e78dd41010e25f/cmd/bd/vc.go#L170-L285) [M cmd/bd/sql.go:16–90](https://github.com/gastownhall/beads/blob/5126de8c1a02d01db2481e4fd5e78dd41010e25f/cmd/bd/sql.go#L16-L90)

This does not invalidate client-over-BDP for the Issues pack. It does require an explicit coexistence policy: keep legacy engine maintenance under legacy bd/provider administration, and give V2 typed “provider administration required” diagnostics rather than misrouting commands or mutating server state as if it were a local workspace.

## Qualification cases to carry forward

1. A generic transactional provider with no Issue/Memory-specific endpoints must run memory create/update/delete, graph plan, export/import chunk and compact/restore scenarios using only BDP requests. Assert request paths and operation discriminators, not just final state.
2. Populate 100k large Memories with one substring match: measure cold bytes and requests, then warm indexed-client freshness/erasure behavior. Success at 50 results is insufficient if it downloaded the whole corpus.
3. Traverse depth 2 in a small component of a million-resource Scope during concurrent Link mutation: verify coherent result/frontier or an explicit consistency mode, and record whole-Scope amplification.
4. Import beyond advertised transaction/resource/event limits: verify no partial chunk, clear committed prefix, idempotent recovery, dependency edges committed with rows, and no accidental whole-job atomicity claim.
5. Export while mutating data: reconstruct Bead/Link agreement from one snapshot, then resume from its checkpoint. Independent collection cursors are insufficient evidence of a common anchor.
6. Versions/show/compare against tracked, not-tracked, undetermined, replaced, erased, incomplete, deleted and unauthorized histories. Never invent local_revision or interpret an incomplete window as “no history.”
7. Execute client-local help/setup/worktree/config against an unreachable BDP URL and verify store-free operations remain store-free; exercise provider-admin refusal before any remote mutations.
8. Test external integrations with partial external success and BDP failure/retry; prove reconciliation rather than claiming a cross-service batch transaction.

These are proposed qualification requirements. The cited existing tests were inspected, not executed. There is no claim here that Rust implementation, a Postgres endpoint, or the current Go CLI has already passed BDP-provider parity.
