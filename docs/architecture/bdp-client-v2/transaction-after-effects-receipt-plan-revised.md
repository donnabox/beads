## Why the current private grammar cannot execute the row

1. `transactional-observation.ts:180–181` explicitly refuses completed source receipts with next!=null (`source receipt exceeds inline fixture`).
2. receiptUrl:56–77 accepts only a canonical root checkpoint token after receipts/, rejecting `/pages/` paths.
3. register:129–201 grants authority only to a canonical mutation POST capture at `/id`; `/next` is treated as an ordinary capture and revokes prior authority.
4. `runner.ts:876–978` resolves a receipt binding, builds the exact one-request route from source.receipt, forces mutationReceipt schema/body.id agreement and next:null at runner.ts:957, then returns a closed client projection. This root-GET restriction is a second required relaxation in addition to source registration at transactional-observation.ts:180–181; actions2/5/12/15 depend on it.
5. Dynamic client receipt-read deliberately has runRequest.captures=[], so its later programmatic captures cannot secretly grant new HTTP authority. Ordinary exact routes are predeclared before execution. Merely capturing a page URL or constructing one from a key cannot work safely.

Thus changing only manifest/coverage/tests is insufficient. This is a small explicit private observation seam requiring root approval, not a new protocol question.
