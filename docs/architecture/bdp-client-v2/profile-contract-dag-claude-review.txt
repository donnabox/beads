## N3 verdict: **CLOSED**

The repair takes the second option the native review offered (`native-review.md:13`, "a catalog-order pass using the existing earlier-than constraint") rather than the three-colour DFS the Claude review proposed (`claude-review.txt:120`). That substitution is sound, and it is actually the stronger of the two choices here because it removes the cycle bookkeeping instead of reimplementing it.

**Why the `ancestors` set was safe to delete.** In the old code the recursive descent was guarded by `earlier(id, dependency) && dependencyReady(dependency, next)` — `&&` short-circuits, so recursion only ever entered a node at a *strictly smaller* catalog position (`earlier` at `:367-368` is a strict `<` on `positions`). Position is a finite integer, so no id could recur on a descent path and `ancestors.has(id)` was unreachable dead code. Cycles were, and still are, rejected by `earlier` alone. Memoizing a well-founded recursion whose only cycle guard was unreachable is exact, not approximate.

**Why one pass suffices.** The loop iterates `selection.catalog.scenarios` in ascending index, and the only map read is `dependencyReady.get(dependency)` behind the same short-circuited `earlier` — so a value is read only when `pos[dep] < pos[id]`, i.e. written in an earlier iteration. No read-before-write; catalog order *is* the topological order. Verified the two invariants this now rests on:

- `required ⊆ catalog.scenarios`, same relative order — `selectApplicableScenariosForProfile` is a `catalog.scenarios.filter(...)` (`selection.ts:54-63`), filtered again by `kind` (`:66-73`). So every required id gets a DP entry.
- ids are unique — `catalog.scenarios = [...byId.values()]` (`profile-contract-plan.ts:109`), so `positions` and the DP map are 1:1 and the loop writes each id once.

## Regression test: no timing dependence

Deterministic: no timers, no concurrency, no randomness; the count is a pure function of catalog size, edge count and parser code.

- `originalGet` is captured *before* `spyOn` (`:435` then `:438`) — no self-recursion. The membership test uses `Set.prototype.has`, not `Map.get`, so the guard can't feed itself.
- It **throws** on overrun rather than waiting, and `profile-contract-plan.ts` has no `try`/`catch` anywhere, so the error propagates intact to the test — a regression fails fast instead of hanging CI.
