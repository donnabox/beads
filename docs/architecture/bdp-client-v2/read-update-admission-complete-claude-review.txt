# Findings

## 1. MEDIUM — Per-carrier parameterized-JSON success was added by *replacing* the bare-`application/json` success, not alongside it

**Location.** `packages/conformance/matrices/read-update-v1.json`, scenario index 33 (`read-update.singleton.unsupported-media-type`), actions `media-route-{create-bead,update-bead,delete-bead,create-link,update-link,delete-link,put-alias,delete-alias,sequence}-corrected`.

**Evidence.** All nine `-corrected` actions were converted from `family:"client"` / `installed.exact-request` (plain `application/json` via the client) to `family:"http"` raw actions carrying `application/json; charset=iso-8859-1; arbitrary=ignored`. That is the whole `43 → 34` client / `73 → 140` raw shift in the media ledger. The media row's raw POST content-type tally is now: absent 9, `text/plain` 10, `text/plain; charset=utf-8; arbitrary=ignored` 9, `application/json; charset=iso-8859-1; arbitrary=ignored` 9, `application/problem+json` 1, `application/json; charset=iso-8859-1` 1, `application/json; arbitrary=ignored` 1 — **zero bare `application/json`**. The only bare-JSON mutation successes left in the row are the two client actions `media-plain-corrected` and `media-problem-corrected`, both on `create-bead`. So per-target bare-JSON success went from 9/9 (client) to 1/9.

**Impact.** This is an exact selected-clause gap, not an out-of-scope law. For `#readupdate-problem-details` / spec 3432–3434 "parameters … are ignored", the row now observes, at each of 9 targets, *parameterized* JSON → 200 and *parameterized* non-JSON → 415. It never compares either against the bare form at 8 of them. An implementation that *required* a Content-Type parameter at those 8 targets would satisfy every media-row observation. This is exactly the degenerate-implementation control the plan's own B.4 clause ("Ordinary `application/json` success remains the baseline") exists to exclude, and whole credit here is row-local, so the key row's 8 bare-JSON client corrections and the other 45 rows do not close it.

**Bounded fix.** Add one bare-`application/json` raw success per remaining target, or re-bare one of the nine and add a parameterized sibling. No new route is introduced (`POST operations/<target>` and `GET beads|links?limit=100` are already in the digest), so `exactConfigurationDigest` is unaffected; manifest + the coverage binding list + the media ledger pin only. Cost ≈ 27 actions ≈ 54 KB at the measured ~2.0 KB/action, inside the 891,401-byte headroom.
