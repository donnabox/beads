## Findings

### 1. HEAD content-length regression cannot fail — the page under test is pure ASCII
**Severity:** Low (test discriminating power)
**Location:** `packages/server/src/transaction-events.test.ts:475-480`; invariant at `read-http.ts:44`

`bead("a")` seeds `properties: {n: 0}` (`transaction-events.test.ts:93-97`) and the source URL is ASCII, so the `beads/a?view=events` body contains no multibyte code unit. `Buffer.byteLength(correspondingText) === correspondingText.length`, and the assertion passes identically if `read-http.ts:44` regressed from `Buffer.byteLength(stringifyJsonValue(body))` to `String#length`. The implementation is correct today; the new control does not hold it. report.md:27 states the invariant as "actual UTF8 byte count," which the test does not discriminate.

**Remedy:** assert HEAD content-length against a source carrying non-ASCII Event data — the `'\"\\\n🦄'.repeat(100)` fixture already used at `:688` — or add `expect(head.headers.get("content-length")).not.toBe(String(correspondingText.length))`.

### 2. Exact wire-byte equality of the new incremental accounting is never observed
**Severity:** Low (test coverage; report overstates observation)
**Location:** `packages/server/src/transaction-store.ts:1286-1288, 1328-1335`; test `:687-718`

I verified the algebra is exact, not merely conservative: `envelopeBytes` is the `{source,events:[],next:null}` serialization minus the 4-byte `null`, `candidateBytes` contributes n−1 commas, the continuation adds `byteLength(json(url))` including quotes/escaping, key order `source, events, next` is identical in both literals, `stringifyJsonValue` preserves enumeration order (`json-values.ts:94-101`), `freezeEventPage` freezes in place without rebuilding keys (`transaction-events.ts:259-269`), and `renderTransactionEvent`'s spread fixes each Event's key order once (`:84-88`). The emitted overflow page is byte-for-byte the measurement that admitted the last accepted Event.

None of that is asserted. The new test proves call counts (`:701`, `:706`) and a loose `< TRANSACTION_EVENT_PAGE_BYTES` (`:707`); `collect()` asserts only `<=` the bound (`:128`); the long-source split test (`:352-363`) splits thousands of bytes below 4 MiB. A one-byte drift — an added envelope field, a renamed `next`, a dropped comma — is silently admissible. report.md:22's "algebraically the same bytes as the prior serialization" is sound reasoning presented alongside observed evidence that does not cover it.

**Remedy:** in the accounting test, assert the accumulated total equals `Buffer.byteLength(stringifyJsonValue({ source, events: result.page.events, next: eventContinuation(source, lastId) }))` — one equality pins the whole derivation.
