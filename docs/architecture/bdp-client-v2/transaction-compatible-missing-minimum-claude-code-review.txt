## Current defects

**1 — Low/Medium — `packages/server/src/transaction-read.ts:112,118` — the ordinary-facet rebuild silently drops *all* delivery-option validation, not just `sourceCondition`.**
`options?.signal ? { signal: options.signal } : undefined` replaces the caller's object with a fresh literal, so `authority-read.ts:1053-1064` never sees the original and `ownData` (`:297-313`) never runs on it. Lost rejections: unknown own keys (`{typo: 1}` → was `AuthorityReadError("invalid-input","unknown Read delivery option")`); a present-but-falsy signal (`{signal: null}`, `{signal: 0}`, `{signal: ""}` → was `"Read signal must be an AbortSignal"`, now silently treated as no signal); Proxy / array / non-plain-prototype options objects; symbol fields; accessor properties — and `options?.signal` now *invokes* a `get signal()` getter that the descriptor-based path deliberately never touched. Plan v2 §Source mechanism authorized only "forward only the caller's optional `signal`; do not forward `sourceCondition`", and §"Done when" accepts only "ordinary-facet `sourceCondition` is explicitly ignored while signal works" — the validation loss is undisclosed in both the plan and `report.md`, which says "forward signal only". It also makes `readFor` strictly weaker than `minimumFor:142`, whose `{...options, sourceCondition: minimum}` still surfaces unknown keys and a null signal to `ownData`. No production impact today: the only caller chain is `transaction-http.ts:220` → `service.readFor` → `facet.perform(parsed, { signal: request.signal })`, always a real `AbortSignal`; and no existing test covers delivery-option validation anywhere (`grep` for `"unknown Read delivery option"` / `"must be an AbortSignal"` in `*.test.ts` returns nothing), which is why the change is green. The exposure is embedder-visible, in a module that otherwise rejects proxies and accessors systematically.
*Repair:* narrow by descriptor instead of by literal. In `createTransactionReadPlane`, add one helper used by both `perform` and `resolveAlias`: reject `options` that is a Proxy, array, or non-plain-prototype object; walk `Reflect.ownKeys(options)` and reject any key other than `"signal"`/`"sourceCondition"` (and any symbol); reject a `signal` descriptor without `"value" in descriptor`; then return `{ signal: descriptor.value }` only when `signal` is an own data property, else `undefined`. Behaviour for `{sourceCondition}` stays "silently ignored" as planned, and a non-`AbortSignal` value still fails downstream. Add a sensitivity test in `transaction-read.test.ts` asserting `{signal: null}`, `{unknown: 1}`, `new Proxy({},{get:()=>undefined})` and `{get signal(){ throw … }}` all reject on the ordinary facet while `{sourceCondition}` is still ignored.

**2 — Low — `docs/design/transaction-implementation-progress.md:676-677` — committed doc cites an evidence path that does not exist in the repository.**
"recorded in the workstream's `transaction-compatible-missing-minimum-implementation/report.md`" resolves to nothing: that directory lives in the sibling, untracked `/Users/dbox/repos/wt/vickie/bdp-integration-logs/`, and `git ls-files | grep bdp-integration-logs` is 0. As written, a reader or doc-link check cannot follow it, and it will silently rot.
*Repair:* either replace with a commit-pinned absolute URL matching the existing precedent, or name the external location explicitly ("the operator's out-of-tree `bdp-integration-logs/transaction-compatible-missing-minimum-implementation/` evidence directory, not tracked in this repository"), or drop the path and keep only the prose claim. Prose content is otherwise accurate — both reconciled paragraphs (661–671 subset prose and the Event paragraph at ~1070) correctly avoid any owner-wide arbitration claim.

**3 — Low — `packages/server/src/transaction-http.test.ts:1234-1235` — no HTTP-level case for a *non-conditional* compatible-missing read.**
`...(earlier ? { "if-none-match": "*" } : { "if-match": '"mismatch"' })` puts a conditional header on every one of the 32 new cases, so the plain `GET`/`HEAD` + minimum-headers + missing-resource path has no unit-level 404/context assertion. The base case is currently proven only by installed rows 3/4/6/7/8, so a regression in the non-conditional HTTP path would surface only in the heavier packed run.
*Repair:* make the conditional dimension three-valued — `for (const conditions of [{}, { "if-none-match": "*" }, { "if-match": '"mismatch"' }])` — decoupled from `earlier`, or add one explicit non-conditional GET+HEAD pair. No production change.
