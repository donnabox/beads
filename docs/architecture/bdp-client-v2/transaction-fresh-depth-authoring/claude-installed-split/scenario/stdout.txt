## Findings — `apps/bdptest/src/transactional-fresh-depth-installed.test.ts` (13-request scenario, oracles, deep comparison, schema)

1. **MEDIUM — unanchored nesting constant.** `…installed.test.ts:136-137` (`"[".repeat(12000)`, `JSON.parse(deepText)`). Nothing ties 12000 to a production-supported depth: the private guard is removed, so the effective bound is V8's *recursive* `JSON.stringify`/parse stack, and the neighbouring installed depth witnesses use 41 levels (`transactional-sequence-depth-installed.test.ts:115`). The snapshot oracle (`:841-863`) requires the server to re-serialize ~5 copies of a 12000-deep array, and module load itself parses the depth twice (`:137`, `:405`). **Impact:** verdict depends on Node version/platform/`--stack-size`; a `RangeError` on either side fails this unexecuted witness for stack reasons while reading as a deep-serving defect. **Fix:** derive the depth from a declared shared constant and assert it (or reduce to a depth with stack headroom), plus one adjacent observation pinning the supported bound; recompute the pinned `bodyBytes`/`bodySha256` and the `169821` total at `:396` if the constant changes.

2. **MEDIUM — `sameJson` has no rejecting self-test.** `…installed.test.ts:100-135` with the only self-test at `:403-407`, which exercises acceptance only. **Impact:** this comparator is the sole content oracle for 9 of the 13 responses (seed/update/no-op receipts, replay, conflict problem, sequence, current link, event page, snapshot, receipt GET); a regression that makes it vacuously accept (lost `valid = false`, misplaced `continue`) turns the whole witness green with no other assertion covering receipt/resource/Event/Snapshot content. **Fix:** add `expect(() => sameJson(a, b, "x")).toThrow()` for a leaf difference at full `deepText` depth, unequal key counts, array-vs-object, and null-vs-object.

3. **MEDIUM — comparator failures report no locus.** `…installed.test.ts:134` (`expect(valid, label).toBe(true)`). Bodies reach ~170 KB with 24001-byte deep members, yet a mismatch yields only e.g. `fresh-depth:complete-Snapshot-and-owned-copies`. **Impact:** a genuine serving regression is reported as an unlocalizable boolean; diagnosing it costs exactly the kind of bounded-review time the earlier inconclusive run consumed. **Fix:** carry a pointer-style path with each worklist pair and append only the path (never values) to the failure label.

4. **LOW — the `-0` seed literal is unobserved.** `…installed.test.ts:152` (`"n":-0`), comparator short-circuit `:107`, expectations `:659`, `:794`. `-0 === 0`, so no assertion in the file can distinguish the admitted or served value from `0`; the only indirect observation is request 3's `effect=false` (`:676-683`). **Impact:** the probe currently tests nothing, and if production ever stopped normalizing `-0` the failure would surface as a bogus no-op/`effectPosition` defect rather than a numeric-normalization defect. **Fix:** after the seed, assert `Object.is(record(l0.properties).n, 0)`; keep the `===` leniency inside the comparator.

5. **LOW — the emitted report claims a body digest for the four bodyless GETs.** `…installed.test.ts:305,318,331,344` (`bodySha256: "e3b0c442…"`, the empty-string digest) projected at `:496-497`, while the wire assertions at `:509` and `:511-513` require `bodyPresent: false` and `bodyDigest: undefined`. **Impact:** the private evidence for requests 10-13 is indistinguishable from "a zero-length body was framed", the opposite of what was serialized. **Fix:** project `requestBodySha256: row.bodyRef === null ? null : row.bodySha256`.

6. **LOW — dead guard.** `…installed.test.ts:465` (`if (!row) throw …`) can never fire; `row` is the object literal built at `:460-464`, and the real lookup guard is already at `:457`. **Impact:** none at runtime; implies a second validation that does not exist. **Fix:** delete the line.
