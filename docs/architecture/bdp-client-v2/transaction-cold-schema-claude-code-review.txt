## Optional follow-ups

**1 — Low / `packages/server/src/transaction-schema-http.ts:63` — the captured `byteLength` never reaches the wire.**
`deliver` (`transaction-runtime.ts:92`) unconditionally sets `content-length` from `Buffer.byteLength(raw)` whenever `raw` is supplied, so the adapter's `content-length` set from `entry.byteLength` is overwritten on every emitted response. Consequences: `entry.byteLength` is retained but unused at runtime; the adapter-level assertion at `transaction-schema-http.test.ts:160-162` validates a header value no client can observe; and plan §46's intent ("set Content-Length to the captured **byte** length") is only nominally met — the emitted length is derived from the decoded string, so a lossy decode would yield a self-consistent wrong-bytes response rather than a length mismatch. Currently harmless: `ingestContractArtifacts` decodes with `TextDecoder("utf-8", {fatal:true, ignoreBOM:true})` at capture (`installed-contract-artifact.ts:346`), so base64→UTF-8→bytes is byte-exact by construction. *Fix (if taken):* either have `deliver` skip the overwrite when `raw` is supplied, or drop `byteLength` from the entry and line 63 and let the sender own the header. Either keeps the one-sender rule from dispositions External 5.

**2 — Low / `transaction-schema-http.ts:21,24,25,26` — four of six filter conditions are unreachable.**
`assertDevelopmentContracts` at line 16 guarantees `contracts` came from `compileDevelopmentContracts` → `ingestContractArtifacts`, which runs `parseCanonicalHttpUrl` on every `retrievalUri` (`installed-contract-artifact.ts:322`). That already rejects `href !== value`, `username`, `password` and any `#` (`read-values.ts:295-304`). Only the `?` check and the `${scope}schemas/` prefix are live filters. Not a defect — defence in depth on a serving filter is reasonable — but those branches are permanently uncoverable through the supported construction path, and a future reader may wrongly treat the adapter as the sole enforcement point. *Fix:* one comment naming capture as the primary validator.

**3 — Low (coverage) / `transaction-schema-http.test.ts:283-291` — no HTTP-level case for an alternate percent-encoded spelling.**
`root + "?x=1"`, `root + "/"`, `schemas/unknown`, an external URL and the type URL are all exercised only through `select(new Request(url))`; only `schemas/unknown` and the differing-`$id` canonical alias go through `wire()`. The installed test's `confinedObserved` checks `%72oot` client-side only. Behaviour is safe by construction (`normalizationSafeRawRequestPath` requires raw path === parsed path; the map is exact-string), but a single `wire(service, ".../schemas/ro%6Ft")` → 404 would pin it at the boundary that actually serves. Costs no new listener or installed request — this is the kind of existing-boundary gap the scope permits closing.

**4 — Low (evidence limit, not a code change) / `transaction-runtime.ts:338,168` — the no-contracts dispatch path is unvalidated locally.**
`createTransactionSchemaHttp` is now constructed unconditionally and `await schemas?.(input, authorization)` sits in the shared GET/HEAD path for *every* request, including runtimes started without `artifacts`. Every runtime in the new adapter suite supplies artifacts; the service run was `-t`-filtered to 2 of 65 cases; no broader runtime/HTTP suite ran locally (`report.md:21`). Risk is low (empty map → immediate `undefined`), and exact-head CI is root-owned — flagging the gap, not requesting a rerun.
