Read-only research, 2026-10-09. No runtime experiments or database writes; existing tests were inspected, not executed. This is evidence for Vickie's BDP comparison, not a release ruling or implementation plan.

## Finding: this already is a committed-effects feed, not merely notifications

Beads 1.3 records Issue mutations in the mutation's SQL transaction. Each record contains `seq`, `ts`, `op`, `issue_id`, optional `actor`, a full Issue post-mutation snapshot or `null` for deletion, plus dependency/comment payload when applicable. It is independent of the human audit history; suppressing audit noise does not suppress enabled journal emission. This is highly relevant reusable machinery for BDP, although its Issue vocabulary and replica-local delivery contract are not already the generic BDP contract. [Emitter and seven operations](https://github.com/gastownhall/beads/blob/f45b249ce6b40ba62aecc03949e6371e8f7c79d8/internal/storage/issueops/journal.go#L18-L120), [published record](https://github.com/gastownhall/beads/blob/f45b249ce6b40ba62aecc03949e6371e8f7c79d8/internal/eventsjournal/record.go#L29-L100).

The seven stored/published operations are create, update, close, delete, dep_add, dep_remove and comment. Labels, metadata, claim/release, lease reclaim, promotion, defer wake, and changed derived `is_blocked` values use update; reopen also uses update. Dependency adds are upserts and can refresh metadata; absent dependency removal emits nothing. ID rename becomes edge removals, old-ID deletion, new-ID creation and edge additions. These are committed effects; neither the original request nor its failed predicates are needed for a consumer to apply them. [Documented contract](https://github.com/gastownhall/beads/blob/f45b249ce6b40ba62aecc03949e6371e8f7c79d8/docs/reference/events-journal.md#L240-L310), [mutation coverage guard](https://github.com/gastownhall/beads/blob/f45b249ce6b40ba62aecc03949e6371e8f7c79d8/internal/storage/issueops/journal_completeness_test.go#L63-L134).

## Atomic source recording is stronger than the consumer transaction contract

Sequence allocation increments one counter row within the same transaction as mutation and journal insertion. Concurrent allocators conflict; rollback returns the increment. This deliberately avoids AUTO_INCREMENT assigning a low ID to a transaction that commits after a higher ID has become visible. Journal-enabled Dolt transactions also put both durable and ignored/wisp writes onto the same SQL transaction, avoiding a split-commit loss. These are substantive guarantees worth retaining. [Allocation](https://github.com/gastownhall/beads/blob/f45b249ce6b40ba62aecc03949e6371e8f7c79d8/internal/storage/issueops/journal.go#L505-L549), [same-transaction pinning](https://github.com/gastownhall/beads/blob/f45b249ce6b40ba62aecc03949e6371e8f7c79d8/internal/storage/dolt/transaction.go#L199-L270).

However, the wire record has no transaction ID, operation index, transaction-end marker, or transaction-size field. Pagination is by individual seq and SSE emits individual rows. A composite mutation can create several records with intermediate post-operation snapshots; the source commits them together, but a mirror cannot generally identify the corresponding atomic boundary from this envelope. It can converge after consuming every effect; it cannot reliably publish each source transaction atomically while following incrementally. This is an inference from the exact envelope and reader, not a claim that ordinary replay is impossible. [Record fields](https://github.com/gastownhall/beads/blob/f45b249ce6b40ba62aecc03949e6371e8f7c79d8/internal/eventsjournal/record.go#L29-L72), [row pagination](https://github.com/gastownhall/beads/blob/f45b249ce6b40ba62aecc03949e6371e8f7c79d8/internal/storage/issueops/journal_prune.go#L254-L277), [SSE row loop](https://github.com/gastownhall/beads/blob/f45b249ce6b40ba62aecc03949e6371e8f7c79d8/internal/httpapi/events_watch.go#L282-L301).

The published Issue snapshot also excludes the internal row-lock optimistic-concurrency token (`RowVersion` is `json:"-"`). A journal mirror is therefore not automatically a source of the token needed for a guarded write, even when its displayed Issue content is current. BDP event identity/revision requirements must be mapped explicitly, not inferred from seq. [Issue serialization](https://github.com/gastownhall/beads/blob/f45b249ce6b40ba62aecc03949e6371e8f7c79d8/internal/types/types.go#L75-L99).

## Payload completeness: the comment warning is real

The actual Issue snapshot is hydrated from the row and labels and augmented with `is_blocked`. It does not hydrate comments or dependencies. Comment records are therefore necessary to reconstruct comment state; dependency records are necessary to reconstruct edges. Creation/import explicitly emits each newly persisted comment after create for exactly this reason. [Hydration](https://github.com/gastownhall/beads/blob/f45b249ce6b40ba62aecc03949e6371e8f7c79d8/internal/storage/issueops/get_issue.go#L46-L66), [journal augmentation](https://github.com/gastownhall/beads/blob/f45b249ce6b40ba62aecc03949e6371e8f7c79d8/internal/storage/issueops/journal.go#L384-L416), [creation comments](https://github.com/gastownhall/beads/blob/f45b249ce6b40ba62aecc03949e6371e8f7c79d8/internal/storage/issueops/create.go#L190-L209).

There is a contradictory six-op projection policy in documentation and `journal.go`: it calls comment engine-only and says an outward projector should skip it because its effect is visible in the Issue snapshot. That explanation is false for the actual snapshot. The shipped journal HTTP and CLI record encoder DOES include the comment payload. `IsWireEventOp` has no production caller elsewhere in the audited source; only vocabulary tests refer to it. Do not mistakenly report that the shipped `/v0/beads/events` already drops comment records. Do not reuse the six-op filtering policy for a complete replica. [Contradictory policy](https://github.com/gastownhall/beads/blob/f45b249ce6b40ba62aecc03949e6371e8f7c79d8/internal/storage/issueops/journal.go#L61-L103), [actual encoder](https://github.com/gastownhall/beads/blob/f45b249ce6b40ba62aecc03949e6371e8f7c79d8/internal/eventsjournal/record.go#L75-L100), [HTTP encodes all rows](https://github.com/gastownhall/beads/blob/f45b249ce6b40ba62aecc03949e6371e8f7c79d8/internal/httpapi/events.go#L164-L169).

A smaller stale comment in `internal/eventsjournal/record.go` describes user delete paths as actorless; current emitter and reference doc explicitly carry requesting actor through user cascade delete. Prefer behavior and current emitter semantics over that DTO comment. [DTO stale comment](https://github.com/gastownhall/beads/blob/f45b249ce6b40ba62aecc03949e6371e8f7c79d8/internal/eventsjournal/record.go#L41-L52), [explicit attribution contract](https://github.com/gastownhall/beads/blob/f45b249ce6b40ba62aecc03949e6371e8f7c79d8/internal/storage/issueops/journal.go#L305-L314).

## Real limitations for a reliable replica

1. **Not all state changes are covered.** Journaling is off by default and enabling it backfills nothing. Every writer must enable it; switching it off can omit mutations without producing seq holes. Sync/merge-arrived data, raw SQL, compaction and restore are documented noncoverage. Compaction/restore can leave a mirror stale until another journaled mutation of the affected Issue. Heartbeat is intentionally excluded as transient clone-local lease liveness, although normal Issue snapshots can contain sampled lease fields; a mirror must not treat these as live lease authority. [Activation](https://github.com/gastownhall/beads/blob/f45b249ce6b40ba62aecc03949e6371e8f7c79d8/docs/reference/events-journal.md#L32-L67), [noncoverage](https://github.com/gastownhall/beads/blob/f45b249ce6b40ba62aecc03949e6371e8f7c79d8/docs/reference/events-journal.md#L434-L469), [heartbeat exemption](https://github.com/gastownhall/beads/blob/f45b249ce6b40ba62aecc03949e6371e8f7c79d8/internal/storage/issueops/journal_completeness_test.go#L199-L215).
2. **No self-identifying stream generation.** Seq is local to one clone/branch. New clone or lost/recreated journal can start at 1; a checkpoint above head returns empty success. This is documented, and the truncation test explicitly pins head regression as not an error. A server URL is insufficient if the backing instance is replaced in place. Need stream identity/epoch and fail-closed resume for a durable replication profile. [Limits](https://github.com/gastownhall/beads/blob/f45b249ce6b40ba62aecc03949e6371e8f7c79d8/docs/reference/events-journal.md#L439-L457), [regression test](https://github.com/gastownhall/beads/blob/f45b249ce6b40ba62aecc03949e6371e8f7c79d8/internal/storage/issueops/journal_truncation_test.go#L89-L93).
3. **No atomic snapshot/checkpoint handoff.** Paged journal reads return head and rows from one transaction. Export can use one consistent read transaction in proxied-server mode, but it returns no journal checkpoint bound to that snapshot. Documentation's “rebuild current state, then follow from head” is unsafe if interpreted as reading a new head after the export: a concurrent write between them can be skipped. A correctly specified overlap protocol or a snapshot-bound checkpoint fixes this; full postimages alone do not establish the handoff. [Page](https://github.com/gastownhall/beads/blob/f45b249ce6b40ba62aecc03949e6371e8f7c79d8/internal/storage/issueops/journal_prune.go#L108-L143), [export transaction](https://github.com/gastownhall/beads/blob/f45b249ce6b40ba62aecc03949e6371e8f7c79d8/cmd/bd/export.go#L79-L103), [rebaseline advice](https://github.com/gastownhall/beads/blob/f45b249ce6b40ba62aecc03949e6371e8f7c79d8/docs/reference/events-journal.md#L340-L348).
4. **Retention is a recoverable window, not permanent archival durability.** Defaults retain at least 7 days or newest 100,000 records, whichever protects more, then auto-prune a prefix. There is no consumer acknowledgment floor. Reader rejects pruned prefixes and interior holes; HTTP uses 410 and active SSE emits truncated then closes. Both floors zero disable automatic pruning (manual prune remains an explicit separate request). This is useful behavior to preserve, paired with a sound rebaseline mechanism. [Retention](https://github.com/gastownhall/beads/blob/f45b249ce6b40ba62aecc03949e6371e8f7c79d8/docs/reference/events-journal.md#L379-L432), [truncation computation](https://github.com/gastownhall/beads/blob/f45b249ce6b40ba62aecc03949e6371e8f7c79d8/internal/storage/issueops/journal_prune.go#L159-L225).
5. **History and erasure are separate.** Updating/deleting an Issue does not redact old full snapshots; retained journal payload remains readable. HTTP authentication is surface-wide rather than a per-principal projected stream. A BDP view/erasure contract cannot be supplied by merely renaming this endpoint. [Exposure warning](https://github.com/gastownhall/beads/blob/f45b249ce6b40ba62aecc03949e6371e8f7c79d8/docs/reference/events-journal.md#L122-L155).

## Changes since 1.3.0 and pending work

The 1.3.1 transaction plumbing adds post-commit derived-blocked-state rechecks to settle concurrent unblocking writes. This can produce a subsequent committed derived update; do not assume all effects attributable to one command fit in the command's original transaction. The core journal envelope is unchanged. [v1.3.1 transaction](https://github.com/gastownhall/beads/blob/c1c4b642ac1c08d8c828007a1c2f96e47e43ef7c/internal/storage/dolt/transaction.go#L158-L175), [settling](https://github.com/gastownhall/beads/blob/c1c4b642ac1c08d8c828007a1c2f96e47e43ef7c/internal/storage/dolt/blocked_recheck_raw.go#L10-L29).

Main adds version-history bookkeeping and label-rename coverage. These do not change the identical journal Record. Version-history ordinals are explicitly local and distinct from wire addresses; a version row is minted after the journal call. Thus new version history must not be conflated with journal seq or assumed to upgrade journal events to BDP version facts automatically. [Main create ordering](https://github.com/gastownhall/beads/blob/d15958a5eb88fc32e3a47680ccc017ff47b561ac/internal/storage/issueops/create.go#L231-L253), [version contract](https://github.com/gastownhall/beads/blob/d15958a5eb88fc32e3a47680ccc017ff47b561ac/internal/storage/issueops/version_history.go#L28-L60), [label rename journaling](https://github.com/gastownhall/beads/blob/d15958a5eb88fc32e3a47680ccc017ff47b561ac/internal/storage/issueops/labels.go#L381-L410).

Read-only PR inspection found three relevant **open**, not shipped, changes:

- [#7211](https://github.com/gastownhall/beads/pull/7211): adaptive journal shape intentionally drops unsupported `comment_json` or `actor` columns with a warning. If a comment body is discarded at recording time, later schema repair cannot reconstruct it from that journal. Operational availability may justify a degraded mode, but it cannot advertise replica completeness. Require an explicit integrity/capability signal, repair before a complete-stream promise, or a defined stream discontinuity/rebaseline.
- [#7213](https://github.com/gastownhall/beads/pull/7213): convergence migration/doctor on top of #7211. Body explicitly says outbox and seq epoch are later work, not present here. This may solve schema shape, not missing past event content or stream generation by itself.
- [#7144](https://github.com/gastownhall/beads/pull/7144): cheap head/floor command. Useful for operational polling; separate head read still does not prove snapshot/checkpoint alignment.

These PR-body claims were inspected as proposed work, not verified executable behavior. The referenced `BEADS-JOURNAL-PLAN.md` was not in pinned main; parent should seek it before recommending competing implementation work.

## Recommendation to carry into the BDP comparison

Reuse the existing **transactional capture, ordered cursor, retry/truncation handling and poll/SSE delivery**, with one canonical committed-effects model projected into both the legacy Issue journal and BDP-facing events. Avoid designing a wholly independent second authoritative history. Keep the legacy envelope compatible while specifying a stronger replication profile: complete mutation coverage or explicit invalidation, stream identity/epoch, snapshot-bound checkpoint, complete transaction envelope, generic object/link identity and revisions, and complete comment/relationship state. Postimages are a valid replication representation; they need not be converted back into original commands. Retain filtered activity feeds only as explicitly non-complete views. Decide 1.4 scope from these integrity guarantees and the already-open journal work, not from cosmetic event-name similarity.
