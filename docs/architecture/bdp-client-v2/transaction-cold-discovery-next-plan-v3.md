## Floor, limits and optional fields

Current owner is fixed no-pruning/no-erasure. Emit `minimumReplayPosition: "pos-0"` in the **position namespace** used by readContext/head and group.position/previousPosition. Empty head equals this floor; first committed group's previousPosition equals it; later head advances and floor stays fixed. Source no-pruning invariant (`transaction-store.ts` readChanges1672–1675) treats missing positive groups as corruption, not retention.

Separately derive the checkpoint at ordinal0 through `transactionCheckpoint(scope, context, 0)`, which is `genesis`. Use that checkpoint in actual after requests after commits/reopen/receipt expiry. Do **not** send discovery.minimumReplayPosition directly to the feed, require checkpointPosition to decode pos-0, change the codec, or rewrite existing fixtures. Protocol position tokens are opaque to clients; fixed pos-N checks here test this private owner, not a universal prefix law. No production history scan. The behavioral no-pruning tripwire is complete replay from genesis after receipt expiry and durable reopen, with the original groups still observed and the advertised floor unchanged. If useful, add the existing fixture style of deleting a real positive retained group and require the actual missing-group corruption refusal; do not inspect source text or assert an absent retention/erasure capability field that the configuration does not define. Future pruning/erasure needs its actual owner floor and is outside this patch; no speculative capability or new owner seam is added.

Build limits member-by-member as exactly:

```text
limits = {
  page: { defaultItems, maximumItems },
  selector: { bytes, depth, nodes }
}
```

All five values come from the same captured/enforcement-validated Read configuration. `cursorTtlMilliseconds` is an internal field and is excluded, including from nested output. No request/resource/patch/sequence/validation/transaction/retention groups are advertised in this candidate; their absence does not remove existing enforcement requirements. No inferred retention duration or retention.idempotency.

Candidate emits the16 required discovery members plus `limits`:17 keys total. Derive the required-key set from the canonical transactionalDiscovery definition in the test, add only `limits`, and compare exact candidate keys; do not pad to an invented eighteenth member. Omit `order` (canonical-uri baseline applies), `maximumEndpointMultiplicity` (actual installed configuration has empty declarations), and `historicalResolution` (unsupported capability). The generic parser still accepts those optional fields when schema-valid; candidate omissions are checked against its exact allowed-key set. Reject unexpected candidate input rather than stripping it.

Structural parser/schema negatives: wrong profile/version, missing/unknown member, wrong directory name/value, forbidden retention.idempotency, invalid limits shape, malformed URL. Independent candidate negatives: foreign but canonical Scope, stale epoch/view/head, wrong otherwise-valid route roots, History addition, unconsumed limits or mutated configuration. The latter may pass the normative schema and must fail the separately named owner/config/literal oracle. Remove the impossible “no lower-profile members” predicate; Transactional legitimately contains inherited Read/RU members.
