# Preview 2 operation crosswalk: bd and BDP

Source review, 2026-10-10. Scope: `bd create`, `delete`, `list`, `show`, and `update` in graph mode. This is an initial shared review artifact, **not an executed parity or conformance claim**. No CLI database was opened or mutated; no release branch was edited.

Do not substitute Beads PR #84 for the qualified CLI. Short installed Type names, whole-object replacement flags, native-prefix generated Issue IDs, and legacy Issue `show --json` output from that work are not assumed here. The tracker explicitly separates their qualification.

The decisive transport boundary is that the qualified Graph Read listener advertises **Read** and accepts GET/HEAD; it does not expose these CLI writers as BDP mutation targets. Native CLI write transactions and retained history do not attest Read+Update or Transactional HTTP behavior. Read+Update itself does not require an Event feed, durable transaction receipts, or History. These distinctions are supported by the [CLI listener](https://github.com/donnabox/beads/blob/76fde9c9cb0865d430bf12d76fc473490f51128a/internal/httpapi/graph_read.go#L34) and [BDP profile requirements](https://github.com/gastownhall/bdp/blob/a9bcf9ed1d869aaba2cb49fe9cca10e3b8d52a94/docs/specs/bdp.md#L109).

Classification: **Equivalent** means the compared semantics match at the source level, not tested interoperability. **Shape** means a legitimate interface difference an adapter can translate. **BDP gap** or **CLI gap** names a missing capability relative to the stated comparison. **Unresolved** requires qualification or a design ruling. A release blocker below means a blocker to the specified claim or deliverable, not an instruction to stop Preview 2 as a whole.

Does not establish multi-operation or cross-provider atomicity. |
| Events | Native Issue creation follows the native writer; Memory creation is a graphstore operation. Neither is exposed as a qualified BDP Event feed. Transactional BDP would emit a generic Bead-created Event with complete properties, metadata, revision and recorded attribution. | **Unresolved Event parity**, nonblocking Read or Read+Update. Do not equate an internal journal row with the BDP Event contract. |

## delete

[CLI dispatch and preview](https://github.com/donnabox/beads/blob/76fde9c9cb0865d430bf12d76fc473490f51128a/cmd/bd/graph_preview_memory_delete.go#L12), [Issue deletion](https://github.com/donnabox/beads/blob/76fde9c9cb0865d430bf12d76fc473490f51128a/internal/storage/graphstore/issue_delete.go#L28), [Memory deletion](https://github.com/donnabox/beads/blob/76fde9c9cb0865d430bf12d76fc473490f51128a/internal/storage/graphstore/memory_delete.go#L46), [BDP mutation results](https://github.com/gastownhall/bdp/blob/a9bcf9ed1d869aaba2cb49fe9cca10e3b8d52a94/docs/specs/bdp.md#L3922).

| Dimension | Qualified CLI → BDP comparison | Finding and release consequence |
| --- | --- | --- |
| IDs and references | CLI resolves one Bead and dispatches by immutable backing Type. Live incident Links prevent deletion before native cleanup; `--force` is not cascading deletion. BDP `deleteBead` likewise refuses incident Links. | **Equivalent** refusal rule. CLI `forget` is Memory-only and outside this five-operation mapping. |
| Guards | CLI delete defaults to a preview; applying deletion requires the CLI application flag and explicit revision guard or unconditional choice. BDP deletion executes immediately; `expectedRevision` is optional. A CLI preflight must not replace the final atomic guard. | **Shape** and stricter CLI user interaction. One guarded BDP delete can implement apply. No protocol dry-run requirement follows from a CLI preview. |
| Properties and metadata | Deletion is not a patch. CLI retains identity and retained versions; current representation becomes gone. BDP deletion returns the final live revision and does not mint a deleted Resource version. | Broad retained-identity agreement; exact historical exposure is **Unresolved** and not promised by Read. |
| JSON input/output | CLI preview/applied result can carry the pre-deletion record and preview/deleted indicators. BDP success carries only deleted identity `{id,type,revision}` and kind. | **Shape**. A client requiring a full preimage must read it and guard deletion with that revision; the BDP result alone cannot reproduce the CLI's full preimage. |
| Errors and atomicity | CLI checks revision and live Links inside the same storage transaction; Issue native cleanup and graph identity deletion commit together. BDP has atomic guarded deletion and incident-Link refusal. Error detail differs: Issue can identify incident Links; Memory reports a count and representative Link. | **Equivalent** atomic refusal conditions; **Shape** for diagnostic payloads. No universal equivalence of HTTP 404/410 and CLI `gone`/`not_found` is claimed. |
| Events | The Issue path explicitly delegates journal behavior to the native writer; Memory deletion records retained state. Transactional BDP uses generic deletion facts with final live revision, not a full deleted preimage. | **Unresolved Event/journal compatibility**, nonblocking current Read. Changes to journal content require a separate wire audit. |

| Dimension | Qualified CLI → BDP comparison | Finding and release consequence |
| --- | --- | --- |
| IDs and references | CLI routes between generic Bead inventory and native Issue filtering. Nominal Type filtering is distinct from Issue classification and labels. BDP offers exact Type/conformance and bounded property selection within a Scope. | **Shape**; Issue policy belongs in client/pack logic or expressible selectors. | IDs and references | CLI dispatches by Resource kind/backing Type. Issue `--properties` accepts a bounded field set; it is not arbitrary Type replacement or a way to mutate identity. | JSON input/output | CLI object/patch input supports literal, `@file`, explicit `@-`, strict JSON admission and supported field checks. CLI returns its command result wrapper. BDP returns complete postimage and, for owned-Link mutations, source identity and resulting source revision. | **Shape**; adapters must preserve attribution and number semantics, not recurse into opaque values. A source postimage may require an additional read. |

| Events | CLI Issue writer owns native audit/journal behavior; graphstore's complete postimage is not an exposed generic Event feed. Owned-Link transitions also version the source and emit its corresponding update; no-op emits none. | **Unresolved Event parity**, outside Read and Read+Update admission. Do not count CLI storage transactions as Transactional-profile qualification. |

## Cross-cutting findings and next checks

1. **Align accepted BDP text and artifacts before claiming Preview 2 wire parity.** The qualified HTTP projection already emits metadata and `basis`. Against main, this is a concrete schema/vocabulary mismatch. #64/#65 are the proposed remedy, supported by the [recorded common-metadata decision](https://github.com/gastownhall/bdp/blob/a9bcf9ed1d869aaba2cb49fe9cca10e3b8d52a94/docs/design/preview2-common-metadata-amendment.md). Their integration does not establish review acceptance or executable cross-repo qualification.
2. **Keep full HTTP Write independent of Preview 2 Read release.** Tracker #7170 says HTTP Write follows CLI completeness. Singleton writes, sequence member outcomes, durable retry recovery and Transactional Events need their own executable qualification gates. No writer or Event failure is inferred solely from their absence in a Read-only product.
3. **Design portable efficient listing and source guards as independent BDP decisions.** These are actual limits on a future cold BDP client, not requests for domain-specific Issue verbs. Consider a bounded, discoverable ordering mechanism and an explicit conditional guard model; do not assume either is already accepted.
4. **Translate errors by semantics, not spelling.** CLI emits codes such as `invalid_properties` (exit 2), `not_found`/`gone`/`revision_unknown` (3), `revision_conflict`/`identity_reserved`/`constraint_violation` (4), `capability_unavailable` (5), and `outcome_unknown` (6). BDP uses Problems with family, status and retry disposition. CLI outcome-unknown explicitly warns against automatic replay; a BDP client instead preserves the original idempotency key and follows the protocol's recovery rules. [CLI error mapping](https://github.com/donnabox/beads/blob/76fde9c9cb0865d430bf12d76fc473490f51128a/cmd/bd/graph_preview.go#L736).
5. **Pin the executable truth when fixing editorial drift.** The CLI source has current metadata and Issue deletion paths; older “not yet implemented” ledger prose must not override these implementations. Janet should reconcile CLI specification claims at the confirmed qualified pin. BDP normative edits remain Vickie's lane.

The next shared checks should use disposable synthetic fixtures and independently verify: create explicit/generated IDs and collisions; Issue/Memory current show and metadata/attribution projection; list defaults versus explicit selectors, ordering and continuation; one guarded combined properties/metadata update, stale guard, no-op and missing-key unset; deletion preview/apply, stale guard and incident-Link refusal; owned-Link update with stale source guard. Separately exercise BDP idempotent retry, changed-body key conflict, restart replay, and protocol errors against the developing reference implementation. Only the first set's Read-facing observations can qualify the current listener; the latter set qualifies a future write surface.

For each run record both repository SHAs, profile/capability discovery, parsed requests and responses, and the actual resulting Resources. Event assertions belong in a separately admitted Event-capable suite. Until those runs and Janet's pin confirmation are complete, this crosswalk is evidence for implementation and review, not a declaration of CLI parity.
