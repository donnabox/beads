## Open findings

### 1 — HIGH · M4 is not closed. Bare file-path import of the emitted entry tears down the importing process's IPC channel and poisons its exit code.

`installed-reference-process.ts:9` guards on `!process.send || process.argv.length !== 2`. Neither is an entry-point check, and `void main()` runs at module load. M4 required refusal unless the module *is* the process entry point, and inertness on bare import. Demonstrated:

- **Non-IPC host.** `node --input-type=module -e 'await import(".../dist/installed-reference-process.js")'` → stderr `installed reference qualification failed`, and the host is left with `process.exitCode === 2`. A host that merely imported the module exits non-zero.
- **IPC host with `argv.length === 2`** — e.g. `node --import file://.../installed-reference-process.js <any-entry>`, which is also what `NODE_OPTIONS=--import` produces. The guard passes, `process.once("message")` **consumes the host application's first IPC message**, `administrativeData(message, ["configuration"])` throws, and the catch calls `process.disconnect()`. Parent-side observation: `PARENT: channel disconnected by child`, `child exit 2`, and the next `child.send` throwing `ERR_IPC_CHANNEL_CLOSED`.

This is precisely the hijack M4 named, and it is worse than predicted — not just signal-handler capture but channel destruction. It is reachable because `files: ["dist"]` ships the module in the tarball and the `exports` map does not govern file-path or `--import` resolution; the repo's own harnesses (`test-support/development-process.ts`, `test-support/development-discovery.ts`) load `dist/*.js` exactly that way. The `smoke-executables.mjs` additions only assert the **exports map** denies `@bdp/server/installed-reference-process` and `@bdp/server/dist/installed-reference-process.js` — both bypassed here. Neither inertness nor the no-IPC refusal is asserted anywhere, so review.md's "No package export, bin or CLI flag" is true while the module is still a live side-effecting import target.

Fix: compare resolved `process.argv[1]` against `fileURLToPath(import.meta.url)`; on mismatch return without writing stderr, setting `exitCode`, or calling `disconnect()`. Pin both the bare-import inertness and the no-IPC spawn refusal.

### 2 — HIGH · H3 is only partially closed. The listener serves credentialed traffic, including committed mutations, before startup completes.

`server.listen` (`:502`) precedes `openDevelopmentAuthority` (`:513`) and the per-credential readiness loop (`:521-542`). The implemented gates are `!authority` → 503 and a `principalViews.get(id)` miss → 401. The `serving` flag the plan review prescribed — published after the composition loop, refusing `temporarily-unavailable` until then — was not implemented.

Demonstrated: with 32 credentials and a composition that issues one HTTP request from inside the **first** `createReadRoute` call, `POST /acme/operations/create-bead` returned **200 with a created resource** while `startDevelopmentReferenceRuntime` had not yet resolved — so a write committed before the caller held any `close()` handle. (`routes constructed: 32, startup ms: 47`.)

Two consequences:

- **(a)** A valid credential whose view has not yet been constructed gets **401 `unauthenticated`** with `www-authenticate`, not 503. A conforming retrying cold client treats 401 as permanent. Fail-closed, so the H3 legacy-200/unguarded-mutation hazard *is* gone — but review.md's "ready follows compilation/store validation/principal checks/route construction" describes the `qualification.ready` message, not the socket.
- **(b)** The startup catch (`:543-556`) does **not** drain `pending`, unlike `close()` (`:565`). A request admitted in that window races `authority.close()`. I attempted to reproduce a write surviving a failed startup twice and lost the connect race to `closeAllConnections()` both times, so I am reporting (b) as the structural mechanism only — not as an observed outcome.

Fix: `let serving = false` set after the loop, refuse until then, drain `pending` in the startup catch, and assert 503-not-401 for both a read and a mutation against a configured port during startup.

## Accepted divergences worth recording, not defects

- **H2 went further than prescribed.** The fix suggested bounding Host to the listener or captured-Scope authority; the implementation accepts any syntactically valid Host and discards the absolute-form authority *and scheme* entirely. Safe — identity never derives from them — and it matches the shipped public listener's rebase-onto-canonical-origin behavior. But it is a decision, not the prescribed fix, and should be recorded as such rather than assumed.
- **Cleartext loopback under an `https` Scope.** The smoke's configured Scope is `https://reference.invalid/acme/` while the listener is plain HTTP on 127.0.0.1, so emitted resource ids are not dereferenceable off-box. Consistent with "not deployment TLS" and inherent to the harness; noting it so it is not mistaken for a conformance claim.
- **`configurationIdentity` commits to exact token digests** (unsalted SHA-256 of high-entropy randoms). No practical disclosure, but publishing the identity lets a token holder confirm the binding. Intended per the credential-to-principal mapping requirement.
- **`schemaArtifacts.find(...)` is a linear scan ahead of all route classification**, bounded at 4096 entries, on every request including mutations. Trivial at realistic counts; mentioning only because it is the same shape as the A10 ordering concern.
