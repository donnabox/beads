# Closed Event validation plan

This is a concrete command and acceptance plan, not an executable supervisor or a release. No tests, build, product imports, install or services were run. Root inspection and actual Claude code disposition remain prerequisites. Other CI is independent; no pending result is labeled green here.

The Event worktree currently has no node_modules. The initial guarded preparation caught this before writing any files; only its owned empty directory had been created. Begin with an explicitly released frozen-lock offline install with scripts disabled, then pin actual resolved tools and native binaries against the unchanged lock. An offline cache miss stops; no automatic network expansion or retry. Existing pinned Node, pnpm and Python identities are real; unavailable tool/build/package identities are null, never fabricated.

Follow commands.json once under a reviewed adaptation of the pinned supervisor. Static work is workspace typecheck plus direct formatting and lint for the only changed test file. `pnpm run build` already performs clean (`tsc -b --clean` and clean-build.mjs), then `tsc -b`; do not duplicate clean. This is a full fresh workspace build, not a one-file compile. Freeze all generated package/app dist outputs and protocol schemas against source and build log/exit hashes before callbacks. No full test suite or smoke rerun is included.

Run historical-default and restart-default as separate exact-title Vitest invocations, clearing both installed overrides. Both callbacks must execute; neither is skipped. The historical callback's 15.1-second sparse stream check remains separate development regression evidence; its legacy installed observation name does not confer installed attribution. The new callback reports development-local. Each title selection leaves the other callback unselected; acceptance checks the exact selected title passed.

Pack new protocol/server archives only from that fresh build. Verify every archive member and exact inventory against source/build, then prepare an exclusive external consumer with file dependencies and the existing protocol override and fast-uri3.1.5. Install offline, scripts disabled. Root inspects and pins the actual generated consumer lock before the installed stage. Verify all eight production packages and resolved dependency paths, exact archive bytes, independent recursive payload hash and actual entry. Only then supply the actual external entry plus sourceCommit to restart-external. The witness harness still uses Vitest source aliases; the launched server and adjacent configuration module must come from verified external packages. No public admission bypass or claimEligible change.

Adapt the pinned packages.py precedent rather than invoking another packet's helper. In particular replace its clean:true assumption with this frozen dirty witness plus unchanged runtime-source/build/archive correspondence. Record witness hash/diff separately from declared runtime sourceCommit. Old artifacts, a source string or external-candidate label do not independently prove provenance. Future artifact hashes remain unfilled until measured.

The pinned smoke supervisor is a reuse precedent, not an Event-ready launcher. Adapt its cwd/env and event adjudication: new owned session/process group per stage, stage-local TMPDIR, scrub inherited BDP/NODE overrides, exact source/tool/preparation pins, exclusive attempt files, no retries, TERM115/KILL119/outer120. The reviewed adapter hashes must be pinned before any launch. This packet deliberately creates no launcher: raw argv templates must not run unsupervised. Standard-library hash/checkpoint stages remain ordered and bounded.

Require acceptance.json's exact request/session evidence, actual normal first-child exit before reopen, stable complete E1/contexts, header-over-query precedence, synchronous live/nonaborted stream gate and exact frames after drain, contextual foreign-source rejection, both controls and successful cleanup. Group samples supplement actual callback PIDs without proving every process birth. The historical callback lacks some new diagnostics; never backfill or relabel them.

This checks bounded installed Event restart composition and default-mode compatibility for two callbacks, not full-suite green, cold discovery, arbitrary ACLs, erasure reconciliation, S1 retained Snapshot minima, G2 incident-Link metadata, Types, optional History, release or profile qualification. Preserve failures for separately bounded diagnosis; do not weaken expectations.
