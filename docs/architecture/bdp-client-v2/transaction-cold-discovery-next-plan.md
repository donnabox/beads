### Replay floor and limits must be explicit

`transaction-store.ts:1660–1690` explicitly implements a no-pruning owner: every committed positive position through head must remain present; missing rows are integrity failures, not retention. `transaction-changefeed.ts:53–85` encodes legal exclusive cursor zero as **`genesis`**, positive checkpoints as `cg_...`, while current read head is **`pos-N`** (`transaction-store.ts:582–589`). Thus derive an internal floor using the existing checkpoint function at zero, not `pos-0`, a receipt effect position, Snapshot anchor or last group's checkpoint. Pin the fixed no-pruning applicability and test replay from the floor after commits/reopen/receipt expiry separately. Do not promise indefinite memory or invent a retention duration. Future pruning requires an explicit owner floor, outside this patch.

Prefer omission of optional discovery limit groups until individually supported by actual consumed inputs. Preserve actual inherited page/Selector limits from `options.read.advertisedLimits`, which runtime capture already derives (`transaction-runtime-configuration.ts:328–349`); pin page maximum equality with persisted receipt maximum, as service startup already does (`transaction-service.ts:63–69`). Do not copy the whole runtime-settings object into normative `limits`. Do not advertise `retention.idempotency`, historicalResolution, fabricated replay duration, or optional transaction bounds without separately tracing their enforcement and exact schema fields. C3 tests must reject unsupported membership rather than silently stripping it. Omission of optional groups is allowed; it does not erase enforcement limits or qualify their required error behavior.

## C4 actual serving acceptance, inherited unchanged from v2

Once readiness is established, the installed client starts with Scope+credentials only, follows actual service-desc Link→descriptor→directory, confines each discovered target to the canonical authenticated Scope, and invokes all twelve actual operations with independent graph/receipt/retry/rollback oracles. It follows returned receipt pages and Snapshot/feed/Event links, checks minimum-consistent current reads, reopens with retained outcomes, and verifies GET/HEAD/405/Accept/auth/conditional current-context behavior. Independent requests may observe different heads; each response must be internally coherent. Required evidence and public profile admission remain a later C5 gate. This audit does not authorize C4 wire publication or a new dynamic-target executor.

The accepted plan already contains the necessary critical path. The next discovery change is a bounded C3 composition implementation; a usable served cold client still requires the named C2 repairs and then C4. Reporting otherwise would replace operational readiness with JSON construction.
