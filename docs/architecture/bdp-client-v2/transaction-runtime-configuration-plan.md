## Outcome and ownership

Make the private runtime return truthful immutable, non-secret startup metadata derived from the very configuration used by its owner, service, authentication and listener. Permit the private installed harness to dial a physical loopback port 0 listener while sending the configured canonical Scope's Host. Preserve existing listener-Host fixture mode and all actual request/refusal behavior outside that explicit authority mode. The result is a private non-attesting runtime binding, not Transactional discovery or a public installation API.

Owned implementation paths proposed:

- `packages/server/src/transaction-runtime.ts`: use captured values, opt-in canonical Host mode, startup metadata and unchanged shutdown ownership.
- New `transaction-runtime-configuration.ts`: closed input capture, required defaults extraction, credential associations/authentication and digest construction. Source-private; no package exports.
- New `transaction-runtime-configuration.test.ts`, and narrow `transaction-runtime.test.ts`/`transaction-http.test.ts` coverage for real runtime Host, permissions, immutable capture and reopen.

Prefer exporting that existing binding under a descriptive private alias (`TRANSACTION_RECEIPT_DETAIL_MS`) rather than duplicating a literal or changing retention behavior. No store policy/default/format changes. Coordinate with root before authoring if S1 starts writing this file.
- `scripts/smoke-executables.mjs`: the new module's four emitted artifacts plus explicit bare/dist deep-import denial. This is packaging inventory only; coordinate with H1b's later additions. If root wants strict runtime-only source ownership, root may carry these deterministic inventory lines at integration, but they must not be omitted from the deliverable.

Do not edit H1a's artifact-bundle, runner, profile-contract-plan, test-support/testing or source-only manifest/fixture files. ## One actual capture, with explicit startup phases

1. **Synchronous administrative capture before the first await/listen/open.** Read exact own data properties, reject accessors/proxies/unknown fields, snapshot nested arrays and plain artifact bytes, and validate directory/create/port and configured Scope. Reuse `administrativeData`/`administrativeArray` and existing artifact ingestion limits. Support the existing optional schema-free Type inventory for private fixtures; never brand it as compiled contracts. Preserve existing accepted principal spelling (nonempty, well-formed Unicode), rather than importing RU's narrower ASCII principal regexp. Bound the new administrative credential list to 32 and principal strings to 16 KiB; these are private capture limits, not a protocol principal policy. Preserve token grammar/length and duplicate-token refusal.
2. **Compile the detached plain artifacts exactly once in the active module instance**, using the existing compiler and the captured explicit stable Scope. Move the existing runtime compile block into this private capture path; do not wrap it with a second compiler or compile expected artifacts on behalf of the child. Keep exact supplied-Type inventory agreement and Scope-local Type checks already enforced by the owner. H1's strict mode requires a compiled closure and an explicit canonical Scope; schema-free fallback stays available to ordinary private runtime tests.
3. **Start physical listener** using captured loopback intent; read actual `server.address()` after successful listen. Port 0 is valid and may change on reopen. For legacy disposable Scope omission, derive the actual Scope only once from that listener; no qualifying H1 metadata is returned for that mode. No caller-owned value is reread after await.
4. **Open the one existing owner and service** from captured contracts/types/Scope/configuration. Validate actual owner Read configuration agrees with receipt maximum, installed descriptor closure and fixed view/empty aggregate policy before publishing ready metadata. The owner remains the authority for its actual fixed view. This check uses its ordinary startup configuration entry, not a diagnostic inspect adapter or a live-state scan.
5. **Construct final immutable runtime metadata only after all startup succeeds.** Capture the actual handler-generated targets, Scope, actual listenUrl and digests. Failed startup returns no metadata, and preserves the existing listener/owner cleanup aggregate and cause chains. H1b must emit child ready only from this actual returned object, never substitute expected hashes.

Metadata availability is deliberately narrow: the strict explicit-Scope, compiled-artifacts, default-behavior path can expose a named metadata record. Existing test-seam executions (clock/scheduler/comparison/minimum callbacks or count/cadence overrides) must not receive an indistinguishable default runtime identity. Proposed API: optional `configurationMetadata` is absent when any behavior seam is supplied, or when compilation/stable Scope requirements are absent; H1b requires its presence. Do not hash function source, invent identifiers for arbitrary callbacks, or claim such instances were captured as production-default behavior. Their ordinary fixture behavior remains intact and separately tested.

## Canonical authority versus physical binding

Add a closed private authority mode to runtime input, proposed `authorityMode: "listener" | "canonical"`, defaulting to existing listener mode for source fixtures. Canonical mode requires explicit canonical Scope before artifact compilation/listen. H1b selects canonical mode, not a Host override in the exact executor.

- Listener mode preserves current exact comparison with `new URL(listenUrl).host` and legacy configured-Scope tests.
- Canonical mode accepts exactly `new URL(capturedScope).host` under existing Host syntax/Node parsing, and continues constructing canonical request URL from raw origin-form path plus Scope. A nondefault canonical port must be part of Host; default URL port normalization follows the existing canonical URL parser. Test both cases.
- Still listen on127.0.0.1 at requested port0; return actual plain-HTTP listenUrl separately. A configured HTTPS identity over an explicitly mapped private loopback transport is not a public TLS endpoint claim. H1's trusted dial map validates and binds canonical identity to the actual local endpoint; ordinary clients receive no arbitrary redirect/dial authority.
- Keep normalized origin-form/raw-target refusal, traversal checks, method-before-Fetch behavior, authentication, Origin refusal, body limits and accepted-work drain ordering. Do not follow X-Forwarded-Host, Forwarded, absolute-form authority or arbitrary Host. Wrong Host fails existing malformed-request handling before credentials reach a mutation owner. Raw CONNECT still does not create a tunnel.
- Physical port, listener URL, directory and create/reopen intent are separate per-start/provisioning facts, not persistent store compatibility or logical runtime digest fields. Changing only requested/allocated port must not change the logical digest with the same explicit Scope/configuration. Reopen validates a new actual endpoint and preserves logical identity. Legacy implicit Scope contains its port by definition and is not eligible for this stability claim.

## Identity definitions and secret handling

Use a versioned, domain-separated SHA-256 over explicit fixed-key-order normalized plain records serialized by existing `stringifyJsonValue`. Do not call this a new RFC canonicalization algorithm. Normalize credential associations by token digest order after duplicate-token rejection; credential list order has no authorization meaning. Raw bearer bytes remain in an encapsulated authenticator/captured internal record consumed by dispatch, never in metadata/logs/errors. Runtime can call that captured authenticator; do not expose mutable buffers on its returned metadata.

- **artifactIdentity**: unchanged `contracts.identity`. Its body is the actual compiled closure already passed to the owner. H1 uses the existing versioned decoder; no second digest or alternate prefix.
- **authenticationIdentity**: scheme/version plus every normalized `{tokenDigest, principal, canMutate}` association. The dispatch authentication result uses the same captured principal/permission values. Both tokens of the same principal remain distinct; no principal→boolean map.
- **policyIdentity**: SHA-256 of actual fixed view/read policy from the owner's configuration, actual empty aggregate policy, and the same per-credential permission associations. Store's literal policyIdentity/view name may be input, never output-as-digest. Including token digests binds the actual permission association without exposing tokens. Authentication and policy digests are coupled; real independent variability is not promised.
- **runtimeConfigurationIdentity**: distinctly named SHA-256 over version, canonical Scope, actual compiled identity, normalized installed settings/defaults above, fixed service/transport modes, policyIdentity, authenticationIdentity, `profile:"transactional"`, `history:false`. It is not store compatibility JSON, a field silently added to `ServedProfileConfiguration`, or an HTTP discovery property. No dynamic head position, current clock value, receipt state, Scope epoch, random cursor, process ID or allocated port goes into this logical configuration identity.
- **Per-start physical binding**: actual listenUrl, selected canonical Scope/Host mode and handler-generated targets. H1b separately validates these together with the digest and source/payload binding. Changing dial endpoint alone must fail that comparison even when logical digest is unchanged.

The returned record also explicitly carries `claimEligible:false`, profile/history and the unchanged artifact/policy/authentication identities. Returning candidate profile metadata is not advertising a schema-invalid Service Description. No owner handle, diagnostic inspect, synthetic outcomes/positions, credential data or generic control hooks are returned.

H1b's private execution binding must retain runtimeConfigurationIdentity in addition to its existing ServedProfileConfiguration and actual physical binding. H1a's shared closed record is untouched here. An isolated configuration-digest mismatch while every other field matches is an **injected counterfactual**; do not describe it as a real config state this capture can produce. Actual real changes generally move multiple coupled identities.
