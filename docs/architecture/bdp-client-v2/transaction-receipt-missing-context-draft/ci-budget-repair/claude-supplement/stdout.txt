## Verdict

**No blocker.** The repair is internally consistent with the approved semantics and, by construction, eliminates the exact reported failure mode. The arming site and `seen` are set in the same macrotask: `target.execute()` resolves → timer armed → the receipt block (inert here, synchronous) → `afterExchange` runs synchronously to its first `await`, setting `seen = true` and registering the abort listener *before* any timer callback can run. So the 100ms budget cannot expire pre-`seen` for any positive value, and no abort can be lost. Findings below are ranked risks, not blockers.

## Requirement checks (all satisfied)

- **Overall ceiling not extended by the option:** `timer` is armed at `budgetMs` from T0 and is neither cleared nor reset when `firstExchangeTimer` is armed. Effective ceiling is `max(budgetMs, S+100)` + drain, not `budgetMs + 100`. The helper's `90000` cap and `< 1` floor are untouched.
- **One-shot:** `firstExchangeTimer === undefined` guard, variable never reset; `controller.abort()` is idempotent, so a both-timers-fire interleaving still yields reason `installed cohort deadline`.
- **Cleanup:** both cleared in the innermost `finally`; `clearTimeout(undefined)` is a no-op, so default callers are byte-equivalent in behavior.
- **Defaults:** option absent ⇒ no timer, no new throw; `expireCohort` extraction is a literal closure of the prior inline body.
- **Discrimination preserved:** `seen=true ∧ deadline-cause` still requires a real non-empty-wire response; the pre-wire overall timer still produces `seen=false`. No mocked response, no synthetic abort.
- **5000ms request window:** 100ms ≪ 5000ms, and runner.ts:1265–1268 tests `signal.aborted` before `requestDeadline.signal.aborted`, so the classification stays `"abort"`, not `"timeout"`.
- **Pre-aborted callback:** unaffected — validation precedes `throwIfAborted()` (consistent with the existing `budgetMs` check) but this caller passes no new option; no timers/dirs/children are created before the throw.

## Findings

1. **Confirmation gap, not a code defect — the deadline cause chain in the in-flight regime is unexercised by the supplied evidence.** Severity: medium (evidence). Location: `enforceDeadline` call, `runner.ts:1255–1259`. The abort-path factory there constructs `HttpTransportError("abort", …)` with **no `cause`**; if that rejection wins the race against the `afterExchange` rejection (which must traverse several microtasks), the chain wrapped at 1266 is `abort ← abort` and `errorCauses` would not contain `installed cohort deadline` — unless the runner reports abort as row state and `observe`'s `failure = signal.reason` path supplies it directly. The one supplied CI observation of that assertion passing came from a **pre-wire** abort (`seen=false`), not from an in-flight one. Smallest fix: none in this diff — the two selected cases root is already running are exactly the right gate; do not treat this as green until that in-flight result is in hand.
2. **Worst-case wall-clock margin against the unchanged bounds shrank by 8s.** Severity: low. Location: callback options (`budgetMs: 10000`) vs. unchanged `expect(performance.now() - started).toBeLessThan(15000)` and the 20000ms Vitest timeout, with the launcher's `bounded()` drain window at 10000ms. Pre-wire-expiry worst case is now ~10000 + drain (previously 2000 + drain), which can exceed both bounds and convert a clean `seen=false` assertion failure into a less diagnosable timeout. Smallest fix: only if that recurs — lower `budgetMs` to the smallest value above measured startup; leave the assertions alone as specified.
3. **`10000` for startup is unmeasured.** Severity: low. If real bootstrap+route+scenario setup exceeds 10000ms on the runner, the identical `seen=false` failure returns. This is the acknowledged missing substage observation, so it is a residual risk rather than a defect; the fix on recurrence is a startup-stage timestamp, not a larger budget.
4. **Which timer fired is not directly identifiable.** Severity: nit. Both call `expireCohort`, which is required to keep the exact-message assertion. `seen` disambiguates adequately (false ⇒ overall, true ⇒ post-wire); no change recommended.
5. **Timers are cleared only after `await target.close()`.** Severity: nit. A hung close leaves `firstExchangeTimer` pending; harmless here (idempotent abort, and the abort actually helps force launcher close). Consistent with the pre-existing `timer` placement — leave as-is.
