# Concrete limiter choice, CLOSED

The candidate entry is the existing local `/usr/bin/perl5.34`, explicitly bound to the local 5.34 core module paths, running `hard_limit.pl`. The native limiter forks the Python owner into its own session, retains the unreaped direct PID, arms a high resolution wall alarm, and independently dispatches TERM115/KILL119/outer120 for ordinary cases or TERM145/KILL149/outer150 for actual host variants. It keeps the alarm armed through its small nonblocking pipe receipt and exit. It performs no file/hash/network/parser tasks on the timer loop. No GNU timeout binary was found at the three recorded local paths; none was installed.

This is an authored enforcement mechanism, not an evaluated hard-real-time guarantee. Perl documents signal delivery and scheduling caveats; the ordinary alarm may be delayed, and safe signal handlers can wait for interpreter safe points. The new timer loop therefore avoids blocking waits and long operations, but actual latency is UNKNOWN. No deadline is widened and any observed late result must fail. [Perl alarm](https://perldoc.perl.org/functions/alarm), [Perl IPC/signals](https://perldoc.perl.org/perlipc), [Time::HiRes](https://perldoc.perl.org/Time::HiRes).

The initial CLOCK_MONOTONIC design was corrected before freeze. CPython 3.14 documents `mach_absolute_time` on macOS. Apple's published libc implementation maps CLOCK_UPTIME_RAW to that counter; local SDK `_time.h` declares its value8. The source therefore calls Time::HiRes clock_gettime(8), passing the same earlier origin to Python, rather than comparing distinct Darwin epochs. This is source-derived reasoning, not an observed clock-equivalence measurement. Time::HiRes export/loading and clock-id support on this exact binary remain unverified. [Python 3.14 clock](https://docs.python.org/3.14/library/time.html#time.monotonic), [Apple libc clock implementation](https://raw.githubusercontent.com/apple-oss-distributions/Libc/main/gen/clock_gettime.c). The local headers/modules are copied exactly with origins; web content is linked and paraphrased, not represented as a locally hashed fetched source. Those web main/docs revisions are historical lookup limitations.

Only Time::HiRes clock foundation loading precedes the first native script clock, analogous to importing Python's clock primitive. Remaining native/Python imports, setup, authorization, hashing, peer creation, IPC, cleanup, result and receipt work use that origin. The kernel wall alarm can expire sooner than an uptime clock after suspension; it cannot authorize a late pass. Runtime/OS bootstrap before the first script clock is not a measured artifact here.

A concrete unresolved limitation blocks evaluation approval: this external timer's safe signal authority covers its own unreaped Python owner group. The Python owner authenticates and cleans separately created nested groups. If that owner stalls or is killed before settlement, the Perl timer cannot independently establish cleanup of those groups. It must not signal historical unrelated numeric groups, and a missing terminal/absence receipt remains failed/UNKNOWN. OTHER-native must independently review this limitation and the limiter's exact bytes, available module/clock/pipe semantics before any use. There is no implied waiver, operator question, installed capability or new clock grace. A stronger mechanism, if required by review, needs its own immutable successor; H2 is an honest partial review candidate.
