## First implementation slice: existing configured baseline only

No new Type, schema or policy installation. All scenarios use the **same exact configured server** as existing cumulative Read+Update, with fresh isolated store per scenario, same authority identity capture and actual credentialed transport. New finite fixture IDs and exact routes are derived through the existing request actions; no wildcard, evaluator call, direct DB mutation, new assertion language or hidden test endpoint.

1. For merge/replace, create two Tasks and an unowned Relates Link, independently assert full seed values and endpoint records before captures. Seed each Link document with distinct sentinel, nested object, array and removable member. Object add must drop only the old nested object member while preserving sibling fields; ordered array insert/append/replace/remove must match a literal independently computed vector. Add null then remove a member to distinguish presence from absence. Exercise `~0`/`~1` pointer escaping with concrete keys, without broad numeric-model scope. Root replacement drops old fields; clear properties and metadata separately so omission preservation is visible. Compare source/target full GETs after Link writes, and assert no source/sourceRevision result pair for this unowned case.
2. For atomicity, use the same unowned Link pattern in this row's own scenario. First apply valid properties+metadata changes under a captured current guard, require the actual postimage and independent GET to match the static intended documents. Use the prechange revision as a subsequent stale guard with a valid proposal, require revision-mismatch and unchanged record; this establishes consecutive revision advancement without deriving revision syntax or claiming global non-recycling. Failure probes have exactly one invalid selected document and a genuinely effectful valid change to the other. No-op uses reordered keys and different actor/agent/message inputs, requiring full previous envelope retention in both response and GET. Existing Bead clause evidence stays present.
3. For validation, create and independently verify a Bead and an unowned Link with nonempty properties/metadata and recorded provenance. Probe root `replace` to null, array, scalar and root remove on each selected document, paired with a valid effectful opposite-document change. Each must be validation-failed422/validation/never with a nonempty canonical diagnostic list, no Type/schemaLocation pair for generic document-shape failure, metadata document discriminator where appropriate, and no write. Avoid assuming one implementation-specific diagnostic message: require the cause and metadata designation when required. Root failures may identify the document root `""`; request-body locations are not accepted as document locations. Follow each by a full independent GET comparison to the validated pre-state, not only properties. Link endpoints likewise unchanged. Include both array orders where applicable, and missing replace/remove after an earlier valid array operation to discriminate partial application.
4. A successful metadata-only update with arbitrary schema-shaped keys (for example `n: "not-an-integer"`) is useful object-domain evidence but **does not prove exemption from Type schemas** while no Type schema exists. Label it accordingly. Empty arrays and omitted arrays can supply small ordered/no-op controls; do not classify numeric-literal, advertised-bound, authorization or retention obligations from them.

Prefer bounded per-kind test tables in authoring, expanded inspectable manifest actions. Do not minify the artifact to hide size. Measure the final manifest against the existing private 4MiB ceiling, preserve all depth/node/container bounds, and stop for review rather than automatically increase it. ## Independent sensitivity controls

Every control selects its own row/scenario and must fail named clause assertions after a real response, with application count checked. Preserve actual transport observations and label post-observation substitution as assertion sensitivity, not server behavior or an octet-transparent proxy.

- Merge row: corrupt only the Link response's unchanged sibling, array order or root-cleared object; a separate actual GET-response corruption must fail the independent state oracle. A correctly updated Bead must not hide a broken Link clause.
- Atomicity row: change one side of a supposedly refused combined mutation in the later GET; require the full preimage assertion to fail. Change only no-op response revision or provenance while leaving GET unchanged; require response retention to fail. Change the GET envelope while retaining response; require afterstate retention to fail.
- Validation row: substitute a schema-valid success for a document-shape refusal; substitute a schema-valid but wrong Problem code; relabel a metadata diagnostic as properties; inject Type/schemaLocation for a generic shape error; corrupt the later full record. Each must trip its specific refusal/diagnostic/unchanged-state assertion rather than depend solely on canonical body-schema rejection.
- All original invalid requests must have actual serialized bodies/statuses retained. Use existing observation assertions; no synthetic write outcomes, fake revision constants or capture-vs-itself comparisons.

## Next configuration seam, separate approval required

The useful next step after baseline clauses is an explicit schema-equipped **new cohort**, not stitching a second configuration's result into the current run. Proposed minimal administrative fixture: preserve every shipped descriptor byte, add fresh local parent/child Bead and Link Type IDs with simple intersecting properties schemas, and install their complete exact local closure before server startup. Never replace a contract at an existing Type ID or use Type lifecycle mutation. The factory already supports this; no runtime feature is requested.

Use one declared schema and an inherited schema that constrain different fields, plus a required member. A patch changes only a discriminating field but the complete result is validated: parent-only failure while child remains valid, child-only failure while parent remains valid, removal of a required member with a valid metadata change, and a final valid combined update. Test the same schema-disallowed value in metadata as a successful update to establish that metadata has no Type schema. To distinguish validating the whole result from validating a changed fragment, maintain an unchanged required member and a cross-field dependency: changing its trigger without the companion must fail, adding both must succeed. This fixture design is a test selection, not a new protocol rule.

Adding descriptors changes the observed Type inventory and contract/configuration identity. Before cumulative whole credit, reconcile the inherited inventory/descriptor fixtures and replay the entire applicable Read+Update catalog against **that one configuration**, with exact schema bytes/descriptor IDs and all current identity bindings captured. Root owns approval and configuration changes; coordinate that lane rather than touching shared startup/runtime files. Basic non-object probes may be implemented before this seam is approved; they remain explicitly incomplete. No user product decision is needed for the baseline slice. Fixture/configuration ownership is the only gating coordination decision for actual Type-schema evidence.
