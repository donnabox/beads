## Reading the matrix

K = this implementation's recognized canonical `pos-N` minimum identity; U = a lexically valid but unrecognized identity such as `opaque` or noncanonical `pos-01`; C = actual current epoch/view; F = incompatible epoch and/or view. Neither lexical validity nor spelling establishes order. The shared `snapshotTransactionMinimum` rejects U (`transaction-consistency.ts:57–61`); `checkCurrentReadMinimum` waits only for U+C when its caller enables it, and returns `TransactionMinimumUnsupported` for U+F (`:115–132`). HTTP maps that to private500, not a normative Problem (`transaction-http.ts:682–688`). K context failures already produce 409/410 and actual behind waits produce 503 under `waitForTransactionMinimum`.

Shared normative anchors: `bdp.md:5794–5851` strict read/receiving/minimum rules; `:5871–5888` checks before conditional shortcuts and HEAD stream parity. Malformed three-field tuples already get contextual-field-free400 after ordinary receiving/auth checks (`transaction-http.ts:403–405`). Mutation POSTs ignore copied read minimum fields by `bdp.md:5853–5856`; they are not a missing read-barrier lane.

## Preserve existing behavior and distinguish unresolved semantics

* **S1** is the recorded retained Snapshot/continuation minimum question. Keep immutable manifest/page identity, old anchor, current response context, fixed expiry, unknown/hidden refusals and cancellation separate; do not “fix” it by serving a fresh Snapshot or skipping the minimum. The broad current collection gate is an implementation gap, but its correct extension depends on that disposition.
* **G2** is metadata-only incident-Link membership in a **Bead Event** projection. `transaction-events.ts:264–266` throws the deliberate projection gap; `transaction-event-sse.test.ts:515` verifies initial Bead500 while Scope/Link succeed, and `:533` verifies a later gap closes an already-open stream without a second response. This is not missing generic SSE or successful incident-list minimum semantics. No membership ruling is inferred here.
* **Foreign opaque** is a shared current gap. U+F is rejected before recognized context comparison in `checkCurrentReadMinimum`, although K already follows epoch/view failures. Completion must produce the pinned normative outcome with same-entry context, not private500 or a guessed expiry based solely on opaque spelling. This audit does not invent a priority when independent source/cursor/retention failures collide; preserve established nondisclosure and route receiving, and make any unresolved collision explicit during the bounded plan. It is not intrinsically an S1/G2 dependency on current-only routes.
* **Streaming success already has substance.** Pumps are one-packet/frame-at-a-time with write/drain backpressure and abortable polling (`transaction-sse.ts:55–172`). Runtime registers a slot only after finite eligibility, then advances Event scans or changefeed checkpoints without reapplying the original admission minimum (`transaction-runtime.ts:193–221`). This is deliberate monotone continuation, not a missing repeated-minimum check. Installed historical tests exercise actual defaults, live commits and restart. Preserve their historical attribution; run the combined successor freshly.
* **After is not one universal abstraction.** Event IDs, changefeed checkpoints including genesis, receipt page tokens and Snapshot/Read continuations have different source binding and validity rules. A batch can share lexical/context/wait mechanics without rewriting their owner-specific identity checks or declaring all of them S1-blocked.
