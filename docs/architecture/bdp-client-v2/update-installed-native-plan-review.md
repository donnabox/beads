## Concrete implementation acceptance gaps

1. **Normalize before all endpoint classification, not just Read.** Plan step2 specifically promises absolute-form Read support, while the shared receiver currently classifies mutation routes by slicing rawUrl (`development-runtime.ts:247–251`). An absolute-form mutation URL would otherwise take the wrong route even after successful normalization. Reuse normalizationSafeRawRequestPath once and classify discovery, directory, mutation and schema paths from the validated path/query. Preserve configured Scope as the only identity base. Public Read's createCanonicalHttpRequest (`index.ts:419–431`) already rebases the validated path onto configured canonical origin. Explicitly choose/test which ingress Host/absolute authorities are accepted or refused without ever rebinding identity; forwarded headers cannot supply Scope. Include absolute-form singleton/sequence as well as Read, malformed raw paths, non-root Scope and unknown operation/query paths. This is receiver consistency, not a new wire feature.

2. **Make the IPC entry own the entire lifetime.** Add explicit one-start/one-owner behavior, idempotent shutdown, startup failure cleanup, and parent IPC-disconnect cleanup. A child whose parent disappears must not leave a durable owner/listener running. Ready/configuration identity must be emitted only after Type compilation, store open/reopen validation, principal-policy checks and route construction complete. The current runtime binds before owner initialization, then returns ready only after checks; it can remain shared if candidate readiness obeys that boundary. SIGTERM should close receiving first and settle admitted work; its current closeListener closes sockets immediately, so test durable completion/retry rather than promise successful response delivery. Exercise a slow/partial unadmitted body as well as accepted work, bind failure, second-owner refusal and refused reopen. No scheduler/clock/fault/store control should enter the startup message.

3. **Bind actual captured installation data, with clear mismatch categories.** The entry should return identities derived by the factory from its immutable captured inputs, not echo caller-supplied digest assertions. Include contract artifact/schema closure, fixed limits, aggregate policy, trusted credential-to-principal mapping and policy snapshots, canonical Scope and installed payload/source. Do not log credentials or raw startup records. U2's policy object intentionally has a private replace handle (`development-contracts.ts:174–203`); keep that handle out of the installed entry, or any policy change requires a newly captured configuration identity and separate observation set. Tests should mutate caller records/arrays after capture and prove runtime/identity stability. Persistent store identity currently binds contracts+aggregate+Scope, whereas policy/auth are live configuration; do not conflate an allowed policy configuration change with a forbidden Type/Scope rebind. Define and test which mismatch refuses before maintenance, and which creates a different qualification configuration without claiming old observations.

These are bounded implementation/test refinements, not reasons to seek operator permission or block the private packaging approach.
