### D. Low — the repaired TypeScript type still admits `{}`, the shape this same commit made invalid
**`packages/protocol/src/history-values.ts:58-59`**

Branch two of `RevisionContext` is all-optional (`committedAt?: never; agent?: never; message?: never`), and `actor` is optional, so every property of `RevisionProvenance` is optional and `{}` is assignable to it. Same commit added `minProperties: 1` so that `{}` is *not* a valid output envelope. The group constraint now mirrors the schema (correctly — and the normative all-or-none rule is stated at `docs/specs/bdp.md#immutable-change-context`), but the nonemptiness constraint does not. The new type test at `schema-bundle.test.ts:115-125` covers the group and not this.

Not a regression — the three-independent-optionals version also admitted `{}`. I could not compile an isolated counterexample (TypeScript 7.0.2 ships no in-memory JS compiler API, and I did not write a scratch file), so this rests on the assignability rule for all-optional object types rather than on an executed check.

**Impact.** Compile-time only, and narrower than the original Finding 6: an SDK consumer can still construct a `RevisionProvenance` that the output schema rejects at runtime. No internal producer reaches it.

**Fix.** If it is worth closing: require at least one member, e.g. `({ actor: RevisionActor } & RevisionContext) | ({ actor?: RevisionActor } & RequiredContext)`, and add `expectTypeOf<{}>().not.toExtend<RevisionProvenance>()`. Reasonable to leave as-is and record the boundary instead.
