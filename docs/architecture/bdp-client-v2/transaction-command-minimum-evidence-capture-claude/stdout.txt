## Verdict

The core correction is sound and I found no demonstrated contradiction in its central claim. One High and five Medium items need wording or authoring changes before the plan is executable as written; several claims are attribution overreach rather than infeasibility.

**Confirmed correct from the excerpts (do not re-litigate):**
- Raw captures are URL-only — `runner.ts:2482–2487`. Removing arbitrary raw JSON/revision captures is required, and this is an authoring defect, not a runtime one.
- Pinning `/id` and never `/next` is correct for a *different* reason worth keeping: the `/next` branch **initializes** `entry.pageBody` from the first GET (`transactional-observation.ts:293–296`) and only compares on later GETs, so `/next` would prove nothing about original wire. `/id` compares unconditionally at `:303`.
- Hook-before-assertions is correct: `afterExchange` is awaited inside the executor (`transactional-matrix.test.ts:264–287`), so the hook must independently validate before retaining a baseline, and the manifest pass must additionally be required post-run.
- Equality is parsed-JSON deep equality, not bytes (`:221`, `:303`, comment `:261–262`). Correctly stated.
- A retained-body mismatch cannot yield a successful action9 under *either* propagation branch: `validate()` at `runner.ts:949` precedes the `projection` assignment at `:965`, and `:980` throws if `projection` was never set.
- Raw-to-client epoch/view equality is not establishable — and the mechanism is stronger than the native report states: the dynamic GET is executed by `createRawHttpExchangeExecutor` at `runner.ts:906–918`, which **bypasses `options.exactExecution.execute`**, so the app hook never observes action9 at all. Keep the disclaimer; cite this bypass as the reason.

## Findings

**1. High — the only replay/state oracle can silently not run or be absorbed.**
Target: addendum §3; native "Raw replay, state and revision comparisons".
The ten-action hook is the sole evidence for replay/resource/revision equality, yet it runs *inside* the executor, so a thrown comparison almost certainly lands as `ObservedExchange.transportError`/`harnessError` (`runner.ts:176–185`) instead of failing the test; and an activation-gate miss or early return (pattern at `test:1851–1861`) makes comparisons silently not execute. Smallest correction: mirror the existing `finish()` (`test:1905–1909`) — assert `active === true`, assert performed-comparison count equals the per-mode expected count (controls truncate the sequence, cf. `maximum` at `test:1841–1842`), and post-run assert no transportError/harnessError on the ten raw exchanges.

**2. Medium — "Remove every arbitrary JSON/revision/transaction capture" over-removes.**
Target: addendum §1; native "Actual interface limits" item 3.
`runner.ts:1126–1133` applies **no** `isHttpUrl`/scope check to programmatic-action captures and stores `cloneRuntimeJson`. Because `:303` already proves action9's body deep-equals original A, an action9 capture *does* make original-A facts available as a binding for authored `equalsBinding` on actions 10/11 — contradicting "capturing action9 does not make original bodies available" as applied to A. Smallest correction: scope the removal directive to raw captures (`:2468–2496`) and pick one explicitly: (a) author one action9 capture plus an action10 `equalsBinding` for the A resource, recording that captures run only after `:1119`, so invalid-receipt mode cascades into the dependent assertion IDs; or (b) keep app-only and reword to "no *raw* capture can carry JSON; programmatic captures exist and are deliberately unused."

**3. Medium — several action9 pins rest on report fields not shown, and one conflicts with documented redaction.**
Target: native retained-root bullet list ("dynamic route is the exact observed A root GET", "receipt equal the genuine A root", source digest); addendum §4.
`runner.ts:1375` applies `redactUrl` to the reported response URL, and no excerpt shows how `TRANSACTIONAL_EXCHANGE_FIELDS` project into the report. Smallest correction: split the pins into (i) *already internally enforced* — route identity (`transactional-observation.ts:253–260` + `runner.ts:900–904`), credential (`:926`), logical session (`:263–269`), configuration (`:974–975`) — and (ii) *report-verified*, listing only fields confirmed unredacted. Drop pins in neither bucket.

**4. Medium — in-hook schema validation "before cloning" is both unshown and stronger than the proof needs.**
Target: addendum §3 first sentence; proposal bullet 2.
No validator is shown as available in `apps/bdptest`, and the existing hook uses literal/`toMatchObject` checks (`test:1889–1901`). Smallest correction: state the pre-baseline gate as exhaustive literal/key-set/absence checks, and take schema validity from the row's own manifest `json-schema` assertion outcomes conjoined at post-run adjudication (already required). Reserve "before" for checks the hook actually branches on.

**5. Medium — action9's three inner assertions and its header-absence are runner-internal, not authored.**

`runner.ts:927–933` hardcodes `raw.headerLines: []` and `actual-status`/`actual-request`/`actual-body`. Smallest correction: exclude those three IDs from the authored manifest mirror as runner-synthesized exchange assertions, and restate absence as derived from the hardcoded empty authored set plus the internal `request-authored-headers` outcome — explicitly flagged as dependent on that assertion kind's semantics, never on report headers (redacted at `:1377`, `:1795–1803`) and never on the hook (bypassed, F-list item above).

The existing hook drives comparisons from index literals (`test:1862–1902`); a ledger that is consulted but not depended on makes clone/delete/redirect rejection tautological.
