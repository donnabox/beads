## Blockers

**1. `full-test` argv may never produce the JSON the stage's own postcondition depends on.** Validation plan `stages[full-test].argv` passes `--reporter=json --outputFile.json=<OUT>/full-test.json` as bare args to `pnpm test`. `--reporter` is also a pnpm global option, so forwarding is not guaranteed, and `json` is not a valid pnpm reporter value. The postcondition "inspect test JSON and all four repaired files executed" then rests on an artifact that may not exist.
*Smallest correction:* `["…node", "…pnpm.cjs", "test", "--", "--reporter=json", "--outputFile.json=<OUT>/full-test.json"]`; add to the postcondition that the file exists, parses, and names the five target tests before any claim rests on it. Make the per-callback argv use the same `--outputFile.json=<path>` form rather than a space-separated value.

**2. `<OUT>`, the pack destination and `<MEASURED_CONSUMER>` are unbound, and two callbacks assert on worktree cleanliness and entry location.** `transactional-fresh-depth-installed.test.ts:419-424` asserts, *only when the entry override is set*, that `git status --porcelain` in the repo root is empty and that the resolved entry is outside the repo root; `transactional-event-sse-installed.test.ts:336-338` enforces the external-entry rule for callback 2. `.gitignore` covers only `node_modules/`, `dist/`, `coverage/`, `*.tsbuildinfo`, so writing report JSON, tarballs or the consumer tree anywhere else inside the worktree makes it dirty — callback 3 fails for purely environmental reasons and the remaining four record `workspaceDirty: true`, poisoning the provenance record the stage exists to produce.
*Smallest correction:* bind `<OUT>`, the pack destination and `<MEASURED_CONSUMER>` to absolute paths under the log directory (outside the worktree), and add a stage precondition that `git status --porcelain` is empty immediately before each callback dispatch.

**3.
