## What I verified

- **Default preserved.** `transaction-runtime.ts:235-237` omits the key entirely when the seam is absent (required: `exactOptionalPropertyTypes: true` in `tsconfig.base.json`), so non-seam callers hit `?? 1000` unchanged. The `=== undefined` test (rather than the truthiness used for `clock`/`scheduler` on the adjacent lines) is the right choice here: `0` is forwarded and rejected by the store instead of silently becoming 1 s.
- **Validation/lifecycle intact.** `60000` passes `Number.isSafeInteger && 1..2147483647` at `transaction-store.ts:200-205`, which runs *before* `openSync(file, "wx")` at :212 — an invalid seam value throws with no file or DB handle created, and the runtime's startup `catch` (`transaction-runtime.ts:271-288`) closes the listener. Timer is still `unref()`'d (:1129) and cleared on `close()` (:1535) and on maintenance failure (:264, :1117).
- **Isolation is complete, not partial.** The store's `setInterval` (`transaction-store.ts:1110`) is the only clock-sensitive background timer in this runtime: `read-pagination.ts:242` short-circuits because the runtime passes `idleCleanup: "on-demand"` (`transaction-runtime.ts:264`), and no other `setInterval` exists in `packages/server/src`. So "no maintenance during the test" follows from this one seam.
- **The race it removes is real and the 1 ms boundary is deliberate.** Receipts are created at `time = 1000` → `expiresAt = 86401000`; `setTime(86401001)` is exactly 1 past the `now <= expires` retention boundary (:348), so the next sweep would `failedForgotten`-delete the failed row (:349-354) — flipping the owner-token read from 500 (`minimum-position`) to 404 (nondisclosure of a missing receipt) — and compact the completed receipt, breaking the `retainedReceipts()` equality at :1346. Both halves of the final assertion depend on the isolation.
- **No public/installed surface change.** `TransactionRuntimeTestSeams` is referenced only by `transaction-runtime.ts` and its test; `transaction-runtime` is reachable from neither package export (`.` → `index.js`, `./development` → `development.js`), and the smoke guard asserting the packed root does *not* expose `startTransactionRuntime` (`scripts/smoke-executables.mjs:372`) is unaffected. No new dist file, so the exact dist file list at :250-254 still matches — the report's "smokes not re-run" claim holds for this delta. `development-authority.ts:62/211` (`lifecycle.maintenanceIntervalMs: 60_000`, the sequence lifecycle, not the store sweep) is untouched.
