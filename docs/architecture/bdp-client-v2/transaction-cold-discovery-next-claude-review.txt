## F1 — HIGH — `minimumReplayPosition: "genesis"` contradicts the repository's own normative corpus

**Location:** handoff §"Replay floor and limits must be explicit" (line 31). Contradicting evidence: `fixtures/transactional/discovery.json:33` (`"pos-17"`), `fixtures/transactional/changefeed.json:739,777` (`"pos-44"`), `fixtures/history/wire.json:83`, `packages/protocol/src/transactional-wire.test.ts:628,658,990`, `docs/specs/bdp.md:3730,3744-3747,6466`, `packages/server/src/transaction-changefeed.ts:56-73`.

**Impact:** The handoff presents as settled ("Thus derive an internal floor using the existing checkpoint function at zero, not `pos-0`") a question the repo answers the other way. Every normative fixture and the protocol wire test carry a **position** token (`pos-N`), and `transactional-wire.test.ts:628` asserts `caughtUp.minimumReplayPosition === group.position`; spec:6466 says it "advances to at least P", i.e. it is ordered against positions. The handoff instead emits a **changefeed cursor** token. The two vocabularies are disjoint in this implementation: `parseCheckpoint` (`transaction-changefeed.ts:56-63`) accepts only `genesis` or `cg_…` and rejects `pos-0`. `$defs/wireToken` constrains neither, so AJV cannot discriminate — predicates #2 and #4 would lock in whichever the implementer chose, with no oracle. If the fixture reading is right, a C4 cold client feeding the advertised floor to `changes/?after=` gets `400 invalid-parameter`; if the handoff is right, `fixtures/transactional/discovery.json:33` is wrong and `minimumReplayPosition` is not comparable with `headPosition`.

**Correction:** Move this to the C2 interpretation list and obtain a root ruling before implementation. If proceeding anyway, require two pinned facts rather than one: `minimumReplayPosition === transactionCheckpoint(scope, ctx, 0)` **and** that `checkpointPosition(scope, ctx, minimumReplayPosition)` accepts it, plus an explicit note that `fixtures/transactional/discovery.json:33` must be amended or the implementation changed. Also note `transactionCheckpoint(…, 0)` ignores both scope and context (`transaction-changefeed.ts:70-72`) and returns the literal `"genesis"` — "derive via the existing checkpoint function" buys coupling, not derivation.

## F3 — HIGH — Nine required absolute-URL members have no named seam; the "no second list" rule is broken at larger scale than it protects

**Location:** handoff line 33. `transaction-runtime-configuration.ts:337-341`; type assembled at `authority-read.ts:369-380`; `schemas/bdp-v0.schema.json:4854-4984` (`transactionalAdvertisedLimits`, `additionalProperties: false`).
