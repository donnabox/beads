### 1. Installed `wronghost` row cannot be produced by the pinned executor — High (actionable defect)
**Where:** `installed-callbacks.json` → "private installed discovery methods authorization transport", row `wronghost` (`rawHost: "wrong.invalid"`, status 400); `plan.md:73`; `source-callbacks.json` "D3 source target transport boundary" is unaffected.
**Source evidence:** `packages/conformance/src/http-executor.ts:346-358` puts `"host"` in `RESERVED_FIELDS`, and `:675` rejects any `raw.headerLines` entry whose lowercased name is reserved (`return configuration()`); exact mode then hardcodes `append("Host", url.host)` at `:724`. `executeExact` reads only `["method","url","signal","rawRequestTarget","credentialRef","raw"]` (`:623-630`) and `raw` only `["headerLines","bodyBytes"]` (`:636`) — there is no Host override. The server-side check is `request.headers.host !== new URL(scope).host` (`transaction-runtime.ts:132-134`).
**Issue:** `@bdp/conformance` is not one of the three owned files, so no authored change can make this row emit a mismatched Host. The nearest reachable substitute (absolute-form `rawRequestTarget`) yields 400 for a different reason — `raw.startsWith("/")` fails at `transaction-runtime.ts:128-137` — i.e. a mislabelled witness, not a Host refusal.
**Impact:** One of the 26 enumerated rows is unachievable; the 26 / 190 / 187 inventory and the "Host400 before service" claim are unsatisfiable as written. An author will either fail the callback or silently record a path-shape 400 as Host evidence.
**Fix:** Either (a) implement this single row with a local `node:net` exchange inside the owned installed test (own 5s bound, own byte caps, explicit Host line), and say so in the contract; or (b) drop the row, rely on the existing source raw Host witness (`source-callbacks.json` "raw wrong Host", which uses the source raw socket lane), and restate the counts as 25 / 189 / 186.

### 2. Query-bearing Scope becomes a newly-reachable success with zero witness — Medium (insufficient witness)

### 3. "Remove or redirect now-unreachable handler-local discovery callbacks" is under-specified and partly mis-characterised — Medium (missing prerequisite)
**Where:** `plan.md:21`. Source: `transaction-http.ts:212` (`discover: async () => developmentGap("transactional-discovery")`) and `:244-245` (`result.kind === "discovery" ? developmentGap(...)`).
**Issue:** (a) `discover` is a **required** member of `ReadHttpRoutes` (`read-http-routing.ts:16`), a non-owned file — it cannot be "removed" without editing out-of-scope source, only redirected. (b) The `perform` arm at `:244-245` was **never** reachable from this router: `requestFromUrl` has no path that yields the `scope-discovery` variant (`read-request.ts:544-554` is the sole registration; `:142-255` never emits it), so calling it "now-unreachable" is inaccurate, and deleting it breaks the result-union exhaustiveness (the discovery member carries `data`, not `body` — `authority-read.ts:749`), so `scopeDataResponse(parsed, result.body, …)` would not type-check.
**Impact:** The authoring step could legitimately read "remove" and either touch a non-owned file or produce a type error; or it could leave a live `developmentGap("transactional-discovery")` reachable and contradict the supersession.
**Fix:** Pin the decision: "retain both callback sites; replace each body with an internal invariant error (never a second `discoveryObserved`, never a `developmentGap`); `read-http-routing.ts` and its interface are unchanged." Correct `plan.md:21` to distinguish `:212` (becomes unreachable) from `:244-245` (already unreachable, type-required arm).

### 4. Close-pending installed callbacks: the "exactly 1 expected abort" is time-dependent and the "sent-only finish" has no public observation point — Medium (insufficient witness / missing prerequisite)
**Where:** `installed-callbacks.json` → three "private installed discovery close pending *" callbacks (`assertion`, row `pending-minimum`, `expectedTransportAbortedRequests: 1`); `plan.md:77`; `observation-contract.json.installedReportPerCallback.expected` last item.
**Source evidence:** The close ordering itself is correct — `transaction-runtime.ts:375-398` sets `closing`, awaits `closeListener()` (which calls `server.close` + `server.closeAllConnections`, `:307-311`) **before** `Promise.allSettled([...pending])` and `service.close()`; `deliver` returns early on `response.destroyed` (`:89`); `closing` only short-circuits at `:119` and `:158`. So no 503 can survive close — the plan's central conclusion holds. But:
  * The parked request stays parked only for `minimumReadBudgetMs`, hardcoded to **1000** at `transaction-runtime-configuration.ts:112`, and `captureInstalledTransactionConfiguration` accepts only `["scope","directory","create","credentials","artifacts"]` (`transaction-installed-configuration.ts:20-26`) — there is **no** way to lengthen it from the installed lane. If the independent descriptor GET plus `close()` take longer than ~1s, the first exchange completes as a 503 `catch-up-timeout` and the callback records 5 completed / 0 aborts.
  * `plan.md:77` requires "observe raw request finish (sent-only)" *before* close. The write observer is internal (`http-executor.ts:888,902-906` `observeWrite` is a private parameter of `exchangeRawBytes`); `writeState` is exposed only on a settled `exactRequest` (`:764`) or on `HttpTransportError.requestWriteState` (`:148`). The public `RawHttpExchangeExecutorOptions`/`ExactHttpModeOptions` (`:125-131`, `:55-70`) expose no pre-settlement hook.
**Impact:** Either a flaky callback, or an author inventing a seam in a non-owned package, or (worst) reporting the independent 200 as proof the first request was sent.
**Fix:** State the dependency on the fixed 1000 ms budget in the three callbacks; require an explicit assertion that the first exchange promise is **unsettled** immediately before `close()` is invoked (a settled-flag check, which fails loudly rather than passing falsely); and define "finish" as `HttpTransportError.requestWriteState === "complete"` observed at settlement, or mandate a local raw socket whose `write` callback supplies the pre-close finish.
