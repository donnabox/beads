## Why a new cohort is necessary

The current cumulative harness passes empty descriptor/schema arrays to the installed factory (`scripts/installed-reference-observation.mjs:87–102`). The factory then installs 13 remapped shipped descriptors, without properties schemas. Existing update/document-validation cases therefore cannot observe rejection by an effective Type schema or distinguish metadata's exemption from that schema. The current whole-contract inventory remains 26 proposed whole IDs, 103 uncovered, out of 129 required; 41 authored rows are not 41 whole contracts.

Use the existing private installed configuration API, unchanged. `packages/server/src/installed-reference-configuration.ts:19–78,124–158` already captures artifacts, compiles local closure, and requires Scope-local hosted identities. A nonempty descriptor list replaces, rather than supplements, the shipped set. Construct all 13 unchanged descriptors with `referenceTypeArtifacts(scope)` and the existing `stringifyJsonValue`, then merge four fresh immutable Type IDs; served inventory is byte-lexicographic Type-ID order, not append order. Install all schema bytes before admitting requests. Never change content at any existing ID or fetch contracts during requests. This follows `docs/specs/bdp.md:2533–2582`.

Make the new configuration the explicit cumulative test cohort: all old and new scenarios run against the same installed configuration, credentials, policy and limits. Do not create a schema-only suite whose results are spliced into the schema-free report. The prior frozen source/report remains reproducible; the new report gets new fixture, manifest, installed-contract and configuration identities. Source is launcher/reviewer-verified metadata, not independent target attestation.

Link source/target constraints permit the existing Task endpoints; no ownership declarations, external pins, multiplicity policy or lifecycle changes. Read the actual full descriptors back over HTTP, including endpoint declarations, before schema-sensitive writes.

Use four open-root JSON Schema resources beneath `schemas/`, with explicit `$id` and draft 2020-12 vocabulary. For each schema, `$id`, hosted `retrievalUri`, and descriptor `propertiesSchema` MUST be the same absolute canonical URI; a fixture invariant asserts all three equal. Base contracts require integer `n >= 0`; child contracts require boolean `enabled` and, when `enabled` is true, require string `detail`. Both categories use the same constraints but distinct schema identities. A retained extra `opaque` property provides an open-properties preservation oracle. The child schema does not restate the base constraint. This discriminates the intersection from parent-only, child-only, or override behavior (`docs/specs/bdp.md:562–607`). Keep references wholly local. No diamond, contradictory schema, remote fetch, new vocabulary, Type installation API, or schema budget stress in this slice.

Expected fixture inventory is 17 Types. Update both fixture oracles explicitly: `/oracles/collections/type-summaries` contains the complete17 ID/name/describes tuples; `/oracles/ordering/types` is their independent canonical byte-lexicographic ID order. The four `schema-*` IDs interleave between relationship and task (one-based positions11–14), not at the end. Keep the real corruption controls. Add all four schema-bearing descriptor GETs and closed normative TypeDescriptor validation to `read.types.descriptor` itself, with exact authored descriptor equality. Keep inherited HTTP GET/HEAD and cache/CORS cases unchanged and rerun them against this same new configuration. New artifact/schema GET routes are exact derived routes, no wildcard. Schema resources should be dereferenced and compared with the authored contract, not merely inferred from capture identity. ## Counterfactuals and limits

Bounded semantic controls: change the reported failing parent Type to the child, change keyword location to another valid absolute URI, change instance location to a request-relative but syntactically legal pointer, corrupt a refused update's independent GET, and corrupt accepted metadata or retained open properties. Each remains schema-valid where intended and must fail the named row-local assertion; generic schema failure alone is insufficient. Existing response-wrapper controls are assertion sensitivity over actual socket observations, not transparent wire forwarding or fabricated qualification results.

No new assertion API for substring/message semantics, array length arithmetic or schema evaluation. Reuse exact-value/equalsBinding/schema assertions. If diagnostic bound measurement needs a small test-local observation assertion, it is non-crediting until its binding to the row/report is explicit; keep diagnostics partial rather than add a matcher language. Single-cause probes avoid assuming unspecified validator ordering. Discovery's fixed count32/bytes524288 are observed, not silently copied as proof of limits.

Measure manifest JSON nodes first, then bytes/depth/container maxima. Current39dd/eded manifest is48,028 nodes and1,806,985 bytes; private manifest cap4MiB and existing100,000-node ceiling remain unchanged. Reuse existing operation bindings and wrappers; do not duplicate the entire cumulative manifest or add schema-only parallel requirement lists. Type inventory is also bounded by the actual default page size20:17 Types fit the existing complete-page (`next:null`) oracle, leaving3 slots. No future expansion may assume single-page completeness beyond that limit. Budget changes require separate review.
