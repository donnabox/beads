**2. Severity: High — exact Problem-body equality is asserted against an uncorroborated hand-written literal**

- Location: `apps/bdptest/src/transactional-collection-minimum-installed.test.ts:736–745` and `:1143–1154`.
- Impact: `toEqual(missingProblem)` asserts the 404 body has *exactly* four members (`type`, `code`, `retry`, `status`). Nothing in the supplied context corroborates that member set: the `transactionalProblem` schema bundle is omitted, no observed 404 body appears anywhere in the excerpts, and the CI note records only the status transition (500 → 404), not the body. The supplied code only evidences that `code` and `retry` are real members (via `foreignEpoch`/`behind` at `:1100` region). If the real representation carries an RFC 9457 `title`, `detail`, or `instance`, then line 742 fails, and every derived assertion collapses with it (743 `bodyText`, 744 `bodyOctets`, 745 `content-length`), plus the independent literal at 1143–1154 asserts a wrong `content-length`. This is the single largest "will it actually be green, and is it green for the right reason" risk in the patch, and it is avoidable at zero request cost.
- Minimal correction: anchor both literals to an actually observed response in the same callback.
  - Resource callback: capture the loop's first GET 404 (`beads/never`, `earlier`) body and add `expect(ahead.bodyText).toBe(firstMissingBody)` alongside `toEqual(missingProblem)`. A uniform 404 must be byte-identical, so this makes the literal self-validating rather than asserted.
  - Alias callback: `absent` (`:1119` region) is already an observed GET 404 on the same `alias/never` URL. Pin `expect(absent.bodyText).toBe(JSON.stringify(notFoundProblem))` there, then replace 1143–1154 with `expect(collision.headers["content-length"]).toBe(absent.headers["content-length"])`. That is also the stronger oracle for the rule being tested — "HEAD retains the corresponding GET response metadata" — because the current code *reconstructs* the expected bytes instead of comparing against the real GET representation.

**3. Severity: Medium — the same Problem literal is duplicated across two callbacks with no shared constant**
