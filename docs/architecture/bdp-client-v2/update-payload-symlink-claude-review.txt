### LOW · the entry guard refuses on symlinks that contribute nothing to `payloadIdentity`

`installed-reference.ts:36`. The throw fires on *every* symlinked entry, before the `/\.(?:[cm]?js|json|node|wasm)$/` filter that decides what is actually hashed. Reachability is the same shape as prior finding C′ — not today's pnpm/npm layouts (regular files and hardlinks), but any store-backed or vendored `node_modules` where package contents are links rather than copies (Nix, Bazel, distro-packaged trees, a tarball that genuinely packs a symlinked license or doc). There, the candidate cannot start at all, and the message names a payload symlink for a file that is not payload. Fail-closed and bounded, so this is a scope-of-refusal flag, not a hole.

Fix if undesired: move the `:36` throw below the directory/extension discrimination, so it refuses only links that would otherwise have been hashed or recursed into — a symlinked `.js`, `.json`, `.node`, `.wasm`, or directory. The three maintained tests all exercise exactly those cases and would stay green.

## Evidence-precision notes (not defects)

- **`:30` is the only guard with no repo test.** It is unreachable through a readdir entry — a recursed directory is already proven non-symlink at `:36`, making the `:30` lstat redundant on that path. Its sole non-redundant role is the explicit `bindFiles("dist")` / `bindFiles("schemas")` calls, and the three new cases all tamper with `fast-uri`, which enters via `bindFiles("")`. Verified externally (probe B); worth a fourth case replacing `@bdp/protocol/schemas`.
- **The listener-rebind assertion at `installed-reference.test.ts:474-481` is near-vacuous.** `launchInstalledReference` rejects *on child exit*, so by the time the test binds `config.listener.port` the child is already dead and could not be holding any port — the assertion cannot distinguish "never listened" from "listened, then exited". The ordering claim in `review.md:11` ("its configured listener port can be rebound") therefore rests entirely on `existsSync(store) === false` at `:472`, which is sound because store creation is durable and precedes the listener. The rebind check is harmless, just not load-bearing.
- **The three cases pin *that* startup refused, not *why*.** `installed reference qualification failed` is the generic redacted stderr (`installed-reference-process.ts:79`) for any factory failure. That redaction is deliberate, so this is inherent rather than fixable — but it does mean an unrelated future failure in that fixture keeps these tests green. The tests are still genuine tripwires: without the guards, all three mutations start successfully (symlinked `utils.js` and `lib` are skipped as neither file nor directory; a symlinked `package.json` is read straight through), so each would fail on the missing rejection.
- A symlinked `@bdp/server/dist` is not reachable as a *symlink* refusal: Node realpaths the ESM entry, so `import.meta.url` already points at the target and `root` becomes the target's parent. It fails closed anyway, on `lstat` ENOENT for the missing `package.json`, with a misdirecting error. Contrived; recording only.
- Nit: each recursed directory is lstat'd twice (once as a Dirent at `:36`, once at `:30` on entry). Negligible at ~14 package visits, but the `:30` call could be hoisted to the two explicit call sites instead.
