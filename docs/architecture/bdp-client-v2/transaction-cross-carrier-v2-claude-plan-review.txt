## High

### H1 — Source-budget byte basis is misstated, and the two guard families it must update measure different quantities
**Location:** plan line 86 ("in normal two-space formatting plus terminal newline: new manifest growth **≤100000 bytes** … provisional absolute ceilings **720094 bytes**"); guard sites `packages/conformance/src/transactional-cumulative.test.ts:863–866` and `apps/bdptest/src/transactional-matrix.test.ts:1584,1593`.

**Issue.** The measured parent `620094` is the **on-disk (Prettier) byte count**, not normal two-space form. Independent local measurement:

| form | bytes |
|---|---|
| `manifest-v1.json` on disk | 620094 |
| `JSON.stringify(manifest, null, 2) + "\n"` | 630676 |
| difference | **10582** |

Prettier collapses short arrays onto one line (e.g. `"requires": ["installed-transactional-http", "transactional-receipt-observation"]`, `"equals": [["updated"], ["b"]]`), which `JSON.stringify` expands. `coverage-v1.json` happens to match normal form exactly (88043 = 88043); `fixture-v1.json` does not (716 vs 728). So the plan's stated basis is wrong for the one artifact whose budget is at issue.

The two guard families then measure different things against the *same literal* `650386`:
- `transactional-cumulative.test.ts:863–864` measures `read("manifest").byteLength` → **disk** bytes (620094; headroom 30292).
- `transactional-matrix.test.ts:1584,1593` measures `JSON.stringify(changed, null, 2) + "\n"` → **stringify** bytes (current derivative 636794; headroom 13592).

**Impact.** `720094` is basis-ambiguous, so root cannot actually bound the stop it is being asked to accept. Written into both sites it yields asymmetric effective headroom (100000 on the canonical disk guard vs ~83300 on the derivative stringify guard). Conversely, a row authored to ≤100000 bytes of *Prettier* growth has strictly larger stringify growth — the format-check-enforced on-disk form and the guarded form drift apart.

**Correction.** State the basis per guard explicitly: canonical delta/absolute guards are **on-disk Prettier bytes** (the form `format:check` enforces); the app derivative guard is **`JSON.stringify(…,null,2)+"\n"` bytes**. Publish both numbers for the candidate at preflight (disk and stringify), and set two separate absolute fences rather than one number reused in two bases. Drop "in normal two-space formatting plus terminal newline" from the manifest stop or change the baseline to 630676 consistently.

### H2 — "Every negative derivative must fit the same absolute byte/node ceilings" is arithmetically unsatisfiable
**Location:** plan line 86, second half; measured against `apps/bdptest/src/transactional-matrix.test.ts:1497–1624` (`applyDeletionControl` derivative preflight).

**Issue.** The proposed absolute ceilings (`720094` bytes / `18973` nodes) are derived from the **canonical** artifact (620094 + 100000; 16373 + 2600). The deletion derivatives are strictly larger than canonical. I reproduced `applyDeletionControl` locally against the c555 manifest:

| derivative | stringify bytes | Δ vs canonical stringify | nodes | Δ vs canonical nodes |
|---|---:|---:|---:|---:|
| `incoming-order` | 636794 | +6118 | 16529 | +156 |
| `outgoing-order` | 636794 | +6118 | 16529 | +156 |
| `committed-prefix-state` | 633780 | +3104 | 16450 | +77 |

With the new row consuming its stated stop, the worst derivative becomes:
- nodes: 16373 + 2600 + 156 = **19129 > 18973** (over by 156)
- bytes (stringify basis): 630676 + ≥100000 + 6118 = **≥736794 > 720094** (over by ≥16700)

**Impact.** At preflight the implementer either halts for a new root disposition (plan line 88: "Overflow stops work for a new explicit disposition") on a condition the plan itself created, or silently sets the derivative guard above the ceiling root accepted. Note today's guards avoid this by setting one fence (`650386`/`17275`) above *both* canonical and derivative, with the derivative binding.

**Correction.** Set the absolute derivative fences to canonical-ceiling **plus the measured derivative delta** (today +6118 bytes / +156 nodes, plus whatever the new row's own two wire controls add), or state two distinct ceilings — canonical and derivative — and say the derivative one is the binding fence. Require the preflight ledger (already produced at `:1599–1611`) to publish `normalBytes`/`nodes` for all three deletion derivatives **plus** the new row's derivatives before anchors are set.

### H3 — The revision-inequality mechanism does not exist where the plan places it
**Location:** plan line 52 ("the owned app positive test **parses the actual responses at actions 1/5** and asserts their present string revisions differ"); F4 at line 126; done-when 5 at line 134. Report shape at `packages/conformance/src/runner.ts:168–175`.

**Issue.** `ObservedExchange.response` exposes only `url`, `status`, `headers`, `decodedBodyBytes`, `wireBodyOctets`, `bodyKind`. **There is no response body in the report** the app test receives from `runCumulativeTransactionalMatrix`. `ObservedAction` is explicitly redacted ("Inputs, bindings, and output values are never reported"). So the positive test cannot "parse the actual responses" from `observed.result`. The predecessor Claude review's F4 fix text ("the owned matrix test … *can* read observed exchange bodies") carries the same error; the plan inherited it.

The only available seam is the shared `observe()` exact-execute closure at `apps/bdptest/src/transactional-matrix.test.ts:260–284`, which does hold `HttpExchangeResponse.bodyText` — the same path `invalidReceiptCredentials` already uses at `:271–279`. That closure is inside the owned file, so the work is in scope, but it is **shared by all 52 observe invocations**, and the plan's owned-file description (line 72) does not mention it and forbids runner changes (lines 72, 132).

By contrast the 409 derivative's cross-status epoch/view comparison (also plan line 52) **is** implementable from the report, since `response.headers` is present. That claim is fine.

**Impact.** F4 and done-when 5 are unimplementable as described. An implementer may substitute a weaker proxy (`decodedBodyBytes`, an out-of-band re-fetch outside the exact-mode route boundary) and still report it as "actual observed", which is precisely what the plan's "not invented constants" clause is meant to prevent.

**Correction.** Name the seam: add a narrow opt-in capture to `observe()`'s `exactExecution.execute` wrapper (`:260–284`) keyed to the two action IDs, defaulting off, and state that (a) it must not perturb any other invocation's prefix, exchange count or child ledger, (b) the 50 existing invocations' ledgers in the §cost table are asserted unchanged by it, and (c) the captured value is compared only against the Event-bound `equalsBinding` pointers so the app comparison and the manifest oracle corroborate rather than substitute. Correct line 52's wording from "parses the actual responses" to the actual mechanism.
