### 1. MEDIUM — Both new coverage rows record a partial flag without naming the unobserved selected-clause conjunct

The in-clause gaps that actually exist:

- `idempotency-key-required`, selected text (catalog `#idempotency-keys`, spec 3175–3178): "a key outside the profile" and "carries it more than once" are observed on **`create-bead` only**. The 8-carrier sweep (`key-route-create-bead` … `key-route-delete-alias`) exercises **omission** only (the 8 raw probes have zero `idempotency-key` lines); all 8 malformed spellings and all 3 repeated-field variants target `operations/create-bead`. Omission is complete across 8 carriers.
- `unsupported-media-type`, selected text (`#readupdate-problem-details`, spec 3432–3434): the 9-target sweep (`media-route-*`, incl. `sequence`) covers **undeclared** type only. "not `application/json`" is observed on `create-bead` only (`text/plain`, `application/problem+json`), as is "parameters … are ignored" (`charset=iso-8859-1`, `arbitrary=ignored`). The parameter conjunct is also observed only in the *accepting* direction; no probe shows a parameter failing to rescue a non-JSON type (e.g. `text/plain; charset=utf-8` → still 415).

**Impact.** The flags are correctly `wholeContract:false`, so nothing is over-claimed numerically — but the plan's "Done when" requires "If any cited obligation remains unobserved, preserve partial flags and **name it**", and the durable reason string is what the later whole-clause audit reads. As written it reads as full per-carrier coverage.

**Bounded fix.** Append a `Whole=false:` clause to both reasons naming the carrier-scope limits above. Coverage file only — no flag, pin, digest, manifest or binding-order change. (For whole credit later, the exact additions are one malformed spelling + one repeated-field variant per remaining singleton carrier, and one declared-wrong-media + one parameter probe per remaining mutation target; budget note in finding 5.)

### 3. LOW — The 156 new collection GETs assert no normative collection envelope schema

**Impact.** `/items` and `/next` are pinned exactly, but an unexpected additional top-level member in the collection envelope would pass unnoticed by these rows. Cross-row observation is explicitly not row-local coverage per the plan.

**Bounded fix.** Add `{"id":"schema","kind":"json-schema","schema":"#/$defs/currentBeadCollection"}` (resp. `currentLinkCollection`) to each collection GET and append the matching `<action>.schema` entries in order to the two coverage binding lists (`cumulative-artifact.test.ts` enforces exact order).
