## Findings

**1. The shared minimum gate dereferences a caller-supplied field before the authority's data-only capture — severity: low (real defect, internal contract; not reachable from HTTP)**

- File/line: `packages/server/src/transaction-read.ts:36` (gate), reached from `:199` and `packages/server/src/transaction-http.ts:531`
- Impact: `request.id.startsWith(scope)` is a *method dereference on a caller-owned field value*, executed before the authority's `snapshotRequest`/`ownData` capture (`authority-read.ts:297-329`, called later at `:1072`). `plane.minimumFor(p, m).perform({kind:"resource", resource:"type"})` — or any non-string `id` — throws `TypeError: Cannot read properties of undefined (reading 'startsWith')` **synchronously out of `perform`**, instead of returning a rejected promise carrying the authority's `invalid-input` classification. That regresses a discipline this very file goes out of its way to preserve: `readFor.perform` wraps option validation in `try/catch` specifically so "invalid options still go through the authority's rejection path, preserving lifecycle/error precedence and Promise delivery" (`transaction-read.ts:162-174`). The pre-change predicate (`isInitialTransactionCollection` plus the inlined bead/link comparison) only compared properties and could not throw, so this is a regression introduced by this diff, not inherited. Secondary: on an accessor-bearing or Proxy request the gate now invokes a caller getter/trap on a field value before `ownData` rejects it (bare property reads of `kind`/`resource`/`collection`/`continuation` had that exposure already; the method call is new).
  Serving impact is nil: `requestFromUrl` always yields a plain object with a canonical string `id` (`read-request.ts:207-219`), and through `service.readAtMinimum` the async `waitForTransactionMinimum` normalizes a sync throw into a rejection, landing on the same `empty(500)`. The defect is observable only on the private `minimumFor` facet — which is exactly where the plan requires the Scope boundary to be tested ("the new explicit Scope check must therefore be tested on the private facet").
- Fix: make the arm total — `(request.resource === "type" && typeof request.id === "string" && request.id.startsWith(scope))`. Keeps the gate shared, cheap, and ahead of the authority (which is required: the authority has no notion of this private subset).
- Note: the author's own `report.md:3` already flags this as an open native-review item ("pre-validation issue in the new Type predicate (`request.id.startsWith` before the authority's data-only capture)"), with repair pending root disposition.

## What I verified as correct (no finding)

- **Predicate delta is exactly the planned subset.** Old gate admitted initial beads/links collections plus bead/link point/properties; new gate adds in-Scope `resource:type`, initial `collection:types`, and initial `bead-links`, with `default: false` keeping `scope-discovery` and any future kind out. Both call sites now share one definition; no stale `isInitialTransactionCollection` reference remains anywhere.
- **Scope oracle is single-sourced.** The facet's `owner.scope` and the authority's validation scope cannot diverge: `prepare` derives `scope = parseCanonicalScope(entry.scope)` and *requires* `pagination.scope === scope` (`authority-read.ts:345,362`); HTTP asserts `scope !== service.scope` at construction (`transaction-http.ts:160`). `parseCanonicalScope` guarantees the trailing `/`, so `startsWith` is a correct boundary, and `parseTypeIdentity` (`read-request.ts:281-293`) still forces any admitted in-Scope Type ID to be canonically `scope + "types/…"`. The `properties` arm correctly enumerates bead/link positively (no `properties:type` variant exists, and a future one would default to excluded).
- **Same-entry minimum/error precedence.** `checkSourceCondition` runs inside the single owner entry after `materialize` and before `finish` allocates a page token (`authority-read.ts:982-994`), so for all three new surfaces: materialized `invalid-parameter`/`limit-exceeded` are preserved ahead of any minimum wait (`validateLimit` covers `collection:types` and `bead-links` via `isPageOperation`, `:751-761`); `resource-not-found` at a compatible minimum returns 404 + same-entry current context; and every failure reason `checkTransactionMinimum` can raise (`behind`, `foreign-view`, `cursor-expired`) is in the visibility-gap list, so missing+behind/foreign stays an explicit gap with no context, with no polling (`waitForTransactionMinimum` only retries on `behind`).
- **Conditional/HEAD/abort.** Type descriptors, inventories and incident views get no ETag — `scopeDataResponse` explicitly excludes `resource === "type"` and never tags pages (`read-http-routing.ts:63-74`) — so `If-None-Match: *` → 304 and a mismatching `If-Match` → 412 only after the read actually executed and the minimum was enforced; a future minimum yields 503 `catch-up-timeout` + Retry-After with no conditional shortcut, and 404/problem responses are never converted to 304 (`applyReadHttpSemantics` gates on `status === 200 && content-type === application/json`). Pre-abort rejects at the wait loop head before `facet.perform`, hence before any owner SQL.
- **Boundaries preserved.** Aliases (`minimumFor.resolveAlias`), every collection/incident continuation, malformed/partial tuples, and the six existing route gaps (`links/?cursor=missing`, `beads/?cursor=missing`, `alias/missing`, empty suffix, `bdp.json`, `operations/`) are intact; `types/<id>?view=properties` and other parser-rejected spellings stay early 400 `invalid-parameter`, not a 500 route gap; 401 precedes any read; `ordinaryDeliveryOptions` is byte-identical to `dfafd82`. `transaction-read.ts` is not re-exported from `packages/server/src/index.ts`, so renaming the predicate changes no public surface. No Type lifecycle, discovery activation, or profile advertisement is touched.
- **Fixed 20/1/7 ledger.** I counted the installed scenario by hand: 1 batch + 6 GET/HEAD + 3 conditional + 3 future + 3 foreign + 3 direction/empty + 1 anonymous = 20, with the ceiling check firing before 21 and `expect(count).toBe(20)`; the 7 URL identities match the asserted set; every authenticated read including the anonymous row transmits the full seed tuple, asserted through the declared credential-resolver channel. Independent oracles hold: `artifacts().descriptors[0]` is the Task descriptor at `${scope}types/task`, and `types/relationship` < `types/task` matches the asserted canonical-URI inventory order. The source fixture's in-Scope `types/task` correctly sorts ahead of the two preserved external descriptors, which is consistent with both the `limit: 3` inventory oracle and the `limit: 1` second-page expectation.
