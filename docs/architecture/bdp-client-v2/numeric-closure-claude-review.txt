## Findings

### N1 — Low, nonblocking future hardening (carried forward, unreachable confirmed)
**Location** `packages/server/src/member-numeric-diagnostics.ts:12` and `:55`

**Evidence (strengthened vs. Report 2).** `let selectedBudget = budget` forwards the embedder's `type`/`schemaLocation` verbatim for any operation outside create/update. Reachability is closed on both callers:
- *Member path* (`member-identity.ts:431`, embedder-supplied budget): the fallback ops are `deleteBead`, `deleteLink`, `putAlias`, `deleteAlias`. Per `schemas/bdp-v0.schema.json`, `deleteBeadMembers`/`deleteLinkMembers`/`putAliasMembers`/`deleteAliasMembers` contain only string refs, `$defs/expectedRevision` = `{"type":"string","minLength":1}`, and `revisionProvenanceInput` (strings/null). No number-typed and no free-form (`"value": true`) member exists, so `mapLosslessJson` can yield no occurrence and `diagnostic` is never invoked.
- *Transactional path* (`transaction-batch.ts:456`): `updateWhere`/`deleteWhere` **would** reach the fallback and **do** carry free-form JSON (`updateWhereMembers.change` → `$defs/propertyChange` with `"value": true`) — but `assertResourceOperation` (`transaction-batch.ts:56–67`, invoked at `:104` and `:118` during prepare) rejects them with `TransactionDevelopmentLimitError` before `evaluateTransaction`, and that path's `diagnostic` is in-tree message-only regardless.

**Impact** No live Spec 3459 violation. Latent: the guarantee rests on per-operation enumeration plus an input schema that happens to have no numbers in those four operations. Adding a numeric-bearing member to any of them, or implementing `updateWhere`/`deleteWhere` for the private owner, silently re-admits Type claims on a non-Type refusal with no test to catch it.

**Fix** Make stripping the default: initialize `:12` to a budget whose `diagnostic` returns `Object.freeze({ message: diagnostic(occurrence).message })`, and let the create/update branches add `document`/`instanceLocation` on top. If `updateWhere` is later implemented, that default also gives it a defined, compliant pointer treatment rather than passthrough. Not a blocker for this supplement — no production source change belongs in it.
