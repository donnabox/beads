## Findings — `transactional-fresh-depth-installed.test.ts` (entry/provenance, transport binding, deadlines/cleanup, retention)

1. **Medium-High — temp directory leaks silently on any launch failure.** `apps/bdptest/src/transactional-fresh-depth-installed.test.ts:925` gates `rmSync` on `stopped`, and `stopped` (911-913) requires a `child` handle. `launchInstalledTransaction` returns a handle only on success (`scripts/transaction-installed-observation.mjs:86-93`), so every startup failure (child exit 2, "exited before ready", abort) leaves `child === undefined` → `stopped === false` → directory never removed. Worse, the "directory remains" failure at 930 is *also* gated on `stopped`, so nothing records the leak; only `directoryAbsent: false` appears in the report. Impact: unbounded `/tmp/bdp-fresh-depth-installed-*` accumulation plus an evidence record that does not state the retention. Minimal fix: have the launcher attach the reaped child/exit outcome to the thrown error (it already SIGKILLs and awaits exit at 38-46/87-93) and treat that as `stopped`; additionally push an explicit failure whenever `directory && !directoryAbsent`, not only when `stopped`.

2. **Medium — `stopped` is read before a cleanup-deadline SIGKILL can be observed.** The cleanup timer kills at line 892 and immediately rejects (893); `stopped` is then computed synchronously at 911-913, before the child's `exit` event fires, so `exitCode`/`signalCode` are still `null`. Every cleanup overrun therefore reports "installed fresh depth child remains active", logs `childSignalCode: null` (970) contradicting the kill, and skips directory removal (finding 1's leak). Minimal fix: after the kill, `await once(child.child, "exit")` under a short extra bound, then compute `stopped`.

3. **Medium — module-scope setup failures produce no observation record.** Entry resolution/hashing (54-56), both `execFileSync` git calls (57-61, default 1 MB `maxBuffer`), fixture/bundle reads (63-71), and Ajv compilation (73-82) all run at module load, outside the `it` body. A missing `packages/server/dist/transaction-installed-process.js`, a git failure/ENOBUFS, a bad env override (52-53), or an Ajv ref error aborts file collection, so the required `{"observation":"private-installed-fresh-depth","outcome":"failed"}` line (935-985) is never emitted — the witness fails with no retained report. Minimal fix: move entry/provenance/fixture/validator construction into the test's `try` (or a `beforeAll` whose error is pushed into `failures`).

4. **Medium — transport-failed exchanges leave no row in the report.** `responseSizes.push` (485) and `responses.push` (487) execute only after the executor resolves. An abort, 5 s timeout, or `body-limit` rejection from `createRawHttpExchangeExecutor` drops the leg entirely: the report shows `attempted > exchanges` with no label, URL, or `HttpTransportError.category` for the failing request, and `responses.at(-1)` in assertion messages (540) then points at the *previous* exchange. Minimal fix: wrap the executor call in `try/catch`, push `{ordinal, label, method, url, transportError: error.category, requestWriteState}`, and rethrow.

5. **Medium-Low — child stdout/stderr are consumed and discarded, so startup failures are undiagnosable.** `scripts/transaction-installed-observation.mjs:14-18` only counts bytes and SIGKILLs past 64 KiB with no recorded reason. The entry writes just `"installed transaction qualification failed"` and exits 2 (`packages/server/src/transaction-installed-process.ts:71-77`), so any configuration rejection surfaces as "exited before ready"/"did not close cleanly", and the test report has no child-output field at all. Minimal fix: retain a bounded tail (e.g. last 4 KiB/stream) on the handle and on thrown errors, and add it plus the overrun flag to the report.

6. **Low-Medium — launcher spawns with the full inherited environment and a hardcoded `cwd`.** `scripts/transaction-installed-observation.mjs:9-12` passes no `env`, so `NODE_OPTIONS` (`--import`/`--require` loaders) and any `BDP_*` variables reach the child, contradicting the entry's stated contract that "configuration arrives only through inherited IPC" (`transaction-installed-process.ts:2`); nothing in the report records the environment or the runtime used. `cwd: "/tmp"` is also POSIX-hardcoded. Minimal fix: pass an allowlisted `env` (`PATH`/`HOME`/`TMPDIR`), use `os.tmpdir()` or the provisioned directory, and record the allowlist plus `process.execPath`/`process.version` in the report. Note this launcher is shared by the other installed witnesses.

7. **Low — hashed entry and executed entry are different paths.** `resolvedEntry` is what gets `realpathSync`'d, hashed (54-56), and location-checked (411), but line 418 passes the unresolved `entry` to the launcher, which spawns `[entry]`. Under a symlink mutated between hash and spawn, `entrySha256`/`entry` in the report describe a file that was not executed. Minimal fix: pass `resolvedEntry` to `launchInstalledTransaction`.

8. **Low — a declared source commit is accepted without an installed entry.** Lines 59-61 honor `BDP_TRANSACTIONAL_SOURCE_COMMIT` even on the in-repo development fallback (the reverse pairing is enforced at 52-53), and the report's `declaredSourceCommit` (940) does not distinguish a declared value from `git rev-parse HEAD`. A run can therefore advertise an arbitrary 40-hex provenance for a fallback entry. Minimal fix: reject the declared commit unless `BDP_TRANSACTIONAL_INSTALLED_ENTRY` is set, and emit `sourceCommitOrigin: "declared" | "head"`.

9. **Low — request 13's route is bound with a hardcoded method and unvalidated target.** Line 470 pushes `{ method: "GET", url }` rather than `literal.method`, and line 469 checks only the 8192-byte length of the derived `receiptTarget`. If row 13 is not GET, or the receipt URL is not origin-equal and `/acme/`-prefixed, `snapshotExactRoutes` (`packages/conformance/src/http-executor.ts:541-546`) fails it as a generic `configuration` `HttpTransportError` rather than a diagnosed route/scope defect. Minimal fix: push `{ method: literal.method, url }` and assert `url.startsWith(scope)` before dispatch.

10. **Low — served artifacts are not tied to the artifacts supplied.** `installedContractsDigest` only strips the `development-schema5-` prefix (`apps/bdptest/test-support/installed-contract-identity.ts:2-6`), and the digest preimage mixes in server-internal ceilings (`packages/server/src/development-contracts.ts:144-152`), so the test cannot recompute it; the report records only `artifactBytes` (956-958). A child that substituted or dropped `ownsOutgoing.max` / `propertiesSchema` would still bind. Minimal fix (no coupling to internals): add the per-artifact `retrievalUri` + sha256 list to the report so the record binds the exact offered bytes.
